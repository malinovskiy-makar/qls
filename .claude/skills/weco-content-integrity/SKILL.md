# Целостность банка задач

Ты следишь, чтобы массовая операция над ~31 тысячей задач была обратимой,
проверяемой и не испортила то, что чинила.

## Когда запускаться

Любое из:
- пишется или правится команда импорта;
- готовится массовая правка `statement`, `answer`, `solution`, подпунктов;
- дедупликация, слияние или удаление задач;
- обогащение полей моделью;
- заливка данных на продакшен.

## Запрещено

- **Массовая правка `statement` / `answer` / `solution` моделью.** ИИ дописывает
  НОВЫЕ поля. Причина не теоретическая: свип испортил 233 поля в 195 задачах —
  13,2% затронутого.
- **Применение без снимка.** Нет бэкапа — нет применения.
- **Применение без ревью выборки человеком.**
- **Считать поле сломанным по текстовым признакам.** Предфильтр к ошибкам KaTeX
  слеп: выборка из 100 «чистых» по признакам полей дала 3 с выросшим числом
  ошибок рендера. Рендерить надо всё.
- **Удаление задач** без явного разрешения владельца. Скрытие (`status='hidden'`,
  флаг шлюза) обратимо, удаление — нет.

## Обязательная последовательность

1. **`--dry-run` по умолчанию.** Боевой прогон — отдельным флагом (`--apply`,
   `--confirm`). Случайный запуск без флага обязан ничего не сделать.

2. **Счётчики до и после.** Сколько задач затронуто, сколько полей, сколько
   правок в каждом классе, сколько отклонено предохранителями. «Готово» без
   чисел — не отчёт.

3. **Выборочный diff.** HTML с парами ДО/ПОСЛЕ, не меньше 15–20 случаев,
   открываемый глазами. Отдельно показать самые длинные и самые короткие правки:
   ломается обычно на краях.

4. **Стоп-гейт владельца** перед боевым прогоном. Показать числа и предпросмотр,
   дождаться ответа.

5. **Обратимый журнал.** Снимок старых значений (JSON `id` → старый текст) плюс
   копия базы. Путь к бэкапу — в выводе команды.

6. **Идемпотентность.** Повторный `--dry-run` после применения обязан дать ноль.
   Это не формальность — так ловятся правила, «доедающие» текст на втором
   проходе.

7. **Инварианты.** Сверить до и после:
   - число задач не изменилось (если операция не про удаление);
   - число подпунктов изменилось ровно на ожидаемую величину;
   - парность `$` не ухудшилась;
   - баланс `{}` не ухудшился;
   - непустые `solution` / `answer` не обнулились.

   Считать **дифференциально** (стало хуже / стало лучше), а не абсолютно:
   в банке есть унаследованные поломки, и абсолютное число всегда некрасивое.

8. **Эмбеддинги.** Изменили текст — пересчитать эмбеддинги изменённых id.
   ⚠️ `night_embeddings` **молча пропустит** id, уже записанный в done-файл, и
   напишет «осталось 0». Сначала вычистить id из done-файла, потом запускать.

## Проверка формул

Конвейер рендера в проверке обязан **дословно** повторять боевой из
`catalog/base.html`: маскировка `\$`, те же разделители, `$$` раньше `$`,
`throwOnError: false`. Любое отличие превращает замер в фикцию.

## Импорт

- Нормализация текста — **до** вычисления `content_hash`, иначе дедупликация не
  работает.
- Источник сомнительного качества → `status='draft'`. `published` — осознанное
  решение про конкретный источник.
- Подпункты адресуются по `pk`, а не по метке: метки не уникальны.
- Каждое рискованное создание — в собственном `transaction.atomic()`: на SQLite
  `IntegrityError` отравляет родительский savepoint.

## Отчёт

**Свидетельство** (команда, числа, путь к предпросмотру) → **находка** →
**серьёзность** → **что делать**.

Обязательно назвать: сколько затронуто, где бэкап, подтверждена ли
идемпотентность, какие инварианты проверены и с каким результатом, какие id
ушли на ручной разбор.

Если операция ограничивает охват (первые N, без повторов, выборка) — **сказать
об этом числом**. Молчаливое усечение читается как «покрыли всё», а это не так.
