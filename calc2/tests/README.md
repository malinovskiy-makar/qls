# Регрессионные тесты математики calc2

Математика калькулятора `/calc2/` живёт в JS (Math.js в браузере), поэтому
проверяется не на «извлечённом» коде, а в **настоящем браузере** через Playwright —
тем же путём, каким её видит пользователь.

## Два способа запуска

### 1. Как часть `manage.py test` (рекомендуется)

```
./venv/bin/python manage.py test calc2
```

`calc2/tests/test_calc2_math.py` поднимает живой сервер (`LiveServerTestCase`),
создаёт суперпользователя и запускает node-раннер против него. Если Playwright,
Node или CDN (Math.js/D3) недоступны — тест **пропускается** (skip), а не падает,
чтобы не ломать остальные тесты в офлайн-окружении.

### 2. Отдельный node-раннер (быстрая проверка при разработке)

Нужен живой dev-сервер (`./venv/bin/python manage.py runserver 8099`):

```
node calc2/tests/calc2_math.mjs
```

Параметры через env: `CALC2_BASE_URL` (по умолчанию `http://127.0.0.1:8099`),
`CALC2_USER` (`admin`), `CALC2_PASS` (`admin12345`).
Коды выхода: `0` — всё прошло, `1` — есть провалы, `3` — calc2 не загрузился.

## Что проверяется (17 контрольных чисел)

Рынок (равновесие, налог), монополия (обычная, дискриминация 1-й и 3-й степени,
ломаный спрос), эластичность, экстерналии (Пигу), рынок труда (монопсония,
профсоюз-монополист, МРОТ), неравенство (доходы, формула Лоренца, прогрессивный
налог), КПВ-сумма (дуги, изломы), торговля Б (эндогенная мировая цена).

Каждый случай приводит calc2 в нужное состояние через глобальные функции
(`loadScene`, `setMonoMode`, `setLaborStruct`, …), дёргает `redrawAll()` и читает
результат из `STATE` (например `STATE.eq`, `STATE.mono`, `STATE.laborMono`,
`STATE.ineqStats`). Числа взяты из выверенных прошлых сессий (см. CLAUDE.md).

**Если тест покраснел** — не подгоняйте число под код вслепую: это может быть
реальный регресс математики. Сверьте с CLAUDE.md и разберитесь в причине.

## Зубастость новых проверок — отсмотр 26.08

Проверка, которая не может покраснеть, ничего не стережёт. По каждому новому
правилу дефект возвращался в код НАРОЧНО, и записано, какие именно случаи от
этого краснеют. Отбор случая по куску имени:
`CALC2_ONLY='кусок имени' node calc2/tests/calc2_math.mjs`.

| Возвращённый дефект | Что краснеет |
|---|---|
| убрать `sumDomainTo` из узлов (`piecewiseNodesQ`, 30-curves.js) | «Сложение · путь суммарной кривой доходит до конца области определения»: путь спроса 40 вместо 160, «НЕ обрывается на изломе» = 0 |
| вернуть `mathToTex` в `tipExpr` (86-workspace.js) | «Подсказка кривой · кусочная запись набрана общим переводчиком»: 8 проверок из 9 |
| вернуть `- STATE.tax` в потоварном `taxAfterD` | «Вмешательство · субсидия покупателю двигает кривую спроса»: D + s выходит из (0; 80) вместо (0; 120) |
| ограничить `intervOnBuyer` одним налогом | там же: сдвинута не та кривая, имя не то, подсказка не та |
| обернуть блок «Итоговая функция» в `.sb-note` | «Итоговая функция · первым блоком…»: 6 проверок, блок уезжает в разбор |
| сломать `xOf` параболы (λ/(2b) → λ/(3b)) | «Сложение КПВ · закрытая форма по равным альт. издержкам»: наборы (а) и (б) |
| сломать сведение набора парабол (`ppfReduceActive`) | там же: набор (б) |
| взять НИЖНЮЮ огибающую вместо верхней | «Сложение КПВ · убывающие альт. издержки»: все значения |
| сдвинуть кусок огибающей на 1 по Y | там же: непрерывность в узле X = 9 (отношение скачков 1,15 вместо 0) |
| выгрузить кривую таблицей точек | `export_audit.mjs`: «кривые выгружены формулами, а не таблицами точек» |
| поставить всем кривым одну толщину (`very thick`) | `export_audit.mjs`: «у каждой кривой указана толщина» |
| подмешать в файл ширину окна браузера | `export_audit.mjs`: «файл при окне 1200 и 1600 px одинаков» |

⚠️ Две проверки из первой редакции пришлось переписать — они краснели на
ВЕРНОМ коде, то есть стерегли не правило, а отпечаток:

* «блок не уехал в разбор» искала в «Объяснении модели» СЛОВА «Итоговая
  функция» — и находила их в честном тексте разбора, где сказано, где эту
  запись искать. Правило про УЗЕЛ: блока с классом `ff` в разборе быть не
  должно ни одного;
* «в узле кривая непрерывна» требовала совпадения значений при шаге 1e-3. Но в
  узле у кривой ИЗЛОМ: наклоны слева и справа разные, и значения законно
  расходятся на |Δнаклона|·2ε. Правило другое: скачок обязан СТРЕМИТЬСЯ К НУЛЮ
  вместе с шагом. Считаем его при двух шагах и смотрим на отношение.

## Превью моделей и экран выбора (ADR 0141)

Превью экрана выбора — `calc2/static/calc2/previews.json`, собирается заранее из записи при рисовании
стандартного старта каждой рабочей модели (опись выгрузки .tex на белом листе: кривые, закраски, сплошные
отрезки, оси; без подписей, чисел и точек; цвета — именами токенов темы).

```bash
./venv313/bin/python manage.py runserver 8099 --settings=config.settings_check --noreload
node calc2/tests/previews/make_previews.mjs          # пересобрать previews.json
CHECK=1 node calc2/tests/previews/make_previews.mjs  # только сверить: файл совпадает с пересборкой побайтно
node calc2/tests/picker_probe.mjs                    # экран выбора; SHOTS=1 — снимки в reports/calc2_picker/
```

| Что | Где | Краснеет, когда |
|---|---|---|
| свежесть превью | `tex/ci_quick.mjs` (CI: `test_calc2_tex`) | отпечаток описи старта ≠ `fp` в `previews.json`: «превью устарело: <модель>, пересоберите командой …» |
| состав превью | `test_calc2_previews.py` (без браузера) | ключи файла ≠ 42 рабочие карточки шаблона, превью у «скоро», путь без `M`, цвет не токен, текст в файле, больше 150 КБ, `.scard-spec` в шаблоне |
| экран выбора | `picker_probe.mjs` | вкладок не 10 или числа не 6, 4, 7, 4, 5, 4, 2, 2, 6, 2; карточек ≠ рабочие + «скоро»; превью ≠ карточки + ряд «Продолжить»; подпись не «Продолжить · <когда>»; страница едет вбок на 390 / 760 / 1440; цель касания меньше 44; контраст кривой превью ниже 3 : 1 |
