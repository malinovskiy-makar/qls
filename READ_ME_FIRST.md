# READ ME FIRST — как развернуть проект «ЭкЗадачи» на Windows

Привет! Это пошаговая инструкция. Она написана так, чтобы её можно было
выполнять, ничего не додумывая: копируете команду, вставляете, жмёте Enter,
сверяете вывод с тем, что написано в «Что должно получиться».

**Главное правило: не пропускайте шаги и не идите дальше, если вывод не
совпал.** Если что-то пошло не так — в конце каждого шага написано, что
делать. Если и это не помогло — напишите Макару и покажите, что вывелось.

Времени на всё: примерно 1–1,5 часа, из них большая часть — распаковка
и ожидание.

---

## Несколько слов о терминале

Терминал (он же «командная строка») — это окно, куда пишут команды текстом.
На Windows нам нужен **PowerShell**.

Как открыть: нажмите **Win + X**, в появившемся меню выберите
**«Терминал»** или **«Windows PowerShell»**.

Три вещи, которые пригодятся:

- Вставить скопированную команду — правая кнопка мыши или **Ctrl + V**.
- Прервать зависшую команду — **Ctrl + C**.
- Строка вида `PS C:\qls>` в начале — это приглашение, его печатать не надо.
  Печатается только то, что после него.

Чтобы начать работать, достаточно **части 1** (`qls_part1_start.zip`) —

## 2. Установка Python

**Python** — программа, на языке которой написан проект. Без неё ничего
не запустится.

### 2.1. Скачайте установщик

Откройте в браузере:

```
https://www.python.org/downloads/release/python-3119/
```

Пролистайте страницу вниз до таблицы **Files** и скачайте файл
**«Windows installer (64-bit)»**.

> ### Почему именно так, а не проще
>
> **Не ставьте Python из Microsoft Store.** Магазинная версия ставит
> урезанную заглушку: команды `python` и `pip` в ней работают не так,
> как ожидает проект, а часть библиотек не устанавливается вовсе.
> Диагностировать это тяжело — всё выглядит установленным, но не работает.
>
> **Версия — 3.11.9.** У Макара проект работает на 3.9, но под Windows
> для Python 3.9 многие библиотеки давно не выпускают готовых сборок,
> и установка будет пытаться собирать их из исходников (это почти всегда
> заканчивается ошибкой). На 3.11 работает боевой сервер проекта — версия
> проверена. Код специально написан без новых конструкций, поэтому на 3.11
> он идёт без единой правки.
>
> Версии 3.12 и 3.13 тоже, скорее всего, заработают, но их с этим проектом
> никто не проверял. Берите 3.11.9.

### 2.2. Установите

Запустите скачанный файл. **На самом первом экране, внизу, поставьте
галочку «Add python.exe to PATH».**

Это самая частая ошибка при установке Python. Галочка означает «разрешить
запускать Python из терминала по имени». Без неё каждая команда из этой
инструкции будет отвечать «python не является внутренней или внешней
командой», и придётся переустанавливать.

Поставили галочку — нажмите **Install Now** и дождитесь конца.

### 2.3. Проверьте

**Закройте терминал и откройте заново** (иначе он не увидит новую
установку), затем выполните:

```
python --version
```

**Что должно получиться:**

```
Python 3.11.9
```

**Если вывелось другое:**

- `python не является внутренней или внешней командой` — забыли галочку
  «Add python.exe to PATH». Запустите установщик снова, выберите
  **Modify**, дойдите до конца, затем повторите установку с галочкой.
  Проще всего — удалить Python через «Установка и удаление программ»
  и поставить заново, не забыв галочку.
- Открылся Microsoft Store — стоит магазинная заглушка. Откройте
  «Параметры» → «Приложения» → «Дополнительные параметры приложения» →
  «Псевдонимы выполнения приложения» и **выключите** там оба переключателя
  со словом Python. Потом проверьте команду ещё раз.
- Версия вида `Python 3.9.x` или `Python 3.13.x` — установилась другая
  версия. Работать, скорее всего, будет, но если дальше что-то сломается,
  первым делом ставьте ровно 3.11.9.

## 3. Установка Git

**Git** — программа, которая скачивает код проекта с GitHub и потом
приносит обновления.

### 3.1. Скачайте и установите

Откройте:

```
https://git-scm.com/download/win
```

Скачайте **«64-bit Git for Windows Setup»**, запустите и **на всех экранах
жмите Next, ничего не меняя**. Настройки по умолчанию нам подходят
полностью. В конце — Install.

### 3.2. Проверьте

Снова **закройте и откройте терминал**, затем:

```
git --version
```

**Что должно получиться:** строка вида `git version 2.47.1.windows.1`
(числа могут отличаться — это нормально).

**Если вывелось `git не является внутренней или внешней командой`:**
закройте терминал и откройте ещё раз — очень часто дело в этом. Не помогло
— переустановите Git, ничего не меняя в настройках установщика.

## 4. Скачать код с GitHub

### 4.1. Создайте папку для проекта

```
cd C:\
```

```
mkdir qls
```

**Что должно получиться:** появится строка с описанием созданной папки
`qls`. Если написано «Уже существует» — ничего страшного, идём дальше.

> **Почему именно `C:\qls`, а не «Документы» или рабочий стол.** У Windows
> есть ограничение на длину пути — 260 символов. Внутри проекта есть файлы
> с длинными русскими названиями, и если начать с длинного пути вроде
> `C:\Users\Анич\Documents\Проекты\...`, часть файлов просто не
> распакуется. Короткий путь `C:\qls` даёт запас. Не переносите папку
> в другое место.

### 4.2. Скачайте код

```
cd C:\qls
```

```
git clone https://github.com/malinovskiy-makar/qls.git .
```

Точка в конце — часть команды, она означает «прямо сюда, без вложенной
папки». Не потеряйте её.

**Что должно получиться:** несколько строк вида `Клонирование в «.»…`,
`Получение объектов: 100%…`. Займёт минуту-другую.

**Если спросили логин и пароль** — репозиторий приватный, и Макар должен
сначала добавить вас соавтором. Напишите ему. Когда добавит — Git
предложит войти через браузер, это нормально.

### 4.3. Переключитесь на рабочую ветку

**Ветка** — это версия кода. На момент сборки этого пакета (18.08.2026)
вся работа уже лежит в **`main`** — отдельную рабочую ветку переключать
не нужно, `git clone` сразу ставит вас на неё.

Если всё же хотите свериться явно:

```
git checkout main
```

> ### ⚠️ Если вывелась ошибка `pathspec ... did not match`
>
> Значит с момента сборки пакета что-то в ветках поменялось. Это не ваша
> ошибка и починить её со своей стороны нельзя. Напишите Макару.

### 4.4. Проверьте, что взяли именно ту версию

```
git log -1 --format=%H
```

**Что должно получиться:** ровно эта строка —

```
72546b1a83af172d29204a754c771ae086b96fcf
```

**Если строка другая:** значит Макар успел что-то дописать после сборки
пакета. Скорее всего, это нормально, но напишите ему и уточните, прежде
чем начинать чистку.

## 5. Куда распаковать архивы

Все три архива распаковываются **в одну и ту же папку `C:\qls`** — ту,
куда вы только что скачали код. Внутри каждого уже лежат правильные папки
(`reports`, `materials`, `backups`), они сами встанут на свои места.

### 5.1. Сначала поставьте 7-Zip

Встроенный распаковщик Windows плохо справляется с большими архивами и
длинными русскими названиями. Поставьте 7-Zip — это бесплатно и стандартно:

```
https://www.7-zip.org/
```

Скачайте **64-bit x64**, установите (везде Next).

### 5.2. Распакуйте

Для каждого архива: правая кнопка по файлу → **7-Zip** → **Распаковать
здесь…** (Extract Here), и в поле пути укажите `C:\qls\`.

Порядок — по важности:

| Очередь | Архив | Куда встанет | Срочность |
|---|---|---|---|
| 1 | `qls_part1_start.zip` | `C:\qls\db.sqlite3`, `C:\qls\reports\`, `C:\qls\backups\` + доки в корень | **распакуйте первым — после него уже можно работать** |
| 2 | `qls_part2_materials.zip` | `C:\qls\materials\...` | не срочно |
| 3 | `qls_part3_materials.zip` | `C:\qls\materials\...` | не срочно |

**После распаковки только части 1 уже можно проверять числа (шаг 6) и
начинать чистку текстов.** Части 2 и 3 — это исходные PDF `materials`, из
которых задачи когда-то импортировали; для самой чистки они не нужны.
Части 2 и 3 распаковываются в тот же `materials\` независимо друг от
друга и в любом порядке — они делят одну и ту же папку `Archive 6` между
собой (это нормально, 7-Zip домешает файлы одной части к файлам другой).

**Если при распаковке частей 2/3 ругается на длинные имена или на файл с
двоеточием в названии** — так и должно быть, см. «Известные грабли»,
пункт 3. Эти файлы к чистке задач отношения не имеют: пропустите их
и идите дальше.

### 5.3. Проверьте, что база на месте

```
cd C:\qls
```

```
dir db.sqlite3
```

**Что должно получиться:** строка с файлом и размером **463 036 416** байт
(Windows покажет как `463 036 416`).

**Если файла нет** — распаковалось не туда. Найдите `db.sqlite3` в папке,
куда распаковали, и перенесите его прямо в `C:\qls`.

## 7. Установить библиотеки

**Библиотеки** — готовые куски чужого кода, которыми пользуется проект
(например, сам Django — каркас сайта).

### 7.1. Создайте окружение

**Окружение** (venv) — отдельная папка, куда библиотеки ставятся только
для этого проекта и не мешают остальному компьютеру.

```
cd C:\qls
```

```
python -m venv venv
```

**Что должно получиться:** ничего не выведется, просто появится новая
строка приглашения. Это нормально. В папке появится каталог `venv`.

### 7.2. Обновите установщик

```
venv\Scripts\python -m pip install --upgrade pip
```

**Что должно получиться:** строки про скачивание и в конце
`Successfully installed pip-…`.

### 7.3. Поставьте основные библиотеки

```
venv\Scripts\python -m pip install -r requirements.txt
```

**Что должно получиться:** много строк про скачивание, в конце —
`Successfully installed Django-4.2.30 …` и список из десятка названий.
Занимает 2–5 минут.

**Если в конце красная ошибка:** посмотрите, на каком названии
споткнулось.

- Споткнулось на `psycopg2-binary` — это библиотека для боевой базы
  на сервере, локально она не нужна. Откройте `requirements.txt`
  в «Блокноте», поставьте `#` в начале строки с `psycopg2-binary`,
  сохраните и повторите команду.
- Споткнулось на `PyMuPDF` или `pdfminer.six` — они нужны только для
  импорта новых PDF, для чистки текстов нет. Закомментируйте так же.
- Ошибка со словами `Microsoft Visual C++ 14.0 or greater is required` —
  библиотека пытается собраться из исходников, потому что готовой сборки
  под вашу версию Python нет. Это верный признак, что установился Python
  не 3.11. Проверьте `python --version`.

### 7.4. Тяжёлые библиотеки — НЕ ставьте

В файле `requirements-local.txt` есть `torch`, `sentence-transformers`
и другие. Это несколько гигабайт, и ставятся они долго и капризно.

**Для чистки текстов задач они не нужны совсем.** Они нужны только для
пересчёта «эмбеддингов» — числовых отпечатков смысла задач, по которым
работает поиск похожего. Пересчёт — отдельная большая работа, и до неё
дело дойдёт нескоро; когда дойдёт, разберёмся отдельно.

Поэтому: **`requirements-local.txt` не устанавливайте.** Если всё-таки
попробуете и `pip` упадёт на `torch` — просто пропустите, на чистку это
никак не влияет. Команды `build_embeddings`, `night_embeddings`,
`find_similar` без этих библиотек работать не будут — это ожидаемо.

### 7.5. Проверьте, что Django завёлся

```
venv\Scripts\python manage.py check
```

**Что должно получиться:**

```
System check identified no issues (0 silenced).
```

**Если ошибка `ModuleNotFoundError: No module named 'django'`** — вы
запустили не тот Python. Обратите внимание: в команде именно
`venv\Scripts\python`, а не просто `python`. Это принципиально: библиотеки
поставлены в окружение, и запускать надо Python из окружения.

**Если ошибка `SyntaxError`** — установился Python старее 3.9. Проверьте
версию.

## 9. Таблица «Mac → Windows»

Все команды проекта в переписке и в файле `CLAUDE.md` написаны
по-маковски. Разница ровно одна: вместо `./venv/bin/python` пишется
`venv\Scripts\python`. Слэш другой и папка называется иначе.

**Мак:** `./venv/bin/python manage.py <команда>`
**Windows:** `venv\Scripts\python manage.py <команда>`

Ниже — те же команды в готовом виде. Выполнять из `C:\qls`.

### Каждый день

| Что делаем | Windows |
|---|---|
| Проверить, что всё цело | `venv\Scripts\python manage.py check` |
| Запустить сайт локально | `venv\Scripts\python manage.py runserver` |
| Прогнать все тесты | `venv\Scripts\python manage.py test` |
| Забрать свежий код от Макара | `git pull` |

Сайт после `runserver` открывается в браузере по адресу
`http://127.0.0.1:8000/`. Остановить — **Ctrl + C** в терминале.

### Ревью и вердикты — то, ради чего переезд

| Что делаем | Windows |
|---|---|
| Собрать пакет задач на ревью | `venv\Scripts\python manage.py export_review_bundle --source-id 25 --out reports\review_bundles\имя_пакета --bundle-id имя_пакета` |
| Загрузить вердикты из reviewer.html | `venv\Scripts\python manage.py import_review_verdicts путь\к\файлу.json` |

## 10. Известные грабли на Windows

Проект год рос на Маке. Вот что мы нашли заранее — отсортировано по тому,
насколько вероятно, что вы на это наткнётесь.

### 1. Русский текст в отчётах ломает команды — САМОЕ ВАЖНОЕ

**В чём дело.** Многие команды печатают отчёты со знаками, которых нет в
старой русской кодировке Windows: линии-разделители `─`, стрелки `→`,
значок `⚠`, знаки `≥` и `≤`. Пока вывод идёт в окно терминала, всё в
порядке. Но стоит направить вывод в файл (`> отчёт.txt`) — команда упадёт
на середине с ошибкой `UnicodeEncodeError`, и часть работы пропадёт.

**Насколько вероятно:** очень. Одних только линий-разделителей в командах
больше двадцати тысяч.

**Лечится одной настройкой раз и навсегда.** Выполните:

```
setx PYTHONUTF8 1
```

**Что должно получиться:** `SUCCESS: Specified value was saved.`

Затем **закройте терминал и откройте заново** — иначе настройка не
подхватится. Проверить:

```
echo $env:PYTHONUTF8
```

Должна вывестись `1`.

Эта настройка говорит Python: «везде работай в кодировке UTF-8».
Она разом закрывает и эту проблему, и следующую.

### 2. Чтение файлов с русским текстом

**В чём дело.** В коде примерно тридцать мест, где файл открывается без
явного указания кодировки. На Маке кодировка по умолчанию — UTF-8, на
Windows — cp1251. Если такой файл содержит русский текст, он либо
прочитается кракозяброй, либо команда упадёт.

**Насколько вероятно:** средне. Мы проверили файлы, которые читают
команды ревью и чистки, — там только цифры (списки номеров задач),
русского нет, так что упасть не на чем. Но в редко используемых
командах импорта риск остаётся.

**Лечится той же настройкой `PYTHONUTF8=1`** из пункта 1. Отдельно ничего
делать не надо.

Хорошая новость: две главные команды ревью — `export_review_bundle` и
`import_review_verdicts` — кодировку указывают явно и работают правильно
в любом случае.

### 3. Слишком длинные имена файлов и двоеточие в названии

**В чём дело.** В `materials` есть 32 файла, путь к которым длиннее 260
символов (это предел Windows), и 2 файла, в имени которых есть двоеточие —
Windows такие имена создавать не умеет в принципе.

Где именно: 23 длинных — в `materials/course_822_materials (1)/`,
9 длинных и оба файла с двоеточием — в `materials/Archive 6/`.

**Насколько вероятно:** сработает обязательно, если распаковывать part3c1 и part3c2.
**Насколько мешает чистке задач: никак не мешает.** Это исходные PDF
курсов, задачи из них давно импортированы и лежат в базе.

**Что делать:** при распаковке 7-Zip покажет ошибки по этим файлам —
нажмите «Пропустить» и продолжайте. Если хочется распаковать всё,
включите поддержку длинных путей (нужны права администратора):

```
New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" -Name LongPathsEnabled -Value 1 -PropertyType DWORD -Force
```

После этого перезагрузите компьютер. Файлы с двоеточием не распакуются
всё равно — это ограничение самой Windows, обойти нельзя.

### 4. Три скрипта `.sh` не запустятся

`recompute_cpu.sh`, `run_full_recompute.sh`, `load_to_render.sh` — это
маковские скрипты, Windows их не выполняет. Первые два запускают пересчёт
эмбеддингов, третий заливает данные на боевой сервер. **Для чистки задач
не нужны ни один.** Если понадобятся — перепишем.

### 5. Экспорт в PDF не заработает

В настройках прописан маковский путь к программе вёрстки
(`/Library/TeX/texbin/xelatex`), и на Windows его нет. Ломается только
кнопка «скачать PDF» на страницах заданий — вместо PDF отдаётся файл
`.tex`. **К чистке задач отношения не имеет.**

### 6. Картинка для игры не нарисуется

Команда `make_og_image` ищет шрифты по маковским путям. Если шрифт не
найден, она не падает, а рисует картинку без текста. К чистке отношения
не имеет.

## 11. Правило эстафеты

**С момента, когда вы получили этот пакет и числа сошлись, в базу пишете
только вы. База Макара становится архивом — он её не трогает.**

Почему так строго:

1. `db.sqlite3` — это **один файл**, и механизма слияния правок для него
   не существует. Если два человека одновременно поправят разные задачи
   в своих копиях, объединить эти копии нельзя ничем: придётся выбрать
   одну и выбросить вторую вместе со всей работой.
2. Через неделю никто не вспомнит, какая копия свежее. База — главный
   актив проекта, и восстанавливать её неоткуда.

Поэтому передача владения — всегда явная, словами: «база у тебя» /
«база возвращается ко мне». Не «я тут по-быстрому поправлю одну задачку».
Код через GitHub так передавать МОЖНО — он умеет сливаться, база нет.

Когда понадобится чистить вдвоём одновременно — сначала переезжаем на
общую базу PostgreSQL на сервере, отдельной задачей. Локальный SQLite
вдвоём вести нельзя ни при каком уровне доверия: это ограничение формата
файла, а не вопрос доверия людям.

## 12. Что делать в первую очередь

По порядку, не перескакивая:

1. **Разверните** — шаги 2–7 этой инструкции. Из архивов достаточно части 1
   (`qls_part1_start.zip`); `materials` (части 2 и 3) можно отложить.
2. **Проверьте числа** — шаг 8, все четыре команды.
3. **Напишите Макару, что всё сошлось.** Пришлите ему вывод
   `python check_handover.py` целиком. С этого сообщения эстафета
   считается принятой: он перестаёт трогать свою базу, вы начинаете
   работать.
4. **Сделайте себе копию базы** до первой правки:

   ```
   copy db.sqlite3 backups\db_before_first_cleanup.sqlite3
   ```

5. **И только теперь беритесь за чистку.** Ближайшая очередь — пакеты
   `aa_20260728` (1 593 задачи), `ap_homeworks_20260728` (936) и
   `matek_20260808` (2 632): они собраны и ждут прохода. Как ими
   пользоваться — в `reports\review_bundles\reviewer_README.md`,
   там инструкция для ревьюера, вы её уже видели по пакету ILE.

**Чего не делать до сообщения Макару:** не запускать команды с
`--confirm`, не импортировать вердикты, не править задачи. Пока числа
не сверены, непонятно, с чем вы работаете.

## Если что-то пошло не так

Напишите Макару и приложите три вещи:

1. Какую команду выполняли — скопируйте её целиком.
2. Что вывелось — скопируйте весь вывод, не пересказывайте.
3. Что показывает `python --version` и `venv\Scripts\python manage.py check`.

Этого почти всегда хватает, чтобы понять причину, не садясь за ваш
компьютер.
