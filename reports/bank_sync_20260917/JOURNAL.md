### 5.1 Сервис поиска
- `search_service/app.py`: загрузка модели начинается при старте процесса в
  фоновом потоке (`lifespan` → `_preload`); `/healthz` — 200 и `ok:true`
  только с загруженной моделью, иначе 503 и `ok:false`. Сообщения о загрузке
  идут в логгер `uvicorn.error` («Модель загружена за N с.») — у прежнего
  логгера сервиса не было обработчика, строк в `docker compose logs` не было.
- `deploy/docker-compose.yml` (search): `interval: 15s`, `start_period: 240s`.
  `web` от здоровья `search` не зависит (только postgres/redis) — сайт не ждёт
  модель. Compose не перезапускает контейнер по нездоровью — долгая первая
  загрузка (пустой том → качается с HF) его не убьёт.
- Тесты (не serial, без настоящей модели; без fastapi — пропуск с причиной, в
  CI fastapi не ставится): 503 без модели, 200 с моделью, загрузка стартует
  при старте, compose 240s/15s. Сериальный `test_healthz_не_требует_модели`
  переписан под новое правило (503).
- `search_client.healthy()` теперь значит «готов» (вызывают только тесты).

### 5.2 Корпус bm25 на диске
- `catalog/rerank.py::get_corpus`: сначала `MEDIA_ROOT/_cache/corpus_<версия>_<отпечаток>/`
  (индекс `lexical_bm25.save_index` + `rows.json` + `meta.json`), иначе сборка и
  атомарная запись (временный каталог → `os.replace`), чужие корпуса старше 10
  мин удаляются.
- **Отклонения от промпта (технические, мои):** не pickle — bandit B301 краснит
  джоб «Безопасность»; ключ — версия + ДЕШЁВЫЙ ОТПЕЧАТОК ДАННЫХ (число/сумма id
  видимых, max(updated_at), число подпунктов и связей тем/тегов) + предельный
  возраст 12 ч: версия корпуса — случайная метка Redis, и файл без отпечатка
  пережил бы правку данных мимо `invalidate_corpus()`.

  умолчанию выкл (разработка и тесты не пишут в media/), в
  `config/settings_production.py` по умолчанию вкл.
