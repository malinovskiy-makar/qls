### Механика показа — переиспользована, не изобретена заново

Миграция **0047**: `ProblemFigure` получает `image_data` + `content_type`.
Одна таблица, два происхождения байтов; путь показа общий — в тексте
маркер, `<img>` подставляется ПОСЛЕ санитайзера по первичному ключу
строки БД.

Создано **835 строк** `ProblemFigure` (SolveHub 832 + ЛЭШ 3), 51,9 МБ.
Тип показа определяется **по байтам файла**: у трёх картинок SolveHub
адрес — googleusercontent без расширения вовсе, а по имени их пришлось бы
либо выбросить, либо угадать.

Два маркера ЛЭШ стояли внутри `$$…$$` (так написано в исходном `.tex`) —
обёртка формулы снимается, иначе KaTeX разбирал бы `[[FIGURE:…]]` как
математику.

### Периметр безопасности — проверен ЗАНОВО целиком

`problems/tests/test_new_source_figures.py`, 25 тестов. Список векторов
повторён полностью, а не урезан «рядом уже проверено»: у растровых картинок
другой путь отдачи. Маркер с URL внутри, `../../`, абсолютный путь, сырой
`<img src=…>`, сырой `<svg onload=…>`, markdown-картинка, несуществующий
хеш, хеш ЧУЖОЙ задачи, хеш в верхнем регистре, инлайновый `data:`. Плюс
три заголовка-рубежа у выдачи (`CSP`, `nosniff`, `Content-Disposition`)
и проверка, что старый SVG-путь не сломан.

Откат защиты «не заменять неразрешённую ссылку» → тест краснеет,
восстановление → зелёный.

### Найденный дефект: `plain` + маркер

Живой прогон конвейера показа по всем 569 задачам с картинками:
835 маркеров → **818 `<img>`**, ни одной markdown-задачи с уцелевшим
маркером. Оставшиеся 17 маркеров — в **12 задачах формата `plain`**:
ветка `plain` боевого шаблона это `linebreaksbr`, без подстановки, и
ученик увидел бы `[[FIGURE:<64 hex>]]` дословно.

Добавить подстановку в эту ветку нельзя, не сняв экранирование со всей
ветки; вырезать маркер молча — потерять картинку. Поэтому заведён
инвариант: **видимая ученику задача не может быть одновременно `plain` и
с маркером**. Сейчас все 12 закрыты, стоят в очереди ручного разбора, а
тест `PlainFormatMarkerGuardTests` краснеет, если их опубликуют.

## Фаза 3 — критерии Школково

Замер по 836 задачам с непустым `criteria_tex` показал, что прежний
парсер знал ровно ОДНУ форму заголовка пункта — `\textbf{(метка)}`
вплотную перед `\begin{itemize}`, — и это меньшинство:

| семейство формата | задач |
|---|---:|
| уже разбиралось | 45 |
| `% criteria: none` — критериев нет вовсе | **110** |
| заголовок пункта + список | 21 |
| список без заголовка пункта | **298** |
| заголовок + проза с баллами | 21 |
| проза с баллами, без заголовков | **279** |
| ни списка, ни баллов | 62 |

**Расширено** (границы блоков ПО ЗАГОЛОВКАМ, не жадным захватом — тот же
урок, что у парсера SolveHub #3498):

- заголовок пункта в шести формах команд (`\subsection*{(а)}`,
  `\textbf{Пункт (а)} (6 баллов):`, …), метка — буква со скобкой, круглой
  или квадратной;
- `enumerate` наравне с `itemize`;
- баллы не только в начале пункта, но и в конце (`~--- 2 балла` — самая
  частая форма семейства) плюс сокращение `2~б.`;
- **вложенные списки**: границы считаются счётчиком вложенности, а не
  нежадным `(.*?)`. У 43 из 362 задач внешний список закрывался на `\end`
  ВНУТРЕННЕГО, и в имя критерия попадал сырой `\begin{itemize}`. Внешний
  `\item` со вложенным списком — это заголовок пункта, а не критерий,
  иначе баллы считались бы дважды;
- `% criteria: none` — «критериев нет», а не «не разобрали».

**Результат: 45 → 362 задачи с рубрикой.** `Rubric` 49 → 366,
`RubricCriterion` 519 → 3 307.

**Что осталось неразобранным — честно.** 364 задачи, где критерии
написаны свободной прозой («Выставлялось по 5 баллов за каждый верный и
полностью обоснованный аргумент…»). Где кончается один критерий и
начинается другой — из текста не следует, и разбиение было бы
выдуманным, а не импортированным знанием. Эти задачи остаются без
рубрики с предупреждением. **Это не блокер публикации.**

Проверка идемпотентности нашла настоящий баг в самой команде: снимок для
сравнения брался из разбора, а не из того, что реально пишется
(`max_points=None` → `0`, имя режется до 300 символов), — повторный
прогон предлагал заменить 134 рубрики впустую. Починено, повтор даёт ноль.
