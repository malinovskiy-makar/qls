# Формулировки промпта пилота v2 — дословно (Фаза 3–5, 2026-09-01)

> Владелец читает именно тот текст, который уйдёт в API. Ничего не
> сокращено и не перефразировано — источник: `problems/enrich/prompts_v2.py`
> (сессия «закрыть блокеры боевого пилота», ветка
> `feat/taxonomy-v2-openai-provider`, до коммита).

Эта версия документа заменяет предыдущую (Фаза 2.1, коммит `0c5ff29`).
Причина полной перезаписи: владелец нашёл в прежних трёх примерах разбора
три реальных дефекта (пример 1 отвечал не на тот вопрос своей же задачи и
нарушал правило шорт-листа; пример 2 описывал другую, притом неразрешимую
задачу; `topic_confidence` во всех трёх было «высокая», включая обрывок
текста) — все три исправлены переходом на РЕАЛЬНЫЕ задачи банка со сверкой
по фактическому `solution`. Плюс отдельная тема: явные правила там, где
раньше было противоречие или пустое место (`difficulty`, `problem_type`,
`answer_consistency`, `econ_concepts`), и новый блок «модель не видит
картинку» — риск тысяч ложных «не_задача» на 41 307 запросах.

## Три примера разбора — полный вход и полный выход

Вход = ровно то, что строит `call1_user_text(problem_full_text(...),
shortlist_for(...))` для реальной задачи из банка (шорт-лист посчитан
реальной функцией `shortlist_for` по реальному `data/econ_terms_df.json`).
Выход = блок `WORKED_EXAMPLES` из `prompts_v2.py`, как он дословно идёт в
ядро вызова 1.

### Пример A — задача #28917 (кофейня-монополист, три формы налога)

Критерий: расчётная задача с непустым `solution`, тема очевидна, есть
подпункты, уверенность высокая.

**Полный вход (что уйдёт в API):**

```
ШОРТ-ЛИСТ ПОНЯТИЙ ДЛЯ econ_concepts (выбирай только отсюда, поле concepts_offlist — исключение, не правило):
производитель; потребитель; потребление; равновесие; налог; общие издержки; функция; издержки; количество; спрос; цена; рынок; фирма; товар; производство

ЗАДАЧА (условие с подпунктами, без сокращений):
Новая и единственная кофейня «Аромат» открывается в центре города и ее издержки заданы функцией $TC = Q^2 + 4Q + 20$. В первые дни работы кофейня смогла выяснить дневной спрос посетителей: $P = 120 - 2Q$; цены измеряются в д.е., а количество - в чашках кофе.
(а) Найдите равновесие

 Однако через неделю, по мере завоевания популярности, мэр города узнал о кофейне и, будучи глубоко убежденным во вреде потребления кофе, хочет ввести налог, но не может выбрать какой, помогите ему рассмотреть разные случаи и выбрать подходящий:
(б) налог на потребителя в размере 10 д.е.
(в) налог на производителя в размере 10 д.е.
(г) налог на потребителя в размере 10% от их цены
```

**Реальный `solution` в базе** (для сверки — НЕ уходит в этот вызов):
равновесие `P≈81,3; Q≈19,3`, затем результат для каждого из трёх налоговых
режимов (`Tx` — налоговые сборы).

**Ожидаемый выход (дословно из `WORKED_EXAMPLES`):**

```
topic_primary: "8" (Монополия и ценовая дискриминация)
topics_secondary: []
tags: ["8.1", "8.11"] (Оптимум монополиста: MR = MC; Регулирование
  монополии: налоги, потолок, тариф)
given: "Дано: заданная функция общих издержек монополиста; заданная
  функция спроса; три варианта налога — потоварный на потребителя,
  потоварный на производителя, адвалорный на потребителя"
find: "Найти: рыночное равновесие без налога и в каждом из трёх
  вариантов налогообложения"
econ_concepts: ["равновесие", "налог", "спрос", "издержки"]
concepts_offlist: ["монополия"]
task_nature: "расчётная"
features_1: []
topic_confidence: "высокая"
```

Почему так: ключевой шаг решения — оптимум монополиста (MR=MC) под разными
формами налога → главная тема «Монополия» (8), не «Вмешательство
государства» (10) — по правилу выбора темы из самого ядра. `econ_concepts`
взяты СТРОГО из вычисленного шорт-листа; «монополия» в шорт-лист не
попала (текст не использует слово «монополист» буквально, только
«единственная кофейня») — это и есть законный `concepts_offlist`.

**Механическая проверка** (`problems/tests/test_pilot_enrich_v2.py::WorkedExamplesShortlistTests`):
каждое понятие `econ_concepts` вычисляется как реально присутствующее в
шорт-листе той же функцией `shortlist_for`, что работает в прогоне; каждое
понятие `concepts_offlist` — как реально ОТСУТСТВУЮЩЕЕ в нём. Тест
воспроизводимо ловит прошлый дефект: временная порча примера A (перенос
«монополия» из `concepts_offlist` в `econ_concepts` при пустом offlist)
красит тест — коммит `fe9d6a1`-подобной диеты сюда не относится, проверено
вручную в этой сессии и отменено.

### Пример B — задача #1045 (постоянные налоговые сборы, на доказательство)

Критерий: качественная/доказательная задача, тема на стыке двух разделов,
уверенность средняя.

**Полный вход:**

```
ШОРТ-ЛИСТ ПОНЯТИЙ ДЛЯ econ_concepts (выбирай только отсюда, поле concepts_offlist — исключение, не правило):
ставка налога; функция предложения; налог на единицу товара; функция спроса; налог; ставка; предложение; товар; функция; рынок; спрос; цена; количество; издержки; фирма

ЗАДАЧА (условие с подпунктами, без сокращений):
На рынке некоторого товара функция спроса строго убывает, а функция предложения строго возрастает. Государство вводит потоварный налог на каждую единицу товара. Может ли случиться так, что при любой положительной ставке налога налоговые сборы государства оказываются одинаковыми (не зависят от ставки)? Если да, приведите пример таких функций спроса и предложения и докажите, что они удовлетворяют условию задачи. Если нет, строго докажите, что это невозможно.
```

**Реальный `solution` в базе:** строит `P_s(Q) = Q/(Q+1)`,
`P_d(Q) = Q/(Q+1) + 1/Q`, проверяет монотонность обеих функций, показывает
`T(t) = 1` — константу.

**Ожидаемый выход:**

```
topic_primary: "10" (Вмешательство государства)
topics_secondary: ["3"] (Спрос, предложение и рыночное равновесие)
tags: ["10.1"] (Потоварный налог на продавца и на покупателя)
given: "Дано: убывающая функция спроса, возрастающая функция
  предложения на конкурентном рынке; потоварный налог с произвольной
  положительной ставкой t"
find: "Найти: можно ли подобрать функции спроса и предложения так,
  чтобы налоговые сборы не зависели от ставки налога — доказать пример
  или невозможность"
econ_concepts: ["налог на единицу товара", "функция спроса",
  "функция предложения", "ставка налога"]
concepts_offlist: ["налоговые сборы"]
task_nature: "теоретическая"
features_1: ["на_доказательство"]
topic_confidence: "средняя"
```

Почему так: формально герой — потоварный налог (тема 10), но ключевой шаг
— не налоговая техника, а конструирование пары функций из равновесия
`P_d(Q) − P_s(Q) = K/Q` (аппарат темы 3). Обе темы дают существенную часть
решения → `topic_confidence` «средняя», тема 3 в `topics_secondary`.

### Пример C — задача #47409 (буквальный обрывок текста, иллюстрация «не_задача»)

Критерий: обрывок из очереди ручного разбора, тема «Другое», уверенность
низкая, `text_quality` = «это не задача».

**Полный вход:**

```
ШОРТ-ЛИСТ ПОНЯТИЙ ДЛЯ econ_concepts (выбирай только отсюда, поле concepts_offlist — исключение, не правило):
коэффициент; цена; спрос; количество; рынок; издержки; функция; фирма; товар; производство; предложение; прибыль; общие издержки; выпуск; ставка

ЗАДАЧА (условие с подпунктами, без сокращений):
ности равны, и каждый бедный зарабатывает в 4 раза меньше, чем каждый богатый.
Из страны уходит ровно половина ее населения. Найдите матожидание коэффициента
Джинни после их ухода.
```

Начинается с середины слова («ности» — обрубок чего-то вроде

**Ожидаемый выход:**

```

topics_secondary: []
tags: ["29.5"] (Тему определить не удалось — на ручной разбор)
```

Почему так: упоминание «коэффициента Джинни» — ловушка (искушает
поставить тему 14). Классифицировать обрывок по теме нельзя — неизвестна
математическая конструкция за условием. `topic_confidence` «низкая», не

«решение есть, но это нечитаемая картинка». Мелкий зазор, не блокер,
владельцу на заметку.

## Якоря шкалы сложности 1–5 (`DIFFICULTY_ANCHORS`, дословно, Фаза 4.2)

```
1 — школьный этап: одна формула или одно определение, один шаг решения.
2 — муниципальный этап: стандартная модель целиком (например обычное
    равновесие спроса и предложения), 2–3 арифметических шага, без развилок.
3 — региональный этап: комбинация двух понятий из разных разделов темы ИЛИ
    несколько подпунктов, каждый из которых по себе — уровень 2.
4 — заключительный этап: нестандартный поворот канонической модели
    (кусочность, целочисленность, параметр вместо числа), доказательство
    или обоснование как основной результат.
5 — уровень IEO и международных олимпиад: несколько связанных моделей в
    одной задаче, длинное доказательство с разбором случаев, или комбинация
    из уровня 4 с дополнительным нестандартным ограничением.

ПРАВИЛО РАЗРЕШЕНИЯ КОНФЛИКТА: если признаки задачи указывают на РАЗНЫЕ
уровни одновременно (например есть и параметр, и доказательство, и три
подпункта) — бери МАКСИМАЛЬНЫЙ из них, не средний и не первый попавшийся.

Уровень 3 — НЕ значение по умолчанию для сомнения. При колебании между
двумя соседними уровнями выбирай тот, чей ключевой признак присутствует В
ЗАДАЧЕ БУКВАЛЬНО (параметр вместо числа виден в условии — значит 4, а не
«наверное, 3» без опоры на конкретный признак).
```

Что изменилось против прежней версии: якоря названы через этап олимпиады
(раньше — «начальный/базовый/…», ни одного слова про этапы), добавлено
правило разрешения конфликта (максимум, не среднее) и явный запрет
использовать 3 как значение «по умолчанию при сомнении» — прежде уровни 3
и 4 могли поймать одну и ту же задачу без правила выбора между ними.

## `problem_type` — допустимые значения и правило выбора (Фаза 4.3)

Семь значений (было шесть — добавлена явная ветка для обрывков):
`единственный_выбор`, `множественный_выбор`, `верно_неверно`,
`сопоставление`, `открытый_ответ`, `несколько_подвопросов`, `не_задача`.

```
Проверяй признаки СТРОГО в этом порядке, останавливайся на первом
совпадении:
  а) текст не является задачей (см. `task_nature` из первого разбора,
     передан ниже) → `не_задача`, дальше не проверяй;
  б) единственное утверждение с вариантами «верно»/«неверно» → `верно_неверно`;
  в) пронумерованный список вариантов ответа: ровно один правильный →
     `единственный_выбор`; больше одного правильного → `множественный_выбор`;
  г) задание на сопоставление двух списков (элемент ↔ элемент) →
     `сопоставление`;
  д) несколько отдельных вопросов или подпунктов без общего списка
     вариантов → `несколько_подвопросов`;
  е) ничего из перечисленного не подошло → `открытый_ответ` (развёрнутый
     ответ без готовых вариантов).
```

Соответствие с `check_type` SolveHub (комментарий в коде, в промпт модели
не идёт, только для сверки инварианта «совпадение ≥ 90 %») не изменилось:

| `problem_type` | `check_type` SolveHub |
|---|---|
| единственный_выбор | single_choice |
| множественный_выбор | multiple_choice |
| верно_неверно | true_false |
| сопоставление | matching_list |
| открытый_ответ | single_freetext, uncheckable |
| несколько_подвопросов | multiple_questions |
| не_задача | (нет соответствия — не тип SolveHub) |

## `text_quality` — граница «мелкие» / «серьёзные» дефекты (Фаза 4.5а)

Прежде граница была не детализирована текстом промпта дальше одной строки
и оставлена на усмотрение модели. Теперь — конкретные признаки:

```
`мелкие_дефекты` — опечатка, лишний пробел, неровный перенос строки,
  разъехавшийся значок `$` вокруг формулы, пропущенный знак препинания
  — смысл условия восстанавливается однозначно, ничего не потеряно.
`серьёзные_дефекты` — пропущено число или часть условия, формула не
  отрендерилась (виден сырой LaTeX-код), два разных вопроса слиплись в
  один абзац без разделения, в условии виден кусок «Решение:»/«Ответ:»
  (утечка), ИЛИ прямая отсылка к визуальному элементу без самого
  элемента рядом (см. блок про визуальные элементы, включая формулировку
  «содержание в утраченном визуальном элементе») — однозначно
  восстановить условие нельзя.
```

Допустимые значения (по-прежнему четыре): `чистая`, `мелкие_дефекты`,
`серьёзные_дефекты`, `не_задача`.

## `answer_consistency` — правило по всем четырём комбинациям (Фаза 4.4)

Было четыре значения без покрытия случая «решение есть, ответа нет».
Теперь пять:

```
Правило по комбинации наличия `answer` и `solution` — валидное значение
есть для любой из них:
  - решения нет вовсе (независимо от того, есть ли `answer`) — не гадай →
    `решение_отсутствует_проверить_нечем`;
  - `answer` пуст, а `solution` дано → `ответ_пуст_решение_есть` (сверить
    с ответом нечего, но решение содержательно; не путай с «согласован» —
    сверки не было);
  - оба даны и совпадают по существу → `согласован`;
  - оба даны и НЕ совпадают → `ответ_не_совпадает_с_решением`;
  - решение выглядит переписанным из условия почти дословно (похоже, что
    кусок решения случайно продублирован в текст условия) →
    `подозрение_на_утечку_решения_в_условии`.
```

## `econ_concepts` — снятое противоречие (Фаза 4.5б)

Было: одновременно «3–6 понятий» и «не подходит ни одно — верни пустой
список» — противоречие само по себе, без условия, когда именно пусто.
Теперь одно правило:

```
— 3–6 понятий, ТОЛЬКО из шорт-листа, для БОЛЬШИНСТВА задач. ПУСТОЙ
список — только в двух случаях: (1) `task_nature` = `не_задача`;
(2) ни один термин шорт-листа не описывает содержание именно этой
задачи (редко). Во всех остальных случаях бери 3–6 терминов из
шорт-листа, даже если некоторые кажутся не идеальными.
```

## `title_candidate` — новое поле (Фаза 4.1, §5.8)

Пишется в **`title_candidate`**, НЕ в `title` (P0 не тронут — существующее
поле моделью не переписывается). Правило перезаписи `title` этим
кандидатом реализовано КОДОМ (`problems/enrich/title_rules.py`), но НЕ
применяется в этой сессии — см. раздел «Раскладка A/B/C/D» ниже.


## Раскладка A/B/C/D для `title` → `title_candidate` (Фаза 4.1)

Правило перезаписи `Problem.title` посчитано (`title_rules.py`,
`classify_current_title`) на ВСЕХ 41 307 задачах — только счёт, без
единой записи в базу:

| Категория | Смысл | Число задач | Доля |
|---|---|---:|---:|
| A | пусто или заглушка | 2 507 | 6,1 % |
| B | сломан (LaTeX-мусор, кракозябры, имя файла, >80 симв.) | 2 554 | 6,2 % |
| C | эхо первых слов условия (точный префикс или ≥85% схожести) | 13 231 | 32,0 % |
| D | не трогаем | 23 015 | 55,7 % |

**Примеры A** (пусто): id 62670 `''`; id 63257 `''`; id 62609 `''`.

**Примеры B** (сломан): id 52076 `'Предложение изменяется: P\textquotesingle{} = Q + 7…'`

**Примеры C** (эхо, ≥85 % схожести или точный префикс): id 53095

⚠️ **Наблюдение, не исправлено в этой сессии** (только посчитано и
напечатано честно, не подогнано): из 13 231 задач категории C у 1 194
(9 %) заголовок — точный префикс условия длиной ≤20 символов. Часть таких

начинаются теми же словами, что и условие, а не являются мусорным эхом.
Правило Фазы 4.1 взято буквально, как задано, — эти случаи попадают в C
формально корректно (короткий точный префикс — тоже префикс), но
владельцу стоит решить, не нужен ли C ещё и минимальный порог длины
заголовка, прежде чем когда-нибудь применять перезапись. Основная масса
категории C (9 212 из 13 231, 70 %) — длинные точные префиксы без
короткого-хорошего-имени эффекта, там сомнений в «эхо, а не имя» нет.

(§5.8) для ВСЕГО корпуса (41 307, не только published) — поле `title` не
