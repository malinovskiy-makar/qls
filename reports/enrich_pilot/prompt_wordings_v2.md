# Формулировки промпта пилота v2 — дословно (Фаза 2.1)

> Владелец читает именно тот текст, который уйдёт в API. Ничего не
> сокращено и не перефразировано — источник: `problems/enrich/prompts_v2.py`
> (коммит `0c5ff29`).

## Три примера разбора — полный вход и полный выход

Вход = ровно то, что строит `call1_user_text(problem_full_text(...), shortlist_for(...))`
для реальной задачи из банка. Выход = блок `WORKED_EXAMPLES` из `prompts_v2.py`,
как он дословно идёт в ядро вызова 1 (поле «ТРИ ПРИМЕРА РАЗБОРА»).

### Пример 1 — задача #41203 (монополист с двумя видами налога)

**Полный вход (что уйдёт в API):**

```
ШОРТ-ЛИСТ ПОНЯТИЙ ДЛЯ econ_concepts (выбирай только отсюда, поле concepts_offlist — исключение, не правило):
адвалорный налог; субсидия; налог на единицу товара; предельные издержки; монополист; деньги; налог; величина спроса; рост; ставка; прибыль; функция; издержки; количество; спрос; цена

ЗАДАЧА (условие с подпунктами, без сокращений):
Адвалорные и потоварные налоги

Спрос на продукцию монополиста представлен функцией:
$$
Q_d=\frac{1}{P^4}
$$
Государство выбирает между двумя способами налогообложения:
• адвалорный налог $\tau >0$ (то есть $P_d-P_s=P_s\times \tau$); или
• потоварный налог $t > 0$

Предельные издержки монополиста постоянны и больше нуля.
(а) Предположим, государство хочет получить одинаковый рост цены при каждом из режимов. Найдите отношение $\dfrac{t}{\tau}$, которое гарантирует такой результат.
(б) Теперь предположим, что государство максимизирует налоговые сборы. Какой вид налогообложения и какую ставку оно выберет?
(в) Государство использует значения полученные в предыдущем пункте.
 Дополнительно, государство вводит потоварную субсидию $s > 0$, возвращающую цену для потребителей на уровень сложившийся до налогового вмешательства.

 Найдите такую субсидию $s$ и прибыль государства от вмешательства. Когда прибыль положительна?
(г) Пусть теперь нет никакой субсидии, но монополист может подкупить государственного представителя для смены налогового режима на другой из двух (ставка всё равно будет соответствовать оптимальной, найденной для этого режима в пункте (б)).

Будет ли монополист предлагать взятку? Если да, то какое максимальное количество денег он готов заплатить представителю? (Монополист выберет смену режима, если ему всё равно, предлагать взятку или нет)
```

**Ожидаемый выход (дословно из `WORKED_EXAMPLES` в prompts_v2.py):**

```
topic_primary: "Монополия и ценовая дискриминация"
topics_secondary: ["Вмешательство государства"]
tags: ["Регулирование монополии: налоги, потолок, тариф"]
given: "Дано: функция спроса на товар монополиста; ставки потоварного и
  адвалорного налога"
find: "Найти: сравнить потери общества (DWL) при двух видах налога"
econ_concepts: ["монополия", "потоварный налог", "адвалорный налог",
  "чистые потери общества"]
concepts_offlist: []
task_nature: "расчётная"
features_1: ["параметры"]
topic_confidence: "высокая"
```

⚠️ Замечено при сборке этой распечатки (не правка промпта, факт для владельца):
шорт-лист, который реально построил код для задачи #41203, не содержит термина
«чистые потери общества» — модель обязана взять его через `concepts_offlist`
(поле для понятий вне шорт-листа), а не как обычный `econ_concepts`. Это
описанный в промпте штатный путь, но сам пример его не иллюстрирует явно.

### Пример 2 — задача #4722 (кривая Лоренца с параметром)

**Полный вход (что уйдёт в API):**

```
ШОРТ-ЛИСТ ПОНЯТИЙ ДЛЯ econ_concepts (выбирай только отсюда, поле concepts_offlist — исключение, не правило):
кривая Лоренца; политика; цена; спрос; количество; рынок; издержки; функция; фирма; товар; производство; предложение; прибыль; общие издержки; выпуск

ЗАДАЧА (условие с подпунктами, без сокращений):
В стране О. кривая Лоренца имеет вид параболы (удовлетворяющей всем условиям кривой Лоренца).

Правительство может выбрать группу, доля которой составляет $\alpha$ (задано извне) в общем населении и перераспределить в ней доходы таким образом, чтобы они стали равны у всех членов группы. Найдите, какую группу нужно выбрать государству для проведения описанной политики для минимизации Джини.
```

**Ожидаемый выход (дословно из `WORKED_EXAMPLES` в prompts_v2.py):**

```
topic_primary: "Неравенство доходов"
topics_secondary: []
tags: ["Расчёт коэффициента Джини", "Построение кривой Лоренца"]
given: "Дано: два региона с равномерным распределением дохода внутри
  каждого, доля первого региона — α"
find: "Найти: коэффициент Джини как функцию α"
econ_concepts: ["кривая Лоренца", "коэффициент Джини", "неравенство доходов"]
concepts_offlist: []
task_nature: "расчётная"
features_1: ["параметры", "графическое_решение"]
topic_confidence: "высокая"
```

⚠️ Расхождение условия и разбора (факт для владельца, не моя правка): реальный
текст задачи #4722 говорит про ОДНУ страну с параболической кривой Лоренца и
выбор доли населения α для перераспределения, а `given`/`find` в примере
описывают «два региона с равномерным распределением дохода» — это текст ДРУГОЙ
формулировки той же темы, не текущего условия задачи #4722 в банке. Владелец
править по своему усмотрению — сюда это только зафиксировано.

### Пример 3 — задача без решения, обрывок текста (иллюстрация «не_задача»)

Без привязки к конкретному id в банке — в `prompts_v2.py` это условный пример,
целиком выдуманный для иллюстрации класса `не_задача`. Полный вход:

```
ЗАДАЧА (условие с подпунктами, без сокращений):
Критерии оценивания: 2 балла за правильный ответ, 1 балл за верный ход решения без ответа.
```

(В реальном вызове перед этим ещё будет добавлен блок «ШОРТ-ЛИСТ ПОНЯТИЙ» —
для этого текста шорт-лист лексически пуст, так что код-добор подставит до 15
терминов олимпиадного ядра по частоте; какие именно — зависит от текущего
кэша частот `data/econ_terms_df.json` и здесь не выписано, чтобы не создавать
у примера ложное впечатление, что это осмысленный подбор.)

**Ожидаемый выход (дословно из `WORKED_EXAMPLES` в prompts_v2.py):**

```
topic_primary: "Другое"
topics_secondary: []
tags: ["Тему определить не удалось — на ручной разбор"]
given: ""
find: ""
econ_concepts: []
concepts_offlist: []
task_nature: "не_задача"
features_1: []
topic_confidence: "высокая"
```

## Якоря шкалы сложности 1–5 (`DIFFICULTY_ANCHORS`, дословно)

```
1 — начальный: одна формула или одно определение, один шаг решения.
2 — базовый: стандартная модель целиком (например обычное равновесие
    спроса и предложения), 2–3 арифметических шага, без развилок.
3 — средний: комбинация двух понятий из разных разделов темы ИЛИ
    несколько подпунктов, каждый из которых по себе — уровень 2.
4 — продвинутый: нестандартный поворот канонической модели (кусочность,
    целочисленность, параметр вместо числа), доказательство или
    обоснование как основной результат.
5 — топ-олимпиадный: несколько связанных моделей в одной задаче,
    длинное доказательство с разбором случаев, или комбинация из
    уровня 4 с дополнительным нестандартным ограничением.
```

Плюс `difficulty_note` — одна строка обоснования (какой шаг определил уровень).
Формулировка задания в ядре вызова 2 (`CALL2_CORE_TEMPLATE`, пункт 4, дословно):

> `difficulty` — целое 1–5 по шкале с якорями: [якоря выше]. Плюс
> `difficulty_note` — одна строка обоснования (какой шаг определил уровень).

## `problem_type` — допустимые значения и правило выбора

Формулировка задания (пункт 3, дословно): «`problem_type` — ровно одно из:
%(problem_type)s.» — то есть подставляется список ниже через запятую, без
каких-либо дополнительных инструкций по выбору внутри самого промпта. Правило
выбора для модели — только сам закрытый список названий; смысловое
соответствие с типами источника SolveHub задано КОММЕНТАРИЕМ в коде
(`prompts_v2.py`, не идёт в промпт модели, только для последующей сверки
инварианта «совпадение с `check_type` ≥ 90 %»):

| `problem_type` (в промпте) | `check_type` SolveHub |
|---|---|
| единственный_выбор | single_choice |
| множественный_выбор | multiple_choice |
| верно_неверно | true_false |
| сопоставление | matching_list |
| открытый_ответ | single_freetext, uncheckable |
| несколько_подвопросов | multiple_questions |

Допустимые значения (ровно один из шести): `единственный_выбор`,
`множественный_выбор`, `верно_неверно`, `сопоставление`, `открытый_ответ`,
`несколько_подвопросов`.

## `text_quality` — допустимые значения и правило выбора

Формулировка задания (пункт 2, дословно): «`text_quality` — ровно одно из:
%(text_quality)s, плюс `text_quality_note` — одна строка, ПОЧЕМУ выбрано
именно это значение (пусто для «чистая»).»

Допустимые значения (ровно одно из четырёх): `чистая`, `мелкие_дефекты`,
`серьёзные_дефекты`, `не_задача`.

Правило выбора в самом промпте текстом не детализировано дальше этой одной
строки — граница между «мелкие» и «серьёзные» дефекты и что считать
«не_задачей» здесь оставлена на усмотрение модели (в отличие от `task_nature`
вызова 1, где «не_задача» пояснена отдельно: «служебный текст, обрывок
критериев оценивания, заметка без условия»).

## `answer_consistency` — допустимые значения и правило выбора

Формулировка задания (пункт 5, дословно): «`answer_consistency` — ровно одно
из: %(answer_consistency)s. Сверяй ответ (`answer`) с решением (`solution`),
если оба даны. Если решения нет — не гадай, ставь
`решение_отсутствует_проверить_нечем`.»

Допустимые значения (ровно одно из четырёх): `согласован`,
`ответ_не_совпадает_с_решением`, `решение_отсутствует_проверить_нечем`,
`подозрение_на_утечку_решения_в_условии`.

Правило выбора: сверка `answer` против `solution`, когда оба присутствуют;
явный приоритет у случая отсутствия решения (жёсткое «не гадай») — модель не
имеет права угадывать согласованность без решения на руках.
