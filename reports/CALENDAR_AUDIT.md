## 3. Как СЕЙЧАС создаётся событие — вся цепочка

1. `calendar_view` (`views.py:246`) отдаёт страницу. В контекст уходит
   `user_role`, `groups_json`, `assignments_json`.
2. В шаблоне при `user_role == 'teacher' or 'admin'` рисуется
   `<button id="btn-add-event">+ Добавить</button>` (строка 240).
3. Инлайн-скрипт строит FullCalendar, затем **ниже** вешает обработчик:
   `addBtn.addEventListener('click', () => openCreateModal(null))` (строка 473).
4. `openCreateModal` (строка 672) очищает поля и открывает `#edit-modal`.
5. Отправка формы → `POST /calendar/api/events/create/` с JSON и CSRF.
6. `event_create` (`views.py:301`) проверяет `is_superuser or is_tutor(user)`,
   разбирает поля, создаёт `CalendarEvent` (и серию при повторении).

## 4. Кто имеет право добавлять, править, удалять

- **Создавать** — `is_superuser or is_tutor(user)`. `is_tutor` (`teacher/access.py`)
  смотрит ОБЕ системы ролей: `is_staff`, `UserProfile.role == 'tutor'`,
  старое `User.role == 'teacher'`.
- **Пометка «общее» (`is_global`)** — только администратор:
  `bool(data.get('is_global')) and user.is_superuser`. Репетитор пометить не
  может. **Ограничение сохраняется.**
- **Тип «Олимпиада»** — тоже только администратор (иначе тип понижается до
  `other`).
- **Править и удалять** — только автор (`_own_event` сужает queryset по
  `author=user`); администратор — всё.
- **Читать** — `_visible_qs`: гость только `is_global`; ученик `is_global` +
  события своих групп; репетитор `is_global` + свои + групп, где он учитель.

Бэкенд закрыт аккуратно и с объяснениями: чужая работа не привяжется
(`_own_assignment`), «не найдено» и «не ваше» отвечают одинаково (`_not_found`),
удаление серии режет только свои звенья.

## 7. ⚠️ ПОЧЕМУ ИСЧЕЗЛА ВОЗМОЖНОСТЬ ДОБАВЛЕНИЯ — главный вопрос аудита

**Гипотеза из задания НЕ ПОДТВЕРДИЛАСЬ.** Она гласила: шаблон проверяет старое
поле `user.role`, а API — новое `is_tutor`, поэтому репетитор кнопки не видит.
Проверка на живой базе (таблица в п. 3) показывает: у всех трёх репетиторов
этой базы `user.role == 'teacher'`, `USER_ROLE` приходит верным, кнопка в
разметке есть, API создаёт события. Расхождение шаблона и API **существует**,
но сегодня ни на кого не влияет — это спящий дефект, а не причина.

**Настоящая причина найдена и воспроизведена.** Весь экран календаря — один
инлайн-скрипт, который НАЧИНАЕТСЯ с `new FullCalendar.Calendar(...)` и только
двадцатью строками ниже вешает обработчик кнопки. Библиотека тянется с чужого
CDN. Если CDN не доехал (нет сети, блокировка, сбой jsdelivr), происходит вот
что:

```
window.FullCalendar === undefined
  → ReferenceError на строке 433
  → ВЕСЬ инлайн-скрипт умирает
  → addEventListener на кнопке (строка 473) никогда не выполняется
```

Кнопка при этом **остаётся на экране и выглядит рабочей**. Нажатие не делает
ничего. Ни ошибки, ни сообщения.

Замер (playwright, вход под ботом, тот же сервер):

| | `window.FullCalendar` | Кнопка есть | Ячеек сетки | Клик открывает окно |
|---|---|---|---|---|
| CDN доступен | `object` | да | 35 | **ОТКРЫТО** |
| CDN заблокирован | `undefined` | да | **0** | **закрыто** |

Это ровно тот симптом, который описал владелец: «добавлять события больше
нельзя», при том что код создания в репозитории есть и работает.

## 8. Что ещё нашлось по дороге

**Две дыры XSS** (чинятся в фазе 11):

1. `calendar.html:509` — описание события вставляется как **разметка**:
   ```js
   descVal.innerHTML = `<a href="${ep.description}" …>${ep.description}</a>`;
   ```
   Описание пишет репетитор, а событие с пометкой «общее» видно **всему
   интернету**. Экранирования нет ни в атрибуте, ни в тексте.
2. `calendar.html:618` — название группы вставляется как **разметка**:
   ```js
   lbl.innerHTML = `<input type="checkbox" value="${g.id}" class="group-cb"> ${g.name}`;
   ```
   Названия групп печатает репетитор, а **администратор видит список ВСЕХ
   групп** (`calendar_view` для суперпользователя). То есть путь до
   привилегированного зрителя.

Прочее: 6 встроенных `onclick`/`onchange`, 24 атрибута `style`, два мёртвых
шаблона, цвета типов событий заданы ТРИЖДЫ (питон, легенда, скрипт).
