## Инструменты замера

`scripts/calc2_canon_probe.js` — два режима, оба против живого сервера:

```
./venv/bin/python manage.py runserver 8601 --noreload
node scripts/calc2_canon_probe.js 8601 tokens <файл.json> [сцены|all]
node scripts/calc2_canon_probe.js 8601 contrast <файл.json> all
```

`tokens` снимает значения :root и вычисленные стили выборки элементов по
сценам и темам — им доказывается «ничего не изменилось» при чистке дублей.
`contrast` обходит ВСЕ подписи холста во всех 41 сцене в обеих темах и печатает
те, что ниже нормы. Снимки лежат рядом: `contrast_before.json`, `contrast_after.json`.

⚠️ Скрипт обязан лежать ВНУТРИ проекта: из папки-черновика `require('playwright')`
не разрешается.
⚠️ Первая версия замера контраста врала вдвое: `--canvas` приходит из токена
шестнадцатеричной записью, а разбирался только `rgb()`. Фон молча становился
белым, и в тёмной теме светлые подписи мерились против белого — 159 «нарушений»
из 312 были выдумкой самого замера. Разбирать обе записи.
⚠️ Подпись почти всегда собрана из `<tspan>`; «только прямые текстовые узлы»
пропускали как раз те подписи, ради которых замер и делается. Брать весь текст,
кроме `<title>` (он есть у легенды и на экран не идёт).

## Канонный долг, замеченный по дороге (не в 82 пунктах)

Записать сюда, чинить в свою фазу — молча объём не расширяем.

1. `:focus-visible { box-shadow: 0 0 0 3px var(--accent-ring) }` в calc2.css —
   кольцо фокуса АКЦЕНТНОЕ. Канон 2.15: нейтральное
   `outline: 2px solid var(--focus); outline-offset: 2px`. → фаза 6.
2. `.panel { border-right: .5px solid var(--border) }` — канон 1.6 требует 1px:
   половина пикселя сглаживается по-разному на разных экранах. → фаза 6.
3. `--shadow-panel` висит на панелях в покое. Канон 1.7: тень только у того,
   что физически над страницей. → фаза 6.

## Что делать следующей сессии

Начинать с фазы 2 (числа и состояние сцены, п. 1–13). Прочитать в таком порядке:
этот файл → `reports/calc2-canon/points.md` → `DESIGN.md` части 2.2, 2.3, 2.13, 2.9 →
`reports/calc2-audit.md` пункты 1–13. Канон и аудит лежат в репозитории,
в контексте их держать не нужно — читать точечно.

Ключевое для фазы 2: единый форматтер `fmt()` в `20-plane.js:81` УЖЕ ЕСТЬ и через
него идут почти все числа (~470 вызовов). Значит задача не «завести форматтер»,
а: (а) считать сумму из ОКРУГЛЁННЫХ слагаемых (`STATE.sw` собирается из сырых
float — отсюда `SW ≠ CS + PS`), (б) провести через `fmt` то, что мимо него,
(в) `tabular-nums` на числах панели.

## Открытые вопросы к владельцу

1. **Код не в одном файле** (см. выше). Правки пойдут по 23 скриптам и CSS
   каталога `calc2/`. Подтверждения не жду — существо работы не меняется,
   но в отчёте это названо.
2. **Фаза 1 сделала на два шага больше, чем сказано в промпте**, и оба
   осознанные:
   а) `templates/_tokens.html` подключён в `<head>` калькулятора. Иначе
      «использовать общие `--accent`» нечем: до этого на странице /calc2/
      общих токенов физически не было. Заодно у калькулятора появились
      `--accent-rgb`, `--act-ink-solid`, `--focus`, сигнальные цвета и пять
      радиусов — без них поздние фазы пришлось бы делать второй копией.
      Прежняя запись в CLAUDE.md «`_tokens.html` НЕ подключается в /calc2/»
      этим отменена.
   б) В тёмной теме главная кнопка стала графитом `#46566d` вместо `#334155`
      (значение канона). Прежний на панели `#1d2330` давал 1,52:1 — кнопка
      не читалась как кнопка; платформа это уже замерила и починила у себя.
   Оба видны на снимке `tokens`: кроме радиусов и этой кнопки не изменилось
   ничего.
