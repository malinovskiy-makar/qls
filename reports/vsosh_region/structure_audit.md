# Аудит структуры ВсОШ-регион (таблицы, списки, рисунки)

Новый класс дефекта: **потерянная структура** — таблица/список размазаны в
строку текста. Формально текст «валиден» (глифы целы, KaTeX не ругается),
поэтому обычная вычитка на битые символы его не ловила.

Детектор: `manage.py audit_vsosh_structure` — геометрия PDF (горизонтальные
линейки одинаковой ширины/x-охвата очерчивают таблицу; ячейки держатся в
колонках по строкам — формула этот тест не проходит), атрибуция к вопросу по
маркеру, сверка с `parsed_<год>.json` (таблицы вне тест-вопросов — Часть 4,
сводные сетки ответов, бланки — отсеиваются).

## Фаза 1 — формат хранения (решение)

**Выбран вариант Б — LaTeX-массив в `$$…\begin{array}…\end{array}…$$`.**

Как рендерится `statement`:
- **Каталог, страница задачи** (`problem_detail.html:219`): `{{ problem.statement }}`
  авто-экранируется (нет `|safe`), но `math-content` прогоняется через
  `renderMathInElement` с делимитерами `$$…$$` (display) и `$…$`. → HTML-тег
  показался бы как текст, а `$$array$$` рендерится KaTeX.
- **Каталог, модал списка** (`problem_list.html:949`): `innerHTML` — HTML бы
  отрендерился (несогласованно с детальной страницей).
- **Карточка игры** (`game.html`): текст вопроса вставляется и прогоняется
  через `renderMath` (тот же KaTeX, `$$…$$` поддержан).

Почему Б, а не А (HTML `<table>`):
- HTML-таблица показалась бы как **текст** на детальной странице (нет `|safe`);
  добавлять `|safe` на все 31 тыс. задач — риск XSS и смена рендера всего
  корпуса. Вариант Б **едет по существующему конвейеру KaTeX во всех трёх
  местах** без правки шаблонов, без `|safe`, без риска инъекций.
- Проверено в браузере: KaTeX отрисовал НДФЛ (6×2 с рамками), Период/Цена
  (2×9), 2018 №12 (формулы В ячейках `D_A=30-P`) — 0 ошибок, кириллица в
  `\text{}` читается, границы `{|l|c|}` + `\hline` рисуются.

Формат ячеек: кириллица — `\text{…}`, числа/формулы — как есть, `%` → `\%`,
десятичная запятая → `{,}`. Границы: спецификация колонок `{|l|c|…|}` +
`\hline` между строками.

Флаг `GameQuestion.has_table` **не заводим** — массив самодостаточен в тексте
вопроса, `renderMath` его отрисует; лишнее поле не нужно (минимально инвазивно).

Правки в `build_game_pool` (Фаза 2): `array` уже в `TALL_MATH_ENVS`; убрать
`\hline` из `BAD_CONTENT_RE` (легитимен внутри массива); в `content_reason`
не отбраковывать по слову «таблица», когда таблица реконструирована
(`\begin{array}` в тексте) — «таблицы пускаем, рисунки нет».

## Фаза 2 — что починено

**Парсер** (`parse_vsosh_region`): `extract_tables` / `reconstruct_table` /
`apply_tables` — реконструкция таблиц из геометрии PDF в `$$\begin{array}…$$`:
- строки — банды между горизонтальными линейками; внутри банда (booktabs
  держит несколько строк в одном банде) — кластеры по базовой линии;
- колонки — по вертикальным линейкам (полная рамка, 2018 №12) либо по
  якорям: центры ячеек строки с максимумом ячеек (booktabs, НДФЛ/Период);
- клип по x-охвату рамки — боковая проза вопроса (2022 №3.2 обтекает таблицу
  сбоку) сохраняется как текст, а не втягивается в ячейки;
- ячейка: чистое число — голым, математика — без `$` (сабскрипты/суперскрипты
  через существующий рендер, `D_A=30-P`), текст — в `\text{…}`;
- `render_paragraph` выводит table-спан своим абзацем-блоком.

Реконструированы **все 4** таблицы (проверено визуально по рендеру KaTeX и
сверено с PDF поячеечно):

| Год | Вопрос | Размер | Проверка |
|---|---|---|---|
| 2025 №3.2 | 6×2 | шкала НДФЛ до 2,4→13 … свыше 50→22 | ✅ |
| 2022 №3.2 | 3×3 | Зерновые/Шерсть × Низины(20,12)/Холмы(6,a) | ✅ |

**Игра** (`build_game_pool`): «рисунок» и «таблица» разделены в `content_reason`
— вопрос с реконструированной таблицей (`\begin{array}`) БЕРЁТСЯ (структура
сохранена), рисунок/график — по-прежнему брак; корректные array-блоки
вырезаются перед фильтром псевдотаблиц (чужой `\hline`/`| |`-мусор ловится).
`reading_length` — markup массива не раздувает лимит длины. Карточка игры
(Классика) визуально показывает таблицу через тот же `renderMath` (скриншот
подтверждён). Побочно в пул впущена #6389 — легитимная таблица L/Q из другого
источника, раньше ошибочно битая `\hline`.

**Проверки:** счётчики вопросов не изменились, правильные ответы не изменились
(0 расхождений), KaTeX 0 ошибок во всех превью, шлюзы ✅, тесты 168/168,
`manage.py check` — 0.

## Фаза 3 — узкая вычитка на структуру (257 вопросов)

Систематическая проверка через `audit_vsosh_structure` (геометрия PDF, все
страницы всех PDF) + сверка с parsed:

- **Таблицы (рамочные):** детектор нашёл 4 в тест-вопросах — все 4 теперь
  реконструированы как `$$\begin{array}…$$` (сверка parsed: `\begin{array}`
  присутствует ровно у этих 4). Таблицы Части 4 / сеток ответов / бланков не
  импортируются — не трогаем.
- **Таблицы (безрамочные):** отдельный скан геометрии (колоночный текст без
  линеек) + скан parsed на уплощённые табличные паттерны (заголовочные слова
  + ряды чисел вне уже реконструированных) — **не найдено ни одной**. В
  корпусе ВсОШ все таблицы набраны с линейками (booktabs).
- **Списки:** маркеры «•» — только 2025 №3.2, **сохранены** при разборе.
- **Рисунки:** 2018 №18, 2024 №2.2 — помечены «в оригинале рисунок» (ранее);
  новых не выявлено.

**Итог структурного класса: найдено 4 таблицы — починено 4; списки целы;
рисунки помечены. Остаточных потерь структуры — 0.**
