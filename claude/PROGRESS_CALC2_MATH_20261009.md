## Фаза 0. Разведка

### Шесть моделей: величины, отрезок поиска, зависимость от кадра

| Модель | Величины «Ответа» | Откуда берётся отрезок поиска | Меняется при масштабе/сдвиге |
|---|---|---|---|
| `m-graph` | нули, f(0), «Вершины», пересечения кривых (`updateGraphPanel`) | `mx.domain()` — видимое окно; пересечения — `keyTargets()` по окну | **да**: нули, f(0) («ось вне окна»), вершины, пересечения |
| `m-transform` | преобразование, a | — (экстремумов нет) | нет, но ответа как такового нет |
| `m-optimum` | наибольшее/наименьшее, лок. экстремумы, перегибы (`mathAnalyse`) | `STATE.mathXmin…mathXmax` — окно; поля «Отрезок» `opt-a/opt-b` = те же границы окна (обе стороны связаны) | **да**: всё, включая концы отрезка |
| `m-tangent` | f(x₀), f′(x₀), угол | шаг производной `mathH()` — доля ширины окна; `setMathWindow` зажимает x₀ в окно | шаг: в 4–5-м знаке (fmt прячет); зажим x₀ — **да**, если окно ушло с x₀ (через `setMathWindow`) |
| `m-minmax` | смены ветви (корни разности пар) | `STATE.mathXmin…mathXmax` — окно | **да** |
| `m-constraint` | x*, y*, f(x*, y*) (условный оптимум двух переменных) | размах ограничения `STATE.consFit` (из самой формулы, при входе и смене формулы) **∪ текущее окно** | приближение — нет; отдаление/сдвиг в минус расширяют область, а с ней шаг сетки 260 узлов → в 3-м знаке **может** |

`m-constraint` — другой смысл ответа: две переменные, область задаёт само ограничение, отрезка по x нет.
Решение: строки «отрезок ответа» у неё нет; область поиска — только `consFit` (без объединения с окном).

### Ключевые точки холста

- `keyTargets(panelId)` (`60-overlays.js`): пересечения `crossPoints` (по окну), нарисованные сценой точки
  (`data-key-point`, объявляет `flushDrawnKeyPoints`), их проекции, экстремумы и изломы `snapTargets` — **всё по окну**.
  Это правильно: точка вне окна просто не видна. Ответ отсюда больше не берём (`updateGraphPanel` брал пересечения).
- Подпись координат — `buildCapsule()` в `drawCrossPoints` (там же), собирается **при первом наведении** (`paint`
  при `hoverCross`), после того как `selfCanvas()` уже прошёл по холсту → «?» не ставится. Закрепка — значок в той же
  капсуле → `pinKeyPoint` → `addMarkAt` (координаты уходят в «Свои точки»).
- Прилипание: `snapPoint` (KEY_SNAP_PX) для вершин площадей и «своей точки»; окошко прокатки `showRollTip`
  пишет координаты курсора на кривой — это чтение графика, не ответ.
- `axisWords()` в режиме `graph` отдаёт «ось Q / ось P» (только `math` даёт x/y) — имя точки «пересечение с осью Q»
  в «Построении графиков». Мелочь, поправить попутно.

## Фаза 2. Ответ на отрезке, а не в окне — сделано

- `updateGraphPanel`: нули, f(0), вершины — `ansAnalyse(f, отрезок)`; пересечения кривых — нули разности на отрезке
  (`ansCrosses`), а не ключевые точки холста. «в окне не пересекает» / «ось вне окна» → «нет».
- `m-optimum`: `mathAnalyse(f, отрезок)`; экстремумы — общим `ansAnalyse` (смена знака f′ внутри отрезка, концы не
  считаются, «плато» больше не объявляется); заливка выпуклости — по окну (это рисунок).
- `m-minmax`: смены ветви — нули разностей на отрезке (`ansZeros` с отсевом полюсов и совпадений).
- `m-tangent`: шаг производной `mathH()` — доля отрезка ответа, а не окна; x₀ окном не зажимается (фаза 1).
- `m-constraint`: область поиска — только размах ограничения `consFit`, без объединения с окном.
- Числа ответа — `ansFmt`: запятая, «−», ТРИ знака (лишние нули срезаются). Общий `fmt` даёт два («−1,73»),
  а решение и контрольные числа «Математики» записаны тремя («−1,732»). Точка «(x; y)», список через «; », «нет».
- Ключевые точки холста по-прежнему по окну (`keyTargets`): точка вне окна просто не видна.
- Попутно: в «Математике» индикатор масштаба считал 100 % от уже приближенного окна (перерисовка внутри
  `setMathWindow` шла до `markViewDirty`) — пометка перенесена выше.

## Фаза 4. Локальные максимум и минимум — главные величины — сделано

## Фаза 5. «Сначала сам»: ответ списком, точкой и «нет» — сделано

- `96-self.js`: `selfParse` — число; список чисел через «;»; точка «(x; y)»; список точек; «нет» (пустой список).
  Пробелы (и U+00A0, U+202F) не важны; «−», «–», «-» — минус; запятая внутри числа — десятичная; «;» — и список,
  и координаты в скобках; регистр «нет» не важен; хвост «°» / «∘» (градус, набранный KaTeX) / «%» у ячейки — единица.
- `checkGuess` — мультимножества: порядок не важен, число значений обязано совпасть, допуск прежний
  `max(0,011; 0,0005·|b|)` на каждую координату. Не разобрали — тост «Впишите числа через «;», точку как (x; y) или
  «нет»», вердикта нет. Неверно — только «✗ не сходится». Поле одно на величину, `inputmode` убран (нужны «(», «;»).
- Ячейка открыта без поля, только если её значение не ответ вовсе (`selfIsAnswer`); то же в `selfAfterAnswer`.
