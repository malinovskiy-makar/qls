### Воспроизведение Safari в WebKit (до правок)

**Поля отрезка (карточка `…818c…`) — НЕ воспроизвелось.** Пробовал в WebKit и Chromium на 1440 и 1280:
1. щелчок (тройной) в «до», «50» посимвольно, паузы 300 мс и 700 мс — фокус в поле, значение «50»;
2. «-60» в «от», затем «200» в «до» с паузами — то же; события: ни одного `focusout` между цифрами, ни одной
   перерисовки (счётчик `redrawAll` 0);
3. то же с перерисовкой `redrawAll()` между цифрами — строка не переезжает (MutationObserver 0), фокус держится;
4. сначала набор `x^2-4` в поле MathLive, потом поле отрезка (подозрение: поле формулы забирает фокус обратно) —
   фокус держится.

Безголовый WebKit от настоящего Safari всё же отличается (окно, автозаполнение, оверлейные полосы прокрутки), поэтому
сделана **защитная починка по всем трём подозрениям карточки** и прибор с помехой (см. фазу 1).

**Поле «Сначала сам» (карточка `…8140…`) — причина найдена замером, в ОБОИХ движках.** Колонка по горизонтали не
уезжает (`scrollLeft` 0 у всех предков, строка «поле + Проверить» 284 = 284 px при 1280, 316 = 316 при 1440). Но у
блока `#scoreboard` осталось `overflow: hidden` от прежнего вида карточек (`#params-panel .side-part`), а поле стоит
ровно на его левой кромке: 980 = 980 px при 1280 (1108 = 1108 при 1440), кнопка «Проверить» — на правой (1264 = 1264).
Кольцо фокуса (2 px + отступ 2 px) срезалось слева и справа; в Safari, судя по снимку владельца, срезалась и рамка
(дробная позиция). Снимки «до»: `claude/shots/calc2_fixes_b_20261013/before_self_*.png` (в git не идут).

## Фаза 1. Safari

**1а. Поля отрезка.**
- `syncAnsSegUI` (70-scenes-math.js) больше не переносит строку `#ans-seg-row`, пока фокус внутри неё: перенос узла с
  полем в фокусе снимает фокус в любом браузере.
- `focusout` строки (86-workspace.js) решает после того, как фокус осел (`setTimeout 0`): фокус снова в строке —
  человек ещё набирает. WebKit отдаёт `relatedTarget = null` чаще Chromium. В Chromium поведение прежнее (Enter, Tab
  с верной парой, уход из строки).
- Событие `input` по-прежнему только ставит `dirty` (перерисовки на символ нет — проверено счётчиком).

**1б. Поле «Сначала сам».** `#params-panel .side-part` получил запас 6 px по бокам (отрицательное поле + такой же
отступ, calc2.css): обрезка отодвинута внутрь отступа колонки (16 px), содержимое стоит на прежнем месте, ширина строк
«Ответа» та же (284 / 316 px).

**Прибор `calc2/tests/webkit_probe.mjs`** (WebKit и Chromium; нет движка — громкий пропуск):
- А: «-60», «200», «50» посимвольно с паузами 300 мс — значение = набранному, фокус до Enter в поле, после Enter
  `STATE.ansA/ansB` и `_ansSeg` = введённому; уход щелчком применяет «80». Всё дважды: чисто и **с помехой** (между

- Б: 1280 и 1440, светлая и тёмная, «Построение графиков», «Сначала сам», «Пересекает ось x», «2; -2», «Проверить»:
  прокрутка 0; поле + 4 px кольца внутри пересечения обрезок всех предков; «Проверить» целиком видна.

**Результат:** `webkit_probe.mjs` — **124 из 124** (WebKit 62, Chromium 62). Поле при 1280: 976…1153 с кольцом при
