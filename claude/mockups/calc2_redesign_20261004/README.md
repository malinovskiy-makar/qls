## 2. Как читать `.dc.html` и что не переносить

- Разметка — внутри `<x-dc>…</x-dc>`: обычный HTML с инлайновыми стилями, шрифты в `<helmet>`. `{{…}}` — подстановки
  из `renderVals()` класса `Component` внизу файла; `<sc-if value>` — условие; `<sc-for list as>` — цикл;
  `style-hover` — стиль при наведении; `hint-placeholder-*` — заглушки холста, не читать.
- Обработчики `onClick="{{…}}"` — методы класса: `commit`, `undo`, `redo` (история), `editFn` (формула),
  `checkGuess` («Сначала сам»), `bgDown`, `svgMove`, `svgUp` (холст: протяжка и щелчок, который зажигает кривую),
  `kpEnter`, `kpKeep`, `kpLeave`, `pinKp` (ключевые точки), `addMarkAt`, `addVertex`, `closeArea` (свои точки и
  площади), `pwApply`, `pwOn`, `pwOff`, `openPwModal`, `pwmDo`, `pwmApply` (кусочная функция), `kbTarget`, `kbPress`
  (клавиатура формул), `openPop` (окна), `toast`.
- Всё, что рисуется, отдаёт `E.view(ключ, состояние, ctx)`; разметка не знает, какая перед ней модель. Это и есть
  предложение для сайта: один каркас (раздел 14).

```
left:    [{ kind: 'fns'|'params'|'iv'|'show'|'tools', title, rows?, items?, pre?, hint?, addLabel? }]
         rows  — карточки { id, sym, name, color, visible, prefix, expr, error, canHide, isQP, canonToks,
                            sliders[], isExtra?, emptyNote?,
                            pw, v, fromPh, pieces[{ i, expr, from, to, errExpr, errFrom, errTo }], notes[],
                            record[{ toks, cond, rest }], canonRows[] }       // кусочная функция, раздел 6.6
         items — { type: 'seg'|'slider'|'toggle'|'static'|'button', id, label, … }
chart:   { panels: [{ id, plot, win, grid, axis, ticksX, ticksY, keyTicks, fills, curves, dashes, segs,
                      points, labels, handles, kps[], kpTip, hits, title }], legend, note }
         kps   — ключевые точки зажжённой кривой { id, cx, cy, x, y, color, hot, style };
         kpTip — подпись точки под курсором (раздел 7.5)
answer:  { status: { tone: 'error'|'warn'|'info', text } | null, hero[], tables[], burden, ff, explain }
         ff    — { name, prefix, toks, copy }; у кусочной — { name, prefix, rows[{ toks, cond, rest }], copy }
primary: главный регулятор модели (разметка не использует)
```

Состояние одной модели `ms` хранят история, автосохранение и ссылка:
`{ fns: { D: { expr, shift, visible, extra?, pieces? } }, letters: { a: 1 }, iv: {…}, show: {…}, par: {…}, colors: {…}, labels: {…} }`;
`pieces` — куски `[{ expr, from, to }]`, поле есть только у кусочной функции.
Правки по id (`E.setValue`): `fns.D.expr|shift|visible|restore`, `fns.D.pieces`, `fns.D.pw.on|off|add|count|del`,
`fns.D.pw.<номер>.expr|from|to`, `fns.add`, `fns.F1.remove`, `letter.a`,
`iv.instr|kind|side|rate|pct|price|quota|ghost`, `show.cs`, `par.P`, `color.D`, `label.D`, `reset.tc`; ручки — `E.drag`.

### 6.6 Кусочная функция (02.10; способ ввода выбран 04.10)
Функция, заданная по-разному на разных участках: спрос с изломом, составной спрос у монополии, ступень. Считает её
движок calc2 той же цепочкой условий, что собирает нынешний конструктор (`pwFormula` в `82-input.js`):
`(Q >= a and Q < b) ? (f₁) : ((Q >= b) ? (f₂) : NaN)`. Макет хранит куски строками `ms.fns.X.pieces = [{ expr, from, to }]`
и собирает из них ту же запись (`E.pwText`), поэтому числа макета и сайта сходятся (раздел 16).

**Правила:**
- Кусок — формула и участок «от … до …»: «от» включительно, «до» не включая; пустая граница — открытая. Подсказка в
  первом «от» — «0» (у производной «−∞»), в последнем «до» — «∞». Кусков от 1 до 12.
- Вход: «Задать кусками» в меню «…» карточки (раздел 10), кнопка «Кусочная функция» внизу клавиатуры формул (6.7),
  у функции, уже заданной кусками, — щелчок по записи в карточке или «Изменить куски» в меню «…». Каждый вход открывает
  окно «Кусочная функция» (раздел 10).
- «Задать кусками» у обычной формулы делит её на **два одинаковых куска** с границей посередине (половина первого
  корня функции, округлённая до одной значащей цифры; корня нет — 50; у производной — 0): эти два куска стоят строками
  в открывшемся окне, график не меняется, пока не нажато «Готово». Формула, уже набранная цепочкой условий
  («Q < 20 ? 100 − 2Q : 80 − Q»), разворачивается в те же строки.
  **Отличие от нынешнего сайта:** сейчас конструктор открывается с примером по умолчанию («100 − Q» от 0 до 40 и
  «80 − 0,5Q» от 40) и заменяет им формулу поля; в макете он начинает с формулы, которая уже стоит в поле.
- Соседние границы связаны: правка «до» куска меняет «от» следующего (и наоборот), пока они совпадали. «Добавить кусок»
  продолжает последний кусок: закрывает его открытую границу на шаг дальше (шаг — длина предыдущего участка, иначе
  значение «от», иначе 10) и добавляет кусок с той же формулой. Удаление куска отдаёт его участок соседу сверху (у
  первого — соседу снизу): дыр не остаётся. Остался один кусок без границ — это снова обычная формула.
- Форма записи у всех кусков одна: либо все P от Q, либо все Q от P («Q = 160 − 5P»). У Q(P) границы идут по цене
  («при P от … до …»), приставка «Q =», а под записью стоит строка «Q(P) · в расчётах P =» с такой же фигурной скобкой:
  канон по участкам, условия уже по Q (формула STIX 16, условие STIX 13 `--text3`). Нелинейные куски Q(P) —
  «обратная функция, считаем численно».
- Буква в условии — переменная поля. В макете это Q, P или x; на сайте её по-прежнему выбирает `pwVarForField`
  (Q, P, L, X, Y, i, r… по формуле самого поля), приставку («P =», «y =») конструктор читает из поля (`pwPrefixOf`).
- Ошибки — по кускам; текстом показывается первая (`role=alert`, 13 px `--error-ink`), поле с ошибкой краснеет
  (формула `--error-ink`, пунктир или рамка границы `--error`): «Кусок 2: впишите формулу»; «Кусок 2: {ошибка формулы
  с маленькой буквы}»; «Кусок 1: граница „от“ должна быть числом»; «Кусок 1: граница „до“ должна быть числом»;
  «Кусок 1: „от“ должно быть меньше „до“»; «Куски записаны по-разному: либо все как P от Q, либо все как Q от P».
  С ошибкой «Готово» не применяет запись (раздел 10): график и ответ держат последнюю верную.
- Замечания — не ошибки (13 px `--amber-ink`, значок треугольника 15 px): «Куски 1 и 2 перекрываются при Q от 15 до 20:
  там считается кусок 1.»; «При Q от 20 до 30 функция не задана.»
- На холсте: излом — узел линии (кривая проходит ровно через него) и ключевая точка (ADR 0084, пункт «г»). На скачке
  линия рвётся, концы помечены кружками радиус 3,4: закрашенный цветом кривой (обводка 1,4 `--canvas`) там, где
  значение есть, пустой (фон `--canvas`, обводка цветом кривой 1,8) там, где его нет. Площади и излишки считаются с
  узлами в изломах; производная у излома односторонняя (MR составного спроса рвётся в изломе на две ветки).
- Ползунка «сдвиг» у кусочной функции нет.
- «Одной формулой» убирает куски и оставляет формулу первого; тост «Куски убраны, осталась формула первого куска» с
  «Вернуть». «Вернуть стартовую запись» тоже убирает куски. Смена роли своей функции переносит запись целиком,
  вместе с кусками.
- История: всё, что сделано в окне, применяется по «Готово» одним шагом; «Одной формулой» — отдельный шаг.

**В карточке функции** (`PwCard.dc.html`, `PwMono.dc.html`) вместо поля формулы стоит запись фигурной скобкой (мин.
высота 40, поля 6 8 6 10, фон `--surface-2`, рамка `--border`, радиус 6): приставка «P =» STIX 17 `--text2`, скобка во
всю высоту (SVG шириной 10, линия 1,3 `--text2`); в строке высотой 24 формула куска слева (STIX 18, не помещается —
многоточие) и условие справа мелко (STIX 14 `--text3`): «0,5Q + 10» и «Q < 40», без слова «если»; хвост без условия —
«иначе» (12,5 px `--text3`); справа значок карандаша 15 px. Вся запись — кнопка (`role=button`, Enter и Пробел,
`aria-label` «Изменить куски: {имя}») и открывает окно «Кусочная функция» (раздел 10). Правки применяются по «Готово»,
одним шагом истории. Это продолжает решение 24.08 «запись кусочной функции видна в карточке, правка через конструктор».

Цепочка условий, набранная руками в обычном поле (клавиша «если»), показывает под полем ту же запись скобкой, «как
понято» (не кнопка, `aria-label` «Запись по участкам: {имя}»).

**Отличие от нынешнего сайта, принятое в макете.** Сейчас конструктор для обычной формулы открывается с примером по

уже стоит в поле (два одинаковых куска), и ничего не теряет. Правило ADR 0021 «строки конструктора принадлежат полю»
при этом остаётся: строки собираются заново при каждом открытии из того, что стоит в этом поле.

**Рассмотрено и отклонено 04.10:** правка кусков прямо в карточке (строки «формула / при Q от … до …» на месте поля,
живая правка без «Готово»; доска `PwInline` в архиве). Не переносить.

### 6.7 Клавиатура формул (02.10)

### 7.5 Ключевые точки (переписано 02.10; вид выбран 04.10)
Поведение — то, что уже решено владельцем для сайта и работает в calc2 (`armCurve`, `drawCrossPoints`, `pinKeyPoint`
в `60-overlays.js`; ADR 0084). Редизайн его не меняет, меняется только вид точки и подписи.

**Поведение:**
- По умолчанию ключевых точек на холсте нет. Щелчок по кривой (полоса попадания 16 px) **зажигает** её ключевые точки,
  без координат; кривая становится на 1 px толще, её карточка получает рамку `--border-strong`.
- Зажжена всегда одна кривая: щелчок по другой гасит первую. Гасят повторный щелчок по той же кривой и щелчок по
  пустому месту холста. Esc не гасит. Смена модели и «Сбросить» гасят.
- Щелчок отличается от протяжки порогом 4 px (сумма сдвигов по x и y): нажали и повели — это сдвиг окна, зажжённая
  кривая не меняется.
- Наведение на зажжённую точку (зона радиус 12; на сайте сейчас 11) показывает координаты и значок закрепки. Уход
  курсора прячет их через 220 мс (на сайте сейчас 160), вход в подпись или значок отсрочку отменяет: подпись обязана
  пережить путь руки от точки до значка. Для этого под подписью лежит невидимая зона — точка ±13 px и подпись с
  запасом 3 px.
- В «Свои точки» точку выносит **только щелчок по значку закрепки** (подсказка «Сохранить в свои точки»). Щелчок по
  самой точке ничего не сохраняет и кривую не гасит. После закрепки: тост «Точка A добавлена в „Свои точки“», подпись
  прячется, кривая остаётся зажжённой, на месте ключевой точки стоит своя (две точки в одном месте не рисуются).
  На сайте закрепка остаётся шагом отмены, как сейчас.
- В инструментах «Точка» и «Площадь» ключевые точки мышь не ловят (как сейчас на сайте): щелчок рядом с ними ставит
  свою точку или вершину; прилипание — раздел 7.6.
- «Сначала сам»: вместо координат в капсуле стоит «(?; ?)».
- Какие точки ключевые, решает движок calc2 (ADR 0084): пересечения с осями и с другими кривыми; всё, что сцена
  нарисовала с пунктиром к осям (E, M, точки при потолке, квоте, МРОТ), и проекции таких точек; изломы кусочных.
  Перегибы — нет. В макете: пересечения с осями, равновесие, (Q₁; P_b) на спросе и (Q₁; P_s) на предложении при налоге,
  Q_c у монополии, изломы кусочной функции.
- Точка красится цветом своей кривой, в том числе цветом, который выбрал человек.

**Место капсулы** (то же правило у подписи своей точки): восемь положений вокруг точки — справа сверху,
справа, справа снизу, слева сверху, слева, слева снизу, над, под (отступ от точки 10 px; у подписи своей точки 8). Выбирается то, где под
подписью меньше всего линий и нет чужих подписей и ручек; за край поля графика подпись не выходит; при равных условиях
выигрывает «справа сверху».

**Вид (решение владельца 04.10, вид Б; доски `KeyPoints.dc.html`, `Work`, `Dark`):**
- **Точка:** кружок цветом кривой, радиус 4, обводка 1,5 `--canvas`, в мягком ореоле того же цвета — круг радиус 9,5 с

## 9. «Сначала сам»

Включается в шапке модели (на телефоне — во вкладке «Ответ») или ссылкой с `self=1`; действует на модели с числами.
- **Прячется:** главные числа → поле ответа (и «было · Δ»); бремя, таблицы, итоговая функция → пунктирная кнопка;
  выделенные значения на осях → обозначения Q*, P*, Q₁, P_b, P_s, Q_m, P_m, Q_c, Q_s, Q_d (заданное самим человеком —
  цена потолка, P у издержек — остаётся числом); на холсте «(?; ?)», «дефицит ?», «Δy = ?», ручка «f′(x₀) = ?»; свои
  точки без координат, «S₁ = ?»; в «Скачать» — «?» под графиком. **Не прячутся:** статус (если в нём нет чисел ответа), график, ставки. «Разбор» закрыт до ответа (поправка в конце раздела).
- Пояснение (13 px `--text2`): «Числа спрятаны, на осях только обозначения. Впишите свой ответ и проверьте; любое число
  можно открыть отдельно.»
- **Ячейка:** подпись; «P_b =» (STIX 17) и поле во всю ширину (34 px, STIX 19, по центру, подсказка «?», `--surface-2`,
  рамка `--border-strong`, радиус 6, `aria-label` «Ваш ответ: {подпись}»); ниже контурная «Проверить» (28 px, 13/600,
  `--surface`, рамка `--border-strong`: графитовая кнопка на экране одна, это «Поделиться») и ссылка «Показать»
  (13/500 `--accent-ink`, подчёркнута).
- **«Проверить» или Enter:** не число — тост «Впишите число, можно с запятой»; иначе пилюля «✓ верно» (`--green-ink` на
  `--green-tint`, рамка `--green-border`) или «✗ не сходится» (`--error-ink`, `--error-tint`, `--error-border`); рамка
  поля того же цвета.
- **Допуск** (`checkGuess`): ответ `a` и число ячейки `b` (уже округлённое до сотых) читаются одинаково — убрать
  пробелы (в том числе U+202F и U+00A0), «−» → «-», запятая → точка. Верно, если |a − b| ≤ max(0,011; 0,0005 · |b|):
  у 1 250 это ±0,625 (ответ «1 245» — «не сходится»), у 11,35 — ±0,011 (ответы «11,35» и «11,354» верны, «11,3» — нет).
- Любая правка модели, отмена и возврат снимают вердикты; вписанное остаётся.
- «Показать» открывает одно число (с «было · Δ»); «Показать всё» и пунктирная кнопка — всё сразу (числа, оси, таблицы,
  бремя, итоговую функцию), шапка снова «пересчитывается сразу». Выключение переключателя открывает всё и забывает
  вписанное; смена модели снимает «Показать всё», вписанное помнится по моделям.
- **«После ответа»:** когда все главные числа модели сошлись или открыты по одному, остальное открывается само — числа
  на осях, «было · Δ», бремя, таблицы, итоговая функция; тост «Всё сошлось: таблица „было → стало“ и итоговая функция
  открыты». Пунктирная кнопка «Таблица „было → стало“ и итоговая функция: после ответа» открывает это раньше.

**Поправка 04.10 по сверке с кодом.** В разборах части моделей стоят числа ответа (производная, экстремумы, КПВ,
сложение КПВ, торговля), поэтому в «Сначала сам» «Разбор» закрыт той же пунктирной кнопкой «после ответа», что таблицы
и итоговая функция, и открывается вместе с ними. Пояснения под числами и строка статуса с числами прячутся по тому же
правилу. Печать и «Скачать» в этом режиме показывают те же «?», что экран.

**Ответ не числом.** Поле ответа получают только главные значения, которые являются одним числом. Если главное значение —
диапазон, пара «(a; b)» или слово (`labor-bilat`, коридор цен у `quota`), в ячейке стоит только ссылка «Показать»; для
правила «после ответа» такая ячейка считается открытой.

## 11. Автосохранение и «Продолжить»

- **Что:** состояние каждой открытой модели `ms` — функции (запись, сдвиг, видимость, свои функции), буквы,
  вмешательство, галочки, параметры, цвета, подписи; тот же объект, что в истории и в ссылке. Свои точки и площади,
  «Вид графика», ответы «Сначала сам» в макете в `ms` не входят.
- **Где:** `localStorage` — запись на модель и время последней правки; состояние текущей модели — в адресе (Moves:
  «localStorage по модели плюс состояние в адресе»). На сайте в адресе стоит только ключ модели: при входе в модель
  адрес становится `/calc2/?m=<ключ>`; `#s=<состояние>` есть только у открытой ссылки «Поделиться» и убирается из адреса
  после первой правки (раздел 18, Б.2). Иначе обновление страницы после правки вернуло бы состояние ссылки. Ключи и формат в макете не заданы; тема — по-прежнему
  `localStorage['theme']`. База не нужна: у calc2 нет моделей Django.
- **Когда:** после каждой правки; «Сохраняю…» → «Сохранено». Без доступа к хранилищу — в макете не задано.
- Открыть модель откуда угодно (строка, «Недавние», переключатель) — вернуть её сохранённое состояние; «Сбросить» —
  стартовое. Переключатель ставит точку у моделей с сохранённым состоянием.
- **«Продолжить»:** последняя открытая или правленая модель — мини-график из карточки (не текущий график), «Продолжить с того места
  · {когда}», имя, сводка (`E.summary`): функции «D = 100 − Q» (у издержек TC или MC/ATC/AVC; кусочная — «D: 2 куска
  (100 − 2Q; 80 − Q)»), вмешательство «налог
  t = 30», «субсидия s = 20», «налог 20 %», «потолок 30», «пол 70», «квота 20»; у издержек «P = 15», у производной «x₀ = 1»;
  всё через « · ». Степени — «²» и «³» (в макете `^`).
- **«Недавние»:** следующие по свежести модели (в макете три) с «сегодня» / «вчера» / «в понедельник»; у «Продолжить» —
  «вчера, 21:40». Правило для старых дат не задано.

досках-спецификациях (раздел 17).

## 14. Один каркас на 42 модели: `E.SPECS`

`calc-data.js` → `E.SPECS[ключ]` — скелет каждой из 42 моделей; по нему собираются «Условие», холст и «Ответ».
Источник — разбор calc2 (`84-picker.js`, `52-modes.js`, `88-params.js`, `90-explain.js`, файлы сцен). Доска
`Skeleton.dc.html` — та же таблица; её 7 слотов идут в порядке экрана: Функции, Параметры, Вмешательство, Показать,
Холст, Ответ, Разбор.

| Поле | Что это | Где на экране |
|---|---|---|
| `fn` | функции: `[обозначение, имя, стартовая запись]` | «Функции», карточки |
| `ax` | оси: «Q, P», «x, y · вся плоскость», «N %, I %» | имена осей, первая четверть |
| `par` | числа и варианты модели: `[обозначение, имя, значение или варианты]` | «Параметры» |
| `sl` | ползунки: сдвиги кривых, регуляторы | под карточкой (сдвиг, буквы) или в «Параметрах» |
| `iv` | каскад вмешательства строкой | «Вмешательство государства» |
| `show` | что включается на графике | «Показать на графике» |
| `hd` | что тянется мышью | ручки холста |
| `cv` | холст: 1 или 2 панели, квадрат | раскладка холста |
| `hero` / `more` | главные / остальные числа | «Ответ»: 2×2 / таблицы |
| `ff` | итоговая функция | карточка «Итоговая функция» |
| `note` | особенность, которую нельзя потерять | проверяется отдельно |

**Правило нуля:** пустой слот (`[]`, `null`, `''`; на доске — прочерк) — секции на экране нет вовсе: ни заголовка, ни
«пусто», ни «Ползунков нет».

Сводка по `E.SPECS`:
- без карточек функций в макете: consumer, cons-slutsky, phillips, ineq (на сайте у потребителя есть поле U(x, y), у
  неравенства — поле L(p) и список доходов: они получают место по `COVERAGE.md`, раздел 3);
- две панели: m-tangent и prod (друг под другом), tradeprice и mono-d3 (рядом); квадрат — ineq;
- вмешательство: taxes, ceil, quota, ext, mono, labor, labor-mono, labor-union, smallopen, cons-slutsky, loanable, fx, ineq;
- ручки: m-tangent, ppf, ppfsum, trade, taxes, ceil, quota, elast, costs, mono, labor, labor-mono, labor-union,
  smallopen, consumer, fx, ineq;
- итоговая функция: taxes, sdsum, ppfsum, trade; ответ-диапазон: labor-bilat, коридор цен в quota;
- без «Параметров»: m-optimum, taxes, elast, prod, mono-d3, loanable;
- `note` у 15 моделей, например «Список функций открытый: новая строка появляется сама.» (m-graph), «Участок „рынка
  здесь нет“ рисуется пунктиром того же цвета.» (sdsum), «Квадрат остаётся квадратом при любом масштабе.» (ineq).

**Б. Рабочие решения для переноса.** Владелец их отдельно не утверждал; они приняты, чтобы перенос не останавливался, и
каждое меняется одной правкой на приёмке. При переносе исполнять как написано и перечислить в отчёте отдельным списком
«принято без вопроса владельцу».
1. **Ширины.** ≥ 1400 — колонки 336 и 348; 1240–1399 — 304 и 316; 760–1239 — «Ответ» сворачивается в выезжающую
   панель справа (кнопка «Ответ» в панели холста, числа 2×2 видны строкой над холстом), «Условие» 304; < 760 — телефонная
   раскладка (раздел 3). Колонка холста не уже 618 px от ширины 1240; на 760–1239 он забирает всё, что осталось после
   «Условия». Порог 760, а не 1024: сейчас на планшетной ширине доступны все органы управления, и раскладка телефона
   не должна их отнимать (`COVERAGE.md`, раздел 8).
2. **Ссылка «Поделиться».** `https://weconomics.ai/calc2/?m=<ключ модели>#s=<состояние>`: состояние — всё `ms` модели
   (записи функций, буквы, сдвиги, вмешательство целиком, галочки «Показать», параметры, цвета, подписи, свои точки и
   площади, «Вид графика»), JSON → UTF-8 → base64url, с полем версии `v`. Открытие восстанавливает ровно это и
   **не затирает** автосохранение открывшего: открытое по ссылке живёт как отдельное состояние, пока человек не начнёт
   править (тогда оно становится его состоянием этой модели). Неизвестная версия или битая строка — модель по умолчанию
   и тост «Ссылка устарела: открыли модель с начальными функциями». `self=1` — сразу в «Сначала сам». Тест: состояние →
   ссылка → состояние совпадает для каждой из 42 моделей. При входе в модель адрес страницы — `/calc2/?m=<ключ>`; `#s=` есть только у открытой ссылки и убирается после первой
   правки. В ссылке и в автосохранении лежит **полное** состояние входов
   модели, а не отличия от стартового: ссылка обязана открывать то же самое и после того, как у модели сменят стартовые
   значения. Отличие от старта считается отдельно: по нему ставится точка «сохранены ваши настройки» и собирается сводка
   «Продолжить». Персональных данных в ссылке нет: только состояние модели.
3. **Автосохранение.** `localStorage['calc2:v1:<ключ>'] = { v: 1, ms, savedAt }`, после каждой правки (не чаще раза в

   «12 сентября». Входят свои точки, площади и «Вид графика»; ответы «Сначала сам» — нет. Хранилище недоступно — работа
   идёт без сохранения, вместо «Сохранено» — «Не сохраняется в этом браузере». «Сбросить» заменяет запись модели стартовой.

  (ADR 0005), пустое — кнопки нет; адрес `/calc2/?m=taxes&from=<id задачи>`; открывается как ссылка из п. Б.2 (не
  затирает сохранённое). В первой очереди на стороне calc2 делается только то, что нужно для ссылки «Поделиться»: этого
  же механизма хватит, чтобы позже открыть модель с данными задачи. Доски `Problem` и `FromProblem` — ориентир для
  второй очереди.
