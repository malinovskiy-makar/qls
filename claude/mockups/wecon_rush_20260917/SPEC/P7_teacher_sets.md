# Фаза P7 — Кабинет учителя: список наборов, сборка на одном экране, страница набора

> Спецификация одной фазы единого прогона. Ветка, Notion, коммиты, отчёт, стоп-гейты — в лаунчере.
> ⚠️ Эта фаза работает в `teacher/` (а не в `game/`). В фазе −1 лаунчера проверено, что в `teacher/`
> нет чужих незакоммиченных правок; если появились — СТОП.

## Макеты
`TeacherSets.dc.html` (prop `empty`), `TeacherSetBuilder.dc.html` (интерактивный прототип),
`TeacherSetDetail.dc.html`. Вопросы в сборке настоящие, с боя (ответы очищены от остатков разметки);
наборы, игроки и очки — условные. Оформление — общее для кабинета (токены `_tokens.html`, шапка
сайта с пунктом «Ученики»), не «игровое».

## Что делаем и почему
Решение владельца в Notion → «Решения»: **«Наборы по коду: у ученика одна страница набора
(приглашение + доска), анонимы как сейчас; у учителя сборка на одном экране, поле „Открыт до“,
страница набора с кодом для класса»** (17.09.2026). Баг в «Задачах»: **«Мастер игрового набора
учителя теряет выбранные вопросы при смене страницы списка или фильтра»** — проверено на бою:
добавил вопрос («В наборе: 1 / 60»), нажал «вперёд →» — «В наборе: 0 / 60». Причина: выбранное живёт
только в переменной `picked` скрипта (`teacher/templates/teacher/game_set_create.html`), а фильтры —
форма `method="get"` и пагинация ссылками, то есть полная перезагрузка. Собрать набор из двух тем
сейчас невозможно.
**Не делаем** (отложено, отдельная карточка): привязка набора к группе учеников и список «кто ещё
не прошёл».

Код: `teacher/game_sets.py` (`game_sets_list`, `game_set_create`, `_save_set`, `game_set_detail`,
`api_game_set_fill`; `MAX_SET_SIZE = 60`, `PAGE_SIZE = 20`), шаблоны `teacher/templates/teacher/
game_sets_list.html`, `game_set_create.html`, `game_set_detail.html`; тесты наборов —
`game/tests/test_sets.py` (найди там тесты учительских страниц; если их нет — заведи
`teacher/tests/test_game_sets.py`).

## Сверка с кодом перед правками
Базовый прогон: `manage.py test game.tests.test_sets` (+ тесты `teacher`, в которых есть `game_set`) —
числа в журнал. Сверь: сигнатуру `api_game_set_fill` (тело запроса, `exclude`, фильтры), `_pool_qs`,
`_answer_text`, `game_stats.bulk_stats`/`public_stat`/`effective_difficulty`, `CANONICAL` (темы),
`game_sources.GROUPS`; поля `GameSet.opens_at`/`closes_at` (уже есть — миграция не нужна); декоратор
`teacher_required`.

## P7.1 — список `/teacher/game-sets/` (по `TeacherSets.dc.html`)
Заголовок «Игровые наборы» 28px 800 + абзац-объяснение (текст из макета) и справа «＋ Собрать набор»
(`--btn-bg`). Таблица-карточка, строки 60px: **Набор** (название 15px 700 + мелко «Блиц · 12 вопросов
· 1 попытка») · **Код** (моноширинный в рамке + кнопка копирования) · **Срок** («открыт до 20 сент.»
зелёным / «бессрочно» / «закрыт 12 сент.» серым) · **Прошли** · **Ср. точность** (нет результатов —
«–») · **Создан** · «Открыть». Подвал: «Код нечувствителен к регистру и пробелам — его можно
продиктовать или написать на доске. Ученик вводит его на странице игры в поле „Играть по коду“.»
Пустое состояние: пунктирная плашка «**Наборов пока нет** · Соберите первый — это пять минут: режим,
вопросы, название.» + кнопка. Счётчики — агрегатами, без запроса на набор.

## P7.2 — сборка на одном экране `/teacher/game-sets/new/` (по `TeacherSetBuilder.dc.html`)
Три шага-пилюли («1 · Режим 2 · Вопросы 3 · Название и код») убрать: они наезжали на заголовок, а
шаги 2 и 3 и так были одним экраном.
1. **Шапка**: «← Игровые наборы», заголовок «Новый набор», справа четыре кнопки режима 52px с
   человеческими подписями: «Пуля — верно / неверно · 1 мин · 566», «Блиц — один верный ответ ·
   2 мин · 1 644», «Рапид — несколько верных · 5 мин · 539», «Классика — числовой ответ · 10 мин ·
   436» (числа — размер пула типа; длительность — из `config.MODES` в минутах). **Слова `boolean`,
   `single`, `multi`, `numeric` и «120 с» учителю не показывать нигде.** По умолчанию выбран Блиц
   (или `?mode=`). Смена режима при пустом наборе — сразу; при непустом — окно «Сменить режим? В
   каждом режиме свой тип вопросов, поэтому собранный набор очистится.» / «Оставить как есть»
   (основная) · «Сменить и очистить».
2. **Слева — вопросы**: строка фильтров (поиск по тексту; «источник»; «сложность от–до»), ряд
   чипов-тем (самые частые + «ещё N тем ▾» — выпадающий список остальных из `CANONICAL`), строка
   «Найдено 1 644 · показано 20 · набор справа при смене фильтра и подгрузке не меняется», список
   карточек (текст в две строки с обрезкой; «ответ: …» зелёным; мелко «тема · сложность N ·
   источник»; справа кнопка «＋ В набор» → после добавления «✓ В наборе» зелёной плашкой, повторный
   клик убирает), внизу «Показать ещё 20» и подсказка «Здесь только вопросы, пригодные для игры: без
   рисунков и длинных условий.»
   **Главное: фильтры и подгрузка НЕ перезагружают страницу.** Новый `GET
   /teacher/api/game-set/pool/?mode=&q=&topic=&source=&dmin=&dmax=&offset=` (под `teacher_required`)
   → `{total, items: [{id, text, answer, topics, difficulty, source, percent}], next_offset}` — та
   же выборка, что сейчас в `game_set_create` (вынеси её в общую функцию, чтобы страница и API не
   разошлись). Клиент перерисовывает только левый список; состояние набора не трогается. Первая
   порция может прийти с сервером в HTML (без мигания).
   Страховка: состав набора, название, попытки и срок дублируются в `sessionStorage` (ключ с режимом)
   и восстанавливаются при случайной перезагрузке; очищаются после успешного сохранения.
3. **Справа — набор** (карточка 500px, прилипает при прокрутке): «Название набора» (placeholder
   «Контрольная по спросу, 10 класс»); «Попыток на человека» — счётчик − 1 + (1…10); **«Открыт до ·
   необязательно»** — дата и время (`<input type="datetime-local">` в оформлении сайта), пусто —
   «не задан — бессрочно»; заголовок «В наборе · **3** из 60» + «порядок у всех одинаков —
   перетащите или двигайте стрелками»; список выбранных: ручка перетаскивания, номер, текст в одну
   строку, кнопки ↑ ↓ ✕ (перетаскивание — существующая логика; стрелки — новое, для клавиатуры и
   телефона); пусто — пунктирная плашка «Пока пусто. Добавляйте вопросы слева или доберите случайные
   под текущие фильтры.»; внизу «Добрать 5 случайных» (**оформленная** кнопка; учитывает текущие
   фильтры и исключает уже выбранные — существующий `api_game_set_fill`) и «Сохранить и получить
   код» (`--btn-bg`; неактивна при пустом наборе). Ссылка «сменить режим» голым системным видом —
   убрать (режим меняется кнопками сверху).
4. **Сохранение** (`_save_set`): к существующему добавить `closes_at` — разбор значения как
   московского времени (`Europe/Moscow`, как `daily_tzinfo`), прошедшая дата → ошибка формы «Срок уже
   прошёл»; пусто → `None`. `opens_at` не трогаем. Остальная валидация прежняя (уникальность с
   сохранением порядка, срез до 60, тип вопросов по режиму).
5. **Текст ответа для показа**: в `_answer_text` (или рядом) — лёгкая чистка только для отображения:
   убрать ведущую метку варианта вида `(a)`, `(b)`, `(3)`, `a)` и хвостовые `;`/`.`. Данные в базе не
   менять. Если чистка задевает что-то сомнительное (ответ целиком в скобках) — не трогать такой ответ.
6. Телефон (≤ 720px): сначала карточка набора свёрнутой строкой «В наборе 3 из 60 · Открыть», ниже
   вопросы; режимы 2×2.

## P7.3 — страница набора `/teacher/game-sets/<код>/` (по `TeacherSetDetail.dc.html`)
1. «← Игровые наборы». Верх — две карточки (`minmax(0,1fr) 470px`):
   - слева: «НАБОР УЧИТЕЛЯ», название 28px 800, плашки «Блиц · один верный ответ», «**12** вопросов»,
     «попыток: **1**», «открыт до **20 сентября, 23:59**» / «бессрочно» + кнопка **«Изменить срок»**
     (маленькая форма: дата-время или «снять срок»; POST под `teacher_required`, только автор или
     персонал); четыре плитки: «ПРОШЛИ **14** · из них 2 без входа», «СРЕДНЯЯ ТОЧНОСТЬ **71 %**»,
     «СРЕДНИЙ СЧЁТ **142**», «САМЫЙ ТРУДНЫЙ **№ 10 · 20 %**» (красным; нет данных — «–»);
   - справа **«Код для класса»**: код 38px моноширинным с пробелом посередине («K7M2 X9QD»), кнопки
     «Скопировать ссылку» (`--btn-bg`), «Скопировать код», «Открыть как ученик» (→ `/game/s/<код>/`);
     подсказка: «Ученик открывает weconomics.ai/game и вводит код в поле „Играть по коду“ — или просто
     переходит по ссылке. Регистр и пробелы не важны.» (домен — из `request`, не хардкод).
     После создания набора учитель попадает сюда же — сообщение об успехе остаётся.
2. Две колонки (`minmax(0,1fr) 600px`):
   - **«Кто прошёл · N»** — подпись «учитель видит всех и время сдачи»; колонки: место (медали 1–3) ·
     Игрок · Счёт · Точность · Макс. комбо · Чем кончилось · **Когда** («16.09 18:42», московское);
     анонимы — «аноним» серым курсивом; все строки (не топ-10) — при большом классе блок
     прокручивается; подвал: «Анонимные раунды засчитаны, но узнать ученика по ним нельзя — попросите
     класс входить в аккаунт.»; пусто — «Набор ещё никто не сыграл. Раздайте код классу.»
   - **«Где ошибся класс»** — подпись «доля верных в этом наборе»; сегмент «сначала трудные / по
     порядку» (по умолчанию — трудные сверху; переключение без перезагрузки или параметром `?sort=`);
     строка: номер вопроса · текст в одну строку + под ним «ответ: …» зелёным · полоска · процент
     (< 40 % — красным). Учителю тексты и ответы видны всегда. Подвал: «Учителю видны тексты и верные
     ответы; ученикам — только после своей попытки.»
3. Ссылка «Публичная доска» исчезает (доска ученика теперь на странице набора, P6); чужой набор —
   как сейчас («Это не ваш набор»).

## Тесты и зубастость
- API пула: те же фильтры дают тот же `total`, что старая страница на тех же данных; `offset`
  листает без повторов и пропусков (объединение трёх порций = первые 60 id выборки); чужим ролям и
  анониму — отказ; в JSON нет ключа/слова `question_type`.
- Страница сборки: в HTML нет `boolean`, `single`, `multi`, `numeric` и «120 с»; нет формы
  `method="get"` и ссылок `?page=`; есть четыре кнопки режима с минутами.
- Браузерный (`game/tests/browser_*.mjs` — по образцу существующих): добавить 2 вопроса → сменить
  тему чипом → «Показать ещё 20» → счётчик по-прежнему «2 из 60», оба вопроса в списке справа;
  перезагрузка страницы → набор восстановлен из `sessionStorage`; стрелка ↓ меняет порядок, и
  `question_ids` в форме отражает новый порядок.
- Сохранение: `closes_at` из «2026-09-20T23:59» сохраняется как 20:59 UTC; прошедшая дата → ошибка и
  набор не создан; пустое поле → `None`; порядок `question_ids` в базе = порядок в форме.
- Страница набора: плитка «Прошли» считает анонимов отдельно; сортировка «сначала трудные» по
  умолчанию; «Изменить срок» чужому учителю недоступно; в таблице есть колонка «Когда».
- Чистка ответа: `(b) Центральный банк Российской Федерации;` → `Центральный банк Российской
  Федерации`; `(3) 800 рублей;` → `800 рублей`; `1,5%` и `увеличить выпуск и сократить цену` — без
  изменений; `(все перечисленное)` — без изменений.
- Зубастость: вернуть форму `method="get"` — тест разметки краснеет; убрать `exclude`-независимость
  (перезаписывать `picked` при перерисовке списка) — браузерный тест краснеет; сохранять `closes_at`
  как наивное время — тест про 20:59 UTC краснеет.

## Числовые инварианты
- Сценарий «2 вопроса → другая тема → ещё 20 → другая тема»: в наборе 2 (на бою сейчас 0).
- `total` API = `paginator.count` старой вьюхи на одинаковых фильтрах (проверить на 3 сочетаниях).
- Вхождений `boolean|single|multi|numeric` в HTML страниц учителя: 0.
- Запросов на `/teacher/game-sets/` не больше фиксированного потолка при 1 и при 20 наборах.
