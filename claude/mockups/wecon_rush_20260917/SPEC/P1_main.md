## Что делаем и почему

Главный экран Wecon Rush (`/game/`, секция `#screen-start` в `game/templates/game/game.html`)
пересобирается целиком. Решение владельца в Notion → «Решения»: **«Wecon Rush: главный экран
пересобрать как „стартовый экран аркады“ — одна кнопка „Играть“, без прокрутки на десктопе»**
(17.09.2026). Прочитай карточку: там обоснование и что убрано.

Суть: игра — автомат «выбрал режим → Играть → итог → ещё». Экран делится на три зоны:
**Забег** (переключатель режимов, детали выбранного, чипы фильтра, одна большая кнопка),
**Таблица / Статистика** (лидерборд следует за выбранным режимом), **Другие способы играть**
(четыре ячейки одной анатомии). Весь текущий функционал сохраняется — меняется только
структура и внешний вид. Ничего, что сейчас доступно на этом экране, потерять нельзя.

Визуальный источник истины — макеты в `claude/mockups/wecon_rush_20260917/`
(см. `README.md` там). Для этой сессии: `Main.dc.html` (аноним), `Student.dc.html`,
`Dark.dc.html` (варианты той же доски через props `who`, `theme`, `mode`), `Mobile.dc.html`.
Читай их как статичную спецификацию: разметка + CSS + данные из `renderVals()`; шаблонные
конструкции `{{…}}`, `<sc-if>`, `<sc-for>`, `<dc-import>` — просто состояния. Все цвета, кегли,
отступы, радиусы, тени бери оттуда; они собраны из `templates/_tokens.html` — в коде используй
`var(--…)`, а не хекс-значения, чтобы работала тёмная тема.

Что вне этой сессии (не трогать, но не сломать): экран раунда, итог раунда, дуэль, вызов дня,
наборы по коду, бесконечные тесты — они должны запускаться с нового стартового экрана так же,
как с текущего.

## ДОПОЛНЕНИЯ 17.09 (после разбора остальных экранов) — они главнее текста выше

1. **Ячейка «Вызов дня» в зоне C — живая** (вместо статичного «один набор на всех… / 4 набора, по
   одному на режим»). Строка сути: анониму — «4 вызова на сегодня · одна попытка на каждый»;
   вошедшему — «сегодня сыграно **N** из 4 · серия **K** дней» (при K = 0 — «сегодня сыграно N из 4»).
   Серая подпись справа от кнопки: «новый через 19 ч 48 мин» — остаток до московской полуночи
   (`game/daily.py: next_reset()`), клиент только рисует. Кнопка «Открыть» → `/game/daily/`.
   N и K отдаёт сервер в контексте страницы игры; функцию серии пишет фаза P4 (`daily.streak_for`) —
   в P1 заведи её заглушку-вызов так, чтобы P4 только наполнила, либо выполни P4.1 раньше.
   В макете это поля `dailyLine` / `dailyLeft`.
2. **Ячейка «Играть по коду» — проверка без перехода.** Сейчас `#code-form` делает
   `location.href = '/game/s/<код>/'`, и неверный код выкидывает игрока на общий 404 сайта
   (карточка в «Задачах»: «Игра по коду: неверный код ведёт на общий 404 сайта…»). Сделай
   `GET /game/api/set_check/?code=<код>` → `{exists: bool, url: str}` (нормализация кода — та же
   `make_code_lookup`; дуэль → её страница `/game/d/<код>/`, остальные → `/game/s/<код>/`).
   Нет набора — под полем строка 12.5px `--error`: «Набора с таким кодом нет. Проверьте код.»,
   у поля рамка `--error`, перехода нет; сообщение гаснет при вводе. Есть — переход по `url`.
   Лимит частоты — как у остальных публичных API игры (посмотри, чем они защищены).
3. **Параметры в адресе.** `/game/?mode=blitz` открывает главную с выбранным Блицем;
   `/game/?duel=blitz` — то же и сразу открывает существующее окно «Создать дуэль» с этим режимом
   (анониму — существующее окно «Дуэль только с аккаунтом»). Оба нужны публичной странице результата
   (фаза P6). Неизвестный режим — игнорировать; после разбора параметров адрес чистится
   (`history.replaceState`), чтобы обновление страницы не открывало окно снова.

## Числовые инварианты сессии
- `scrollHeight <= innerHeight` при 1440×800, аноним и ученик.
- Вкладок режимов: 4; медалей в таблице при ≥3 строках: 3; ячеек в полосе: 4.
- Нажатие `1` → `startRun` не вызван; `Enter` → вызван 1 раз.
- Число вопросов под фильтром в подписи вкладки = число, которое раньше стояло на карточке режима
  (тот же источник `poolCounts`).
- `manage.py check` = 0 проблем; затронутые тесты зелёные; новых тестов ≥ 6.
- Неверный код: 0 переходов, 1 сообщение под полем.
