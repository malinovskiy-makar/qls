# Зависимости

**Исходники** — `*.in`, правятся руками:

| Файл | Что описывает | Где ставится |
|---|---|---|
| `base.in` | боевой сервис, без ML | прод + все окружения |
| `local.in` | `base` + ML-стек эмбеддингов + `anthropic` | машина разработчика |
| `dev.in` | `base` + инструменты проверок | машина разработчика, CI |

**Локи** — `*.txt` с точными версиями, компилируются:

```bash
pip-compile requirements/base.in  -o requirements/base.txt
pip-compile requirements/local.in -o requirements/local.txt
pip-compile requirements/dev.in   -o requirements/dev.txt
```

⚠️ **Компилировать только на целевом Python 3.13.** `base.in` требует Django 5.2,
а он не ставится на Python 3.9 — лок, собранный на старом интерпретаторе, будет
и неполным, и неверным.

До перехода на 3.13 боевым локом остаются корневые `requirements.txt` и
`requirements-local.txt` — они описывают то, что реально стоит на проде сегодня.
Удалить их можно только после того, как `base.txt` соберётся и прогон на нём
пройдёт.

**Лок без хешей.** `pip-compile` без `--generate-hashes` фиксирует версии, но не
контрольные суммы: подмена пакета на зеркале так не ловится. Включить хеши стоит
одновременно с переходом на собственный сервер.
