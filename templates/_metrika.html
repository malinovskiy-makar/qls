{% comment %} Яндекс Метрика (ADR 0133): счётчик, цель регистрации и просмотр при смене экрана без перезагрузки. Стоит в КАЖДОГО корневого шаблона сайта; его пара `_metrika_noscript.html` — первой строкой . Номер — настройка YANDEX_METRIKA_ID через `config.context_processors.metrika`. Пусто (локально, площадка dev, тесты) — не выводится ничего. Код загрузки — из справки Метрики («Инициализация счетчика»). Параметры: Вебвизор включён (решение владельца), остальные — значения по умолчанию, выписанные явно, как их выписывает интерфейс Метрики. ⚠️ `metrika_private` передают кабинеты (репетитор, ученик, профиль и родитель, календарь, печатный листок): в заголовках их страниц стоят имена детей, а Метрика по умолчанию пишет заголовок каждой страницы. Справка Метрики сама велит в таком случае `sendTitle: false`. ⚠️ `metrika_goal` — ФУНКЦИЯ: она ЗАБИРАЕТ цель из сессии. Поэтому читается ровно один раз, через `with`, — так цель и срабатывает один раз на аккаунт. Скрипт вдобавок помнит метку цели в localStorage: страницу, открытую снова из кэша кнопкой «Назад», браузер исполнит заново, а второй цели быть не должно. ⚠️ `weco.metrikaHit` зовёт `static/track.js` из `trackPage()` — в той же точке «экран сменился без перезагрузки», что и своя аналитика беты («Стол», карта тем, «назад» по ним). Смена адреса через replaceState (фильтры, период статистики, чистка `?mode=`) просмотром НЕ считается: это тот же экран. По справке тег сам History API не отслеживает — для таких сайтов она велит звать `hit` вручную. {% endcomment %}{% if metrika_id %}{% with goal=metrika_goal %}{% endwith %}{% endif %}
