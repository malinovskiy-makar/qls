## Разведка Фазы 0.1 — НАСТОЯЩАЯ ПРИЧИНА (гипотеза промпта не подтвердилась)

**Гипотеза промпта:** «механика подпунктов наложилась на тесты, каждый
вариант стал пунктом со своим баллом». **Проверена и ОТВЕРГНУТА.**
`part_grading.applies(item)` возвращает `False` для любого теста (признак —
`item.is_test`), а `assignment_rows.answer_parts()` для теста отдаёт `[None]`
(вид ввода не `ANSWER_TEXT`). То есть тест в механику пунктов не заходит
вообще; `row['answer_parts']` у него пустой список.

**Настоящая причина — в другом месте и старше на две сессии.**
`student/views.py::auto_check_submission` (автопроверка КАТАЛОЖНОГО теста,
написана в эпоху «В2», до появления `AssignmentItem`) ставит балл
**жёстко зашитой единицей**:

```python
score = 1.0 if is_correct else 0.0     # ← максимум задачи не спрашивается
```

Максимум при этом везде читается из `AssignmentItem.points`
(`work_review._item_max`). В демо-данных у «все верные» `points=3`, у
«верно/неверно» `points=2` — отсюда «1 / 3 б.» и «1 / 2 б.» при полностью
верном ответе, а `work_summary` по правилу `score >= points → correct,
score > 0 → partial` честно печатает «ЧАСТИЧНО».

Комментарий «Верно ✓» пишет ТА ЖЕ функция — поэтому карточка и
противоречила сама себе: вердикт брался из проверки ответа, а состояние —
из сравнения балла с максимумом.

**Почему свои задачи репетитора не сломались:** соседняя
`auto_check_custom` написана уже в платформенной сессии и балл берёт
правильно — `max_points = float(item.points) if item.points is not None
else 1.0`. Один и тот же вопрос был решён в двух местах по-разному, и
устарело то, которое никто не трогал.
