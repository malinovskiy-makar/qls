## Разведка (Фаза 0, по факту кода)

### Что сломано на самом деле — найденные причины

**0.1. Два списка задач.** `student/views.py::assignment_detail` ходит по
`assignment.problems` (старый M2M) отдельным циклом и по `assignment.items`
(свои задачи) — отдельным. Отсюда два блока и два разных набора полей.
На стороне репетитора `teacher/views_groups.py::group_assignment_detail`
уже ходит ТОЛЬКО по `items` — то есть источник правды выбран, но ученик
до него не доехал. Позиций у старых домашек может не быть вовсе → нужен
бэкфилл.

**0.2. Комментарий ученика — вложенная форма.** Причина найдена чтением
разметки, а не гаданием: `<form class="pf-comment-form">` стоит ВНУТРИ
`<form method="post" action=".../submit/">` (страница домашки целиком —
одна форма отправки). Вложенные формы запрещены HTML — парсер браузера
выбрасывает внутренний `<form>`. Следствия ровно те, что видно на
скриншоте:
* селектор `.pf-comment-form` не находит ничего → обработчик отправки не
  навешивается → кнопка «Спросить» отправляет ДОМАШКУ, а не вопрос;
* правило `.pf-comment-form textarea { width:100%; min-height:56px }`
  не применяется (нет предка с этим классом) → крошечная коробочка
  браузера по умолчанию с обрезанной подсказкой.
У репетитора форма комментария НЕ вложена ни во что — потому и выглядит
нормально. Лечение: не форма, а `<div>` + кнопка `type="button"`.

**0.3. Два поля срока.** `Assignment.deadline` (историческое) и
`Assignment.due_at` (добавлено в 0023 для контрольной типа Б).
`student/views.py::dashboard` показывает `a.deadline` напрямую → у
контрольной с `due_at` выводится «без срока». Аксессор `deadline_at`
и хелпер `assignment_deadline()` уже есть, но применены не везде.
