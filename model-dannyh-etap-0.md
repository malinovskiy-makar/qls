# Модель данных платформы — Этап 0 (черновик v1)

Платформа для олимпиадной экономики (российской). Этот документ — «скелет»
будущего сайта: список сущностей (entities) и того, как они связаны. Его задача —
быть планом, который мы передадим в Claude Code, чтобы код строился по нему.

Тебе **не нужно** запоминать или понимать всё это сразу. Просто держи документ
под рукой — мы будем возвращаться к нему на каждом этапе.

---

## 1. Что показал источник (Задачник Бахарева)

Реальный источник сразу подсказал несколько важных решений по структуре:

- Это книга, собранная в LaTeX, 206 страниц.
- Иерархия материала: **глава (тема) → подраздел (подтема) → «Задача N»**.
- Сложность кодируется **звёздами** (`*`, `**`, `***`) — это «родная» шкала источника.
- У задач есть **подпункты (а), (б), (в)** — у каждого свой ответ.
- **Ответы лежат отдельным блоком** в конце каждой главы, по номеру задачи и подпункту.
- В этой книге есть условия + ответы, но **нет отдельного раздела «Решения»**.
- В условиях встречаются **формулы, математика и вложенные списки** (например,
  описания нескольких «цехов»), а также **графики** (КПВ, спрос/предложение).

**Решения по модели, которые из этого следуют:**

1. Поле «решение» (`solution`) делаем **необязательным** — часть источников даёт
   только ответы.
2. Сложность храним **двумя полями**: числовая шкала (например 1–5) + «родная метка»
   из источника (`*`, `**`…), чтобы ничего не терять при импорте.
3. «Условие» — это **не простой текст**, а форматированное содержимое (текст + LaTeX
   + изображения), чтобы пережить математику, списки и графики.

## 2. Сущности по этапам

Ниже каждая сущность описана простыми словами + указано, какие из твоих 20
требований она закрывает (например `[req 1]`).

### Этап 1 — Ядро контента

- **Problem (Задача)** — центральная сущность. Хранит общее условие, тип задачи,
  числовую сложность + родную метку, статус публикации, автора-владельца, даты.
  Статусы: `draft / needs_review / published / archived / hidden / duplicate`. `[req 3]`
- **ProblemPart (Подпункт)** — пункты а/б/в. У каждого своё условие, ответ, решение,
  подсказки и баллы. `[req 1]`
- **ProblemVersion (Версия задачи)** — снимок истории: условие, решение, теги,
  подсказки, параметры. Позволяет откатиться к прошлой версии. `[req 2]`
- **Source (Источник)** + **SourceReference (Привязка задачи к источнику)** — не
  только название и год, но и этап олимпиады, класс, номер задачи, страница, ссылка,
  исходный файл, заметка об авторских правах. `[req 4]`
- **Topic / Subtopic (Тема / Подтема)** — иерархия тем (как главы и подразделы в
  книге). Задача связана с одной или несколькими темами.
- **Tag (Тег)** — свободные метки.
- **FileAsset (Файл)** — единое хранилище для картинок, PDF, графиков, исходных
  файлов, вложений и решений учеников. `[req 14]`
- **User (Пользователь) + Role + Permission/Share** — права: owner, editor, viewer,
  student, public. Ученик не видит teacher-version, ответы и решения, пока
  преподаватель это не разрешил. `[req 5]`

### Этап 2 — Педагогический слой

- **Skill (Навык)** — отдельно от тем и тегов: построить график, решить систему,
  посчитать DWL, найти MR, проверить NE, написать интерпретацию и т.д. Прогресс
  ученика считается и по навыкам тоже. `[req 9]`
- **MistakeTag (Типичная ошибка)** — самостоятельная сущность, связанная с задачами,
  учениками и темами. `[req 10]`
- **Hint (Подсказка)** — упорядоченные подсказки, привязанные к задаче или подпункту. `[req 6]`
- **Rubric / RubricCriterion (Критерии оценивания)** — критерии по пунктам, для задач
  и для домашних заданий. `[req 8]`
- **TheoryPage (Мини-теория)** — раздел теории по темам: определения, формулы,
  типичные ошибки, связанные задачи и связанные графики. `[req 12]`

### Этап 3 — Цикл «ученик ↔ преподаватель»

- **Lesson (Занятие)** — конструктор занятия: цели, тайминг, warm-up, основные задачи,
  challenge-задачи, домашка после занятия, заметки преподавателя. `[req 11]`
- **Assignment / Homework (Домашка / назначение)** — набор задач, выданный ученикам.
- **Submission (Решение ученика)** — открытие назначенной задачи, написанное решение,
  загруженный файл/фото, какие подсказки открыты, отправленный ответ, статус. `[req 6]`
- **TeacherFeedback (Проверка)** — преподаватель ставит баллы, отмечает ошибки (ссылки
  на MistakeTag), пишет комментарий. `[req 7]`
- **Progress (Прогресс)** — прогресс ученика и по темам, и по навыкам. `[req 9]`

### Этап 4 — Импорт / экспорт / шаблоны / фон

- **ImportSession (Ручная нарезка PDF)** — выбор страниц, выделение условия/решения/
  ответа, crop картинок и графиков, сохранение ссылки на исходную страницу. `[req 13]`
- **Template (LaTeX-шаблон)** — редактор шаблонов: preamble, header, поля (margins),
  шрифты, нумерация, стили задач/ответов/решений, предпросмотр. `[req 17]`
- **Job (Фоновая задача)** — длинные операции идут через очередь: импорт, экспорт PDF,
  генерация графиков, AI-подсказки, дедупликация, генерация вариантов. `[req 15]`
- **Export (Экспорт)** — форматы: TeX, PDF, Markdown, DOCX, ZIP-архив, экспорт
  коллекции. `[req 20]`
- **Backup (Резервное копирование)** — полный экспорт базы задач, вложений,
  LaTeX-архива и JSON backup. `[req 16]`
- **Collection (Коллекция)** — сохранённый набор задач (для экспорта и шеринга).

### Этап 5 — Интеллект

- **AnalyticsEvent (Аналитика использования)** — какие задачи открывают, сохраняют,
  добавляют в домашки, где ученики открывают подсказки, какие темы чаще проваливаются. `[req 18]`
- **SimilarityEngine (Движок похожих задач)** — поиск похожих по теме, подтеме, тегам,
  навыкам, сложности, типу задачи, источнику и по text similarity. Кнопки: найти легче,
  найти сложнее, найти похожую из другой олимпиады, заменить в домашке похожей. `[req 19]`

## 4. Открытые вопросы (на них ответишь — уточню модель)

1. **Решения.** Будут ли у задач часто полноценные решения, или в основном только
   ответы? (Модель уже допускает отсутствие решения, но это влияет на интерфейс.)
2. **Предметы.** Только экономика — или позже добавятся математика / другие предметы?
   Если да, «Subject (Предмет)» стоит сделать сущностью верхнего уровня.
3. **Сложность.** Оставляем единую числовую шкалу (1–5) + родную метку источника (`*`)?
4. **Пользователи на старте.** Кто будет в системе сначала — только ты + твои ученики?
   Публичный доступ нужен сразу или это задача на потом?
