# Правила команд импорта и массовых правок

Локальные правила для `problems/management/commands/` (около 155 команд).
Общие запреты — в корневом [CLAUDE.md](../../../CLAUDE.md).
Состояние банка и конвейеры — в [docs/DATA.md](../../../docs/DATA.md).

---

## Главное правило

> **Существующие `statement` / `answer` / `solution` моделью не переписываются.**

Свип Батча 2 испортил 233 поля в 195 задачах — 13,2% затронутого
([ADR 0005](../../../docs/adr/0005-ai-writes-new-fields-only.md)). Механические
правки текста делает **детерминированный код** по явным правилам: он проверяем,
идемпотентен и объясним построчно. Модель дописывает новые поля.

---

## Обязательный конвейер

Любая команда, которая пишет в банк массово:

1. **`--dry-run` по умолчанию.** Боевой прогон — отдельным флагом
   (`--apply` / `--confirm`), а не отсутствием `--dry-run`. Случайный запуск без
   флага должен ничего не делать, а не всё сделать.
2. **Счётчики до и после** в выводе. «Готово» без чисел — не отчёт.
3. **Выборочный предпросмотр.** HTML-файл с парами ДО/ПОСЛЕ, открываемый глазами.
4. **Стоп-гейт владельца** перед боевым прогоном.
5. **Бэкап.** Снимок изменяемых полей (JSON id → старое значение) плюс копия базы.
6. **Проверка идемпотентности.** Повторный `--dry-run` обязан дать ноль. Это не
   формальность: так ловятся правила, которые «доедают» текст на втором проходе.

Обратимый журнал важнее скорости. Команда без бэкапа — это команда, ошибку
которой нельзя отменить.

## Импорт

Общая схема: разбор источника → нормализация текста → дедупликация по
`content_hash` (MD5 условия) → запись со `status='draft'` или `published` в
зависимости от доверия к источнику → `SourceReference` со ссылкой на оригинал.

- **Нормализация — ДО хэша.** Иначе один и тот же текст с разными пробелами даёт
  разные хэши, и дедупликация не работает.
- **Не доверяйте источнику по умолчанию.** Материалы сомнительного качества
  идут `draft`; `published` — осознанное решение про конкретный источник.
- **`grade` живёт у `SourceReference`**, а не у задачи.
- Подпункты адресуются **по pk**, а не по метке: метки не уникальны — в одной
  выборке нашлось 34 пары дублей «а».

## Ловушки, на которых уже подрывались

⚠️ **SQLite и вложенные savepoint.** `IntegrityError` внутри общей транзакции
отравляет родительский savepoint. Каждое рискованное создание (например тега со
слагом, который может совпасть) заворачивается в собственный
`transaction.atomic()`.

⚠️ **Эмбеддинги после правки текста.** Изменили `statement` или подпункты —
пересчитайте эмбеддинги изменённых id. И помните про ловушку done-файла:
`night_embeddings` **молча пропустит** id, который уже там записан, и напишет
«осталось 0». Порядок — сначала вычистить id из done-файла, потом запускать.
Подробности — [docs/EMBEDDINGS.md](../../../docs/EMBEDDINGS.md).

⚠️ **Прод: `bulk_load_fixtures` только вставляет.** `ignore_conflicts=True` молча
пропускает существующие по pk записи — правки в существующих задачах так на прод
**не попадают**. Для обновления — `update_prod_problems`.
См. [docs/RUNBOOK.md](../../../docs/RUNBOOK.md).

⚠️ **Отставшие sequence в PostgreSQL.** Заливка с явными id не двигает счётчик
таблицы; следующая вставка без id получает занятый номер. На SQLite не
воспроизводится, поэтому локально не видно.

⚠️ **Кодировка на Windows.** Читаете и пишете файлы — указывайте
`encoding='utf-8'` явно. Локаль на Windows cp1251, и без явной кодировки
кириллица превращается в кашу молча.

## Проверка формул

Считать поле сломанным по текстовым признакам **нельзя**: предфильтр к ошибкам
KaTeX слеп — выборка из 100 «чистых» по признакам полей дала 3 с выросшим числом
ошибок рендера. «Сломанная формула» — то, что решил KaTeX.

Конвейер рендера в проверке обязан **дословно** повторять боевой из
`catalog/base.html`: маскировка `\$`, те же разделители, `$$` раньше `$`,
`throwOnError: false`. Любое отличие превращает замер в фикцию.
