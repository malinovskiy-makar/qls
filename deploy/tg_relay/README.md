# Посредник Telegram: инструкция для Андрея

Зачем это. С нашего боевого сервера Telegram не открывается (28.10.2026: `curl https://api.telegram.org/`
– `Connection timed out`). Без Telegram бот стены не может ни получить «Старт», ни проверить подписку.
Решение владельца 28.10: маленький **свой** сервер за рубежом, который пересылает запросы бота в
Telegram. Наш сервер ходит на него (`TELEGRAM_API_BASE`), он – в Telegram. Входящих соединений от
Telegram к нам не нужно: бот сам спрашивает новые сообщения (служба `tgbot`).

Время: около часа. Нужны: карточка для оплаты VPS, доступ к DNS у регистратора (Spaceship), доступ к
боевому серверу, токен боевого бота `@weconomics_bot` (его даёт Макар).

В командах ниже **подставляйте свои значения** вместо слов `ВАШ_IP_ПОСРЕДНИКА`, `IP_НАШЕГО_СЕРВЕРА`,
`ваш@адрес`. Имя посредника в примерах – `tg.weconomics.ai`; если выберете другое, меняйте везде.
Команды выполняйте по одной; после каждой написано, что вы должны увидеть. Увидели другое –
остановитесь и напишите Макару, не продолжайте.

## 0. Что нужно знать про безопасность

⚠️ **Через посредника идёт токен бота** (он в адресе каждого запроса) и номера Telegram учеников.
Поэтому:

- доступ к посреднику – **только у вас**, никому не давайте ключ и пароль;
- журнал запросов на нём **выключен** – не включайте его, ни на минуту: в нём был бы токен;
- посредник пускает **только наш боевой сервер** (по IP); чужим отвечает «403»;
- если токен или доступ к посреднику могли попасть не туда – Макар перевыпускает токен в BotFather
  (`/revoke`), вы меняете его в `.env` на боевом сервере.

## 1. Какой сервер арендовать

Любой недорогой VPS **вне России** с оплатой в рублях: Ubuntu 24.04, 1 ядро, 512 МБ–1 ГБ памяти, 10 ГБ диска.
Нагрузка ничтожная (сотни запросов в час).

**До оплаты, на самом сервере**, проверьте, что оттуда открывается Telegram. Войдите по SSH (данные
пришлёт хостер) и выполните:

```bash
curl -sS -m 10 -o /dev/null -w "%{http_code}\n" https://api.telegram.org/
```

Должно быть **число** (обычно `302` или `200`). Написало `timed out` – сервер не подходит, смените
хостера или страну (Нидерланды, Германия, Финляндия подходят).

## 2. Закрыть вход, кроме ключа SSH

Сначала убедитесь, что вы вошли **по ключу**, а не по паролю (в панели хостера при создании сервера
укажите свой публичный ключ). Затем:

```bash
printf 'PasswordAuthentication no\nPermitRootLogin prohibit-password\n' > /etc/ssh/sshd_config.d/00-keys-only.conf
```

Имя файла начинается с `00-`: на Ubuntu облачный образ кладёт свой файл с разрешением пароля, и важно, чтобы
наш прочитался раньше.

```bash
sshd -t && systemctl reload ssh
```

Ничего не напечатает – это нормально. **Не закрывайте текущее окно**, откройте второе и войдите по ключу.
Только если вошли – продолжайте.

```bash
sshd -T | grep -i passwordauthentication
```

Должно быть: `passwordauthentication no`.

Файрвол (`ufw`) – пускаем только 22, 80 и 443:

```bash
ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp
```

```bash
ufw --force enable && ufw status
```

В списке должны быть три строки `ALLOW` – 22, 80, 443.

Автоматические обновления безопасности (чтобы сервер не забыть):

```bash
apt update && apt install -y unattended-upgrades
```

## 3. DNS

У регистратора (Spaceship), в зоне `weconomics.ai`, создайте запись:

| Тип | Имя | Значение |
|---|---|---|
| A | `tg` | `ВАШ_IP_ПОСРЕДНИКА` |

Проверка с вашего компьютера (через 5–30 минут после создания записи):

```bash
dig +short tg.weconomics.ai
```

Должен напечатать `ВАШ_IP_ПОСРЕДНИКА`. Пусто – подождите ещё, не продолжайте.

Запись должна быть **только A** (без AAAA): наш сервер приходит по IPv4.

## 4. Nginx и сертификат

Установка:

```bash
apt install -y nginx certbot
```

Уберите страницу nginx «по умолчанию» и заведите каталог для проверки сертификата:

```bash
rm -f /etc/nginx/sites-enabled/default && mkdir -p /var/www/certbot
```

**Шаг 4а. Временная настройка только для получения сертификата** (весь блок целиком – это одна команда):

```bash
cat > /etc/nginx/sites-available/tg_relay <<'EOF'
server {
    listen 80 default_server;
    server_name _;
    location /.well-known/acme-challenge/ { root /var/www/certbot; }
    location / { return 444; }
}
EOF
```

```bash
ln -sf /etc/nginx/sites-available/tg_relay /etc/nginx/sites-enabled/tg_relay && nginx -t && systemctl reload nginx
```

Должно быть: `syntax is ok` и `test is successful`.

Сертификат (подставьте свою почту – на неё придёт предупреждение, если продление сломается):

```bash
certbot certonly --webroot -w /var/www/certbot -d tg.weconomics.ai -m ваш@адрес --agree-tos --no-eff-email
```

Должно быть: `Successfully received certificate` и путь `/etc/letsencrypt/live/tg.weconomics.ai/`.
Ошибка «Timeout during connect» – DNS ещё не обновился (шаг 3) или не открыт порт 80 (шаг 2).

**Шаг 4б. Настоящая настройка.** Файл `deploy/tg_relay/nginx.conf` лежит в репозитории, ветка
`feat/vp-wall-20261029`. С компьютера, где у вас скачан репозиторий, скопируйте его на посредника:

```bash
scp deploy/tg_relay/nginx.conf root@ВАШ_IP_ПОСРЕДНИКА:/tmp/tg_relay.conf
```

На посреднике подставьте два значения (в файле они записаны метками `__RELAY_HOST__` и `__OUR_SERVER_IP__`):

```bash
sed -e 's/__RELAY_HOST__/tg.weconomics.ai/g' -e 's/__OUR_SERVER_IP__/IP_НАШЕГО_СЕРВЕРА/g' /tmp/tg_relay.conf > /etc/nginx/sites-available/tg_relay
```

`IP_НАШЕГО_СЕРВЕРА` – внешний IPv4 боевого сервера (Selectel). Если не помните, на боевом сервере:

```bash
curl -4 -sS https://ifconfig.me
```

Проверьте и включите:

```bash
grep -c "__" /etc/nginx/sites-available/tg_relay
```

Должно быть `0` (ни одной неподставленной метки).

```bash
nginx -t && systemctl reload nginx
```

Должно быть: `syntax is ok` и `test is successful`.

Автопродление сертификата ставится вместе с certbot. Проверьте:

```bash
certbot renew --dry-run
```

В конце: `all simulated renewals succeeded`.

```bash
systemctl list-timers | grep certbot
```

Должна быть строка с `certbot.timer`.

## 5. Проверка

**С самого посредника** (его адрес в списке разрешённых нет – должен быть отказ):

```bash
curl -sS -m 10 -o /dev/null -w "%{http_code}\n" https://tg.weconomics.ai/
```

Должно быть `403`. То же самое будет с любого другого адреса.

**С нашего боевого сервера** (по SSH, как обычно):

```bash
curl -sS -m 10 -o /dev/null -w "%{http_code}\n" https://tg.weconomics.ai/
```

Должно быть **число, но не `403` и не `timed out`** (обычно `302` или `200` – это ответ Telegram).

- `403` – наш IP в настройке не тот: проверьте `curl -4 -sS https://ifconfig.me` на боевом сервере и
  повторите шаг 4б с правильным адресом.
- `timed out` – не открыт порт 443 (шаг 2) или DNS (шаг 3).
- `502` – с посредника не открывается Telegram; повторите проверку из шага 1 на нём. Если Telegram сменил
  адрес, а nginx держит старый: `systemctl reload nginx`.

## 6. Настроить боевой сервер

В файле `/srv/weconomics/.env` на **боевом** сервере добавьте (токен и секрет без пробелов и кавычек):

```
TELEGRAM_API_BASE=https://tg.weconomics.ai
TELEGRAM_BOT_TOKEN=<токен @weconomics_bot от Макара>
TELEGRAM_BOT_USERNAME=weconomics_bot
TELEGRAM_WEBHOOK_SECRET=<длинная случайная строка>
```

Адрес `TELEGRAM_API_BASE` – без слэша на конце и обязательно `https://`. Секрет нужен, даже когда вебхука
нет (без него путь Telegram считается ненастроенным); получить его:

```bash
python3 -c "import secrets;print(secrets.token_urlsafe(32))"
```

Дальше – «Выкатка стены – по шагам» в [docs/VP.md](../../docs/VP.md) (пересоздать `web`, `tg_setup --ping`,
включить `tgbot`). **`.env` никому не пересылайте и в чаты не вставляйте.**

## Если не работает

| Что видите | Что делать |
|---|---|
| `tg_setup --ping` на боевом сервере: `timed out` | шаги 5 и 3: сначала `curl` из шага 5 с боевого сервера |
| `tg_setup --ping`: `403` | IP боевого сервера в `allow` не тот (шаг 4б) |
| в логе `tgbot` постоянные «пауза 60 с» | та же причина; пока посредник недоступен, стена пускает по почте |
| `certbot renew --dry-run` не проходит | порт 80 закрыт или `nginx.conf` изменён: должен быть блок `/.well-known/acme-challenge/` |
| сервер посредника пропал/сменился IP | новый сервер по шагам 1–5, запись `A` обновить; боевой `.env` не меняется |

Посредник – только пересылка: у него нет базы, нет данных и нет ничего, что надо резервировать. Потеряли –
подняли новый за тот же час.
