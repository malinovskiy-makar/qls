# CLAUDE.md — рабочая память проекта (техническая)

Платформа задач по олимпиадной экономике (российской). Этот файл — **актуальный
рабочий контекст** для сессий Claude Code: стек, структура, модели, команды,
текущее состояние, рабочие памятки и ближайшие планы.

**Где что лежит (важно):**
- `CLAUDE.md` (этот файл) — ТОЛЬКО техника: стек, структура, модели, команды,
  движки, деплой, дизайн-токены, известные ловушки. Держим коротким.
- **Notion-штаб** — ВСЁ остальное: задачи, баги, идеи, решения, результаты,
  стратегия, дорожная карта.
  Главная: https://app.notion.com/p/39ab11c92bc181f7bbe1efa8a89e38a9
- `CLAUDE_ARCHIVE.md` — история завершённых сессий. Справка «как это было сделано».
- `STRATEGY.md`, `PRODUCT.md` — ЗАМОРОЖЕНЫ. Актуальные версии — в Notion.
- `DESIGN.md` — живой, техническая дизайн-система. В Notion лежит зеркало.

**Правило: одно и то же не пишем в двух местах.** Планы, статус, баги и
обоснования решений — только в Notion. Техника — только здесь.

Преподаватель (не программист) ведёт проект и принимает решения; код пишет Claude
Code. Объяснять простыми словами, комментарии в коде — по-русски.

## Стек

- Python **3.9** + Django 4.2 (LTS) + SQLite локально / **PostgreSQL на проде**.
- Проект: `config/`. Основное приложение: `problems/`. Локальная база — `db.sqlite3`.

- Виртуальное окружение в `./venv/`. Все команды — через `./venv/bin/python manage.py …`.

⚠️ **Совместимость Python 3.9.** Синтаксис `int | None` (union через `|`) появился
только в 3.10 и даёт `TypeError` при импорте. Всегда использовать
`from typing import Optional` → `Optional[int]`. Никогда не писать `int | None`.

## Движки и команды (всё локально, без внешнего API)

**Эмбеддинги (семантика):**
- Модель **`BAAI/bge-m3`** (sentence-transformers, русский, CPU, ~1.4 ГБ). Имя
  вынесено в единую константу `EMBEDDING_MODEL_NAME` в `problems/embedding_config.py`
  — все команды и поиск обязаны импортировать оттуда.
  ✅ Полный пересчёт на BGE-M3 выполнен 2026-07-04: **31 472 вектора**, кэш похожих
  перелит (105 245 связей). Лог — `reports/recompute_2026-07/recompute.log`,
  замер «после» — `reports/bge_benchmark/after_bge_m3.txt`.
  ⚠️ На Mac с BGE-M3 обязательно `--device cpu`; на 8 ГБ RAM — `--encode-batch 8`.
- `build_embeddings` — строит эмбеддинги батчами. `--limit N` (первые N без
  эмбеддинга), `--reset` (пересчитать все).
- `night_embeddings --ids-file <файл>` — пересчёт по списку id (см. ловушку ниже).
- `find_similar --problem-id N --limit 10` — топ-N похожих по косинусу.
- `cache_similar` — заливает похожие в M2M `similar_problems` (прод работает по кэшу,
  без модели).

**Дедупликация:** `find_duplicates` — `--threshold 0.95` (по умолч.), `--reset`.
Заполняет `DuplicateCandidate`; разметка через админку (подтвердить/отклонить).

**Темы:** `auto_assign_topics` (kNN по эмбеддингам, порог 0.70), `apply_topic_mapping`
(21 каноническая тема).

**Шлюз качества:** `quality_gate --apply` / `--revert` (обратимый). Детекторы читаются
из `reports/quality_audit/gate_*.txt` и смежных. Прячет зафлагованные задачи из
публичной выдачи (`needs_quality_review`).

## Как строятся эмбеддинги

**Формула `problem_to_text`** (в `build_embeddings.py`), 7 блоков:
`title` + `statement[:500]` + подпункты `ProblemPart.statement` (≤500 символов
суммарно) + `«Темы: …»` (канонические, кроме технической «Тест») + `«Навыки: …»`
+ `ai_blurb[:400]` (суть из Батча 1) + `«Теги: …»` (только канонические из
`CANONICAL_TAG_NAMES`). Решение и ответ в отпечаток НЕ входят. Пустые блоки не
добавляются. Требует `prefetch_related('parts', 'topics', 'skills', 'tags')`.
Все 31 472 эмбеддинга в базе посчитаны именно этой формулой (пересчёт 2026-07-04).

⚠️ **Ловушка done-файла (ВАЖНО).** `night_embeddings` вычитает из очереди все id, уже
записанные в `reports/night_session/embeddings_done_ids.txt`. Если у задачи изменился
текст, но её id уже в done-файле — повторный запуск **молча пропустит её** (вывод
«осталось 0» обманчив). Флага `--force` нет. Правильный порядок:
1. Удалить нужные id из done-файла.
2. Запустить `night_embeddings --ids-file <файл>`.

```bash
# Удалить id из done-файла перед пересчётом:
python3 -c "
parts = set(open('ids_to_recompute.txt').read().split())
kept = [l for l in open('reports/night_session/embeddings_done_ids.txt') if l.strip() not in parts]
open('reports/night_session/embeddings_done_ids.txt', 'w').writelines(kept)
print('removed', len(parts))
"
```

После любого патча, меняющего `statement` или `parts`, обязательно пересчитать
эмбеддинги изменённых id (иначе поиск похожих хуже для разбитых задач).

## calc2 — собственный графический движок

Стратегия: свой движок на открытых библиотеках вместо переламывания Desmos.
Старый Desmos (`graphs/`, `/desmos/`) НЕ тронут.

**Стек:** D3.js v7 (рисование SVG, оси, перетаскивание) + Math.js 12.4.3 (разбор/
вычисление формул, численные методы). Без npm/сборки — всё в одном шаблоне через
`<script src>`. Приложение `calc2`, страница `/calc2/` (`Calc2View`, TemplateView,
`@login_required`), шаблон `calc2/templates/calc2/calc2.html`. **Моделей/миграций
НЕТ** (сохранение графиков — будущее).

**Принципы:**
- Кривые задаются как **P = f(Q)** (Math.js принимает Q и x). Только первая четверть
  (Q≥0, P≥0); оси/сетку рисуем сами через D3; кривые/заливки обрезаются `clipPath`.
- Вся экономика **численная**: равновесие D=S — сканирование сетки + **бисекция**;
  площади CS/PS — **метод трапеций** (∫), а не формула треугольника. Так нелинейные
  кривые работают без переписывания.

**Сцены/режимы:** равновесие, налог/субсидия, потолок/пол, монополия (с областями),
издержки фирмы, КПВ (одна и сумма двух стран), торговля (КТВ), рынок труда (с МРОТ),
неравенство. Редизайн «Окно сценариев + рабочее место Сцена».

**Живой пульт (ветка `feat/calc2-live-pult`, готова к слиянию):** панель
«Инструменты» свёрнута по умолчанию; ключевые регуляторы — в горизонтальной
ленте-пульте `#pult` у нижнего края графика. Перетаскиваемые панели (`makeDockable`),
реестровый перенос DOM-узлов (`syncPultRegulators` — `appendChild`, не clone, чтобы
сохранить listeners). Слайдер пульта и drag кривой используют один сеттер
`setCurveFreeTerm`. Слайдеры строятся только для линейных кривых (`c.linear !== null`).
Плавность осей — `animateRanges` (твин через requestAnimationFrame, ~0.45с),
дебаунс/тротл, уважается `prefers-reduced-motion`. Frosted-glass панели.

**Как проверять без браузера:** `manage.py check` (0 ошибок) + рендер `/calc2/` → 200.
JS-математика — node-харнесс: извлечь инлайн-скрипт, подгрузить с заглушками DOM/D3 и
настоящим Math.js, вызвать реальные функции (`findEquilibrium`/`integrate`/`recompute`)
на контрольных числах. Тесты математики — в `calc2/tests/calc2_math.mjs`.
**Визуальную проверку (перетаскивание, заливки, темы) всегда делает преподаватель
в браузере.** «Тесты зелёные» доказывают математику, НЕ внешний вид.

**Контрольные числа (эталон математики):** `100-Q`@30=70; равновесие D:100-Q,S:Q →
Q*=50,P*=50; нелинейное D:100-Q,S:Q²/100 → Q*≈61.80; CS=PS=1250; налог t=20 →
Q1=40,Pb=60,Ps=40,Tx=800,DWL=100; субсидия s=20 → Q1=60,расход −1200,DWL=100.

## Econ Rush — игра на скорость (`game`, `/game/`, ветка `feat/game-modes`)

Публичная (без логина) игра-таймер по тестовым вопросам — инструмент привлечения.
**Четыре режима** (как контроли времени в шахматах), параметры — `game/config.py::MODES`
(значения = предмет тюнинга):

| Режим | Ключ | Тип вопроса | Время | Верно | Неверно | Скип |
|---|---|---|---|---|---|---|
| Пуля | `bullet` | `boolean` — данетка Верно/Неверно | 60 с | +2 с | −5 с | −2 с |
| Блиц | `blitz` | `single` — один из вариантов | 120 с | +5 с | −5 с | −3 с |
| Рапид | `rapid` | `multi` — несколько из вариантов | 300 с | +15 с | −15 с | −5 с |
| Классика | `classic` | `numeric` — числовой ответ вводом | 600 с | +30 с | −10 с | −5 с |

Очки одинаковые во всех режимах: 100×комбо-множитель (×2/×3/×4 на сериях 3/6/9).
Неверный ответ рвёт комбо; **скип комбо НЕ рвёт**. Рапид засчитывается только при
полном совпадении множества выбранных с правильным. Классика: точное равенство
значений через `fractions.Fraction` (`views.py::parse_exact_number` — целые,
десятичные с запятой/точкой, дроби a/b; 0,1 = 0.1 = 1/10 верно, 1/3 ≠ 0.33;
мусорный ввод = неверно, не 500).

- **`GameQuestion`** (кэш, пересобирается `build_game_pool`, контент-таблицы не
  трогаются): FK на Problem (+ nullable FK `part` — задел под данетки-пачки,
  `UniqueConstraint(problem, part)`), `question_type`, `options`,
  `correct_index` / `correct_indices` / `correct_value` (по типу), difficulty
  (в основном эвристика), темы денормализованы, `lang`; `stage`/`year`/`grade`
  заполнены у вопросов ВсОШ (денормализовано из `SourceReference`) — задел под
  фильтр «только регион».
- **Пул (локально, после пере-импорта ВсОШ 2026-07-13): 2 917** — boolean 380
  (ru), single 2 225 (ru 801 + en 1 424, en в игре не используется), multi 248
  (ru), **numeric 64 (ru) — «Классика» жива**; источник numeric — тесты
  ВсОШ-регион 2016–2025 (см. «Импорт ВсОШ-регион»). Вопросов с заполненными
  `stage`/`year`/`grade` (ВсОШ) в пуле: **165** — задел под фильтр «только
  регион». Таблицы (реконструированные `$$\begin{array}…$$`) и кусочные
  функции (`\begin{cases}…\end{cases}`) не бракуются — часть таких вопросов
  вошла в пул (numeric-тип с лимитом длины 700), часть отсеялась по общему
  лимиту длины (300 у boolean/single/multi) из-за длинного условия сценария —
  это НЕ связано с таблицей/cases как таковыми (проверено: даже после замены
  таблицы/cases на плейсхолдер условие всё равно длиннее лимита).
  Разведка данеток (`reports/game_modes/01_boolean_recon.md`): пачек с разметкой
  по подпунктам в базе НЕТ — «тест: верно/неверно» это одиночные утверждения
  (текст в `statement`, подпункты = варианты Верно/Неверно), конвертация 1:1;
  «тест: все верные» → multi, буквы `Problem.answer` через `normalize_label`,

- **Схлопывание повторов на сборке пула** (`build_game_pool.py::pool_dedup_key`/

  numeric — одинаковый текст с разным числовым ответом это разные вопросы, не
  дубликат). Совпадение ключа → побеждает более свежий `year`, при равенстве —
  меньший `problem_id`; проигравший считается в `duplicate_in_pool` и не
  попадает в пул. При пере-импорте ВсОШ 2026-07-13 схлопнуто **84** повтора
  (в основном межгодовые повторы вопросов ВсОШ, см. «Хвосты» ниже). Тесты —
  `PoolDedupTests` в `game/tests/test_game.py`.
- API: `session/start?mode=&topic=` (без mode — blitz; неизвестный — 400;
  тайминги режима в ответе), `question`, `answer` (POST: `{question_id,
  choice|choices|value}` по типу, null/отсутствие = скип; повтор = 409).
  Анти-чит: правильный ответ (`correct_*`) НИКОГДА не входит в payload
  вопроса — только в ответ на ответ. Числовой вопрос (Классика) несёт `unit`
  в payload, если у задачи есть единица ответа (напр. «%»).
- **Выдача — случайная, но «сначала невиданные»** (прогрессии сложности больше
  нет): session-ключ `econ_rush_seen` `{mode: [id…]}` живёт МЕЖДУ забегами
  (последние 1500 id на режим); пул режима исчерпан → список чистится, цикл
  по кругу. Внутри забега повторы исключены строго.
- **Клавиатура — первична:** 1–5 ответ (в рапиде — переключение выделения,
  Enter — отправить), пробел пропуск, Enter старт/ещё раз; в классике ввод
  в поле (`inputmode=decimal`, символы `0-9 , . / -`), Enter — отправить.
  Рекорды — localStorage `econ_rush_best_<mode>` (старый общий ключ мигрирует
  в блиц). Слой токенов `--rush-*`; полоса времени малиновый→амбер(<15с)→
  красный(<7с) — задокументированное исключение из «сигналы священны».
- Тесты: `game/tests/test_game.py` — 81 (извлекатели по типам, parse_exact_number,
  4 режима, multi/numeric-проверки, анти-чит, «невиданные», дедуп пула).
- **Не сделано:** звук; глобальный лидерборд (рекорд только локальный);
  деплой (ветка не в `main` — решение о выкатке за преподавателем);
  английская часть пула не используется; фильтр «только регион» в UI (данные
  в пуле уже есть — `stage`/`year`/`grade` заполнены у 165 вопросов).
- **Планы:** возврат вопросов с ошибками, ежедневный вызов, рандомизация
  чисел в классике, фильтр «только регион» в UI.

## Импорт ВсОШ-регион (тесты первого тура) — ✅ 2016–2025 в базе, пере-импорт 2026-07-13

Все 10 годов регионального этапа импортированы: **218 задач** (после
вычитки и пере-импорта 2026-07-13; исходно было 225 — см. «Почему 225→218»
ниже), Source «ВсОШ — региональный этап» (id=25) один на все годы, различие
в `SourceReference` (year/grade/problem_number/url). Списки id — в
`materials/vsosh_region/<год>/imported_ids.txt`; главные отчёты —
`reports/vsosh_region/proofread_summary.md` (вычитка 257 вопросов, 25
mechanical-фиксов, 0 расхождений ответа) и `reports/vsosh_region/
structure_audit.md` (таблицы/cases/подписи графиков, см. ниже).

**Конвейер года:** PDF (качает преподаватель вручную — сеть машины к
российским сайтам заблокирована) → нормализация имён `test_answers_<кл>.pdf`
→ при битой кодировке `fix_vsosh_tounicode --year N` → `parse_vsosh_region
--year N` (span-парсинг PyMuPDF: правильный вариант = полужирный маркер;
типы boolean/single/multi/numeric; LaTeX с восстановлением этажных дробей,
кусочных функций и реконструкцией таблиц — см. ниже) → `preview_vsosh_region`
(HTML с KaTeX) → `check_vsosh_gates` (шлюзы: unparsed ≤3 и ≤10%, диапазон
12–60, валидность ответов, парность $/{}) → `import_vsosh_region --year N
[--confirm]` (двухфазная; дедуп = условие **плюс варианты**, точное
совпадение нормализованного текста против ВСЕЙ базы — генерические стемы не
съедают новые вопросы, но и настоящие межисточниковые дубли не плодятся).
Правило «ничего не выдумывать»: неоднозначный ответ/тип/нерасшифрованный
глиф → вопрос в unparsed.

**Годоспецифика вёрстки (профили в `parse_vsosh_region.PROFILES`):**
- 2020–2023 `zadanie`: секции «Задание N», данетки в №1, numeric в №4;
  у 2021 в конце сетка «Правильные ответы» (стоп-строка).
- 2016–2019 `chast_flat`: секции «Часть N» со старыми типами и СКВОЗНОЙ
  нумерацией вопросов 1–20 (защита: номер = предыдущий + 1).
- 2024–2025 `chast`: «Часть N», без данеток, numeric в №3, «Часть 4» —
  задачи второго тура (стоп-секция, не тест).
- Общие файлы: 2016–2017 один PDF на 9–11; 2018–2020 один на 10–11
  (копия файла в слоты классов, merge схлопывает в `grades`).

**Битые кодировки (`fix_vsosh_tounicode`):** PDF 2024 (весь) и 2021 (11
класс) — CID-шрифты без ToUnicode / с врущим ToUnicode, текст извлекается
кракозяброй. Референсные карты глиф→юникод снимаются `texttrace` с 2023/2025
(те же Libertinus, Identity-H ⇒ код = глиф оригинала), в PDF вписываются
корректные CMap; недостающие глифы размечены вручную в `MANUAL_GLYPHS`
(каждый проверен по рендеру страницы). Ловушки: texttrace обрезает имена
шрифтов ~31 симв. (SemiboldItalic маскируется под Semibold — лечится
italic-битом flags); непокрытые глифы MuPDF отдаёт как chr(gid), и мусор
маскируется под ASCII — фиксер принудительно маппит их в U+FFFD, а парсер
отправляет такие вопросы в unparsed. Литеральный доллар (валюта) хранится
как `$\$$` — KaTeX рендерит знак, голые $ спаривались бы в псевдоформулу.

**Вычитка (257 вопросов, `proofread_summary.md`):** узкая построчная сверка
всех вопросов против PDF по классам дефектов (винкулум-гард, глифы,
курсив-сдвиг, дроби только при наличии черты, подписи осей, гомоглифы,
задвоенные знаки и т.п.) — 25 mechanical-находок починены, 0 расхождений
ответа. Отдельным заходом — **структурный класс** (`structure_audit.md`):
вычитка на битые символы пропускала таблицы/списки, размазанные PDF-парсером
в строку («валидный» текст, KaTeX не ругается):
- **Таблицы** (`extract_tables`/`reconstruct_table`/`apply_tables` в
  `parse_vsosh_region.py`): распознаются по геометрии PDF (горизонтальные
  линейки booktabs), реконструируются в `$$\begin{array}{|l|c|…|}\hline…$$`
  (формат Б — LaTeX-массив, а не HTML `<table>`: `problem_detail.html` не
  использует `|safe`, HTML-тег показался бы текстом; массив едет по
  существующему KaTeX-конвейеру везде без правки шаблонов). Реконструировано
  **4** таблицы (2018 №12, 2022 №3.2 и №4.5, 2025 №3.2). Игра больше не
  бракует вопрос с реконструированной таблицей (`\begin{array}` в
  `TALL_MATH_ENVS`, `\hline` внутри массива не путается с псевдотаблицами).
- **Кусочные функции** (Класс В, `_assemble_cases` в `postprocess_text`):
  литеральная уплощённая `\{значение1, условие1; значение2, условие2.`
  собирается в `\begin{cases}…\end{cases}` (признак — открытая `\{` без
  `\}`, ветви через `;`, каждая «значение, условие»; множество `\min\{A,B\}`
  со `\}` не трогается). Собрано **5** записей (4 вопроса: 2020 №4.3, 2021
  №3.5[9]/[10,11], 2022 №3.4[9]). `cases` уже в `TALL_MATH_ENVS` — игра
  берёт такие вопросы.
- **Подписи осей графика** (Класс Г, `drop_figure_labels`/
  `_polyline_figure_marks`): графики, нарисованные полилинией (короткие
  прямые сегменты, не кривые Безье), теперь детектируются; короткие подписи
  (≤4 симв.) у края зоны графика вычищаются из решения; владелец графика
  атрибутируется по потоку чтения (page, y) — ловит график на стыке страниц.
  Пометка «в оригинале рисунок»: 2018 №18, 2021 №3.5[10,11], 2024 №2.2.
- **Остаточные плашки** «математика линеаризована» (нечиненные floor-fraction
  в решениях): **7** — 2017 №13/№14, 2019 №11, 2020 №3.1, 2021 №4.5, 2022
  №4.2, 2024 №2.5 (плашка зовёт сверить с PDF).

**Почему 225 → 218 при пере-импорте (2026-07-13, полностью протрассировано,
0 неожиданностей):** удаление старых задач года по `imported_ids.txt` →
`import_vsosh_region --year N --confirm` для всех 10 лет → сверка каждой
пары (год, номер, классы) со снимком базы до пере-импорта: **0 расхождений
ответа** на всех 217 сохранившихся вопросах. Пропали 8 старых записей
(появилась 1 новая = чистый минус 7):
- **2019 №19** — два старых вопроса (классы `[9]` и `[10, 11]`) схлопнулись
  в один общий `[9, 10, 11]`: младший класс получил тот же текст, что и
  старшие, после нормализации; аналогично пропало отдельное **2019 №9
  [10,11]** — совпало с уже существующей задачей в другом источнике после
  того, как `0{,}5` (LaTeX-запись без математики) нормализовалось в `0,5`.
- **2016 №17, 2017 №8** — вычитка убрала приклеенный подвал страницы
  («Первый тур. Тест Всероссийская олимпиада школьников (2016 г.)»), после
  чего текст стал байт-в-байт совпадать с уже существующей в банке задачей
  из другого источника (Overleaf-архив / Сборник тестов АА) — дубль
  корректно отфильтрован тем же механизмом дедупа, что и раньше.
- **2017 №11** — та же история, но подвал был приклеен к тексту ВАРИАНТА
  ответа, не условия.
- **2023 №3.5[11]** — вычитка восстановила дефис («врачей-рентгенологов»,
  раньше слова были склеены), после чего текст совпал с существующей
  задачей.
- **2024 №2.1[11]** — вычитка исправила гомоглиф («долгоcрочном» с латинской
  `c` → «долгосрочном»), после чего текст совпал с существующей задачей.

Во всех случаях — существующий дедуп-механизм `import_vsosh_region.py`
(точное совпадение нормализованного текста+вариантов против всей базы)
сработал ПРАВИЛЬНО: контент не потерян (та же формулировка уже есть в банке
под другим id из другого источника), просто у конкретно этого вхождения

другим дублям при первом импорте.

## Дизайн-токены и правила публичных страниц

Акцент сайта — **малиновый** (`#BE185D` светлая / `#FF4D94` тёмная). Токены — в
`templates/_tokens.html` (подключается ПЕРВЫМ в `<head>` каждой публичной базы:
`catalog/base.html`, `student/base.html`, `teacher/base.html`, login, calendar_stub).
`:root` (светлая) + `[data-theme="dark"]` + анти-мигание (скрипт ДО CSS ставит
`data-theme` по `localStorage['theme']`). Переключатель тем ☾/☀ — в `_nav.html`.

⚠️ `/calc2/` имеет СВОЙ изолированный мир токенов (`--curve-*`, `--cost-*`, свой
bootstrap темы) — не трогать его общими токенами. Единый ключ темы для всего сайта —
`localStorage['theme']` (calc2 тоже на него переведён).

**Правила (соблюдать на любой новой публичной странице):**
- Каждый цвет — через `var(--…)`. Хардкод hex ломает тёмную тему (исключение — цвета
  типов событий календаря и `rgba(0,0,0,…)` тени).
- **Сигналы священны:** амбер = звёзды сложности, зелёный = «решение ✓». Никогда не
  делать их акцентом. (`--green #1d7e45`, `--amber #b26b00` — затемнены под WCAG AA.)
- **Кнопки «Сцены»:** крупные действия (отправить/создать/сохранить/найти/скачать) —
  графитовые `var(--btn-bg)` + `var(--on-btn)`. Малиновый сплошной — ТОЛЬКО на
  мелочах/активном (логотип, активный nav, фильтр, ссылки, фокус-кольца, чипы).
  Акцент ≤ ~10% экрана.
- **Иерархия поверхностей:** страница — серая (`--bg`); карточки-контент — белые
  (`--surface`); `--surface-2` — только рецессивное (рельсы, инпуты). Карточка без
  явного `background` сольётся с фоном — задавать `var(--surface)`.

**Каталог (Фаза 2):** доп. логика в `problem_list` (catalog/views.py) — только
additive: `sort`, `view` (rows/table/gallery), нулевое состояние `is_zero_state` +
`atlas` (21 тема), `source`/`grade` в карточке. Теги в `catalog_filters.py`:
`set_param`, `remove_param`.

**Процент в шаблоне:** выводить через `{% widthratio pct 1 100 %}` (даёт integer).
`{{ pct|floatformat:0 }}` НЕ использовать — возвращает строку с запятой.

  `main`. Python 3.11 на проде. Docker НЕ используется (нет TeX → PDF-экспорт отключён,

- Файлы деплоя: `requirements.txt` (без ML), `requirements-local.txt` (с ML),

**Деплой = пуш в `main`** (Auto-Deploy On Commit, 2–4 мин; Start Command прогоняет
`migrate` + `collectstatic`). Откат: Render → Events/Deploys → Rollback.

**Рабочее правило:** недоделанное — в отдельных ветках; в `main` пушим только то, что
преподаватель одобрил глазами по скриншотам.

⚠️ **Ограничения free-tier (выяснено в Г1):**
- **Нет Shell** на free — команды на проде напрямую НЕЛЬЗЯ. Только локально против
  внешней базы или временно через `startCommand`.
- `startCommand` обязан открыть порт за ~3 мин (`gunicorn` первым), иначе деплой
  `Timed Out`. Долгие операции до gunicorn убивают деплой.
- 1 общий CPU / 512 МБ; сон после 15 мин без HTTP (просыпается ~30 с).

**Загрузка/обновление данных в прод (рабочий способ).** Внешнее `loaddata` непригодно
(часы, обрывы). Используем bulk_create локально против внешней базы:
```
# 1. собрать порционные gzip-фикстуры (исключают embedding, чистят NUL-байты)
./venv/bin/python manage.py dump_for_deploy --outdir deploy_fixtures --chunk 2000
gzip -f deploy_fixtures/*.json
# 2. залить (ignore_conflicts → идемпотентно)
SECRET_KEY=любой DATABASE_URL="<EXTERNAL_DB_URL>?sslmode=require" \
DJANGO_SETTINGS_MODULE=config.settings_production \
./venv/bin/python manage.py bulk_load_fixtures --dir deploy_fixtures
```
EXTERNAL_DB_URL — Render → qls-db → Connections → External Database URL.

⚠️ **`bulk_load_fixtures` ТОЛЬКО ВСТАВЛЯЕТ новые записи** (`ignore_conflicts=True`) и
молча пропускает существующие по pk → **правки в существующих задачах на прод так НЕ
попадают.** Для обновления существующих — команда **`update_prod_problems`** (точечный
`bulk_update` по списку id из `reports/ai_cleanup_ile/affected_ids.txt`; пересобирает
подпункты; задачи с привязанными Hint пропускает; одна транзакция; `--dry-run`).
Последовательность: (1) бэкап `pg_dump "<URL>?sslmode=require" -Fc -f backup.dump`
(`brew install libpq`), (2) `--dry-run`, (3) боевой.

⚠️ **Мина: отставшие sequence в PostgreSQL.** `bulk_load_fixtures` грузит явные id, но
НЕ двигает счётчик таблицы → при вставке без явного id → `UniqueViolation`. На SQLite
не воспроизводится. `update_prod_problems` выравнивает sequence для ProblemPart через
`setval`. **TODO:** выровнять sequence ВСЕХ таблиц перед следующей крупной заливкой
новых записей (`sqlsequencereset problems` против прода).

## Семантический поиск — проработка + Стадия 1 (АКТИВНАЯ ветка)

Фича: пользователь описывает задачу словами → система возвращает похожие задачи из
банка по смыслу. **Главный сдвиг в позиционировании:** это НЕ «найди ровно ту самую
задачу» (недостижимо и не нужно), а «**подбери 15–20 похожих**» для подборки/листка —
и в этом качестве уже работает. Фича названа «Подобрать похожие задачи».

**Путь:** ввод (текст + фильтры) → (опц.) HyDE → эмбеддинг локальной моделью →
косинусный поиск (грубый перебор numpy по ~31к векторов — векторная БД не нужна) →
жёсткие фильтры (тема/сложность/решение) ранжируют → карточки.

**Две стороны проблемы качества (диагностика из ручных тестов):**
- *Сторона запроса:* сухое описание ≠ форма олимпиадного условия. Лечится **HyDE**
  (дешёвая модель придумывает гипотетическое условие как «магнит»; доказано — подняло
  задачу с «не найдено» до 88%). Эффективен на «чистых» задачах, слабее на сюжетных.
- *Сторона задачи:* олимпиадные условия НАМЕРЕННО сюжетные (бабушка, ресторан) — это
  неустранимое свойство домена, не дефект данных. Сюжет забивает экономический смысл в
  отпечатке. Лечится **ИИ-резюме сути** (сухая строка «о чём задача», эмбеддить её) —
  это **главный рычаг**. Разовая трата ~$20–65 на корпус, сначала пилот 300 задач за <$1.

- НИКОГДА ничего не удалять. Только менять статусы и добавлять.
- Перед созданием карточки — поиск по названию. Не плодить дубли.
- Не заводить новые базы, разделы и варианты select без спроса владельца.

### Как генерировать блок «Текущий фокус»
Между маркерами NOTION-SYNC:START и NOTION-SYNC:END:
- строка «Обновлено: ГГГГ-ММ-ДД»
- ссылка на штаб
- «В работе:» — все задачи со статусом «В работе» (название + ответственный)
- «На проверке:» — все со статусом «На проверке»
- «Надо (ближайшее):» — до 7 задач со статусом «Надо»
- «Последние решения:» — 3 последних из базы «Решения»
Блок только читается из Notion и никогда не правится руками. Notion — истина.
