# Работы победителей и призёров «Высшей пробы»

Корпус настоящих проверенных олимпиадных работ с баллами — для проверки
рукописных решений ИИ (ИИ-стратегия, раздел «Данные»). «Высшая проба»
публикует сканы работ победителей и призёров заключительного этапа:
https://olymp46.hse.ru/schoolwinners.html. Команда `vp_works` выгружает
списки дипломантов, скачивает PDF и читает баллы по задачам с первой
страницы.

## Правила (не переоткрывать)

1. **Данные — вне репозитория**, по умолчанию
   `C:\Users\shipu\weconomics-data\vp_works\` (ключ `--dir`; папка внутри
   репозитория отвергается). В git — только код, тесты на выдуманных
   данных и этот документ.
2. **ФИО не храним нигде** — ни в index, ни в именах файлов, ни в
   отчётах, ни в Notion. Участник = номер работы (`work_id`, тот, что в
   `local.getWork`). Строка index строится из белого списка полей
   (`listing.INDEX_FIELDS`), поле `FullName` ответа сайта не читается.
   Сами PDF содержат фамилии — они лежат только в папке данных.
3. **В модель уходит только вырез таблички баллов** без шапки с ФИО
   (`scores.crop_scores`), через `core.run` — единственную дверь к моделям.
   Каждый отправленный вырез сохраняется в `crops/`.
4. **Вежливость к чужому серверу** — в `hse.Client`: не чаще 1 запроса в
   секунду, User-Agent `WeconomicsResearchBot`, 3 повтора с паузой
   5/15/45 с; 403/429/капча → `Blocked`, команда останавливается, а не
   обходит.
5. В базу команда не пишет ни строки (вызов модели обёрнут в
   `transaction.atomic()`: при отказе поставщика `core.run` пишет строку
   `AiUsageLog` даже с `log=False` — известный баг, исключение её откатывает).

## Как устроен сайт

Страница — пустая оболочка на Dojo. Данные отдаёт фреймворк `mill`
POST-запросами `query=<xml>` на `https://olymp46.hse.ru/hseAnonymous/<вид>`
(механизм выяснен по `/schoolwinners.js` и `/milljs/mill.js`):

| Шаг страницы | Вид | Запрос |
|---|---|---|
| список сезонов | `cursor.xml` | `TAdmissionYear`, `PublishSchOlymp=1` |
| туры сезона (по классу) | `batch.xml` | `TBachRound`, `Master=<сезон>`, `brtOlimpic` |
| вкладки предметов | `cursor.xml` | `TRoundComp.Name` по турам |
| блоки «Олимпиада NN класс» | `cursor.xml` | `TRoundComp` с `Name=<предмет>` |
| «Дипломы I/II/III степени» | `xsltreport.xml` | шаблон `SchoolWinners` (`TRoundAbiturSt`) |
| ссылка на ФИО → PDF | `executeoleobjectmethod` | `TAbiturientStatus.GetWorkImage(ID)` |

Куки не нужны. Список дипломантов — структурированный XML: `ID` (номер
работы), `AddRoundMark` (балл до апелляции), `AddFinalMark` (после; пусто —
сайт показывает балл до), класс, предмет, степень. Запрос PDF принимается
и GET-ом — так записан `source_url` в index.

## Команды

```bash
manage.py vp_works index    --dir D [--subjects economics,fingram,business] [--seasons 2019/2020,…]
manage.py vp_works download --dir D [--limit N] [--only id,…|@файл] [--stop-after-fails N]
manage.py vp_works scores   --dir D [--limit N] [--only id,…|@файл] [--max-usd 3.00] [--yes]
manage.py vp_works report   --dir D
```

- Предмет — параметр: `economics`, `fingram`, `business` или любой другой
  как `slug=Название вкладки` (`--subjects law=Право`) — без правки кода.
- `download` — докачка: файл на месте (есть, не пустой, начинается с
  `%PDF`) заново не качается, неудачные (`failed`) пробуются снова; пишет
  через `.part`; после 20 неудач подряд — пауза 10 минут, не больше трёх
  пауз. `--stop-after-fails N` — выйти после N неудач подряд (сайт лёг): так
  его ждёт внешний цикл с одной пробой в 10 минут, а не повторы на каждую
  работу. `--only` качает часть, но index сохраняет целиком.
- `scores` без `--yes` — только план и вырезы в `crops/`, ни одного вызова
  модели. С `--yes` — GLM-5.3-Flash, 6 потоков (`VP_WORKS_WORKERS`).
  `--max-usd` — потолок на ВСЕ прогоны вместе (прежние траты берутся из
  `scores.jsonl`): достигнут — новые вызовы не начинаются (отправленные, не
  больше числа потоков, доезжают). `--limit N` — случайная воспроизводимая
  выборка из скачанного (проба).

⚠️ **index.jsonl пишет только `download`, баллы живут в `scores.jsonl`.**
Скачивание идёт часами, и `scores` может работать одновременно с ним: два
процесса, пишущие один файл целиком, затирали бы поля друг друга.
`report` и `review.csv` склеивают оба файла по `work_id` (`load_records`).

## Файлы в папке данных

| Файл | Что |
|---|---|
| `index.jsonl` | строка на работу: списки и скачивание (см. ниже) |
| `scores.jsonl` | баллы по задачам, строка на прочитанную работу |
| `volume.jsonl` | сезон × предмет × класс × степень → число работ |
| `pdf/<subject>/<2019_2020>/<grade>/<degree>_<work_id>.pdf` | сканы |
| `crops/<2019_2020>/<subject>_<work_id>.png` | вырез, ушедший в модель |
| `review.csv` | очередь ручной проверки баллов по задачам |
| `scores_runs.jsonl` | журнал платных прогонов: вызовы, ok, $ |
| `RECON.md`, `REPORT.md` | разведка и итоговый отчёт (только числа) |

Поля index: `work_id, subject, season ("2019/2020"), grade, degree (1/2/3),
rank (номер в списке), score_before, score_after, score_after_listed
(был ли балл после апелляции в списке), source_url, listed_at`; после
скачивания — `pdf_path, bytes, sha256, pages, has_text_layer, status
(ok/failed), reason`. Поля scores.jsonl: `work_id, scores_status (ok/review),
scores_source (text/model), scores_reason, scores_tasks, scores_sum,
scores_model_total, scores_crop, scores_cost, scores_raw` (сырой ответ — у
review).

## Баллы по задачам

Баллы по задачам жюри вписывает в «Протокол проверки» на первой странице:
от руки, цифрами-шаблонами в клетках, а у основ бизнеса 2024/25 — впечатано
на компьютере. ФИО на первой странице нет ни в одном виденном бланке (шапку
отрезают по «линии отреза» до сканирования).

**Путь (а), текстовый слой** (`scores.text_scores`): если цифры есть текстом,
таблица разбирается по положению — верхний ряд цифр в полосе 0,3–0,6
высоты страницы, цифры одной ячейки вплотную, правая группа — «Итого».
Подписей строк в тексте нет, поэтому результат принимается только после
сверки суммы; не сошлось — путь (б).

**Путь (б), вырез → модель.** Одна раскладка на все бланки:
`LAYOUTS['protocol']` = полоса (0,02; 0,25)–(0,98; 0,77) — весь протокол
между блоком «Заполняется участником» и «Итоговым баллом» со штрихкодом.
Узкие полосы по сезону не годятся: у финграмотности и основ бизнеса 4–7
заданий, малая таблица «Баллы» или большая с двумя членами жюри и «Баллы
итог», и форма меняется от сезона к сезону. В вырез попадают подписи/коды
членов жюри (это не данные участника). Модель берёт строку «Баллы итог»,
иначе «Средний балл», иначе первую заполненную «Баллы»; строки подписей и
«Номер члена жюри» баллами не считает (системный блок `scores.SYSTEM`).

⚠️ **В модель идут только пары (сезон, предмет) из `scores.VERIFIED`** —
те, чьи вырезы просмотрены глазами. Остальные — `review` с причиной
`no_layout`. Новая пара → открыть 2–3 выреза (план без `--yes`), убедиться,
что ФИО/шифра/подписи участника нет, дописать пару в `VERIFIED`.

Проверка — наша, не модели: сумма по задачам == `score_before` (в PDF
стоит балл ДО апелляции) с допуском 0,5; пустая ячейка = 0, нечитаемое
(null) — review. Совпало — `ok`; не совпало, нечитаемо, сбой формата —
`review` и строка в `review.csv`. На пробе 09.10: 22 из 25 ok через модель,
2 из 2 через текст; все три промаха (25 прочитано как 28 и т. п.) пойманы
сверкой суммы.

## Объём (замер 09.10.2026)

4 619 работ в списках: экономика 2 495 (13 сезонов), финграмотность 996 и
основы бизнеса 1 128 (с 2017/2018). Пробные PDF — сканы по 12–16 страниц,
0,6–9,0 МБ (средний 3,5 МБ) → весь корпус ≈ 16 ГБ. Смета чтения баллов
GLM-5.3-Flash по пробе ≈ $0,0003 на работу (до пробы оценивали в $0,0006).
Таблица по сезонам, классам
и степеням — `RECON.md` в папке данных.

## Зависимости

Ничего нового: HTTP — стандартный `urllib`; PDF — PyMuPDF (`fitz`, уже в
`requirements/base.txt`); картинки — Pillow.

## Тесты

`problems/tests/test_vp_works.py` — только выдуманные данные (свой XML
списка с выдуманными именами, PDF собираются в тесте, подставной
поставщик ИИ, сеть не трогается). Зубастость проверена семью внесёнными
дефектами (ФИО в index, потеря балла после апелляции, повторная
закачка, битый файл как ok, сумма без сверки, модель без `--yes`,
`--max-usd` без обрыва) — каждый краснит свой тест.
