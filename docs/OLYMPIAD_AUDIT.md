# Аудит олимпиад по официальному эталону

Цель (решение владельца 08.10.2026): у каждой олимпиады все исторические
задания на сайте с верными метатегами. Конвейер отлажен на пилоте «Высшая
проба» (ВП) по экономике; дальше по тому же пути идут остальные олимпиады
списка. Как устроены строки `OlympiadRef` и методы привязки — в
[DATA.md](DATA.md), раздел про олимпиады.

## Эталон

Данные лежат ВНЕ репозитория, в `weconomics-data\olympiads\audit_<slug>_<дата>\`:

| файл | что это |
|---|---|
| `raw\pdf\` | официальные PDF условий и решений (скачаны один раз, сеть дальше не нужна) |
| `reference_events.jsonl` | комплекты: `event_id` вида `vp-<год>-final-<класс>-v1` (`-reserve` — резервный день, класс `8-9` — общий комплект), год, этап, источник |
| `session2\reference_problems_full.jsonl` | задания эталона: `event_id`, `number`, `grade`, `academic_year` (`2019/2020` — в банк пишется `2019/20`), `raw_text`, `norm_text`, `solution_text`, `max_score`, `has_figure`, `source_url` (PDF) |
| `session2\proposed_new_refs.csv` | новые привязки AUTO (строгий порог: текст ≥ 0,97 + числа + запас) |
| `session2\review_queue.csv` | очередь проверки; `review_tier` «высокий (…)» — кандидаты для проверки по тексту |
| `session2\claude_review_*.md` | проверка Claude по тексту: таблица подтверждённых высоких пар и таблица перенумеровок «на глаза» |
| `session2\proposed_updates_existing.csv` | план правок существующих строк: `action`, `coord_status`, `official_event_id`, `proposed_*` |
| `session2\import_queue_*.jsonl` | задания эталона, которых в банке не нашлось |
| `session3\` | журналы записи, вырезанные рисунки (`figures\<event_id>_<номер>.png` + `.json` с подписями) |

`norm_text` — та же нормализация, что у `find_olympiad_text_duplicates`
(`problems/text_dedup.normalize_for_compare`). Сравнение текста банка с
эталоном — `fuzzy_ratio` по условию вместе с подпунктами.

## Команды

```bash
manage.py olympiad_official_sources --olympiad vp|mosh [--apply]
```
Справочные строки: `Source` «<олимпиада>: официальный архив» из реестра;
у ВП ещё карточки `olympiads.Olympiad` для `vp-fingram`, `vp-ob`
(НЕопубликованные), у остальных — проверка карточки своего слага (пустой
официальный сайт дописывается). Данные, а не миграция. ⚠️ `import_olympiads_data --wipe` и `seed_olympiads_demo
--wipe` сносят все карточки `Olympiad` — после них запустить снова.

```bash
manage.py apply_olympiad_audit --olympiad vp --new-refs proposed_new_refs.csv --tier auto
manage.py apply_olympiad_audit --olympiad vp --new-refs review_queue.csv --tier high --confirmed-by claude_review.md
manage.py apply_olympiad_audit --olympiad vp --update-existing proposed_updates_existing.csv --confirmed-by claude_review.md [--include-eyeball] [--twin-pdf-to-pdf]
manage.py apply_olympiad_audit --olympiad vp --import import_queue.jsonl [--figures-dir DIR] [--assume-updates ЖУРНАЛ…]
manage.py apply_olympiad_audit --olympiad mosh --delete-refs ID,ID --out-dir DIR
manage.py apply_olympiad_audit --olympiad vp --rollback session3\apply_<время>_<режим>.json
```

По умолчанию — сухой прогон: таблица «создать / обновить / пропустить,
почему» с числами и примерами, журнал `…_dryrun.json`. Запись — только
`--apply --yes-i-have-owner-approval` вместе (фраза = «владелец сказал да
на стоп-гейте»). Эталон ищется рядом с входным файлом (`--reference`),
журналы — в папке журналов из реестра рядом с папкой входного файла
(`--out-dir`).

Флаги многоэтапной олимпиады (так записан МОШ, сессия 2):
`--stage-from catalog_vs_official.csv` — пустой этап заполняется только у
комплектов агрегатора с этапом, доказанным текстом (`stage_established`
без «?»; id вида `…__propagated…` сводится к базовому);
`--renumber-by-containment` — сомнительные перенумеровки из файла проверки
(список «- id event текущий→предложенный …») применяются, только если текст
банка входит в задание под новым номером (≥ 0,90) и не входит под текущим;
`--text-check existing_refs_text_check.csv` — найденный комплект для
близнецов, когда в CSV правок нет причины (у МОШ её нет); `--assume-updates
ЖУРНАЛ…` работает и для правок — сухой прогон видит итог высокого яруса.
`--delete-refs` снимает только строки своей олимпиады; полная копия строки
— в журнале, `--rollback` возвращает её с тем же id.

**Порядок важен:** `--new-refs` (оба яруса) → `--update-existing` →
`--import`. Импорт пропускает задание, к которому уже привязана задача
банка — строкой с официальным `event_id` или строкой агрегатора,
переведённой правками на официальный комплект
(`raw_meta['official_event_id']` + номер). До записи правок увидеть
итоговое число импорта можно так: `--import … --assume-updates <журналы
сухих прогонов new-refs и update-existing>`.

### Что пишет каждый режим

- **Новые привязки** — `source_site='official'`, слаг и название из
  реестра, официальный `event_id`, этап из эталона (у ВП всегда `final`),
  класс, номер, ссылка на PDF, учебный год в формате банка; вариант
  задания — в `raw_meta['task_variant']` и хвостом `record_id`, тур
  (`tour2`) — в `raw_meta['tour']`. AUTO: `match_method='text_fuzzy_numeric'`,
  `reviewed_by_human=False`. Высокий ярус: только пары из таблицы
  подтверждений, `manual`, `reviewed_by_human=True`,
  `raw_meta['reviewed_by']`.
- **Правки существующих строк** — этап (пусто → `final`), класс (только
  пустой), ссылка на PDF, номер по PDF, слаг финграмотности. Старые
  значения агрегатора сохраняются: `raw_meta['aggregator_url']`,
  `aggregator_number`, `aggregator_grade`; официальный комплект —
  `raw_meta['official_event_id']`. Строки без эталона (до 2012) и без
  совпадения текста не трогаются.
- **Импорт** — через `corpus_converter.ingest.create_problem`, как у
  штатных импортов: `status='draft'`, `hidden_pending_review=True`, формат
  `markdown` (как у копий Школково той же олимпиады; в `plain` маркер
  картинки не превращается в изображение). `SourceReference` на
  официальный `Source` со ссылкой на PDF, `OlympiadRef(source_site=
  'official')`, рисунок — `ProblemFigure` с маркером `[[FIGURE:…]]` после
  абзаца, где упомянут рисунок. Рисунок задан, но не вырезан —
  `needs_quality_review=True`.
- Чистка текста PDF (`problems/olympiad_official.clean_pdf_task`) —
  только форма: колонтитулы, шапка «Задача N. «Название» (N баллов)» →
  заголовок, подписи внутри вырезанного рисунка, переносы строк по ширине
  страницы, курсивные математические буквы. Формулы, рассыпанные при
  извлечении из PDF, НЕ чинятся — их помечает `formula_suspect` в отчёте.

### Журнал и откат

Каждый `--apply` пишет `session3\apply_<время>_<режим>.json`:
`created_ref_ids`, `updated_refs` [{id, field, old, new}],
`created_problem_ids`, `created_part_ids`, `created_sourceref_ids`,
`created_figure_ids`, счётчики до и после. `--rollback <журнал>` (сухой
по умолчанию) удаляет созданное и возвращает поля к `old` — только если
сейчас там `new`; иначе поле не трогается и попадает в отчёт конфликтов.

## Правило близнецов

Одно задание часто дают двум соседним классам. Строка, чей текст совпал
с комплектом ДРУГОГО класса, — не ошибка, если то же задание есть и в
комплекте её класса: тогда класс остаётся, дописываются номер и PDF своего
класса. Иначе класс исправляется на найденный — но не если у задачи уже
есть строка ВП того же тура в том классе (строка остаётся как есть, в отчёт).

«То же задание» — сходство ≥ 0,90. По умолчанию сравнивается текст банка
с заданием своего комплекта. С `--twin-pdf-to-pdf` (выбор владельца
09.10, [ADR 0141](adr/0141-olympiad-official-reference.md)) — ещё и
найденное задание соседнего класса с заданиями своего: два PDF одной
вёрстки между собой. Без флага в пилоте 19 из 59 близнецов не дотянули
до порога (шапка «(20 баллов)» против «(25 баллов)», вёрстка), и одна
строка получила бы неверный класс.

## Ловушки

⚠️ **Номер SolveHub — позиция в их списке, а не официальный номер.** В
пилоте ВП у 123 из 573 строк номер агрегатора не совпал с PDF (перестановки
4→1, 3→1, 2→4). Номер берётся из эталона после сверки текста.

⚠️ **Косинус по голому тексту PDF не работает.** Вектор банка строится по
формуле (условие + темы + решение, `problems/embedding_formula.py`), и
против голого текста PDF он нашёл 1 % верных пар. Сравнивать текстом; если
нужен вектор эталона — строить его по формуле банка.

⚠️ **Очередь импорта устаревает от записи привязок.** В пилоте из 21
«недостающего» задания 15 оказались в банке: 9 закрыли новые привязки к
копиям Школково, 6 — перенумерация и близнецы. Импорт — последним, и
команда сама сверяется с привязками.

⚠️ **Привязка меняет вектор поиска.** Блок «Олимпиада» (название, этап,
год) входит в отпечаток эмбеддинга: после записи у затронутых задач вектор
устаревает. Пересчёт — `build_embeddings --stale` (в пилоте устаревших
было ровно 437 = затронутые сессией).

⚠️ **«На глаза» в файле проверки — только строка, НАЧИНАЮЩАЯСЯ с этих
слов.** У МОШ слова «на глаза» стоят и в пояснении перед таблицей
подтверждённых — по вхождению все 657 пар ушли бы в «на глаза» (поймано
сухим прогоном).

⚠️ **Пустой класс «подходит» любому комплекту.** Две строки ILE без класса
у одной задачи (`…-10-1` и `…-9-3`) — пару высокого яруса дописывает строка,
чей комплект агрегатора назван классом пары; одну строку не дописывают две
пары. Строка, уже сверенная с ДРУГИМ официальным комплектом (в том числе с
соседним вариантом v1/v2 того же тура), — не «та же строка тура»: при
записи МОШ 09.10 пары варианта v2 переписали ссылку трёх строк v1, запись
откачена журналом и повторена после правки.

⚠️ **Инвариант дублей — один официальный комплект И пересекающийся
класс.** Строки 8 и 9 класса на общий комплект `8-9` — не дубль; две
строки агрегаторов (ILE + SolveHub) одного класса — дубль, вторая правками
не трогается и уходит в отчёт.

## Оцифровка зрячей моделью

Текст, вытащенный из PDF программно (v1), для банка «идеального качества»
не годится: формулы рассыпаются, таблицы идут в столбик, отборочные МОШ
2020/21–2024/25 — сканы без слоя. Поэтому эталон v2 строится зрячей
моделью: страница PDF → PNG → GLM-5.3-Flash → JSON-блоки. **Эталон v2 —
источник правды для импорта; v1 больше не использовать.**

```bash
manage.py olympiad_digitize inventory --olympiad vp|mosh     # опись raw\ → digitized\inventory.jsonl, events_files.jsonl
manage.py olympiad_digitize render --olympiad X              # PDF → pages\<sha16>\p<N>.png + .txt (слой), 200 dpi
manage.py olympiad_digitize transcribe --olympiad X --max-usd 20 [--limit N] [--pages-file F [--redo]] [--workers 20] [--yes]
manage.py olympiad_digitize rescore --olympiad X             # пересчёт мерила слоя без модели
manage.py olympiad_digitize assemble --olympiad X            # → reference_problems_v2.jsonl, events_v2.jsonl, figures\
manage.py olympiad_digitize assemble --olympiad X --suffix v1 # у новой олимпиады первая оцифровка — v1 (v2 не создаётся)
manage.py olympiad_digitize transcribe … --strict-prompt     # усиленная инструкция (transcribe.STRICT_SUFFIX)
```

`--settings` у этой команды ставится ДО подкоманды (подпарсеры) — проще
через `DJANGO_SETTINGS_MODULE`.

**`--strict-prompt`** (пилот 13.10, финграмотность и бизнес): к системной
инструкции добавляются три правила — вступление комплекта (время, баллы,
правила, источник кейса, «Критерии оценивания (всего N баллов)») безномерным
блоком `task`; логотипы спонсоров — `noise`, не `figure`; строка таблицы
критериев — блок `criteria` с номером задания. Без флага промпт прежний; в
`p<N>.json` — поле `prompt` (`base`/`strict`). На 20 страницах пилота: layer
0,925 → 0,961, numbers_ok 11 → 13 из 17, «на глаза» 8 → 6.

Пишет только `weconomics-data\olympiads\<audit>\digitized\`, в базу —
ничего. Папка страниц — по первым 16 знакам sha256 файла (дубль попадает
туда же, путь короче 260 знаков Windows). Протоколы и списки участников в
модель не идут (инвентарь, `exclude_reason`).

**Деньги.** Без `--yes` — только план и смета; `--max-usd` обязателен и
останавливает прогон с запасом на вызовы в полёте; расход каждого вызова
— строкой в `transcribe_cost.jsonl` до разбора ответа (терпимый разбор не
бросает исключений, сбой формата не теряет расход). Повтор на 429 — 5/15/45
с; готовые страницы (`ok`/`needs_eyes`) не вызываются повторно. Замер
пилота 09.10: вызов ≈ $0,0013 (≈ 6 300 токенов входа — в основном
картинка, 600–900 выхода), страница с повторами и судьёй ≈ $0,002.

**Флаги качества страницы** (`p<N>.json`):
- `layer_ratio` — совпадение СЛОВ расшифровки и текстового слоя PDF в обе
  стороны (F1 по словам от трёх букв, ключ без разметки). Ловит пропуск
  абзаца и лишний текст; формулы в него не входят — в слое они
  рассыпаны. `layer_fuzz` — посимвольное сходство (`token_sort_ratio`), для
  сравнения: на дословной расшифровке страницы с формулами Cambria Math
  оно 0,78;
- `numbers_ok` — множества чисел без знака совпали (с полями номера и
  баллов; числа шапки не лишние; одиночные числа слоя на странице с
  рисунком — подписи осей — не требуются);
- не сошлось (`layer_ratio < 0,90` или числа) — один повтор с усиленной
  инструкцией, затем `needs_eyes`;
- сканы без слоя: каждая 5-я — `needs_eyes`; страницы с формулами,
  таблицами, рисунками — второй вызов «модель-судья», замечание судьи —
  `needs_eyes`.

**Сборка.** `task_continuation` без номера дописывается к последнему
заданию файла; решения и критерии ложатся на задание по (номер, вариант
задания), без номера — по названию (≥ 0,85); ответ теста из файла
ответов-скана берётся из поля `answer`; рисунок вырезается по рамке
(доли 0..1000) с запасом 2 %, пустая вырезка — флаг. Сверка с v1 —
`compare_v1_v2.csv`, несопоставленные решения — `unmatched_solutions.txt`.

Правила сборки, найденные на данных (каждое — с тестом):
- «задание» без номера до первого — вступление комплекта (`preamble_md`),
  после — кусок текущего задания; «X.Y» без своего задания — к X;
- файл теста (`…-test-…`) нумерует вопросы `тест-N`; если в одном файле
  нумерация пошла заново после ≥ 8 вопросов — первая часть файла тест
  (`тест-N`); продолжение не переходит границу файла;
- общий файл ответов на несколько классов («5.1» — 5 кл., задача 1): номер
  чужого класса — мимо; смешанный файл (условия + решения) читается один раз;
- комплект без файла условий (финал МОШ 2017/18, 8, 9, 11 кл.): решение с
  номером заводит задание с пустым условием (на глаза); условия только в
  docx — задания берутся из v1 (текст docx);
- неудачная рамка рисунка условия заменяется тем же рисунком из файла
  решений (подпись ≥ 0,85); кусок со строчной буквы на новой странице
  клеится к предыдущему пробелом;
- (13.10) безномерной блок с таблицей «№ | Формулировка | Критерии | Макс.
  | Баллы» в файле решений/критериев режется по строкам на блоки своего
  задания, балл — из «Макс.»; продолжение таблицы на следующей странице —
  по шапке файла; таблица данных (Q | P) не трогается (`explode_table_rows`);
- номер с ведущим нулём («06.11») — дата в тексте кейса, не номер задания;
- номер больше любого задания комплекта СРАЗУ за решением/критериями того
  же вида (тот же файл, та же или предыдущая страница) — пункт списка внутри
  них; иначе по-прежнему в несопоставленные;
- несколько вариантов в одном файле (МОШ-финграм, отборочный 2017/18–2021/22):
  вариант из шапки переносится на блоки без своего варианта (шапка без номера
  и блоки до первой шапки — вариант 1); одна шапка «1 Вариант» + сброс
  нумерации к 1 после ≥ 8 пунктов — следующий вариант (`_header_variants`);
  файл без номеров вариантов в шапках не меняется;
- у рисунка в эталоне — `page_dir` и `bbox_model` (рамка модели): по ним
  инструмент сессии уточняет вырезку по графике страницы PDF.

### Очередь «на глаза»: ярусы, судья, перечитывание

Страницы со статусом `needs_eyes` разбирает `problems/olympiad_audit/` —
`triage.py` (ярусы, срочность, заплатки), `judge.py` (судья, перечитывание),
`review_pack.py` (пакет для человека). Старые `pages\…\p<N>.json` **не
перезаписываются никогда**: результат — «заплатки» в `pages_v3\<sha16>\p<N>.json`,
`PageOverlay` накладывает их при сборке v3.

```bash
manage.py olympiad_digitize triage --olympiad X                  # → triage_plan.csv, triage_summary.json (без модели)
manage.py olympiad_digitize judge --olympiad X --max-usd 1.5 --resume [--yes]   # судья: ярус A + выборка контроля B/C
manage.py olympiad_digitize judge --olympiad X --max-usd 0.1 --redo-answer-artifact [--yes]   # (история, см. ловушки)
manage.py olympiad_digitize report --olympiad X                  # сводка судьи, доля дефектов на контроле
manage.py olympiad_digitize reread --olympiad X --max-usd 1.7 [--yes]            # needs_fix: ОДНО перечитывание + судья
manage.py olympiad_digitize reread --olympiad X --max-usd 0.4 --rejudge-answers [--yes]   # пересуд human с замечанием про ответ
manage.py olympiad_digitize assemble --olympiad X --v3           # → digitized\v3\ (v2 не трогается) + compare_v2_v3.json
manage.py olympiad_digitize review-pack --olympiad X             # остаток → human_review\ + human_review.csv
manage.py olympiad_digitize control-pack --olympiad vp           # 30 страниц яруса A, пропущенных судьёй (обе олимпиады)
```

**Ярусы.** A — «текст расходится со слоем» (в том числе слой без слов, мерило
не посчитано), «не хватает чисел», «скан: судья уже нашёл расхождения»,
сбой формата; B — только лишние числа (подписи графиков), C — плановая
выборка сканов. B и C — норма по умолчанию: судья смотрит только выборку
контроля (5 %, но не меньше 20, seed 20261009), остальные в сборке v3 —
`ok_norm`. Срочность страницы — по заданиям, которые она питает
(`source/solution/criteria_pages` эталона): «в банке нет» (будет импорт),
«в банке есть похожая» (ключ (комплект, номер) в `existing_refs_text_check.csv`
или привязка `official:<комплект>:<номер>` в базе), «не срочная» — страница
не вошла ни в одно задание.

**Судья** получает картинку и расшифровку, отвечает строгим JSON
(`ok`, `issues[{kind, where, detail}]`, `numbers[{number, on_image,
in_transcript}]`); невалидный ответ — один повтор, потом `judge_error`
(страница остаётся «на глаза»). `ok_judge` — ноль замечаний И нет
**реального пропуска числа**: число слоя, которого нет в расшифровке и
которое судья подтвердил на картинке; число, которого на картинке нет
(артефакт слоя) или которое в расшифровке есть, не считается, число, про
которое судья промолчал, — считается. Замечание или реальный пропуск —
`needs_fix`. **Перечитывание** — ровно одна попытка на страницу: картинка +
замечания судьи + недостающие числа слоя («есть на картинке — включи, нет —
не добавляй»), пересчёт мерила, повторный судья: чисто → `fixed`, иначе
`human` (берётся расшифровка с меньшим числом замечаний, но на `human`
она применяется в сборке только при том же «скелете» блоков — тип+номер
заданий/решений/критериев, иначе задание могло бы тихо исчезнуть:
`mosh-2019-final-6-v1`, блок «6.1» стал `solution`).

⚠️ **Поле `answer` судье — с пометкой «часть блока».** Голой строкой
«Ответ: …» судья принимал дубль за «лишнее» (на картинке такой строки нет:
10 из 15 срабатываний на контроле), а скрытое — жаловался на «пропущенный
ответ», лежащий в поле (87 страниц `human`). Оба раза поправлено пересудом
дешёвых страниц (≈ $0,35 вместе).

⚠️ До 13.10.2026 `vp-ob` и `vp-fingram` указывали в ту же папку аудита, что
`vp`; теперь у них своя (`audit_finbiz_20261013`). `control-pack` по-прежнему
дедуплицирует папки — на случай общей папки у слагов одной семьи.

**Итог 09–10.10.2026** (очередь ВП 305 + МОШ 1 178 = 1 483 страницы; судье —
577 страниц яруса A + 77 контроля): `ok_judge` 276, `fixed` 113, `human` 265,
829 страниц B/C вне выборки — норма. Доля «дефектов» судьи на контроле B+C:
19,5 % с видимым `answer` без пометки → 7,8 % после поправки. Заданий с
`needs_eyes`: ВП 321 → 76, МОШ 1 153 → 187. Расход разбора ≈ $1,96. Реальные
дефекты — в основном пропуск вступления («время выполнения», правила, баллы
подпунктов), сносок, таблиц и подписей; перечитывание иногда вносит новую
опечатку или теряет нумерацию списка (примеры — в `v3_text_changes_examples.md`),
поэтому `human` и контроль смотрит человек.


### Разбор «на глаза» для эталонов v1 (финграмотность и бизнес, сессия 2)

У финграм-эталонов первая оцифровка — v1, поэтому база разбора — v1, заплатки —
`pages_v2\`, итог — `reference_problems_v2.jsonl` (v1 не трогается):

```bash
manage.py olympiad_digitize triage --olympiad X --base v1 --rows v2 --auto-publish
manage.py olympiad_digitize judge  --olympiad X --base v1 --only-control --max-usd 0.1 --yes   # гейт 30 %
manage.py olympiad_digitize report --olympiad X --base v1
manage.py olympiad_digitize judge  --olympiad X --base v1 --max-usd 0.8 --yes                  # ярусы A и D
manage.py olympiad_digitize judge  --olympiad X --base v1 --only-auto --max-usd 0.3 --yes      # B/C заданий к импорту
manage.py olympiad_digitize reread --olympiad X --base v1 --max-usd 0.4 --yes
manage.py olympiad_digitize assemble --olympiad X --suffix v2 --overlay   # → reference_problems_v2, figures_v2manage.py olympiad_digitize review-pack --olympiad X --base v1
```

- `--base vN` — эталон разбора `reference_problems_vN.jsonl`, заплатки
  `pages_v<N+1>` (по умолчанию v2 → `pages_v3`, как у ВП/МОШ по экономике);
  `triage --rows vK` — задачные причины и срочность по свежей сборке.
- **Пересчёт мерила без модели** (`triage` при `--base` ≠ v2): страница «на
  глаза» только из-за слоя, прошедшая порог по новому мерилу, — заплатка
  `ok_rescore`, поля мерила — в `rescore` заплатки (старый `p<N>.json` не
  меняется). Мерило с 13.10: полнота — против слоя без колонтитулов, точность и
  «лишние числа» — против ВСЕГО слоя страницы (повторённые на каждой странице
  формулировки теста, вступление, одиночные «1/2/3» вариантов раньше срезались
  как колонтитулы и давали ложное «лишнее»).
- **Задачные причины яруса A** (`triage.task_risks`): пустое/короткое условие,
  нет ответа при файле решений, внутри условия заголовок другого задания,
  пропуск номеров после задания (склейка), служебный блок как задание.
- **Ярус D** (`--auto-publish`): страница вне очереди, питающая задание «в банке
  нет», ниже автопроверки (слой < 0,95, числа, скан без слоя) — к судье.
  `judge --only-auto` — B/C вне контрольной выборки у заданий к импорту
  («норма» для сборки, но не уверенность для публикации без человека).
- **Защита заплаток:** перечитанная расшифровка, потерявшая номера блоков
  заданий/решений/критериев (`triage.numbers_kept`), не применяется даже со
  статусом `fixed` — страница `human_skeleton`, в пакет человеку (МОШ-
  предпринимательство 2009/10: 15 ответов перечитались одним блоком без номера).

Новые правила сборки (сессия 2, каждое с тестом, `test_olympiad_finbiz2`):
служебная строка («Комплект заданий № 1», «Код участника») и повтор вступления
— мимо, вступление и после первого задания — в `preamble_md`; хвост условия,
повторённого в файле решений, — не решение, абзацы-повтор условия и заголовок
«Задача N» в начале решения срезаются, ответ хвостом в блоке условия — решение;
несколько тестов в файле теста — `тест-<k>.<N>`; повторный сброс нумерации к 1
после «тест → задачи» — подпункты следующего задания (`4.1…`); файл решений —
по тексту повторённого вопроса (условие целиком ≤ 600 знаков, покрытие ≥ 0,8,
только совместимый номер: N, `тест-N`, `тест-k.N`, `4.N`), номер без своего
задания — продолжение последовательности (`4.5` → «6» = `4.6`) или
единственный `тест-N`; бланк ответов (сетка «вопрос → отмечено», «№ | А | В …
+», таблица «номер | буква», список «1. В», поле answer «1 — А; 2 — Г»);
метка варианта текстом блока («2 вариант»); «Комплект заданий № 2», «Решебник,
16 марта» в шапке — не вариант; склейка вопросов режется по пропуску номеров
(«N.» раньше «N)», не поверх существующего номера); дата «20.11.2013» в начале
блока — не номер.

**`auto_publish_ok`** (вход будущей автопубликации, решение 13.10 «без ручной
проверки, если строгая автопроверка уверена») считает инструмент сессии
`audit_finbiz_20261013	ools\p5s2_queue.py` → `import_queue_v2.jsonl`
(`auto_publish_ok`, `auto_publish_fail`, `auto_publish_notes`): каждая страница
задания — судья без замечаний (`ok_judge`/`fixed` с сохранёнными номерами) или
слой ≥ 0,95 и числа; скан — только судья; есть ответ при файле решений;
условие не пустое; KaTeX без ошибок и «красных» команд
(`node scripts\katex_render_check.js` из основной папки); рисунки без флага;
автопроверка v4 «рисунок на странице не привязан» и «служебный блок» — провал,
«таблица не передана» (эвристика по линиям) — замечание.
