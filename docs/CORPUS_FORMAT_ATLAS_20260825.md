каждый — своими скриптами по живым данным. Выборки: `random.seed(20260825)`,
`random.sample` (не первые N подряд). Сквозные числа по всему банку главная

без числа в документе нет.

**Три числа прошлой сессии не воспроизвелись** — см. раздел «Расхождения,
которые не разрешены». Это не повод не доверять порядку величин, но повод

Ещё оттуда: `LIST_LINE_RE` (`diagnostics.py:108`) распознаёт `•`, `-`, `–`, `—`
и `\d{1,2}[.)]` — домашний стандарт списка уже определён, рендерер должен
взять его же, а не изобретать второй.

**6 markdown-таблиц чинили вручную поштучно**: стили разделителей разные

## Что рендерер обязан уметь

Объединённый список всех конструкций, встреченных хотя бы в одном источнике.
Прямой вход для проектирования.

### Обязательный минимум (без этого рендерер не работает)

1. **Math-aware защита формул плейсхолдерами.** Четыре разделителя
   (`$$`, `$`, `\[…\]`, `\(…\)`), порядок `$$` раньше `$`. Не вырезать —
   **защищать и возвращать**. Без этого ломаются 314 задач ILE с `Q^*…P^*`
   и ~1000 с индексами `_`.
2. **Учёт экранированного `\$`** — как в `_katex_dollars.html`, а не как в
   `strip_math_regions`. Иначе Python и браузер разойдутся в границах формулы.
3. **Обработка нечётных `$`** — 213 задач банка (метод 3) плюс 84 задачи
   SolveHub. Их надо **карантинить, а не рендерить молча**.
4. **Абзацы** — 96.2% банка имеют `\n\n`. Но у ILE их 0.8%, у ВсОШ-региона
   81.7% одиночных `\n`: одного правила на всех не хватит.
5. **CSS-фолбэк шрифта для кириллицы в математике.** `\text{}` с кириллицей —
   250 задач SolveHub, 274 задачи ILE. Кириллица в математике **вне** `\text{}` —
   329 задач ILE (8.3%), 182 МатЭк (4.9%), 165 Акимовой (57.1%).
