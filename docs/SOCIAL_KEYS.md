# Ключи входа через Яндекс ID и VK ID — пошагово

> **Владелец:** Claude Code · **Обновлён:** 2026-10-29 (вход и онбординг, раунд 3) ·
> **Статус:** актуален

Это инструкция для владельца: как получить ключи двух сервисов, вписать их и
проверить вход вживую. Код входа — `problems/social/`, значки и правила кнопок —
`static/social/README.md`, безопасность — `docs/SECURITY.md`, раздел «Вход через
VK ID и Яндекс ID».

⚠️ **Ключи в репозиторий не класть.** Ни в код, ни в `.env.example`, ни в Notion,
ни в чат. Только в окружение: PowerShell перед запуском или `.env` на сервере.

## Почему в раунде 1 вход не работал

| Что видел владелец | Причина | Доказательство |
|---|---|---|
| Яндекс: «400 Неизвестное приложение» | Подставной ключ `YANDEX_CLIENT_ID=demo`. Приложения с таким номером у Яндекса нет | Документация Яндекс ID: на неизвестный или заблокированный `client_id` сервис отвечает ошибкой `invalid_client` (https://yandex.ru/dev/id/doc/ru/codes/code-url). Без входа в Яндекс адрес с `client_id=demo` уводит на паспорт, после входа — страница ошибки |
| VK: «ошибка загрузки» | Подставной ключ `VK_ID_CLIENT_ID=demo` + VPN | Проверено 30.10 запросом к `id.vk.com/authorize`: с `client_id=demo` VK ID отвечает `"client_id is missing"` (номер приложения у VK — только цифры), с выдуманным числом — `"app is deleted"`. VPN мешает отдельно: VK ID может не открыться с зарубежного адреса |

Параметры нашего кода сверены с официальной документацией обоих сервисов — ошибок
в адресах и полях нет (подробности — журнал `reports/login_onboarding_20261029/JOURNAL.md`,
раунд 2, фаза 1). Чтобы это не повторилось, с раунда 2 **кнопка не показывается,
если ключ пустой, `demo` или не похож на настоящий** (у VK ID — только цифры, у
Яндекса — 32 знака 0–9 a–f), а прямой заход на `/auth/<сервис>/start/` показывает
нашу страницу «Вход через … пока не настроен».

## 1. Яндекс ID

1. Войти в свой Яндекс и открыть https://oauth.yandex.ru/client/new/id/
   («Создать приложение»).
2. Название — «Weconomics», иконка — знак сайта.
3. Платформа — **«Веб-сервисы»**. В поле **Redirect URI** вписать ОБА адреса,
   каждый отдельной строкой:
   - `https://weconomics.ai/auth/yandex/callback/` — боевой;
   - `http://127.0.0.1:8010/auth/yandex/callback/` — для проверки на своём компьютере.
4. **Доступ к данным** — отметить ровно это:
   - «Доступ к логину, имени и фамилии, полу» (`login:info`);
   - «Доступ к адресу электронной почты» (`login:email`);
   - «Доступ к портрету пользователя» (`login:avatar`);
   - «Доступ к дате рождения» (`login:birthday`) — можно отметить сразу: сайт
     попросит её, только когда включён `SOCIAL_STORE_BIRTHDATE=1` (после ред. 3
     документов).
   - **Телефон НЕ отмечать** (решение 08.10.2026).
5. Почта для связи — служебная. «Создать приложение».
6. На странице приложения взять:
   - **ClientID** — 32 знака, это `YANDEX_CLIENT_ID`;
   - **Client secret** — это `YANDEX_CLIENT_SECRET` (при нашем способе входа он не
     обязателен, но если задан — сайт его передаёт).

## 2. VK ID

1. Открыть кабинет VK ID для бизнеса: https://id.vk.ru/about/business/go
   (войти своим VK), «Создать приложение».
2. Платформа — **Web**, название — «Weconomics», иконка — знак сайта.
3. **Базовый домен** — добавить оба:
   - `weconomics.ai`;
   - `localhost` — для проверки на своём компьютере (без порта).
4. **Доверенный Redirect URL** — оба:
   - `https://weconomics.ai/auth/vk/callback/`;
   - `http://localhost/auth/vk/callback/` — для проверки на своём компьютере.

   ⚠️ **У VK ID на своём компьютере работает только `localhost` на порту 80** (или
   `https://localhost` на 443): «Доверенный redirect URL пропишите с http и без
   порта — http://localhost… Другие порты временно не поддерживаются» (документация
   VK ID, «Создание приложения»). Адрес `127.0.0.1:8010` VK не примет — поэтому для
   проверки VK сервер запускается по-другому (ниже).
5. **Доступы** — включить «Почта» (по умолчанию выключена) и в «Авторизация →
   Данные для регистрации» подтвердить, что почта запрашивается. Имя, фамилия, фото
   и дата рождения приходят сами (`vkid.personal_info`). **Телефон не запрашивать.**
6. Уровень конфиденциальности — оставить обычный (не «конфиденциальное
   приложение»): наш вход работает с PKCE и сервисный ключ при обмене не шлёт.
7. Взять **ID приложения** (только цифры) — это `VK_ID_CLIENT_ID`.
   «Защищённый ключ» — `VK_ID_CLIENT_SECRET` (сейчас не используется, но пусть
   лежит рядом).

## 3. Вписать ключи на своём компьютере (PowerShell)

Команды — в одном окне PowerShell, из папки проекта (или worktree):

```powershell
$env:SOCIAL_LOGIN_ENABLED="1"; $env:YANDEX_CLIENT_ID="<ClientID Яндекса>"; $env:YANDEX_CLIENT_SECRET="<Client secret>"; $env:VK_ID_CLIENT_ID="<ID приложения VK>"; $env:ONBOARDING_ENABLED="1"
```

**Проверка Яндекса** — сервер на 8010:

```powershell
venv313\Scripts\python.exe manage.py runserver 127.0.0.1:8010
```

Открыть http://127.0.0.1:8010/login/ → «Войти с Яндекс ID».

**Проверка VK ID** — сервер на `localhost:80` (только так VK пустит обратно):

```powershell
venv313\Scripts\python.exe manage.py runserver localhost:80
```

Открыть http://localhost/login/ → «Войти с VK ID». Если Windows ответит, что
порт занят, — закрыть Skype/IIS или проверить на сервере. **VPN выключить.**

Ключи живут только в этом окне PowerShell: закрыли окно — их нет.

## 4. Вписать ключи на сервере

На сервере (`/srv/weconomics/app/deploy`, см. `docs/SERVER.md`) дописать в `.env`:

```
SOCIAL_LOGIN_ENABLED=1
YANDEX_CLIENT_ID=<ClientID Яндекса>
YANDEX_CLIENT_SECRET=<Client secret>
VK_ID_CLIENT_ID=<ID приложения VK>
VK_ID_CLIENT_SECRET=<Защищённый ключ>
SOCIAL_REDIRECT_BASE=https://weconomics.ai
```

и перезапустить `web` (`docker compose up -d web`).

⚠️ **`SOCIAL_REDIRECT_BASE` обязателен на бою.** `https` за nginx сайт и так
видит (`SECURE_PROXY_SSL_HEADER` + `X-Forwarded-Proto` в
`deploy/nginx/available/django.conf`), но сайт отвечает на ДВУХ именах —
weconomics.site и weconomics.ai, — а в кабинетах сервисов прописан один адрес
возврата. Без переменной человек с weconomics.site получил бы от сервиса отказ
«redirect_uri не совпадает». С ней адрес возврата всегда
`https://weconomics.ai/auth/<сервис>/callback/`, а вход, начатый на .site, сначала
переводится на то же начало на .ai (иначе `state` остался бы в сессии другого
имени).

Проверить после выкатки (внутри контейнера, см. `docs/SERVER.md`):

```bash
docker compose exec web python manage.py social_check
```

Ожидается две строки в конце: «Яндекс: готов …» и «VK: готов». `SOCIAL_STORE_BIRTHDATE=1` —
только после ред. 3 документов (карточка Notion у Анича).

## 5. Диагностика: `manage.py social_check`

```powershell
venv313\Scripts\python.exe manage.py social_check --base http://127.0.0.1:8010   # Яндекс у себя
venv313\Scripts\python.exe manage.py social_check --base http://localhost        # VK ID у себя
venv313\Scripts\python.exe manage.py social_check                                # боевой адрес
```

По каждому сервису: флаг, ключ («задан, длина N», сам ключ не печатается),
адрес возврата, ответ адреса авторизации (код, конечный хост, признаки ошибки) и
итог одной строкой. Что команда видит без входа в сервис:

- **VK ID** проверяет приложение и адрес возврата сразу: «готов» значит, что
  страница VK открылась с названием приложения; «адрес возврата не прописан в
  кабинете сервиса» — добавить адрес в «Доверенный Redirect URL»;
- **Яндекс** без входа ведёт на паспорт и о приложении молчит, поэтому команда
  ещё меняет заведомо неверный код: известному приложению Яндекс отвечает
  `invalid_grant`, неизвестному — `invalid_client` («Яндекс не знает приложение с
  этим ClientID»). Адрес возврата Яндекс сверяет только после входа — его нужно
  сверить с кабинетом глазами по строке «адрес возврата».

Если вход сорвался уже после «Разрешить», сайт показывает свою страницу с одной
фразой («Вход через Яндекс ID отменён», «VK ID не ответил…») и кнопками
«Попробовать снова» / «Войти по почте». В журнал сервера уходит только сервис,
шаг (`authorize`, `state`, `exchange`, `data`) и причина — без кода
авторизации, токена, `device_id` и почты.

**Причины в журнале (раунд 4)** — строка вида `Вход через vk не удался: шаг
exchange, причина timeout`:

| Причина | Что значит | Повтор |
|---|---|---|
| `timeout` | не соединились с сервисом за `SOCIAL_HTTP_TIMEOUT` (20 с) | один |
| `network`, `network_dns`, `network_tls` | сеть, имя хоста, шифрование — до отправки запроса | один |
| `timeout_response` | запрос ушёл, ответа нет | нет: код мог быть погашен |
| `network_response` | связь оборвалась после отправки | нет |
| `http_400 invalid_grant` | HTTP-код и поле `error` из ответа сервиса | нет |
| `bad_response` | ответ не JSON-объект | нет |
| `no_token`, `no_user_id` (шаг `data`) | сервис ответил без токена или без номера аккаунта | нет |
| `access_denied` и др. (шаг `authorize`) | `error=` в адресе возврата | — |

Таймаут человек видит как «VK ID долго не отвечает. Попробуйте ещё раз». Весь
вход с повтором укладывается в 50 с (`TOTAL_BUDGET`) — меньше 60 с gunicorn и
nginx. Тот же адрес возврата, пришедший второй раз (браузер повторил запрос,
пока первый ждал сервис), второго обмена не делает: «Вход уже выполняется».

На своём компьютере кнопка VK ID на `127.0.0.1` или на другом порту показывает
подсказку «Для проверки VK ID откройте http://localhost/login/» (только при
`DEBUG`) — вместо чужой ошибки VK.

## 6. Что должно получиться

1. На `/login/` и `/register/` сверху две кнопки во всю ширину: чёрная «Войти с
   Яндекс ID» и синяя «Войти с VK ID», под ними «или».
2. Нажал → страница сервиса с названием «Weconomics» и списком данных (без
   телефона) → «Разрешить».
3. Новый человек → экран «Почти готово, {имя}» с двумя галочками → «Продолжить» →
   онбординг. Если сервис не отдал почту — сначала «Осталась почта».
4. Человек, чья почта уже подтверждена у нас, — сразу входит в свой аккаунт.

Если вместо этого чужая страница с ошибкой — проверить, что адрес возврата в
кабинете сервиса совпадает с адресом в строке браузера ДО знака `?` буква в букву
(включая `/` на конце и `http`/`https`).
