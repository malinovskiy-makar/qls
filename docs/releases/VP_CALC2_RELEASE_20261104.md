Графики влиты merge-коммитом, без squash, force-push и общего rebase. Сохранены
обе истории, актуальные зависимости, регистрация, почта, Telegram, согласия,
cookies и атрибуция VP. Конфликты CLAUDE/архива сведены вручную; центральные
SEO-компоненты VP сочетаются с новой страницей графиков. Инструкции старой
изолированной Mac-сессии сохранены в её архиве, а не распространены на репозиторий.

Последнее уточнение владельца заменяет промежуточные макеты: три действия
остаются в hero; проверка числа — четвёртая карточка нижней панели. Для гостя
регистрация занимает три места, проверка числа — четвёртое. На обычном desktop
страница помещается в окно; на телефоне используется обычная вертикальная
прокрутка. Класс по умолчанию — 11, в заголовке есть «по экономике», «До тура»
написано с большой буквы. Лидерборд и предыдущие действия сохранены.

V01–V05 исправляются в размещении SVG, без изменения формул: легенда двигается
единым блоком; подпись точки сохраняет привязку; учитываются границы холста и
кривые; числа отступают от ручек поперёк оси; близкие координаты получают второй
ряд. Область двойного щелчка следует за подписью. Шрифт измеряется без скрытого
CSS-перехода. На телефоне у графиков один поток страницы; ни в выборе, ни в
открытой модели нет нижнего юридического футера. Cookie-панель сохранена.

Production пока не содержит pdflatex. Поэтому образ дополнен TeX Live,
кириллическими CM-Super/LH и системными метриками T2A. Метрики готовятся при
сборке, а не в HOME пользователя. Ограничения PDF-компилятора (закрытый каталог,
openin/openout, запрет shell escape, таймаут) не ослаблены. Цена решения —
увеличение размера образа и времени первой сборки; ML-пакеты не добавлены.

Два консервативных решения: реальные данные из восстановленного дампа не
подключаются к просмотру или исходящим сервисам; main не обновляется до
проверки единого кандидата, поскольку таймер main автоматически обновляет dev.
Ручная приёмка владельцем не является условием завершения подготовительных работ.

На полном исходном прогоне обнаружен недостаточный запас шапки персонала:
1022,5 / 1118,5 px для ряда и 28,5 px запаса у имени вместо требуемых 35.
Три порога увеличены на 8 px; текст и состав навигации не меняются. Проверка
18 граничных ширин прошла, полный перебор 700–1920 остаётся в браузерном CI.
Общий бюджет CI увеличен с 45 до 120 минут по фактически измеренному
последовательному A+B (92 минуты). Таймауты отдельных тестов не повышены.

## Доказательства перед выпуском

На **одном и том же окончательном SHA** обязательны пять категорий CI:
ruff; bandit и pip-audit; миграции с нуля и отсутствие новых миграций;
полные A и B последовательно без `--parallel`; production deploy-check.
B должен завершиться даже при падении A. Старые сбои не переносятся в новый
отчёт как разрешённые исключения. Не уменьшать набор, точность или пороги.

Дополнительно: 44 модели / 1053 числовых проверки / 2062 проверки паритета;
128 аналитических сценариев; состояние, undo/redo и ссылки; 48 настоящих
TeX/PDF с проверкой Poppler; контрольные круг и Лаффер; запрет нелинейной второй
страны. Галерея — 44 × 2 темы × desktop/tablet/phone в Chromium и WebKit.
WebKit-эмуляция не является проверкой настоящего iPhone.

Новые проверки интерфейса включают нижнюю панель VP, отсутствие перекрытия
трёх действий, desktop без прокрутки, доступный диалог проверки числа;

Контрольные мутации выполняются после checkpoint, затем исходники возвращаются
побайтно и проверки снова проходят. Журналы и изображения находятся вне Git:

2. Повторно прочитать production SHA, сервисы, миграции, активные попытки,
   свободное место и таймеры. Сохранить текущий image ID всех web/ws/tgbot и
   старую статику. Не трогать `.env`, nginx, ключи и архив
   `deploy/deploy_fixtures_approved.tar.gz`. Не запускать старый импорт 33 YAML
   или rescore: данные уже загружены, эта сессия не меняет их.
3. Собрать образ из **git archive**, а не грязного рабочего каталога:

   ```sh

   RELEASE_DIR=/srv/weconomics/releases/$RELEASE_SHA
   install -d -m 700 "$RELEASE_DIR/source"
   git archive "$RELEASE_SHA" | tar -x -C "$RELEASE_DIR/source"
   docker build --build-arg GIT_SHA="$RELEASE_SHA" -t "weconomics-web:$RELEASE_SHA" "$RELEASE_DIR/source"
   ```

   Сохранить digest; проверить non-root, отсутствие torch/sentence-transformers,

4. В короткое окно обслуживания остановить новые записи по существующему

   pg_restore --list и восстановление в отдельной БД. Не обрывать активную

   проверенным production SHA и кандидатом новых файлов миграций нет.

6. Проверить из контейнера и снаружи: healthz, статические CSS/JS без 404,

## Откат и main

До открытия записей: вернуть сохранённый образ и соответствующую статику для
всех web/ws/tgbot; сверить здоровье. Поскольку схема не меняется, восстановление
БД обычно не нужно. Если оно необходимо из-за повреждения, делать только в
закрытом окне по проверенному плану восстановления, с явной сверкой backup.

После появления новых записей: **не восстанавливать старый дамп автоматически**.
Совместимый откат кода/статики сохраняет новые ответы и регистрации. При
несовместимости — исправление вперёд либо отдельный план переноса новых записей;
удалять их ради быстрого отката нельзя. Отказ Telegram сам по себе не причина
откатывать базу.

Актуальная объединённая ветка и PR публикуются на GitHub. Слияние в main должно
сохранять проверенный SHA (fast-forward, где возможно) либо пройти CI заново
на merge-SHA. Force-push/rebase общих веток не применяются. Автовыкатка dev
из main учтена; публикация ветки не означает, что production обновлён.
