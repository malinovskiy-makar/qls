# Работы победителей и призёров МОШ по экономике

Корпус настоящих проверенных олимпиадных работ с баллами по задачам — для
проверки рукописных решений ИИ (ИИ-стратегия, раздел «Данные»). Организатор
публикует сканы работ победителей и призёров заключительного этапа 2021–2025
(«2025» = учебный год 2024/2025). Команда `mosh_works` разбирает таблицы
призёров, скачивает zip со сканами и читает баллы по задачам с первой страницы.

## Правила (не переоткрывать)

1. **Берём ТОЛЬКО работы, на которые есть ссылка в таблице призёров.** Адрес
   zip берётся из ссылки и никак больше: четыре цифры в конце имени у каждой
   работы свои, формулы нет. **Подбор адресов запрещён** — ни четырёх цифр, ни
   соседних номеров работ, ни других папок на reg.olimpiada.ru. Остальные
   участники — только через запрос организатору. Парсер отбрасывает ссылку
   неожиданного вида (`listing.pick_zip_url`), клиент ходит только на два хоста
   (`fetch.ALLOWED_HOSTS`), а работа без ссылки получает `status=failed`,
   причина «нет ссылки на zip в таблице», и ни одного запроса.
2. **Данные — вне репозитория**, по умолчанию
   `C:\Users\shipu\weconomics-data\mosh_works\` (ключ `--dir`; папка внутри
   репозитория отвергается). В git — только код, тесты на выдуманных данных и
   этот документ.
3. **ФИО не храним нигде** — ни в index, ни в именах файлов, ни в отчётах, ни в
   логах, ни в Notion. Участник = номер работы. Столбец «Ф.И.О.» отбрасывается в
   самом разборщике таблицы (текст его ячеек не накапливается даже во
   временных списках). Имена файлов внутри zip с кириллицей и пробелами
   распаковываются под нейтральным `fNNN.<расширение>`, в журнал идёт только
   причина. Сами сканы содержат фамилии только на листах решений — они лежат
   лишь в папке данных.
4. **В модель уходит только вырез таблицы баллов** (`scans.BAND`: x 0,02–0,98,
   y 0,50–0,91 первой страницы — ниже QR, номера участника и «аудитории»), через
   `core.run` — единственную дверь к моделям. Каждый вырез сохраняется в
   `crops/`. Текст решений и пометки проверяющих на листах не читаются.
5. **Вежливость к чужим серверам** — общий клиент ВП (`vp_works.hse.Client`,
   метод `fetch`): не чаще 1 запроса в секунду НА ВСЁ (один клиент на
   reg.cpm.moscow и reg.olimpiada.ru), User-Agent `WeconomicsResearchBot`, три
   повтора с паузой 5/15/45 с, `IncompleteRead` и обрывы — повторяемая ошибка,
   403/429/капча → `Blocked`, команда останавливается, а не обходит. 404/410 не
   повторяются. Если страница открывается в Chrome, а из Python нет — стоп и
   отчёт владельцу (на машине владельца постоянно включён VPN).
6. В базу команда не пишет ни строки. Вызов модели обёрнут в
   `transaction.atomic()`: при отказе поставщика `core.run` пишет строку
   `AiUsageLog` даже с `log=False` — известный баг (карточка в Notion),
   исключение её откатывает.

## Команды

```bash
manage.py mosh_works index    --dir D [--years 2021,…]
manage.py mosh_works download --dir D [--limit N] [--only id,…|@файл] [--stop-after-fails N]
manage.py mosh_works scores   --dir D [--limit N] [--only …] [--years …] [--max-usd 1.50] [--yes] [--retry-review] [--preview 5]
manage.py mosh_works report   --dir D
```

- `index` — 5 запросов к страницам призёров → `index.jsonl`.
- `download` — докачка: целый zip (`zip_ok`: открывается, `testzip` чист) заново
  не качается, прерванная распаковка достраивается; zip пишется через `.part`.
  Распаковка — `fetch.extract_safe`: плоские имена, ни `..`, ни `/`, ни диска,
  ни расширений вне `pdf/jpg/jpeg/png`; файлы не исполняются.
- `scores` без `--yes` — только план (+ `--preview N` вырезов для осмотра),
  ни одного вызова модели. С `--yes` — GLM-5.3-Flash, 6 потоков
  (`MOSH_WORKS_WORKERS`). `--max-usd` — потолок на ВСЕ прогоны вместе (прежние
  траты берутся из `scores.jsonl`): достигнут — новые вызовы не начинаются.
  По умолчанию 2021 год исключён (пятна), `--years 2021` включает его.
  `--retry-review` — второй проход по review: тот же вырез с подсказкой про
  похожие цифры, затем повёрнутый на 180°.

## Файлы в папке данных

| Файл | Что |
|---|---|
| `index.jsonl` | строка на работу: таблица и скачивание (поля ниже) |
| `scores.jsonl` | баллы по задачам, строка на прочитанную/закрашенную работу |
| `zip/<год>/<work_id>.zip`, `scans/<год>/<work_id>/` | zip и распаковка |
| `crops/<год>/<work_id>.png` | вырез, ушедший в модель (`_rot180` — повёрнутый) |
| `review.csv` | очередь ручной проверки баллов |
| `RECON.md`, `REPORT.md` | разведка и итоговый отчёт (только числа) |

Поля index: `work_id, year, season ("2024/2025"), grade_participation (класс
заданий на бланке), grade (класс ученика), total_listed (балл из таблицы призёров),
result (winner/prizewinner), prize_degree (2/3 только у 2021), zip_url, listed_at`;
после скачивания — `zip_path, zip_bytes, sha256, files, pages, status (ok/failed),
reason, skipped_members` и разбор первой страницы: `source_kind (jpg/pdf),
first_page, variants, stickers_pct, has_stickers, band_stickers_pct,
band_red_pct, pdf_stickers_pct`.

## Что внутри zip (разведка 09.10.2026)

2021 и 2025 — один PDF (растровый, без текстового слоя); 2022 — JPG и PDF
(JPG — проверенный скан, PDF — вариант без красных пометок и с жёлтыми
пятнами); 2023 — JPG; 2024 — два комплекта JPG, чистый и проверенный. Первая
страница — «титул» с таблицей «Задача 1–4 | Сумма» × строки «Баллы / Член жюри /
Итог»: её находит `scans.analyze` по сходству с первым файлом, при двух
комплектах берёт тот, где в полосе больше красных чернил; JPG приоритетнее PDF.
ФИО на первой странице нет ни в одном бланке.

⚠️ **Обложка с ФИО (2021).** У части работ 2021 (4 из 237, найдены 13.10.2026
до первого платного вызова) первая страница PDF — «Уважаемые участники
олимпиады!» с фамилией, именем, отчеством и школой; таблица баллов на второй.
Вырез «y 0,50–0,91 первой страницы» с такой страницы унёс бы ФИО в модель.
Защита (`scans.is_cover`): страница, чей верх (логотип, QR) почти совпадает с
верхом следующей страницы того же скана, — обложка; у 2021 ещё чернила в зоне
ФИО. Обложка пропускается (`first_page_index`, `cover_skipped`), нет безопасной
страницы — `first_page=None`, работа в модель не идёт; `first_page_image` проверяет
страницу ещё раз перед вырезом. Автоматика не заменяет глаз: **перед платным
прогоном вырезы (`scores --limit N --preview N`) смотрятся человеком**; так
пройдены вырезы всех проб. Зону ФИО для шаблонов 2022–2025 применять нельзя
(там в ней обычный текст) — только сходство шапок.

**Жёлтые пятна** — закрашенные пометки жюри: в таблице баллов они непрозрачны
(баллы под ними не читаются), поверх решения — полупрозрачны. `has_stickers` —
доля жёлтого на странице больше `scans.STICKER_PCT`; работа, у которой жёлтым
закрыта полоса таблицы (`band_stickers_pct ≥ HIDDEN_BAND_PCT`), получает в
`scores.jsonl` статус `hidden_by_stickers`: она не идёт ни в модель, ни в
review, денег не тратит.

## Проверка баллов

Балл в таблице призёров — ПОСЛЕ апелляции, на скане — ДО (в 2025 скан меньше на
8–18). Поэтому `ok` ставится не по сверке с `total_listed`, а по внутренней
согласованности скана: сумма баллов по задачам == клетка «Сумма» той же строки
(допуск 0,5). `appeal_delta = total_listed − итог скана` обязана быть ≥ 0
(отрицательная — review `appeal_negative`). Если клетка «Сумма» пуста, а сумма
задач == `total_listed` — тоже `ok`, `verified_by = listed`. Пустая клетка
«Сумма» и расхождение с таблицей — review `no_total_cell` (разница пишется).
Статусы: `ok` / `partial` (не все задачи вписаны, например нет задачи 4 в 2022:
`missing` перечисляет недостающие) / `review` / `hidden_by_stickers`. У 7 класса
2025 первый столбец «1-5» — одна клетка; баллы пишутся как есть с пометкой
`merged_1_5`, делить их не пытаемся. Пустая клетка = «не вписано», прочерк = 0,
нечитаемое (null) — review.

## Щит выреза и второе чтение (правила владельца 13.10.2026)

**Щит (`scans.table_shield`)**, годы 2022–2025: вырез идёт в модель, только если
на нём видны рамка таблицы и её шапка — после выравнивания наклона ищутся
вертикали (6–12), по ним таблица, горизонтали внутри (3–12) и чернила в
клетках шапки («Задача | 1 | 2 | 3 | 4 | Сумма», не менее 3 клеток). Обложка,
пустая страница и лист решения линий таблицы не дают, клетчатая бумага даёт их
слишком много. Не прошёл — `scores_status=held_shield`, причина
`shield_no_frame` / `shield_no_header`, вырез лежит в `held/<год>/` (для глаз),
в `crops/` не попадает, строка есть в `review.csv`. Посмотрели глазами и всё в
порядке — `--release id,…|@файл` пускает работу в модель. Для 2021 щит не
применяется (там свои правила: отсев обложек и зона ФИО в `scans.analyze`).
Проверено на 44 вырезах проб: 42 проходят, 2 удержаны (очень бледная таблица
и таблица с недорисованными линиями); все негативы (4 обложки 2021, листы
решений, клетчатая бумага, работы без титула) удержаны.

**Второе чтение (`scores.double_read`).** Когда клетка «Сумма» пуста и сумма
задач не равна `total_listed` (review `no_total_cell`), вырез читается второй
раз — повёрнутым на 180° и с подсказкой про похожие цифры и половинки. `ok`
(`verified_by=double_read`) — только если ОБА чтения дали одни и те же баллы И
`appeal_delta = total_listed − сумма скана` больше нуля и не больше 10 %
`total_listed`; иначе review с причиной (`double_read_disagree`,
`double_read_delta_not_positive`, `double_read_delta_large`). Если баллы
записаны столбцом «1-5» одним числом (`merged_1_5`) и сумма не равна
`total_listed` — всегда review `merged_unverified`, без второго чтения.

## Бланк 2021 (правила владельца 13.10.2026)

Пятна закрывают часть клеток, остальные читаются; нередко вторая проверка
(строка «Баллы» №3) дублирует первую. Для 2021 модель читает ОБЕ строки «Баллы»
отдельно (`scores.SCHEMA_ROWS`, `SYSTEM_ROWS`), закрытое пятном — null; итог по
задаче — последняя непустая из строк; `ok` — только если значение есть у всех
задач и сумма == `total_listed` (`verified_by=listed`); часть задач закрыта или
не вписана — `partial` (найденное хранится, закрытое — null); закрыто всё —
`hidden_by_stickers` (при полосе, закрытой на ≥ 8 %, — без вызова модели).
Второй вид бланка 2021 — «Задание №1…№5 / Балл» (одна строка, 5 задач): те же
правила (`form: tasks5`). `scores` по умолчанию 2021 не берёт: включать
`--years 2021`; массовый прогон 2021 — только после «да» владельца.
`--limit N` стратифицирован: поровну на каждый год.

## Тесты

`problems/tests/test_mosh_works.py` — только выдуманные данные (свой HTML
таблицы с выдуманными именами, zip и сканы собираются в тесте, подставной
поставщик ИИ, сеть не трогается). Зубастость проверена двенадцатью внесёнными
дефектами (ФИО в index, адрес по шаблону, повторная закачка, битый zip как ok,
`../` в архиве, сумма без сверки, модель без `--yes`, `--max-usd` без обрыва,
отрицательная `appeal_delta` как ok, обложка 2021 идёт в модель, вырез без рамки
идёт в модель, `double_read` ставит ok без совпадения чтений) — каждый краснит
свой тест.

161 вторых чтений не совпали 115. Теперь второе чтение — тот же ровный вырез,
увеличенный вдвое, с другой подсказкой («читай каждую клетку отдельно; маленькая 5

для независимости GLM-5.3 (полную), но она **картинки не принимает** (замер 15.09 и
повтор 13.10.2026: 400, код 1210), а `glm-5v-turbo` дал пустой ответ в 5 из 6 вызовов
и стоит ≈ $0,015 за вызов. Читает поэтому та же Flash (`scores.MODEL_SECOND`);
независимость слабее, чем у разных моделей — правдоподобие разницы (`0 ≤ appeal_delta ≤
10 %`) остаётся обязательным. `--second-pass` пересчитывает review
`double_read_disagree` и `no_total_cell`; сбой второго чтения не стирает первое.
