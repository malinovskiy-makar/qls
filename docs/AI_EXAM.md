# Экзамен для ИИ

Линейка, на которой меряется любая модель и любая правка чата. Решение и
его причины — [ADR 0134](adr/0134-ai-exam-v0.md). Не путать с
`problems/exam_engine.py` — это контрольные учеников.

**Версия v0 — «Решатель-150».** 150 расчётных задач банка с числовым ответом,
каждую проверил человек; 30 из них — «сейф»: на них ничего не настраивают,
смотрят только в конце.

| Сессия | Что делает |
|---|---|
| «Экзамен A» (07.10.2026) | разведка банка, отбор кандидатов, страницы проверки для людей |
| «Экзамен A2» (07.10.2026) | до раздачи людям: у вопроса несколько чисел или «не проверяется», формат разметки 2, неравенства и коэффициенты формул не предлагаются ключом; страницы перевыпущены |
| «Экзамен B» | приём разметки, сборка экзамена и сейфа, прогон моделей, отчёт |

⚠️ **ВНЕ репозитория.** Репозиторий публичный, экзамен утечь не должен. Папка
по умолчанию — `<рядом с репозиторием>/weconomics-data/ai_exam/v0`
(тот же приём, что в `verify_matek_fixed.py`), у каждой команды есть `--dir`.

## Команда

```bash
manage.py ai_exam_candidates --recon                              # воронка → RECON.md
manage.py ai_exam_candidates --count 232 --chunks 4 --seed 20261007
manage.py ai_exam_candidates ... --force                          # перезаписать кандидатов
manage.py ai_exam_candidates ... --dir ПАПКА
```

Только чтение: в базу ни строки, к модели ни одного вызова. Существующий
`candidates.jsonl` без `--force` не перезаписывается — после раздачи страниц
список меняться не должен. В конце команда печатает инварианты: кандидатов
ровно `--count` (меньше — только если меньше пул), повторов id 0, пар из
одной группы копий 0, пачки различаются не больше чем на 1, повтор с тем
же seed даёт тот же sha256, число строк `Problem` и максимум `updated_at`
до и после совпадают.

## Воронка (двенадцать фильтров по порядку)

Основа — `catalog.filters.base_queryset('catalog')`, свой признак видимости
не заводится.

1. `task_nature` = расчётная
2. `answer_consistency` = согласован
3. `text_quality` = чистая
4. решение `Problem.solution` не короче 200 знаков, `solution_needs_review` = False
   (решений у подпунктов в видимом банке нет)
5. `multiple_problems` = False
6. не тест с вариантами: `problem_types.test_kind` не single / boolean / multi
7. без картинки: нет маркера `[[FIGURE:` в условии и условиях подпунктов
8. условие вместе с подпунктами 100–4000 знаков, подпунктов не больше 6
9. ключ предлагается (`exact` или `extracted`) на каждый вопрос: вся задача,
   если подпунктов нет; иначе каждый подпункт с ответом `ProblemPart.answer`
10. одна задача на группу копий: с `dup_is_best`, иначе с меньшим id
11. есть каноническая тема
12. нет открытого расхождения второго мнения: последняя `AnswerSecondOpinion`
    не (agrees=False и resolved=False) и не `resolution='model_right'`

**Правило решения.** Пул ≥ 600 и не меньше 24 тем с 8+ задачами — дальше.
Иначе ослабления по одному с пересчётом: (а) `text_quality` допускает
«мелкие_дефекты»; (б) решение от 80 знаков; (в) в темах, где меньше 8 задач,
допускается ключ `none` — его впишет проверяющий. После всех трёх пул < 350
или тем с 5+ задачами < 20 — СТОП, решает владелец.

**Своя тема** задачи — та из её канонических, у которой пул меньше (при
равенстве — меньший `Topic.order`, затем id).

### Отбор и пачки

- Квота темы = `count // число тем с непустым пулом`; остаток — по одной
  темам с самым большим пулом. Нехватку темы забирают темы с наибольшим
  остатком пула, по одной задаче за круг.
- Внутри темы — по кругу уровней: средняя (3) → сложная (4–5) → лёгкая (1–2)
  → без оценки. Внутри уровня `exact` раньше `extracted` раньше `none`, дальше
  порядок от `random.Random(seed)`. Не больше трёх задач одного источника на
  тему, пока есть другие.
- Пачки: задачи раздаются по кругу общим счётчиком; внутри пачки порядок —
  по кругу тем. **Последняя пачка — резерв**: её проверяют, только если после
  остальных годных меньше 150.

## Форматы

### candidates.jsonl

Строка на задачу, ключи отсортированы, UTF-8:

| Поле | Что это |
|---|---|
| `id`, `topic`, `section` | задача, своя тема, блок (`problems.sections.section_of`) |
| `difficulty`, `level` | сложность 1–5 и уровень: лёгкая / средняя / сложная / без оценки |
| `problem_type`, `source` | как в банке; источник — первая привязка по id |
| `statement_hash` | sha256 условия, ответа и подпунктов — ловит правку банка после проверки |
| `asks` | `[{part_id, label, bank_answer, value, unit, percent, kind}]` — вопрос и предложенный ключ |
| `chunk`, `n`, `seed` | пачка, номер в пачке, зерно |

### Разметка `ai_exam_review/2`

Отдаёт страница кнопкой «Скачать разметку (JSON)», файл
`ai_exam_review_chunk<k>_<имя>.json`. Формата 1 (одно число на вопрос) больше
нет: он не доходил до людей, обратной совместимости нет, `validate_review`
его отвергает.

```json
{"format": "ai_exam_review/2", "seed": 20261007, "chunk": 1,
 "reviewer": "…", "exported_at": "…",
 "rows": [{"id": 1, "verdict": "ok", "reason": "", "comment": "",
           "asks": [{"part_id": null, "skip": false,
                     "values": [{"label": "P", "value": "5", "unit": "",
                                 "percent": false, "tol": ""},
                                {"label": "Q", "value": "20", "unit": "шт.",
                                 "percent": false, "tol": ""}]}]}]}
```

`verdict` — `ok` / `bad` / `skip`. Причины `bad`: `statement`,
`answer_wrong`, `not_numeric`, `needs_figure`, `not_calc`, `other`.

**Вопрос** — задача целиком, если подпунктов нет, иначе каждый подпункт
(`part_id`). У вопроса:
- одно число — подпись `label` можно не писать;
- несколько чисел («найдите цену и количество») — у каждого своя подпись,
  непустая и не повторяющаяся (без учёта регистра и пробелов по краям);
- `skip: true` — «не проверяется (ответ не число)»: пункт просит объяснить,
  построить график, вывести формулу. Задача остаётся в экзамене с остальными
  вопросами; `values` такого вопроса при приёме игнорируется (страница
  выгружает его пустым).

Проверка — `problems.ai_exam.review.validate_review(payload, candidates_by_id)`
→ (годные строки, жалобы). Плохая строка — жалоба, а не падение; годные
возвращаются, даже если соседние плохи. Десять видов жалоб:

| Вид | Когда |
|---|---|
| `unknown_id` | задачи нет среди кандидатов |
| `unknown_verdict` | вердикт не ok / bad / skip |
| `no_reason` | у `bad` нет причины |
| `no_reviewer` | пустой `reviewer` (на весь файл) |
| `key_shape` | у `ok` список `asks` не совпал с вопросами задачи — по числу или по `part_id` |
| `no_values` | у непропущенного вопроса нет ни одного числа |
| `labels` | у вопроса два и больше чисел, а подписи пустые или повторяются |
| `key_value` | значение не разбирается `to_number` |
| `bad_tol` | `tol` не пусто и не положительное число |
| `all_skipped` | у `ok` все вопросы «не проверяется» — проверять нечего |

Не файл разметки вовсе (чужой `format`, нет `rows`) — `ValueError`.

## Страница проверки

Самодостаточный HTML: открывается двойным щелчком с file:// без сети, KaTeX
вшит (`katex_head` и `render_field` — импортом из `dedup_human_review_html`),
ответы копятся в localStorage под ключом `qls-ai-exam-v0-<seed>-chunk<k>-f2` (суффикс — версия формата: состояние страницы прежней версии не подхватывается).
Клавиши: 1 / 2 / 3 — вердикт, стрелки — соседняя карточка (в полях ввода
клавиши не перехватываются).

**Ключ на карточке — по вопросам.** У каждого вопроса: строки чисел («что
это» / число / единицы / «это проценты» / допуск), кнопка «+ ещё число»,
крестик у лишней строки (последнюю строку убрать нельзя) и галочка «не
проверяется (ответ не число)» — она гасит строки вопроса. Первая строка
заполнена предложением программы; подпись к нему зависит от вида ключа:
`exact` — без подписи, `extracted` — «ключ извлечён программой — проверьте»,
`none` — «ответа в банке нет — впишите из решения».

**Выгрузка не блокируется никогда.** Предупреждение печатается над списком
после скачивания: «Годится» без имени проверяющего; у непропущенного вопроса
нет числа; несколько чисел без подписей; все вопросы «не проверяется».
Пустые строки чисел в файл не попадают.

⚠️ **Проверка слепая:** на странице нет ни второго мнения модели, ни
`answer_consistency`, ни `human_review` — человек проверяет задачу, а не
согласие с машиной. Сторожит `test_ai_exam_review.PageTests.test_page_is_blind`.

## Правило сравнения чисел

`problems/ai_exam/numbers.py`, чистые функции.

**`to_number(text)`** → `Fraction` или `None`. Перед разбором: снять `$…$` и
`$$…$$`; `\,` `\;` `\!` `\ ` и `~` — в пробел; `{,}` → запятая; `−` и `–` →
минус; разрядный пробел (обычный, неразрывный, тонкий) перед группой из трёх
цифр убрать («1 250» → 1250); снять ведущие `≈ = ~` и хвостовую точку;
`\frac{a}{b}`, `\dfrac`, `\tfrac` с целыми a и b → a/b; хвостовой `%` или `\%`
— признак процентов; короткий хвост единиц (до 12 знаков без цифр) отделить.
Дальше — `problems.answer_check.parse_number` (запятая — десятичная).
Степени и «2·10^3» — вне v0, это `None`.

**`find_numbers(text)`** — все числа в тексте с TeX. Индексы (`Q_1`, `Q_{1}`,
`P1`) и степени (`x^2`, `10^3`) числами не считаются.

**`propose_key(raw)`** → `{value, unit, percent, kind}`: `exact` — вся строка
это одно число (хвост единиц допустим); `extracted` — в тексте ровно одно
число; `none` — иначе.

⚠️ **Заведомый мусор не предлагается** (с A2): ключ `none`, если в ответе
есть знак неравенства (`< > ≤ ≥ \le \ge \leq \geq \lt \gt`) или число стоит
вплотную к латинской букве справа либо умножается на неё (`240Q`, `2x`,
`240\cdot Q`, `240·Q`, `240*Q`) — это коэффициент формулы, а не ответ.
Кириллический хвост вплотную («5кг», «20ед.») по-прежнему единицы. Причина:
в A программа предлагала для `A>25` и `TC=240Q` числа 25 и 240 с пометкой
«проверьте», и проверяющий мог им поверить. Остаётся `extracted` для всего
прочего, где число одно (`Q = 20`), — на странице оно подсвечено.

**`matches(given, value, percent=False, tol=None)`** — верно, если
|g − k| ≤ допуск. Допуск — `tol`, если задан; иначе
max(0,005; 1 % от |k|; 0,5·10^(−d) при d ≥ 1), где d — число знаков после
запятой в записи ключа (у дроби d = 0). При `percent=True` верно и для
100·g; если в ответе стоит `%`, а ключ — доля, верно и для g/100.
