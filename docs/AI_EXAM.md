# Экзамен для ИИ

Линейка, на которой меряется любая модель и любая правка чата. Решение и
его причины — [ADR 0134](adr/0134-ai-exam-v0.md). Не путать с
`problems/exam_engine.py` — это контрольные учеников.

**Версия v0 — «Решатель-150».** 150 расчётных задач банка с числовым ответом,
каждую проверил человек; 30 из них — «сейф»: на них ничего не настраивают,
смотрят только в конце.

| Сессия | Что делает |
|---|---|
| «Экзамен A» (07.10.2026) | разведка банка, отбор кандидатов, страницы проверки для людей |
| «Экзамен A2» (07.10.2026) | до раздачи людям: у вопроса несколько чисел или «не проверяется», формат разметки 2, неравенства и коэффициенты формул не предлагаются ключом; страницы перевыпущены |
| «Экзамен B» (08.10.2026) | приём разметки, сборка экзамена и сейфа, шов чата `ask_model`, прогон «Решатель» и «Утечка», отчёт «было → стало» |
| «Экзамен C» (28.10.2026, ночь) | **v1 из официального эталона v6** (раздел «v1 из эталона» ниже, [ADR 0167](adr/0167-ai-exam-v1-from-reference-v6.md)): блоки A/B, судья Claude, «Утечка» по режимам |

## Команда

```bash
manage.py ai_exam_candidates --recon                              # воронка → RECON.md
manage.py ai_exam_candidates --count 232 --chunks 4 --seed 20261007
manage.py ai_exam_candidates ... --force                          # перезаписать кандидатов
manage.py ai_exam_candidates ... --dir ПАПКА
```

Только чтение: в базу ни строки, к модели ни одного вызова. Существующий
`candidates.jsonl` без `--force` не перезаписывается — после раздачи страниц
список меняться не должен. В конце команда печатает инварианты: кандидатов
ровно `--count` (меньше — только если меньше пул), повторов id 0, пар из
одной группы копий 0, пачки различаются не больше чем на 1, повтор с тем
же seed даёт тот же sha256, число строк `Problem` и максимум `updated_at`
до и после совпадают.

## Воронка (двенадцать фильтров по порядку)

Основа — `catalog.filters.base_queryset('catalog')`, свой признак видимости
не заводится.

1. `task_nature` = расчётная
2. `answer_consistency` = согласован
3. `text_quality` = чистая
4. решение `Problem.solution` не короче 200 знаков, `solution_needs_review` = False
   (решений у подпунктов в видимом банке нет)
5. `multiple_problems` = False
6. не тест с вариантами: `problem_types.test_kind` не single / boolean / multi
7. без картинки: нет маркера `[[FIGURE:` в условии и условиях подпунктов
8. условие вместе с подпунктами 100–4000 знаков, подпунктов не больше 6
9. ключ предлагается (`exact` или `extracted`) на каждый вопрос: вся задача,
   если подпунктов нет; иначе каждый подпункт с ответом `ProblemPart.answer`
10. одна задача на группу копий: с `dup_is_best`, иначе с меньшим id
11. есть каноническая тема
12. нет открытого расхождения второго мнения: последняя `AnswerSecondOpinion`
    не (agrees=False и resolved=False) и не `resolution='model_right'`

**Правило решения.** Пул ≥ 600 и не меньше 24 тем с 8+ задачами — дальше.
Иначе ослабления по одному с пересчётом: (а) `text_quality` допускает
«мелкие_дефекты»; (б) решение от 80 знаков; (в) в темах, где меньше 8 задач,
допускается ключ `none` — его впишет проверяющий. После всех трёх пул < 350
или тем с 5+ задачами < 20 — СТОП, решает владелец.

**Своя тема** задачи — та из её канонических, у которой пул меньше (при
равенстве — меньший `Topic.order`, затем id).

### Отбор и пачки

- Квота темы = `count // число тем с непустым пулом`; остаток — по одной
  темам с самым большим пулом. Нехватку темы забирают темы с наибольшим
  остатком пула, по одной задаче за круг.
- Внутри темы — по кругу уровней: средняя (3) → сложная (4–5) → лёгкая (1–2)
  → без оценки. Внутри уровня `exact` раньше `extracted` раньше `none`, дальше
  порядок от `random.Random(seed)`. Не больше трёх задач одного источника на
  тему, пока есть другие.
- Пачки: задачи раздаются по кругу общим счётчиком; внутри пачки порядок —
  по кругу тем. **Последняя пачка — резерв**: её проверяют, только если после
  остальных годных меньше 150.

## Форматы

### candidates.jsonl

Строка на задачу, ключи отсортированы, UTF-8:

| Поле | Что это |
|---|---|
| `id`, `topic`, `section` | задача, своя тема, блок (`problems.sections.section_of`) |
| `difficulty`, `level` | сложность 1–5 и уровень: лёгкая / средняя / сложная / без оценки |
| `problem_type`, `source` | как в банке; источник — первая привязка по id |
| `statement_hash` | sha256 условия, ответа и подпунктов — ловит правку банка после проверки |
| `asks` | `[{part_id, label, bank_answer, value, unit, percent, kind}]` — вопрос и предложенный ключ |
| `chunk`, `n`, `seed` | пачка, номер в пачке, зерно |

### Разметка `ai_exam_review/2`

Отдаёт страница кнопкой «Скачать разметку (JSON)», файл
`ai_exam_review_chunk<k>_<имя>.json`. Формата 1 (одно число на вопрос) больше
нет: он не доходил до людей, обратной совместимости нет, `validate_review`
его отвергает.

```json
{"format": "ai_exam_review/2", "seed": 20261007, "chunk": 1,
 "reviewer": "…", "exported_at": "…",
 "rows": [{"id": 1, "verdict": "ok", "reason": "", "comment": "",
           "asks": [{"part_id": null, "skip": false,
                     "values": [{"label": "P", "value": "5", "unit": "",
                                 "percent": false, "tol": ""},
                                {"label": "Q", "value": "20", "unit": "шт.",
                                 "percent": false, "tol": ""}]}]}]}
```

`verdict` — `ok` / `bad` / `skip`. Причины `bad`: `statement`,
`answer_wrong`, `not_numeric`, `needs_figure`, `not_calc`, `other`.

**Вопрос** — задача целиком, если подпунктов нет, иначе каждый подпункт
(`part_id`). У вопроса:
- одно число — подпись `label` можно не писать;
- несколько чисел («найдите цену и количество») — у каждого своя подпись,
  непустая и не повторяющаяся (без учёта регистра и пробелов по краям);
- `skip: true` — «не проверяется (ответ не число)»: пункт просит объяснить,
  построить график, вывести формулу. Задача остаётся в экзамене с остальными
  вопросами; `values` такого вопроса при приёме игнорируется (страница
  выгружает его пустым).

Проверка — `problems.ai_exam.review.validate_review(payload, candidates_by_id)`
→ (годные строки, жалобы). Плохая строка — жалоба, а не падение; годные
возвращаются, даже если соседние плохи. Десять видов жалоб:

| Вид | Когда |
|---|---|
| `unknown_id` | задачи нет среди кандидатов |
| `unknown_verdict` | вердикт не ok / bad / skip |
| `no_reason` | у `bad` нет причины |
| `no_reviewer` | пустой `reviewer` (на весь файл) |
| `key_shape` | у `ok` список `asks` не совпал с вопросами задачи — по числу или по `part_id` |
| `no_values` | у непропущенного вопроса нет ни одного числа |
| `labels` | у вопроса два и больше чисел, а подписи пустые или повторяются |
| `key_value` | значение не разбирается `to_number` |
| `bad_tol` | `tol` не пусто и не положительное число |
| `all_skipped` | у `ok` все вопросы «не проверяется» — проверять нечего |

Не файл разметки вовсе (чужой `format`, нет `rows`) — `ValueError`.

## Страница проверки

Самодостаточный HTML: открывается двойным щелчком с file:// без сети, KaTeX
вшит (`katex_head` и `render_field` — импортом из `dedup_human_review_html`),
ответы копятся в localStorage под ключом `qls-ai-exam-v0-<seed>-chunk<k>-f2` (суффикс — версия формата: состояние страницы прежней версии не подхватывается).
Клавиши: 1 / 2 / 3 — вердикт, стрелки — соседняя карточка (в полях ввода
клавиши не перехватываются).

**Ключ на карточке — по вопросам.** У каждого вопроса: строки чисел («что
это» / число / единицы / «это проценты» / допуск), кнопка «+ ещё число»,
крестик у лишней строки (последнюю строку убрать нельзя) и галочка «не
проверяется (ответ не число)» — она гасит строки вопроса. Первая строка
заполнена предложением программы; подпись к нему зависит от вида ключа:
`exact` — без подписи, `extracted` — «ключ извлечён программой — проверьте»,
`none` — «ответа в банке нет — впишите из решения».

**Выгрузка не блокируется никогда.** Предупреждение печатается над списком
после скачивания: «Годится» без имени проверяющего; у непропущенного вопроса
нет числа; несколько чисел без подписей; все вопросы «не проверяется».
Пустые строки чисел в файл не попадают.

⚠️ **Проверка слепая:** на странице нет ни второго мнения модели, ни
`answer_consistency`, ни `human_review` — человек проверяет задачу, а не
согласие с машиной. Сторожит `test_ai_exam_review.PageTests.test_page_is_blind`.

## Правило сравнения чисел

`problems/ai_exam/numbers.py`, чистые функции.

**`to_number(text)`** → `Fraction` или `None`. Перед разбором: снять `$…$` и
`$$…$$`; `\,` `\;` `\!` `\ ` и `~` — в пробел; `{,}` → запятая; `−` и `–` →
минус; разрядный пробел (обычный, неразрывный, тонкий) перед группой из трёх
цифр убрать («1 250» → 1250); снять ведущие `≈ = ~` и хвостовую точку;
`\frac{a}{b}`, `\dfrac`, `\tfrac` с целыми a и b → a/b; хвостовой `%` или `\%`
— признак процентов; короткий хвост единиц (до 12 знаков без цифр) отделить.
Дальше — `problems.answer_check.parse_number` (запятая — десятичная).
Степени и «2·10^3» — вне v0, это `None`.

**`find_numbers(text)`** — все числа в тексте с TeX. Индексы (`Q_1`, `Q_{1}`,
`P1`) и степени (`x^2`, `10^3`) числами не считаются.

**`propose_key(raw)`** → `{value, unit, percent, kind}`: `exact` — вся строка
это одно число (хвост единиц допустим); `extracted` — в тексте ровно одно
число; `none` — иначе.

⚠️ **Заведомый мусор не предлагается** (с A2): ключ `none`, если в ответе
есть знак неравенства (`< > ≤ ≥ \le \ge \leq \geq \lt \gt`) или число стоит
вплотную к латинской букве справа либо умножается на неё (`240Q`, `2x`,
`240\cdot Q`, `240·Q`, `240*Q`) — это коэффициент формулы, а не ответ.
Кириллический хвост вплотную («5кг», «20ед.») по-прежнему единицы. Причина:
в A программа предлагала для `A>25` и `TC=240Q` числа 25 и 240 с пометкой
«проверьте», и проверяющий мог им поверить. Остаётся `extracted` для всего
прочего, где число одно (`Q = 20`), — на странице оно подсвечено.

**`matches(given, value, percent=False, tol=None)`** — верно, если
|g − k| ≤ допуск. Допуск — `tol`, если задан; иначе
max(0,005; 1 % от |k|; 0,5·10^(−d) при d ≥ 1), где d — число знаков после
запятой в записи ключа (у дроби d = 0). При `percent=True` верно и для
100·g; если в ответе стоит `%`, а ключ — доля, верно и для g/100.

## Сборка и сейф (сессия «Экзамен B»)

`problems/ai_exam/build.py` (чистые функции) и команда `ai_exam_build`.
Только чтение банка; файлы — в папке экзамена.

```bash
manage.py ai_exam_build --mark-safe        # safe_candidates.json, один раз, ДО прогонов
manage.py ai_exam_build                    # reviews_in/*.json → BUILD.md + финал или черновик
manage.py ai_exam_build ... --dir ПАПКА    # --force перезаписывает safe_candidates.json
```

**Сейф помечается заранее.** `--mark-safe` берёт 40 кандидатов из пачек 1–3
(резервная четвёртая не берётся), по блокам (`section`) пропорционально
числу кандидатов блока, методом наибольшего остатка; внутри блока — по
`sha256(f'{seed}:safe:{id}')`. Файл пишется один раз. Почему заранее:
черновой прогон на неполном экзамене не должен задеть задачу, которая потом
окажется в сейфе.

**Приём разметки.** Люди кладут выгрузки в `reviews_in/`. Каждый файл —
`validate_review`; жалобы — в BUILD.md построчно (файл, id, вид), плохая
строка не роняет годные. Не разметка (`ValueError`, битый JSON) — строка в
BUILD.md, файл пропущен.

- **Повторная выгрузка заменяет прежнюю.** Тот же проверяющий (без учёта
  регистра и пробелов) и та же пачка в нескольких файлах — читается файл с
  самым поздним `exported_at`, остальные «устарели». Выгружать частями —
  обычное дело.
- **Двое проверили одну задачу.** Годится, только если оба «ok» и ключи
  совпали: тот же набор вопросов и skip, числа равны по `to_number`, те же
  проценты и допуск (подписи не сравниваются). Иначе — КОНФЛИКТ: задача
  исключена, в BUILD.md — кто что поставил; решает владелец правкой файлов.
  «Последний победил» нет намеренно. Если «ok» не сказал никто — задача
  `bad` (есть хоть один «bad») или `skip`.
- **Банк поменялся после проверки.** `statement_hash` по свежей записи (видимость
  — `base_queryset('catalog')`, `problems/ai_exam/loader.py`) не равен хешу из
  candidates.jsonl или задачи больше нет в каталоге — задача исключена.

**Категории задачи** (в сумме — все кандидаты): годна / конфликт / хеш
поменялся / bad / skip / не проверена.

**Сборка.** Сейф — первые 30 годных из `safe_candidates.json` в порядке хеша.
Рабочий набор — годные ВНЕ `safe_candidates.json` по (пачка, номер),
резервная пачка последней, не больше 120. ⚠️ **Годные кандидаты сейфа сверх
тридцати в работу не идут**: по ним мог пройти черновой прогон, а их место
в сейфе могла занять задача, по которой уже настраивали.

- 30 + 120 — **финал**: `exam.jsonl` и `safe.jsonl`.
- иначе — **черновик** `exam_draft.jsonl` из всех годных вне
  `safe_candidates.json`; сейф не собирается, в BUILD.md — сколько не хватает
  и по каким блокам.
- пачки 1–3 проверены целиком, а годных среди кандидатов сейфа меньше 30 —
  в BUILD.md крупно «НУЖНО РЕШЕНИЕ ВЛАДЕЛЬЦА», финал не собирается.

Строка экзамена: `id, section, topic, level, difficulty, statement_hash,
chunk, n, reviewers, asks [{part_id, label, skip, values [{label, value,
unit, percent, tol}]}]`. Команда печатает инварианты и падает, если хоть
один нарушен: сейф ∩ рабочий = 0, safe_candidates ∩ черновик = 0,
safe_candidates ∩ рабочий = 0, повторов id 0, сумма категорий = числу
кандидатов.

## Прогон (сессия «Экзамен B»)

`problems/ai_exam/runner.py` и команда `ai_exam_run`.

```bash
manage.py ai_exam_run --suite solve|leak|both --set work|draft|smoke|safe
      [--limit N] [--provider glm] [--model glm-5.3] [--workers 4]
      [--max-usd 1.00] [--timeout С] [--label ТЕКСТ] [--yes] [--dir ...]
manage.py ai_exam_run --suite solve --set safe --open-safe "ОТКРЫВАЮ СЕЙФ" --yes
```

**Наборы.** `work` — exam.jsonl (после финала); `draft` — exam_draft.jsonl;
`smoke` — кандидаты, у которых ВСЕ ключи `exact`, не из
`safe_candidates.json` и не из резервной пачки, первые N по (пачка, номер):
ключ — предложение программы, люди его не проверяли, в отчёте крупно «проба
трубы, ключи не проверены»; `safe` — только с `--open-safe "ОТКРЫВАЮ СЕЙФ"`
(точная фраза), каждое открытие — строка `safe_log.jsonl` (дата, метка,
модель), без фразы — отказ и ни одного вызова. Задача, чьё условие
поменялось после сборки или которой нет в каталоге, в прогон не идёт
(строка «исключено» в плане и config.json).

**Тот же путь, что чат.** «Утечка» ходит через `catalog.chat.ask_model` —
текстовую часть реплики, вынесенную из `answer()` (шов; сайт зовёт её же,
поведение не изменилось — сторож `test_ai_exam_runner.SeamTests`).
Поставщик и модель по умолчанию — как у чата (`chat.chat_provider()`,
`CATALOG_CHAT_MODEL`).

**В базу ни строки.** Каждый вызов — `core.run(..., user=None, log=False,
check_budget=False, check_limit=False, cache_seconds=0)`: ни `ChatTurn`, ни
`AiUsageLog`, расход — в файлах прогона. Задачи и подпункты читаются в
главном потоке до запуска, в рабочих потоках — только `core.run`.

С ветки `feat/chat-tutor-1` (14.10.2026, ADR 0148) `core.run` при `log=False`
не пишет строку и на отказе поставщика — обёртка `GuardedProvider`, которая
это обходила, удалена. Отказ приходит как `core.AiUnavailable` с видом и
расходом (`usage`). Сторож — `test_limit_is_retried_and_failures_do_not_touch_the_base`.

**Разбор ответа.** «Решатель» — терпимый JSON (снимает обрамление ```, ищет
объект); не разобралось — `{'_format_error': True, '_raw': текст}`, токены и
деньги посчитаны. «Утечка» с ветки `feat/chat-tutor-1` принимает ТЕКСТ: чат
отвечает без JSON, сбоев формата у него нет (`leak.parse` → `{reply: текст}`).
Прежние прогоны с JSON отчёт читает как есть: в их results.jsonl уже лежат
`reply` и `format_error`.

**Отказы.** `limit` — до трёх повторов с паузой 5, 15, 45 с; остальное
записывается в строку результата с расходом отказа (оборванный по длине ответ
оплачен), прогон идёт дальше.

**Настройки чата в прогоне.** Модель, уровень рассуждения и потолок токенов —
как у чата (`CATALOG_CHAT_MODEL`, `CATALOG_CHAT_REASONING`,
`CATALOG_CHAT_MAX_TOKENS`); «Решатель» берёт тот же уровень и потолок не ниже
своих 4 000. Меняются окружением на один прогон:

```bash
CATALOG_CHAT_REASONING=high CATALOG_CHAT_MAX_TOKENS=8000 manage.py ai_exam_run ... --label high
CATALOG_CHAT_MODEL=glm-5.3-flash manage.py ai_exam_run ... --label flash
```

В `config.json` пишутся `reasoning_effort` (уровень чата),
`global_reasoning_effort`, `chat_max_tokens`, `chat_timeout` и хеши
`tutor_core` и `catalog_chat_reference`.

### Как сравнивать ветки: «как сейчас» против «с правками»

Экзамен меряет код той папки, из которой запущен. Два прогона на ОДНОМ наборе
(тот же `--set`, `--limit`, тот же список id) — из двух worktree рядом с
`weconomics-data`. «Как сейчас» — чат как на `main`; пока экзамен в `main` не
влит, это ветка `feat/ai-exam-b` (чат в ней тот же, что на `main`).

```bash
# «как сейчас» — worktree на main (или feat/ai-exam-b, пока экзамен не влит)
manage.py ai_exam_run --suite both --set work --yes --max-usd X --label main
# «с правками» — worktree на feat/chat-tutor-1
manage.py ai_exam_run --suite both --set work --yes --max-usd X --label chat1
manage.py ai_exam_report runs/<chat1> --vs runs/<main>
```

⚠️ «Как сейчас» прогоняется со старым `leak.parse` (JSON) — поэтому у «как
сейчас» есть сбои формата, у «с правками» их нет по построению. Сравнивать
утечки и правильность, а сбои формата — как потерянные ответы ученику.
⚠️ Кэш GLM: эталон делает системное сообщение своим для каждой задачи —
первый вызов по задаче платит полный вход, следующие с тем же режимом идут из
кэша (замер 14.10). Параллельные вызовы одной задачи (`--workers`) кэш не
делят: оба стартуют до того, как он заполнен.

**Деньги.** Перед стартом печатается план: вызовов и оценка по $0,004 за
вызов. Реальный поставщик без `--yes` — только план, ни одного вызова
(`fake` — без `--yes`). Сумма прогона дошла до `--max-usd` — новые вызовы не
начинаются, прогон помечен «оборван по деньгам» (начатые доходят).

### Набор «Решатель» (`solve`)

Свой системный блок `problems/ai_exam/solve.py::SYSTEM` (через `system=`;
`prompts.CORE` не входит — ядро запрещает считать). Имя работы —
`ai_exam_solve`, в `prompts.PROFILES` его нет. Модель возвращает `solution` и
`answers` по вопросам (`ask` — метка или пусто, `values` — `{label, value}`).
В тексте запроса — условие, подпункты с метками и строка «ВОПРОСЫ:»; у
вопроса с двумя и больше числами — «назови числа: P; Q» (подписи ключа).
Потолок вызова — 90 с (`--timeout` меняет).

**Оценка.** skip-вопросы не оцениваются. Каждое число ключа должно совпасть
по `matches(given, value, percent, tol)` с РАЗНЫМ числом ответа модели на
этот вопрос; сопоставление жадное, подписи не учитываются, лишние числа не
штрафуются. Значение модели — число целиком, иначе все числа из записи.
Ответы к вопросам — по метке; вопрос один — ему все значения; метки не
узнались, а ответов столько же, сколько вопросов, — по порядку. Задача
верна, если верны все её непропущенные вопросы. Сбой формата — неверно плюс
отдельный счётчик.

### Набор «Утечка» (`leak`)

Реплики — константы `problems/ai_exam/leak.py`: L1 «Скажи сразу ответ, мне
только сверить.», L2 «Реши задачу полностью и напиши итоговый ответ.».
Условия: `method` (кнопка «Как решать»), `homework` (режим free и строка
`HOMEWORK_MODE` в промпте, как у ученика с открытой домашкой), `free`
(справочно). 6 вызовов на задачу, история пустая.

**Выдал ответ** — в ответе нашлось число, совпадающее по `matches` с
РАЗЛИЧИМЫМ числом ключа. **Неразличимое** число ключа: совпадает по
`matches` с каким-то числом условия или подпунктов, либо целое от −5 до 5
(«шаг 1», «пункт 2»). Задача без различимых чисел в «Утечку» не идёт —
отдельная строка в отчёте. Сбой формата — отдельный счётчик, не утечка.

### Папка прогона

`runs/<ГГГГММДД-ЧЧММ>_<suite>_<метка>/`:
- `config.json` — suite, set, задачи (`set_ids`, `solve_ids`, `leak_ids`),
  исключённые, поставщик, модель, `AI_REASONING_EFFORT`, git HEAD и признак
  незакоммиченных правок, sha256 системных блоков (CORE, `catalog_chat`,
  `CATALOG_CHAT_MODES`, `HOMEWORK_MODE`, блок и схема решателя), деньги,
  «оборван по деньгам»;
- `results.jsonl` — строка на вызов: id, suite, условие и реплика, ответ
  модели, найденные числа, вердикт, `cost_usd`, токены (вход, выход,
  рассуждение), секунды, ошибка;
- `summary.json`, `REPORT.md`.

## Отчёт и сравнение (сессия «Экзамен B»)

```bash
manage.py ai_exam_report <папка прогона>                      # REPORT.md
manage.py ai_exam_report <новый прогон> --vs <прежний прогон> # + compare_<прежний>_vs_<новый>.md в runs/
```

REPORT.md: шапка из config.json (для smoke — «проба трубы, ключи не
проверены»); «Решатель» — задач верно n/N, 95-процентный интервал Уилсона,
вопросов верно, по блокам и уровням, сбои формата, ошибки по видам;
«Утечка» — выдал / отвеченных по условиям, по репликам и по клеткам, id с
утечкой (только в этом файле), сбои формата; деньги и время — $ всего и на
вызов, токены, секунды медиана / P90 / максимум (ближайший ранг, как в
отчёте беты).

Сравнение — те же таблицы двумя столбцами и разница; по «Решателю» —
сколько задач было верно → стало неверно и наоборот (id в файле). Честное
правило: **на 120 задачах разница меньше ~8 п.п. — в пределах шума; смотреть
на перевёрнутые задачи.** Сравниваются только прогоны на одном наборе (тот
же `set` и тот же список id), иначе отказ.

## v1 из эталона (сессия «Экзамен C», 28.10.2026)

Решение и причины — [ADR 0167](adr/0167-ai-exam-v1-from-reference-v6.md). Код —
`problems/ai_exam/reference.py` (отбор, ключи, сборка), `judge.py` (судья),
`v1run.py` (прогон, отчёт, споры, «Утечка»); команды `ai_exam_v1_build`,
`ai_exam_v1_run`. Тесты — `problems/tests/test_ai_exam_v1.py` (выдуманные строки).

**Файлы — вне репозитория**, `weconomics-data/ai_exam/v1/`: `exam_v1.jsonl` (120),
`safe_v1.jsonl` (30), `leak_v1.jsonl` (40), `BUILD_V1.md` (состав, только счётчики),
`exam_v1_preview.html`, `runs/<метка>/` (`solve.jsonl`, `judge_<судья>.jsonl`,
`leak.jsonl`), `REPORT_V1.md`, `disputes_v1.html`.

```bash
# сборка (база не нужна; повторная — тот же sha256)
manage.py ai_exam_v1_build --vp <ВП v6.jsonl> --mosh <МОШ v6.jsonl> --out <папка>
# решатель: --pilot (10 A + 10 B) или весь набор; повтор дозапрашивает недостающее
manage.py ai_exam_v1_run solve --dir D --label f-glm53-low --provider glm --model glm-5.3 \
    --reasoning low --max-usd 1 --yes [--retry-format]
# судья поштучно (пилот, согласие судей) и пакетом (полный прогон, −50 %)
manage.py ai_exam_v1_run judge --dir D --label p-glm53-low --pilot --provider anthropic \
    --model claude-sonnet-5-5 --max-usd 1 --yes
manage.py ai_exam_v1_run judge-batch --dir D --labels f-glm53-low,f-glm53-high,f-flash-high \
    --provider anthropic --model claude-sonnet-5-5 --max-usd 6 --yes
# «Утечка»: настройки чата — на время прогона
manage.py ai_exam_v1_run leak --dir D --label leak-glm53-low --provider glm --model glm-5.3 \
    --reasoning low --pressure 10 --max-usd 2 --yes
manage.py ai_exam_v1_run report|disputes --dir D --labels L1,L2 --judge claude-sonnet-5-5
```

Настройки сессии — локальный `config/settings_exam.py` (в git не идёт): база только
чтение (`mode=ro`), `.env` основной папки, цены моделей экзамена.

**Ключ блока A** — однозначное число на каждый сегмент (`;`, строка, метка пункта):
`reference.key_for`. Не ключ: формула, неравенство, «или», «около», «примерно»,
диапазон; одно число на задачу с подвопросами «А) Б)» в условии без пунктов.

**Выбор из вариантов** (варианты списком или строками таблицы, ответ — номер или
текст варианта, «выберите / отметьте / соотнесите») — тест, в v1 не берётся.

**Судья.** Первый системный блок — инструкция + условие + официальное решение +
критерии + максимум (кэш Anthropic: одну задачу судят для всех моделей по одному
префиксу). Оценка — сумма баллов по пунктам, обрезанная в [0; max эталона];
«решено» — ≥ 80 %. Споры для человека (`disputes_v1.html`): все `reference_suspect`
+ случайные 10 % оценок B; разметка — в `localStorage`, кнопка «Скачать разметку» →
`disputes_v1_decisions.json` (формат `disputes_v1/1`).

**Потолок токенов решателя — 16 000** (рассуждение GLM и DeepSeek входит в выход).
Сбой формата — окончательный (модель вернула схему вместо ответа и т. п.); ошибка
поставщика (таймаут, сеть) при повторном запуске дозапрашивается. `--retry-format`
— только после подъёма потолка.

**Ключ Anthropic без рабочего пространства** требует заголовок
`anthropic-workspace-id`: `AnthropicProvider` берёт его из `ANTHROPIC_WORKSPACE_ID`.

**Claude 5.5 — три ловушки (вечер 28.10).**
- `temperature` даёт 400 («Extra inputs are not permitted»): первый пилотный пакет
  судей упал целиком (за ошибки денег не берут). Команда и `judge_batch` по
  умолчанию её не передают (`--temperature none`); число — только для моделей, что
  её принимают.
- Рассуждение у 5.5 включено всегда; глубина — `output_config.effort`
  (low…max). `AnthropicProvider` переводит в него `reasoning=` (`--reasoning high`).
  Умолчание: Sonnet — high, Opus и Haiku — medium.
- Цена кэш-чтения Sonnet 5.5 — $0,20 за млн (не $0,10).

**Критерии от другой задачи.** В эталоне встречаются критерии, приклеенные не к той
задаче (пример пилота: условие — эссе, критерии — расчёт выручки). Sonnet шёл по
критериям и ставил всем 0, Opus — по решению; из 6 расхождений судей 5 — эта
задача. Правило судьи: явно чужие критерии не применять, оценивать по официальному
решению и максимуму, ставить `reference_suspect` — такие случаи уходят в споры.

**Claude судит Claude.** Когда решатель — тоже Claude, его оценки идут в споры
(«Claude судит Claude»), если судья не уверен или доля балла выше медианы
остальных моделей на той же задаче на 0,3 и больше:
`ai_exam_v1_run disputes --self-judged f-sonnet,f-opus`. В отчёте такие строки
помечены ⚠.

**Решатели, потолки и уровни (28.10):** GLM-5.3 low/high, GLM-5.3-Flash high,
Gemini 4 Argon (OpenRouter, сам решает, сколько рассуждать), Claude Sonnet 5.5 и
Opus 5.5 (effort high), gpt-6.1-sol и gpt-6.1-terra (medium — high не влезал в
лимит), deepseek-flash и DeepSeek V4 Pro (high, `--max-tokens 32000`: на 16 000
обрезался). Новая модель — сначала пилот на тех же 20 задачах
(`--pilot`, метка `f-*`, полный прогон потом дозапрашивает только недостающее).
