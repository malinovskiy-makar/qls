# Почта: отправка, коды, флаг MAIL_ENABLED

Сайт отправляет только **служебные письма с кодом** (регистрация, смена пароля,
подтверждение почты). Рассылки и воронка живут в сервисе рассылок (Unisender) —
это сессия 2, здесь её нет. Решения владельца от 26.10.2026 — Notion «Решения»
и [ADR 0159](adr/0159-mail-codes-email-password-registration.md).

⚠️ **Запрещено законом и решением владельца:** вход по ссылке из письма, вход
только по коду без пароля, вход через Telegram, Google, Apple. В письме только
код и две ссылки — на главную и на Telegram-канал. Галочка рассылки никогда не
отмечена заранее (ст. 18 закона «О рекламе»).

## Флаг и переменные

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `MAIL_ENABLED` | разработка `1`, тесты `0`, бой `0` | включает всё новое; при `0` сайт ровно прежний |
| `EMAIL_HOST` | пусто | пусто → письма печатаются в окно `runserver` (консольный бэкенд) |
| `EMAIL_PORT` | `587` | `465` → SSL, иначе STARTTLS |
| `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD` | пусто | идентификатор и секрет API-ключа сервисного аккаунта Postbox |
| `DEFAULT_FROM_EMAIL` | `Weconomics <noreply@weconomics.ai>` | отправитель |
| `MAIL_REPLY_TO` | `LEGAL_CONTACT_EMAIL` | куда ведёт «Ответить» |

`MAIL_ENABLED=0`: регистрация в один шаг без почты, «Логин» на входе, «Забыли
пароль» ведёт в Telegram, почта редактируется в профиле, страниц
`/register/confirm/`, `/password/forgot/`, `/password/forgot/code/`,
`/account/email/`, `/legal/consent-mail/`, `/legal/mail/*` нет (404), документа
«Согласие на рассылку» нет в списке `/legal/`. Экраны входа, регистрации и
профиля при этом **байт в байт** прежние (проверено снимком до и после).

`mail.E001`: при `MAIL_ENABLED=1` и `DEBUG=False` пустой `EMAIL_HOST`,
`EMAIL_HOST_USER` или `EMAIL_HOST_PASSWORD` роняет `manage.py check` — контейнер
не поднимется с почтой, которая никуда не отправляет.

## Потоки

**Регистрация (два шага).**
1. `/register/`: логин, почта, пароль ×2, роль, согласие с документами, галочка
   рассылки. Аккаунт **не создаётся**: в сессию `pending_registration` ложится
   анкета с ХЕШЕМ пароля, на почту уходит код.
2. `/register/confirm/`: код. Верный → в одной транзакции повторная проверка, что
   логин свободен и почта не подтверждена другим аккаунтом, затем `User`
   (`email_verified_at`), профиль с ролью, согласие `pd` (+ `mail` по галочке),
   вход, возврат на `next`. Анкета живёт 30 минут. «Изменить почту» возвращает
   форму заполненной, кроме пароля.

**Вход.** «Логин или почта». Почтой — только **подтверждённой**, без учёта
регистра; подтверждённая почта главнее чужого логина с «@».

**Сброс пароля.** `/password/forgot/` (почта) → `/password/forgot/code/` (код и
новый пароль ×2). Ответ одинаков для любой почты, таймер повтора — от момента
запроса в сессии. Сначала проверяется пароль, потом код. После смены прежние
сессии человека гаснут сами (у них устаревший хеш пароля).

**Страница «Почта»** `/account/email/` (только вошедшим): состояние, почта,
галочка рассылки. Та же подтверждённая почта — меняется только галочка, без
кода. Новая почта → код → в транзакции повторная проверка занятости, адрес и
`email_verified_at`, согласие по галочке.

## Лимиты

| Что | Значение |
|---|---|
| Код | 6 цифр, `secrets.randbelow`, ввод — только цифры («123 456» = «123456») |
| Срок жизни кода | 10 минут |
| Повторная отправка | не раньше 60 с на тот же адрес и цель |
| Писем на адрес | 5 в час на цель |
| Неверных вводов | 5 на код, затем код мёртв |
| Адрес в сети | лестница `ratelimit`, scope `email_code:ip`, множитель 6 (30 писем → 30 с, 48 → 2 мин …) |
| Сброс пароля | scope `reset` (почта + адрес в сети): промахи кода, ступени входа |
| Регистрация | scope `register` считает УДАЧНЫЕ регистрации — теперь в момент создания аккаунта (шаг 2) |
| Временный отказ SMTP (4xx) | одна повторная попытка через 1,2 с |
| Квоты Postbox по умолчанию | 200 писем в сутки, 1 в секунду (заявка на увеличение — Андрей) |

В базе только HMAC-SHA256 на `SECRET_KEY` от «цель:почта:код»; новый код гасит
прежние. Неотправленный код удаляется и не съедает ни минуту, ни часовой лимит.
В журнал `problems.mail` не попадают ни тема, ни текст письма (там код) —
только маска адреса, класс и код ошибки.

## Интерфейс для других приложений

Стена тренажёра ВП и всё будущее пользуются только этим:

```python
from problems.email_codes import has_verified_email   # у человека есть подтверждённая почта
from legal.consent import wants_mail                  # согласился на рассылку (любой редакции)
```

Собрать почту и согласие — увести на
`/account/email/?next=<свой адрес>&src=vp`: `next` — куда вернуть (только свой
адрес, чужой отбрасывается), `src=vp` — источник согласия «Стена тренажёра ВП».
Вернувшийся человек проверяется теми же двумя функциями.

Нужно отправить код из своего экрана — `email_codes.send_code(email, purpose,
user=…, request=…)` и `check_code(email, purpose, code)`; результаты —
`SendResult` / `CheckResult` с причиной отказа.

## Как проверить у себя

`EMAIL_HOST` пустой → письма печатаются в окно, где запущен `runserver`: код
видно прямо там. `MAIL_ENABLED` при разработке по умолчанию `1`; `MAIL_ENABLED=0`
в `.env` и перезапуск — всё как раньше.

## Включение на бою — по шагам

Порядок не менять: каждый шаг проверяет предыдущий.

1. В `/srv/weconomics/.env`: `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`,
   `EMAIL_HOST_PASSWORD`, `DEFAULT_FROM_EMAIL`, `MAIL_REPLY_TO` (или пусто).
   `MAIL_ENABLED=0` пока не трогать. Пересоздать `web`:
   `docker compose up -d --force-recreate web`, затем `docker compose restart nginx`.
2. Из `/srv/weconomics/app/deploy`:
   `docker compose exec web python manage.py send_test_email <свой ящик>` — команда
   работает при выключенной почте и печатает бэкенд, отправителя и «Ответить».
3. Письмо пришло; в заголовках `DKIM=pass`, `SPF=pass`, `DMARC=pass`.
4. Выкачены новые правовые тексты (Согласие ред. 2, Политика, финальное
   «Согласие на рассылку») и `LEGAL['docs_version'] = '2'` — отдельная сессия.
5. `MAIL_ENABLED=1` в `.env` → `docker compose up -d --force-recreate web` →
   **`docker compose restart nginx`** (иначе 502, ловушка из [SERVER.md](SERVER.md)).
6. Регистрация настоящими ящиками Gmail, Яндекс и Mail.ru: письмо, код, вход
   почтой, сброс пароля.

Откат — `MAIL_ENABLED=0` и те же две команды: аккаунты, созданные с почтой,
продолжают входить логином; подтверждённые почты остаются в базе.
