# ADR 0159 — Почта: коды подтверждения, регистрация «почта + пароль», флаг MAIL_ENABLED

* **Дата:** 2026-10-27
* **Статус:** принято владельцем — решения Notion от 26.10.2026: «Регистрация — почта +
  пароль, почта подтверждается кодом из письма; вход — почтой или логином и паролем; без
  входа по ссылке и без входа только по коду», «Воронка писем живёт в российском сервисе
  рассылок…», «Почтовые провайдеры: коды — Yandex Cloud Postbox, рассылки — Unisender…».
  Ветка `feat/mail-codes-20261026`, сессия 1 из 2. Подробности — [docs/MAIL.md](../MAIL.md).

## Контекст

Сайт не отправлял ни одного письма: регистрация по логину и паролю, почта в профиле
необязательна и не подтверждается, «забыл пароль» — через Telegram и админку (решения
04.09.2026). Перед открытой регистрацией так нельзя: нет самостоятельного сброса пароля,
нет контакта для воронки тренажёра ВП, нет основы для будущего письма родителю. 199-ФЗ:
с 07.07.2026 штраф (ст. 13.55 КоАП) за вход через иностранные сервисы; почта как логин +
пароль и код подтверждения как канал связи допустимы (позиция РКН, 27.08.2026).

## Решение

1. **Коды — по SMTP через Yandex Cloud Postbox**, без новых библиотек. Одно место отправки
   (`problems/mail.py`), одно место правил кода (`problems/email_codes.py`): 6 цифр, 10 минут,
   60 с между письмами, 5 писем в час, 5 неверных вводов, лимит по адресу в сети; в базе
   только HMAC-отпечаток.
2. **Регистрация в два шага**: аккаунт создаётся только после верного кода; до того анкета
   (с хешем пароля) живёт в сессии 30 минут.
3. **Вход почтой — только подтверждённой** (`User.email_verified_at`, уникальность без учёта
   регистра среди подтверждённых). Старые адреса профиля считаются неподтверждёнными;
   старых пользователей без почты не блокируем — мягкая плашка «Добавьте почту».
4. **Сброс пароля кодом** без раскрытия существования аккаунта.
5. **Страница «Почта»** `/account/email/?next=…&src=vp` — единственный вход для стены ВП.
6. **Согласие на рассылку** — отдельный вид `ConsentRecord.Kind.MAIL`, галочка никогда не
   отмечена заранее; действует запись любой редакции (`wants_mail`), чтобы поднятие
   `docs_version` не отписывало всех.
7. **Флаг `MAIL_ENABLED`**: выключен — сайт ровно прежний (экраны байт в байт). На бою по
   умолчанию `0`; включается после `send_test_email`, DKIM/SPF/DMARC и новых правовых текстов.
8. **Два бэкенда входа**, а не один наследник: `EmailOrUsernameBackend` (путь почты; неверный
   пароль обрывает цепочку `PermissionDenied`) и штатный `ModelBackend`. Путь бэкенда записан в
   каждой живой сессии — его исчезновение разлогинило бы всех в момент выкатки.

## Отвергнуто

* **Вход только по коду без пароля** — письмо на каждый вход; ответа РКН по такой схеме нет.
* **Вход по ссылке из письма** — юристы считают его входом через иностранный сервис.
* **Почта по желанию** — нет контакта для воронки и для сброса пароля.
* **Всё в Unisender** (коды через Unisender Go) — потолок 500 писем в сутки, 800 ₽/мес после
  пробного периода. **Всё в DashaMail** — от 1 750 ₽/мес.
* **Цепочки писем в коде сайта** — каждая правка письма стала бы сессией разработки.
* **Один бэкенд-наследник вместо `ModelBackend`** (так было в задании) — разлогинил бы всех
  на бою при выкатке; поведение входа у выбранной схемы то же.

## Последствия

* Новых корневых шаблонов (с doctype) заводить нельзя — так сложились два старых сторожа
  (`test_signup_source`, `test_cookie_bar`); экраны почты наследуют `register.html` и
  `platform/base.html`.
* Миграции `problems/0082_email_codes`, `problems/0083_consent_mail_kind`.
* Сессия 2: передача контактов с согласием в Unisender и обратная отписка.
