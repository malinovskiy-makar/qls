# ADR 0112 — Дуэль: лобби отдельной страницей, приглашение, одно сравнение для обоих, «Реванш»

* **Дата:** 2026-09-17
* **Статус:** действует

## Контекст

Лобби дуэли жило на странице игры поверх скрытого стартового экрана и занимало узкую колонку.
Страница `/game/d/<код>/` одна на всех говорила «<автор> бросает вызов» и показывала «150 вопр.»
(запас очереди, а не длина раунда). Сравнение строилось парой «автор + я», поэтому автор своего
сравнения не видел никогда. Сопернику, закончившему раньше автора, подпись «вызвавший» доставалась
вместо автора. Кнопка «Реванш» была ссылкой на адрес, который вошедшему отвечает JSON.

## Решение

Макеты `DuelCreate`, `DuelLobby`, `DuelLobbyReady`, `DuelInvite`, `DuelResult`, спецификация P3.

* **Окно создания:** вкладки режимов «1 мин · 568» (вопросов под фильтром), строка «Что решаем»
  тремя чипами-сводками и «Настроить фильтры», подвал «N вопросов под фильтром · раунд без лимита
  вопросов», «Отмена» / «Создать дуэль». Чипы с крестиком убраны.
* **Лобби — отдельная страница** `/game/s/<код>/`: зоны стартового экрана сервер не отдаёт вовсе,
  по центру карточка 720 px — условия словами, код 44 px, ссылка, слоты «автор VS соперник», общий
  отсчёт 84 px «Старт у обоих одновременно». Когда старт назначен, код, ссылка и «Отменить» уходят.
  «Нет связи с комнатой» — не раньше двух секунд после открытия.
* **Страница дуэли в трёх видах:** приглашение («<логин> зовёт вас на дуэль», строка об авторе,
  пилюли условий, «Принять вызов», гостю «Войти, чтобы принять»); ожидание («ещё играет» или «ещё
  не пришёл» по комнате дуэли, без таблицы); сравнение — вердикт «Вы победили» / «Победа за …» /
  «Ничья», счёт, разрыв и чем кончилось словами, двое карточками, «По цифрам» с лучшим в каждой
  строке, «Кто что взял» до последнего сыгранного вопроса и фраза-вывод.
* **Пара сравнения** — результат автора и один другой; результат автора — только автора (подмена
  «первый сыгравший» осталась для старых дуэлей без автора). Больше двоих — остальные строкой.
* **«Реванш»** — запрос к `duel_new` с `rematch=<код>` и переход в лобби новой дуэли; на итоге
  раунда — когда соперник уже отыграл.
* Имена на страницах дуэли — логины, как на досках: страница публичная, полное имя ученика по
  ссылке не уходит. Вердикт соперника — «Победа за <логин>», без рода.

## Отвергнуто

* Прятать главную позади лобби стилями — разметка и запросы главной оставались бы, а тест лобби
  проверял бы только видимость.
* Чинить сравнение для автора отдельной веткой шаблона — две вёрстки одного итога разъехались бы.
* Подсвечивать весь столбец победителя — по очкам выиграл один, а отвечал быстрее, может, другой.

## Цена

* Код старта на странице лобби получает пустышки вместо элементов главной (`$` в `game.html`): ошибка
  «нет элемента» на этой странице молчит.
* «Ещё играет» знает комната дуэли, а она живёт в кэше полчаса — дальше «ещё не пришёл».
* Запрет начать раунд без соперника по-прежнему стоит в интерфейсе, а не на сервере (карточка в Notion).

## Следствия

* Разметка лобби — `game/templates/game/_start.html`, страница дуэли — `game/templates/game/duel.html`,
  сервер — `views.set_page`, `duel_page`, `_duel_compare`, `_duel_story`, `_duel_waiting`.
* Проверки: `test_duel_page.py`, `DuelLobbyTests` в `test_duel_sync.py`, браузерные `browser_lobby.mjs`
  и `browser_duel_sync.mjs` (синхронный старт — на PostgreSQL).
