# ADR 0032. Эталон дубликатов строится по тексту, а не из таблицы `DuplicateCandidate`

**Источник:** сессия С14 «эталонные наборы + базовый замер поиска»,
28.08.2026, ветка `feat/search-eval-c14`. Решение принято владельцем в ходе
сессии, после того как сверка с базой опровергла премиссу `EMBEDDINGS.md`.

## Контекст

Уровень 0 `EMBEDDINGS.md` описывает набор A измерителя так:

> **Набор A — подтверждённые дубликаты. Бесплатно, размечено людьми.**
> Подтверждённая пара — это два текста, про которые человек уже сказал, что
> это одна и та же задача.

Расчёт был на то, что разметка уже лежит в базе и достаётся даром.

Сверка показала, что разметки нет. В таблице `DuplicateCandidate` **10 731
пара**, и все со статусом `confirmed`, но:

- `reviewed_by` — `NULL` у всех 10 731;
- `reviewed_at` — `NULL` у всех 10 731;
- все записи созданы **за шесть секунд** 08.06.2026 (21:42:18 → 21:42:24);
- `similarity` ровно в диапазоне 0,95000 … 1,00000.

Статус проставила команда `process_duplicates` — она автоматически помечает
пары `confirmed` по порогу косинуса (`THRESHOLD_A = 0.97`,
`THRESHOLD_B = 0.95`) и не спрашивает человека. **Ни одну пару человек не
подтверждал.**

## Проблема

Пары отобраны по косинусной близости **тех самых эмбеддингов**, качество
поиска по которым измеритель и должен проверять. Мерить поиск на таком
наборе — замкнутый круг: recall по построению выйдет около единицы, и число
не будет означать ничего, кроме «порог 0,95 действительно отбирает то, что
ближе 0,95».

Это худший вид ложной метрики: она зелёная, выглядит убедительно и молча
подтверждает любое изменение формулы.

## Рассмотренные варианты

1. **Взять пары как есть.** Отвергнут: круг не разрывается, число ложное.
2. **Взять только пары с косинусом ≈ 1,0** (их 4 068 — почти дословные
   копии). Отвергнут как основной путь: набор всё равно отобран мерилом,
   которое проверяется. Допустим только с явной подписью «проверка на
   вменяемость, не метрика».
3. **Дождаться ручной разметки владельцем.** Отвергнут как блокирующий: С14
   встал бы до появления свободных часов у человека, а от С14 зависят С15–С21.
4. **Отложить набор A совсем.** Отвергнут: блок «Похожие задачи» остался бы
   вообще без сторожа регрессии, и поломка формулой v2 прошла бы незаметно.
5. **Собрать пары заново по совпадению нормализованного ТЕКСТА.** Принят.

## Решение

Набор A строится по совпадению нормализованного условия задачи. Признак
независим от измеряемого: текст сравнивается с текстом, эмбеддинги в отборе
не участвуют вовсе.

Нормализация (`problems/eval_sets.py::normalize_statement`): регистр вниз,
«ё» → «е», разметка и пунктуация отбрасываются, пробелы схлопываются,
**числа сохраняются**. Тексты короче 80 символов не участвуют.

Два обоснования деталей:

- **Числа остаются.** Именно они отличают похожие задачи друг от друга; без
  них половина банка склеилась бы в одну группу.
- **Короткие тексты выбрасываются.** «Найдите равновесную цену.» встречается
  в банке сотнями и одинаковой задачей не делает — такие группы были бы
  мусором.

Результат: **2 619 групп, 5 602 задачи**.

## Чем этот набор является и чем не является

**Является** сторожем регрессии для блока «Похожие задачи»: если формула v2
сломает вектор-к-вектору поиск, это станет видно немедленно. Базовая линия
на 28.08.2026 по полному банку: recall@5 = 0,991, recall@50 = 1,000,
MRR@10 = 0,938.

**Не является** оценкой сложности поиска. Тексты внутри группы совпадают
дословно, задача лёгкая по построению. Сравнивать эти цифры с набором C
нельзя: набор A мерит «задача → задача», набор C — поиск по описанию.

⚠️ **Набор A запускается только с `--scope all`.** На срезе прода 98,8 %
дублей физически недостижимы: та же `process_duplicates` пометила их
`status='duplicate'` или `hidden`, и в индекс сайта они не попадают. Цифры
набора A по срезу прода читать нельзя.

## Что это не отменяет

Таблица `DuplicateCandidate` остаётся как есть — она не трогалась и не
трогается. Ручная разметка дубликатов человеком по-прежнему полезна и
по-прежнему не сделана; когда она появится, набор A можно будет пересобрать
на ней и сравнить с текстовым — расхождение само по себе будет диагностикой.

Отдельно стоит помнить: раз ни одна из 10 731 пар не просмотрена человеком,
то и **5 393 задачи, помеченные `status='duplicate'`, скрыты автоматически по
косинусу**. Это уже вопрос не про поиск, а про содержимое банка, и решать его
владельцу отдельно.
