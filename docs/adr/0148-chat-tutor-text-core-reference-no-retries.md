# ADR 0148 — Чат-репетитор: ответ текстом, своё ядро и эталон во всех режимах, без скрытых повторов

* **Дата:** 2026-10-14
* **Статус:** сделано в ветке `feat/chat-tutor-1` (сессия «Чат-репетитор, правки 1»), **в
  `main` не влито**. Выкатка — решение владельца по итогам экзамена C («как сейчас» на
  `main` против «с правками» на этой ветке). Заменяет часть [ADR 0080](0080-problem-chat-is-stateless.md)
  про ответ `{reply}` и уточняет потолок времени [ADR 0079](0079-catalog-attempt-check-is-synchronous.md)
  для чата.

## Контекст

Стратегия ИИ (25.09) и данные беты (сессия «Данные беты 1», 08.10) показали, почему чат на
задаче решает «не как олимпиадник» и почему ученик ждёт и теряет ответы:

1. Первым системным блоком у чата стояло общее ядро `prompts.CORE`, написанное для
   служебных работ: «Ты не источник знаний… ничего не считай в уме… свободный текст не
   принимается». Профиль чата исключения из него оговаривал, но ядро шло первым.
2. Эталон решения модель видела только в режиме «Проверь моё решение»; ответы и решения
   пунктов не передавались, `solution_needs_review` не учитывался.
3. Ответ был упакован в JSON `{reply}`: формулы TeX ломались экранированием (`\times` →
   табуляция), 10 реплик беты потеряны как «неожиданный ответ».
4. Три бага с деньгами и временем:
   * клиенты `openai` создавались без `max_retries` — библиотека повторяла запрос ещё дважды
     (таймаут, обрыв, 5xx): вопрос ждал до 3 × 25 с ≈ 78 с и оплачивался трижды (проба
     `ai_load_probe --ai 8` на бою, 09.10); таймаут у GLM шёл веткой «не удалось связаться…
     соберите домашку вручную»;
   * `core.run` писал строку `AiUsageLog` при отказе поставщика даже с `log=False`
     (сортировщик поиска из рабочего потока открывал соединение с базой);
   * строка расхода писалась `ok=True` ДО разбора ответа: сбой формата съедал личный
     лимит, а `ChatTurn` такой реплики получал цену и токены 0 ($0,038 за бету мимо
     журнала чата).

## Решение

### 1. Без скрытых повторов у поставщиков

* Все клиенты — `openai.OpenAI(..., max_retries=0)` (OpenAI, GLM, DeepSeek, OpenRouter) и
  `anthropic.Anthropic(..., max_retries=0)`. Повтор, если нужен, решает вызывающий: прогонщик
  экзамена (на `limit`), пилот обогащения (`RETRYABLE_PROVIDER_ERROR_KINDS`, теперь с
  `timeout` и `network`).
* `openai.APITimeoutError` — своя ветка ДО `APIConnectionError` (он её подкласс): вид
  `timeout`, текст «Ответ занял больше N секунд и прерван. Попробуйте ещё раз.» Обрыв
  связи — вид `network`, текст со словом «связаться», без «домашки».
* Потолок чата — своя настройка `CATALOG_CHAT_TIMEOUT_SECONDS` (45 с, меньше 60 с у nginx);
  шаг зрения и шаг текста делят один потолок (шагу текста — не меньше 10 с). Глобальные
  `AI_TIMEOUT_SECONDS` = 25 с у остальных функций не меняются.

### 2. Журнал и деньги в `core.run`

* `log=False` уважается и на отказе поставщика; сведения об отказе — в
  `AiUnavailable.usage`.
* Строка расхода пишется ПОСЛЕ разбора: сбой — `ok=False`, но с ценой. Деньги видит
  суточный денежный потолок (`spent_today` — все строки), личный лимит (`used_today` —
  только `ok=True`) за неразобранный ответ не списывается. Это касается всех работ сайта, не
  только чата: тот же баг.
* `AiUnavailable` получает `usage`; чат переносит токены и цену в `ChatTurn` и при отказе.

### 3. Чат отвечает текстом

* `core.run(schema=None)` и все поставщики: без `response_format` и без приписки «ОТВЕЧАЙ
  РОВНО ОДНИМ JSON…»; `AiResult.data` — строка. Пустой ответ — вид `empty`, обрыв по
  `finish_reason == 'length'` — вид `length` (раньше `finish_reason` не читался вовсе).
* Чат — исключение из правила `problems/ai/CLAUDE.md` «ответ разбирается по схеме»: ответ
  чата — текст для человека, у него нет полей, которые программа читает. Предохранители
  длины — прежние `REPLY_MAX` / `CHECK_REPLY_MAX`.

### 4. Своё ядро репетитора и эталон во всех режимах

* `prompts.TUTOR_CORE` — первый системный блок ТОЛЬКО у `catalog_chat`
  (`prompts.CORE_BY_PROFILE`). `CORE` не изменился (сторож — хеш в тесте): им живут план
  домашки, темы, проверка попытки, OCR, шаг зрения чата.
* Порядок блоков (кэш у GLM — по началу системного сообщения): `TUTOR_CORE` → профиль
  `catalog_chat` → блок режима → [канон темы — точка расширения, пока пусто] → эталон.
* Эталон (`catalog/chat.py::reference_text`, по образцу `catalog/attempts.py`): ответ,
  решение, ответы и решения пунктов, рубрика; `solution_needs_review` — решений нет, ответы
  есть; решения вместе не длиннее 8 000 знаков. Системным блоком, последним, во ВСЕХ
  режимах; в тексте запроса его нет (P0-сторож чата). Подпись: ученику не пересказывать и не
  цитировать, итоговый ответ не называть, кроме подтверждения в «Проверь», если ученик сам
  пришёл к верному.

### 5. Уровень рассуждения — настройкой чата

`CATALOG_CHAT_REASONING` (по умолчанию `low` = прежнее поведение: GLM при
`AI_REASONING_EFFORT=none` слал `low`) и `CATALOG_CHAT_MAX_TOKENS` (3 000). `core.run(...,
reasoning=)` и `provider.complete(..., reasoning=)` — уровень на вызов; не задан — глобальный
`AI_REASONING_EFFORT`. Умный поиск и обогащение уровень чата не видят (тест).

### 6. История разговора

Ошибочные ответы в историю для модели не кладутся (`stol_task.js`). Расшифровка фото идёт в
историю вместе с репликой ученика: сервер отдаёт `history_text` и в ответе чата, и в
`api_chat_history`.

## Отвергнуто

* **Поменять `CORE` для всех** — сломало бы план домашки, темы, OCR (им как раз нужно «не
  выдумывай, не считай») и сбросило бы кэш всем.
* **Оставить JSON и чинить экранирование** — у GLM нет `json_schema`, формат проверяется
  только у нас; сбой формата — потерянный ответ ученика. Тексту чинить нечего.
* **`max_retries=1`** — повтор после 45 с всё равно не укладывается в 60 с nginx; повтор
  нужен только там, где его решает вызывающий (пакетные прогоны).
* **Эталон текстом запроса** — нарушает P0-правило чата и смешивает его с репликой ученика.
* **Потоковый вывод** — отдельная сессия: другой транспорт, `proxy_buffering` у nginx,
  отдельный ADR вместо части ADR 0080.

## Последствия

* Утечку ответа при эталоне во всех режимах меряет набор «Утечка» экзамена; дымовой прогон
  этой сессии — проверка трубы, а не вывод о модели (10 задач smoke: утечек 0/36 у GLM-5.3
  low и high, 1/36 у Flash high — пограничная подсказка; сбоев формата у чата 0).
* **Реплика чата дороже на ~65 %** ($0,0018 → $0,0029 у GLM-5.3 low на дымовом прогоне).
  Причина — сам эталон, а не поломка кэша: системное сообщение стало своим для каждой задачи,
  и ПЕРВЫЙ вызов по задаче платит полный вход (~1 700–2 000 токенов вместо ~130, когда
  системное сообщение было общим для всех задач). Второй и следующие вызовы с тем же
  системным сообщением идут из кэша GLM: некэшированный вход ~50 токенов (разбор логов
  прогонов 14.10; одновременные вызовы кэш не делят). У GLM-5.3-Flash кэш срабатывает
  реже — учитывать при выборе модели.
* `ai_exam_run` пишет в `config.json` уровень рассуждения и потолки чата, хеши `TUTOR_CORE` и
  подписи эталона; «Решатель» идёт с уровнем и потолком токенов чата.
* Отчёт беты знает вид `length`; старые тексты ошибок узнаются по-прежнему.
