# ADR 0118 — Вложение чата: ученик открывает своё фото или PDF отдельной файловой вьюхой

* **Дата:** 2026-09-18
* **Статус:** действует

## Контекст

С 15.09 ученик прикладывает к реплике чата фото или PDF решения, но увидеть приложенное потом не
может: в пузыре оставалась строка `[файл: имя]`, `/media/` закрыт на всех слоях (docs/SECURITY.md),
файл показывала только админка (`ChatTurnAdmin.file_view`). Перед бетой к реплике разрешено до трёх
файлов, и ученику нужно открыть то, что он отправил.

## Решение

* `GET /catalog/chat/attachment/<id>/` — отдаёт файл только владельцу (`ChatAttachment.user`) или
  сотруднику. Чужое, несуществующее и гостю — **одинаково 404**, без редиректа на вход: номер не
  должен подтверждать, что файл есть.
* Путь — из поля `file`, тип — из поля `mime`, определённого сервером при загрузке;
  `X-Content-Type-Options: nosniff`, `Cache-Control: private, max-age=0`. Картинка — `inline`,
  PDF — скачиванием, как в админке: PDF не открывается на нашем домене.
* Вьюха живёт **отдельным модулем** `catalog/chat_files.py`: сторож
  `NoOtherFileServingViewTests` разрешает файловые вьюхи пофайлово, и разрешить весь
  `catalog/views.py` значило бы пропускать будущую отдачу файла рядом.
* Для подписи в пузыре и в истории разговора у вложения появилось поле `name` — имя с устройства
  ученика; в хранилище файл по-прежнему под нашим uuid-именем.

## Отвергнуто

* **Открыть `/media/chat/`** — это SEC-06 (приватное хранилище, подписанные ссылки), отдельная работа.
* **Отдавать через админку** — ученик не сотрудник.
* **PDF тоже `inline`** (так было в промпте ночи) — расходится с принятым для админки правилом, а
  выигрыш для ученика мал: PDF он и так открывает у себя.
