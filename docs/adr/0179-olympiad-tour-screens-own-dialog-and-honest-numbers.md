# ADR 0179 — Экраны тура: своё окно вместо браузерного, честные баллы и статусы, PDF только из своей копии

* **Дата:** 2026-10-30
* **Статус:** принято дневной сессией 30.10 по приёмке владельцем и ревьюером; подтверждение — по журналу дня.
* **Ветка:** `feat/olympiads-screens-20261031`; код `olympiads/templates/olympiads/_tour_dialog.html`,
  `olympiads/views_training.py` (`item_status`, `training_recheck`, автосохранение),
  `olympiads/training_engine.py` (`package_points`, `tour_maximum`, `NO_WORK`),
  `olympiads/training_files.py` (`variant_file`), `olympiads/navigator.py` (`tour_pdfs`,
  `months_phrase`, `feed_order`), тесты `olympiads/tests/test_day_U.py`, сценарии
  `claude/day_olymp_20261030/tools/`. Продолжение ADR 0174–0177.

## Решение

1. **Нативных `alert` / `confirm` / `prompt` в разделе нет.** «Сдать тур?»,
   «Завершить тур?», «Сдать задание без решения?» — своё окно (`<dialog>`,
   `showModal`, Esc и «Вернуться к решению» закрывают). Общий `exam.js` и
   `WorkForm` не меняются: кнопки перехватываются на фазе захвата документа.
   Каждый сценарий Playwright роняет проверку на событии `dialog`.
2. **Автосохранение сданного задания не отвечает 409.** `exam.js` читает 409
   как «время вышло» и отправляет форму на «Завершить тур» — запоздавшее
   автосохранение сдавало весь тур (У6). Ответ — 200 «принято, не записано».
3. **Балл задания — только балл позиции пакета; неизвестен — числа нет.**
   Служебные 10/3 (`AssignmentItem.save`) наружу не выходят; максимум тура —
   `navigator.tour_max_score` (ADR 0173, решение ночи 1).
4. **Статус сданного задания — один на плитку, блок и результат**
   (`item_status`): «решения нет · 0» (модель не зовётся), «не проверено» с
   «Проверить ещё раз», «ждёт проверки», балл. Ответ модели вне схемы
   удаляется из кэша ядра — иначе повтор вернул бы его же.
5. **PDF — только своя копия, `inline`, по адресу раздела**; внешний адрес
   файла на экран не попадает; «Условия в PDF» — только вид «условия» (файл с
   решениями открыл бы разбор до решения); первым — файл с сайта организатора.
6. **Поле краткого ответа — только у теста** (по типу задачи); эталонный ответ
   развёрнутой задачи уходит в запрос ИИ-проверки (эталонное решение — нет).
7. **Даты без числа — только из месяца, названного ориентиром;** события без
   даты — в порядке этапов.

## Почему

Владелец и ревьюер прошли экраны руками: браузерное окно «Завершить
контрольную?», «Сдать задание», завершившее тур, «10 баллов» и «из 88» из
ниоткуда, «Без балла» при пустой сдаче и «0 из 12» на плитке одновременно,
поля «Ответ а/б/в» у развёрнутой задачи, «Разборы тура», ведущие в архив
чужого облака. Всё это — неправда на экране; правило проекта — не выдумывать.

## Отвергнуто

- Хук в `WorkForm.confirmSubmit` — синхронный `confirm` не превратить в окно
  без правки `exam.js`; перехват на захвате обходится без правки общего кода.
- Чинить У6 в `exam.js` (различать 409) — общий код контрольных; сервер — единственная
  точка, где «задание сдано» отличается от «время вышло».
- Новая модель/поле для «решения нет» — достаточно строки итога и наличия решения.
- Отдавать PDF скачиванием, как листы учеников, — это файлы организаторов из
  пакета, сверенные по SHA-256; ученику их надо читать в браузере.
