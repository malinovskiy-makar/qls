# ADR 0056. Ноль — это значение, а погашенная кривая для модели отсутствует

- **Дата:** 2026-09-01
- **Статус:** принято
- **Автор:** Claude Code
- **Ветка:** `feat/calc2-panels-and-keypoints`
- **Решение владельца:** разбор калькулятора глазами 01.09 —
  «поставить потолок 0 или пол 101 при дефолтных функциях покажет равновесие
  50;50 — бред»

## Контекст

Два разных дефекта с одной причиной: **отсутствие значения путалось со
значением**.

1. По всему рынку стояли проверки вида `STATE.pReg > 0`, `STATE.quota > 0`,
   `Pw > 0`. Ноль — осмысленное значение («запрещаем торговлю совсем»), а код
   понимал его как «вмешательства нет» и показывал прежнее равновесие. При
   D = 100 − Q и S = Q потолок 0 рисовал равновесие 50; 50 — рынок, которого
   при такой цене нет.

2. Крестик у кривой со штатной ролью её не удаляет, а **гасит**
   (`curve.visible = false`, решение владельца 22.08 — гашение вместо удаления
   оставлено намеренно). А `curveByRole` про видимость не спрашивала вовсе:
   `STATE.S` продолжала указывать на погашенную кривую, и равновесие с
   излишками считались как ни в чём не бывало. На экране кривой нет, а числа
   есть.

## Решение

### Ноль значит ноль

Значение и «задано ли» разведены явно: `STATE.pRegSet`, `STATE.quotaSet`,
`STATE.openPwSet`. Признак ставится в ЕДИНОЙ двери каждого регулятора
(`setPRegFields`, `setQuotaFields`, `setOpenPw`) и гаснет в `loadScene` и при
смене вида вмешательства. Проверки `> 0` заменены на «задано» в 16 местах
(`40-scenes-market.js`, `42-scenes-mono.js`, `60-overlays.js`).

### Погашенная кривая для модели отсутствует

`curveByRole(role)` отдаёт только ВИДИМУЮ кривую. Для интерфейса и пресетов
заведена `curveByRoleAny(role)`: там роль занята и погашенной кривой, иначе
пресет монополии завёл бы вторую такую же. Решения по всем 17 вызовам:

| Кому | Какая |
|---|---|
| `STATE.D` / `STATE.S`, `laborD` / `laborS`, `mcSourceCurve`, TC, ATC, ключ кэша сложения | `curveByRole` — это МОДЕЛЬ |
| `ensureMonopolyCurves`, пресет рынка труда в `setMode` | `curveByRoleAny` — это про «занята ли РОЛЬ» |

### Рынка нет — честный ответ, а не пустое табло

Пол выше резервной цены покупателя (`Pf > D(0)`) и потолок ниже резервной цены
продавца (`Pc < S(0)`) означают нулевой объём торговли. Проверяется **по самим
кривым**, а не сравнением с равновесием: равновесия может и не быть.
Формально отрицательный объём срезается в ноль — продавец не выходит на рынок
«минус на десять единиц».

Ответ один на все случаи — **прежний механизм «Равновесия нет»**, второго не
заведено. Погашенная кривая говорит там же и называет свою причину: «одна из
кривых выключена», а не прежнее «отметьте одну кривую как D» — кривая
отмечена, её просто выключили.

## Отвергнутый вариант

**Считать «не задано» отдельным значением `null`, а не признаком рядом.**
Выглядит чище: одно поле вместо двух. Отвергнуто: `STATE.pReg` читают ползунок,
числовое поле, перетаскивание линии и четыре рисователя, и все они ждут число.
Пустить туда `null` значило бы переписать каждое место с проверкой на `null`,
то есть завести ровно ту же ошибку с другой стороны — и притом там, где сейчас
всё работает.

## Контрольные числа

D = 100 − Q, S = Q (равновесие 50; 50, CS = PS = 1250, SW = 2500):

| Случай | Ответ |
|---|---|
| Потолок 0 | Q 0, CS 0, PS 0, DWL 2500, «Равновесия нет» |
| Пол 101 | то же: Q 0, DWL 2500 |
| Потолок 40 (связывает) | Q 40, дефицит 20 — **не сдвинулись** |
| Погасили S крестиком | равновесия нет, излишки пусты, спрос на месте; галочка вернула 50; 50 и CS = PS = 1250 |

Монополия D = 100 − Q, MC = 20:

| Случай | Ответ |
|---|---|
| Квота 0 | Q 0, PS 0, CS 0, DWL 3200 |
| Квота 20 | Q 20, P 80, PS 1200, CS 200, DWL 1800 — приёмка 31.08, **не сдвинулись** |
| Квота 40 и 60 | по-прежнему не связывают |

⚠️ Значение «пол 101» упирается в потолок ползунка (`CONFIG.Pmax` = 100) и
становится ровно 100. Это и есть резервная цена покупателя, поэтому числа те
же — но сам зажим к этой правке отношения не имеет и остаётся как был.
Карточка заведена.

Проверки: контрольные числа 203/203, `calc2/tests/panels_probe.mjs` 83/83.
