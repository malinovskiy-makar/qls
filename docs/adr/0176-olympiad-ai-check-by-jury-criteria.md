# ADR 0176 — ИИ-проверка решения тура по критериям жюри: разбор критериев, своя валидация, очередь без Celery

* **Дата:** 2026-10-30
* **Статус:** принято ночной сессией; подтверждение владельцем — утром 31.10.
  Флаг `OLYMPIAD_AI_CHECK` на бою выключен до правовой части.
* **Ветка:** `feat/olympiads-screens-20261031`; код `olympiads/ai_check.py`, профиль
  `olympiad_check` в `problems/ai/prompts.py`, модель `TrainingCheck` (миграция
  `olympiads/0015`), тесты `olympiads/tests/test_night_E7.py`.
* **Основа:** решение владельца 30.10 «Развёрнутые олимпиадные решения проверяет
  ИИ по официальным критериям; ученик прикрепляет фото или файл» (карточка
  «Решения» 408b11c9…), образец — `catalog/attempts.py` (ADR 0079, 0081).

## Решение

1. Критерии — раздел после `## Критерии оценивания` в `Problem.solution`.
   Строка «K1 … → 1 балл» — критерий `{код, текст, максимум, пункт}`; строка с
   кодом без балла («K7 Если…, то…») — правило, уходит модели целиком.
   Сумма максимумов ≠ максимуму задания (или ни одной строки с баллом) —
   проверка одним баллом по тексту критериев, «оценка ориентировочная».
   Критериев нет — модель не зовём, ученику эталонное решение.
2. Наружу — условие и пункты, критерии и правила, максимум, текст решения и
   листы (расшифровка — `catalog.attachments.recognise`, тот же путь, что у
   фото в «Столе»). Эталонное решение не уходит: оценка только по критериям.
   Полей профиля нет (тест читает собранный запрос).
3. Схема ответа — балл по каждому критерию `{code, score, verdict, why}` и
   общий комментарий. Своя валидация: коды только из списка и каждый ровно
   раз, балл 0..максимум критерия с шагом 0,5, сумма ≤ максимума задания.
   Нарушение — `status='error'`, балла нет, страница не падает.
4. «Без времени» — проверка синхронно при «Сдать задание», потолок времени
   ядра. «На время» — при сдаче тура все открытые задания с критериями и с
   решением встают в очередь `queued`; страница результата зовёт
   `POST …/check-next/`, который проверяет одно задание за запрос. Без
   Celery и Redis.
5. Итог проверки пишется в `TrainingItemResult` (балл, `is_pending=False`),
   итог попытки — `engine.recount`. Кто: только вошедший с согласием `ai`;
   суточный лимит обращений ядра и денежный потолок `olympiad_check`
   ($1 в сутки, как у `catalog_check`). Гость — «Войдите, чтобы ИИ проверил».

## Отвергнуто

- **Балл 0..10, как у `catalog_check`.** Олимпиадный балл — сумма критериев
  жюри; переводить его в десятибалльную шкалу значит терять разбивку, ради
  которой критерии и взяты.
- **Эталонное решение в запросе.** Критерии самодостаточны («любым корректным
  способом»), а эталон подталкивал бы модель снимать баллы за другой путь.
- **Celery для очереди.** Проверка одного задания укладывается в запрос;
  очередь из базы и опрос страницы закрывают «4 задания после тура».
