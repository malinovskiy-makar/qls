# ADR 0125 – Прохождение варианта ВП: доступ к попытке, время с запасом, сохранение без потерь

* **Дата:** 2026-09-21
* **Статус:** действует

## Контекст

Сессия 2 «Высшей пробы» делает экран, на котором школьник решает вариант: одна страница,
44 задания, серверный таймер, автосохранение, сдача. Вход не нужен никому (решение владельца),
поэтому «чья это попытка» приходится решать без аккаунта. Тур идёт 26 и 30 сентября, на
экран одновременно придут сотни людей, и потеря введённого во время тура недопустима.

## Решение

**Доступ.** Одна функция `views._get_attempt(request, code)`. Если у попытки есть `user` — он
должен совпасть с `request.user`. Иначе (гостевая) — код в `request.session['vp_attempts']`
(последние 50) ИЛИ ключ сессии равен `attempt.session_key`. Иначе **404, а не 403**: чужую
попытку не должно быть видно даже по факту существования. Список кодов в данных сессии, а не
только ключ: при входе в аккаунт ключ сессии меняется, данные — нет, и гость не теряет свою
работу. Публична только `result` (по коду, без ответов) — ссылкой можно поделиться.

**Время.** Считает сервер: `problems.exam_engine.seconds_remaining` и `can_accept`, своей
арифметики остатка нет (там же защита «остаток не больше выданного»). Завершение ленивое:
любой запрос к `take`, `save`, `time_left`, `finish` по истёкшей попытке сначала сдаёт её
(`_finalize(auto=True)`). «Истёкшей» считается попытка после `expires_at + GRACE_SECONDS`
(10 с, `can_accept`): запас нужен ради последнего ответа, который летит по сети в момент, когда
таймер дошёл до нуля — «засчитается всё, что введено» выполняется только с запасом. Время
автосдачи — всегда `expires_at`, а не «когда заметили».

**Пустой ответ — не «неверно».** `score_item` возвращает `(0.00, None)` для пустого; `wrong_penalty`
к пустому не применяется никогда. «Не успел» и «ошибся» — разные вещи для разбора и статистики.

**Сохранение.** `POST save` принимает пачку `{"answers": [{"item": N, "raw": …}]}`, проверяет
её целиком до записи (кривой ответ отклоняет всю пачку), пишет только `raw` (upsert; гонка двух
сохранений уходит в UPDATE), баллов не считает. Клиент копит изменения: через 3 с после
последнего нажатия, не чаще одного запроса в 10 с; уход из поля приближает отправку к моменту,
когда интервал позволяет; уход со страницы — сразу (`sendBeacon`, он не умеет заголовков,
поэтому шлёт форму с `csrfmiddlewaretoken` и `payload`).

**Перезагрузка без пустых полей.** `sendBeacon` доставляется ПАРАЛЛЕЛЬНО загрузке новой страницы:
сервер может отрисовать её раньше, чем дойдёт последняя запись (найдено браузерной проверкой —
все 30 полей пусты, через две секунды на месте). Поэтому несохранённое ещё и синхронно
откладывается в `sessionStorage` при уходе и возвращается в поля при загрузке.

**Сдача не затирает.** «Сдать» сначала дожидается отправки того, что участник менял; `finish`
принимает поля формы только как запасной путь и **пустое значение из формы ничего не стирает**
(страница, отрисованная раньше последней записи, несёт устаревшие пустые поля). Стереть ответ
можно только через `save`.

**`table_html` через `|safe`** без очистки — решение владельца: содержимое приходит только из
наших YAML через `import_vp` и из админки (доступ у staff); пользовательский ввод в поле не
попадает никогда. Комментарий стоит в шаблоне.

## Отвергнуто

* **Финализация строго в `expires_at` без запаса** (как у `exam_engine.finalize_if_expired`):
  последний ответ, летящий в момент нуля, получал бы 409 и терялся.
* **Синхронный XHR на уходе со страницы** — Chrome запрещает его во время выгрузки страницы.
* **Форма сдачи как единственный источник правды** («побеждает последний» для всех полей):
  устаревшая вкладка затирала бы сохранённое пустыми полями.
* **403 вместо 404 для чужой попытки** — выдаёт факт существования кода.
* **Ключ сессии как единственный признак гостя** — гость терял бы работу при входе в аккаунт.

## Последствия

* Все обращения к попытке идут через `_get_attempt` / `_load_attempt`; проверка владения не
  дублируется. Защищено тестами 4, 4b, 4c и зубастостью: без проверки краснеют семь тестов.
* Браузерный тест `vp/tests/test_browser.py` идёт на PostgreSQL (`config.settings_test_pg`); на
  SQLite в памяти пропускается — живой сервер делит с тестом одно соединение и ловит ложные 500.
* Разбор ответов (цепочка змейки, арифметика штрафов) — сессия 3; здесь только итоги.
