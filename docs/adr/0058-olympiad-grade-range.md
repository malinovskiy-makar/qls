# ADR 0058. Расхождение по классу — это диапазон, а не конфликт

**Дата:** 2026-09-02
**Статус:** принято
**Контекст сессии:** поиск текстовых копий олимпиадных задач по всему банку
(`find_olympiad_text_duplicates`), правка плана владельцем по ходу работы.

## Контекст

После привязки задач к олимпиадам (`OlympiadRef`, 2 930 строк на 2 426 задач)
у 379 задач оказалось больше одной строки. Первая формулировка правила
объявляла любое расхождение метаданных между строками конфликтом —
с записью в файл разбора и без автоматической записи в базу.

Проверка на исходном экспорте ILE показала, что это неверно. Задача
`https://iloveeconomics.ru/z/2438` («Коэффициент Джини и рокировка») числится
у источника двумя записями: `ile-proba-2011-10-1` (класс 10) и
`ile-proba-2011-11-2` (класс 11) — олимпиаду «Проба» 2011 года с этой задачей
писали и десятые, и одиннадцатые классы.

Это не порча данных и не спор источников. Так устроены сами олимпиады: одну
задачу регулярно дают нескольким параллелям сразу. Источники лишь пишут это
по-разному — SolveHub кладёт готовый диапазон одной строкой («7-11»), ILE
заводит отдельную запись на каждый класс.

## Решение

**Конфликт — это расхождение по `olympiad_slug`, `year` или `stage`.**
Расхождение только по `grade` при совпадающем туре конфликтом не является:
классы объединяются в множество и печатаются диапазоном.

Разбор ведёт `problems/olympiad_grades.py`:

* `parse_grades('7-11')` → `{7,8,9,10,11}`, `parse_grades('9')` → `{9}`;
* `format_grades` схлопывает подряд идущие в диапазон, разрывы разделяет
  запятой: `{9,10,11}` → `'9-11'`, `{7,8,10,11}` → `'7-8, 10-11'`;
* группировка идёт по ключу тура `(olympiad_slug, year, stage)` — класс в
  ключ намеренно не входит, иначе строки не встретились бы в одной группе.

**Провенанс не схлопывается.** Строки `OlympiadRef` остаются как есть, по
одной на исходную запись источника; диапазон — это способ ПОКАЗАТЬ группу,
а не заменить её. Пропагация на найденную копию тоже пишет отдельную строку
от каждого согласного якоря.

**Значение считается на лету, отдельного поля в базе нет.**

## Что это дало на фактических данных

Из 379 задач с несколькими строками:

| | задач |
|---|---|
| `agree` — тур и класс совпали, различаются только `event_id` | 29 |
| `grade_only` — тур совпал, классы разные → объединяем | **347** |
| `conflict` — разошлись олимпиада, год или этап | **3** |

Правило снимает 347 ложных конфликтов из 379. Все три оставшихся —
**внутри одного сайта**; между SolveHub и ILE противоречий нет ни одного.

Полученные диапазоны: `9-11` ×114, `10-11` ×56, `9-10` ×56, `8-9` ×46,
`7-11` ×12 и другие. С разрывами: `7-9, 11` ×4, `8, 10` ×2, `9, 11` ×2,
`7-8, 10-11` ×1, `7-8, 11` ×1 — «список через запятую» без схлопывания
пробегов на `7-8, 10-11` не хватило бы.

У задач `#61600` и `#1733` конфликт и объединение классов сосуществуют:
расхождение по олимпиаде идёт поверх нормального «задача для двух
параллелей». Группировка по ключу тура разводит эти два случая правильно —
конфликт остаётся конфликтом, а классы внутри каждого тура сливаются.

## Отвергнутые варианты

**Денормализованное поле на `Problem`** (например `olympiad_grade_range`).
Отвергнуто по трём причинам, в порядке веса:

1. Жёсткая граница задачи прямо запрещает менять `Problem`,
   `SourceReference` и `ProblemPart`. Новое поле её нарушает.
2. **Одно поле физически не выражает ответ.** У `#1733` два разных тура с
   разными классами; скаляр на задаче обязан один из них потерять. Ответ —
   это отображение «тур → класс», а не значение.
3. Строки `OlympiadRef` прибавляются при каждом прогоне пропагации, и поле
   устаревало бы молча. Потребовались бы команда пересборки и сторож
   устаревания — ровно тот класс ловушек, про который предупреждает
   `CLAUDE.md` (ловушка done-файла, устаревший кэш `cache_similar`).

Стоимость расчёта на лету нулевая: у задачи 1–4 строки.

**Считать конфликтом любое расхождение, включая класс.** Отвергнуто
измерением: это отправило бы 347 из 379 задач на ручной разбор, из которых
ни одна разбора не требует. Очередь, на 92 % состоящая из не-проблем,
перестаёт читаться — и настоящие три случая утонули бы в ней.

**Брать класс из случайной строки группы.** Отвергнуто: значение зависело бы
от порядка выборки из базы, то есть одна и та же задача показывала бы разный
класс на разных прогонах.
