# ADR 0054. Порог близости — настройка со стартовым 0,55, а не число в коде

**Источник:** сессия «умный каталог», 01.09.2026, ветка `feat/smart-catalog`.
Решение владельца: «смысловой поиск отсекает результаты по порогу… Сделай
порог НАСТРОЙКОЙ, а не числом в коде». Здесь записано, откуда взялось
стартовое значение и почему оно именно такое.

## Что решили

`SEMANTIC_SEARCH_MIN_SCORE` в `config/settings.py`, умолчание **0,55**,
переопределяется переменной окружения. Совпадения ниже порога не
показываются вовсе.

## Почему порог вообще нужен

Без него смысловой поиск ВСЕГДА возвращает двадцать «самых похожих» — даже
когда похожего нет. На «как сварить борщ» человек получал двадцать задач про
издержки и не мог понять, при чём тут они.

## Откуда 0,55 — замер, а не вкус

Корпус 14 458 видимых задач, BGE-M3, живые запросы через поднятый локально
`search_service`:

| Запрос | Максимум | ≥0,55 | ≥0,60 | ≥0,65 |
|---|---|---|---|---|
| «как сварить борщ» | 0,493 | 0 | 0 | 0 |
| «квантовая хромодинамика» | 0,423 | 0 | 0 | 0 |
| «монополия» | 0,630 | 200 | 37 | **0** |
| «налог» | 0,611 | 172 | 3 | 0 |
| «фискальная политика мультипликатор госзакупок» | 0,672 | 55 | 16 | 4 |
| «монополист максимизирует прибыль при линейном спросе…» | 0,752 | 200 | 200 | 164 |
| «эластичность спроса по цене» | 0,778 | 200 | 200 | 200 |

Мусор отсекается с запасом: лучшее совпадение бессмысленного запроса — 0,493,
то есть **0,057 до порога**.

## ⚠️ Почему НЕ 0,65 и не выше

**Близость BGE-M3 не калибрована по длине запроса, и это видно замером.**
Одно слово «монополия» даёт максимум 0,630, а абзац с описанием той же задачи
— 0,752. При пороге 0,65 абзац сохранил бы 164 совпадения, а слово — **ноль**:
поиск молча переставал бы работать для коротких запросов, оставаясь рабочим
для длинных. Ни одна проверка этого бы не показала.

## Что отвергли

**Относительный порог** (доля от лучшего совпадения) напрашивается и, вероятно,
правильнее: он снимает зависимость от длины запроса. Но это СМЕНА ПОВЕДЕНИЯ
поиска, а не подбор числа, и решать её владельцу. Зафиксировано как вопрос.

**Оставить как было, без порога.** Отвергнуто: см. «зачем порог нужен».

## Что делать дальше

Порог придётся калибровать заново после прогона обогащения: отпечатки задач
станут другими. Место для калибровки — Dataset B. Значение живёт в одной
строке настроек именно поэтому.

## Чем стережётся

`catalog/tests/test_smart_catalog.py` — поведение вокруг поиска (пустой запрос
не будит модель, деградация отвечает 200 и находит словами). Само число
проверкой не стережётся намеренно: оно обязано двигаться.
