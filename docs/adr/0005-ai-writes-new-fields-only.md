# ADR 0005. ИИ дописывает новые поля, а не переписывает существующие

**Дата:** зафиксировано задним числом 2026-08-18 (решение принято после происшествия)

## Контекст

Банк — около 31 тысячи задач из ~24 источников, собранных парсерами из PDF, DOCX,
LaTeX и OCR. Тексты местами покорёжены импортом, и соблазн «пусть модель всё
почистит» естественный.

Свип Батча 2 прошёл по текстам массово. Последующий замер по бэкапу отката
показал: правка **ухудшила 233 поля в 195 задачах** — 13,2% затронутого.
Отчёт — `reports/batch2_sweep/applied_revert_audit.md`.

Отдельно выяснилось, что дешёвого детектора ухудшения не существует. Текстовый
предфильтр к ошибкам KaTeX слеп: выборка из 100 полей, не отмеченных ни одним из
шести признаков порчи, дала 3 поля с выросшим числом ошибок рендера. «Сломанная
формула» — это то, что решил KaTeX, а не то, что мы про него думаем.

## Решение

**Модель дописывает НОВЫЕ поля. Существующие `statement`, `answer`, `solution`
она не переписывает.**

Результат работы модели попадает в отдельные поля (`ai_blurb`, теги, темы,
вынесенное решение) — там ошибка не разрушает исходник и откатывается удалением
поля, а не восстановлением из бэкапа.

Механические правки текста (склейка PDF-нарезки, чистка LaTeX-мусора) делает
**детерминированный код** по явным правилам, а не модель. Такой код проверяем,
идемпотентен и объясним построчно.

## Обязательный конвейер массовой правки

`--dry-run` → HTML-предпросмотр → **стоп-гейт владельца** → бэкап → применение →
проверка идемпотентности (повторный dry-run обязан дать ноль).

Ни один шаг не пропускается. Проверка идемпотентности — не формальность: она
ловит правила, которые «доедают» текст на втором проходе.

## Последствия

- Чистка идёт медленнее, чем хотелось бы.
- Зато любой шаг обратим, а исходный текст задачи остаётся тем, что написал автор.
- Рендерить при проверке надо **всё**, а не выборку по признакам: экономия на
  рендере уже один раз стоила 195 задач.
