# ADR 0129 – Защита банка от выгрузки: решения и ответы — только вошедшим, квоты и лимиты на условия

* **Дата:** 2026-09-24
* **Статус:** действует.

## Контекст

Банк задач — главный актив. Условия обязаны оставаться открытыми: без них страницы задач не
проиндексируют Google и Яндекс. Но до 24.09 выгрузить можно было и то, что ценнее условий:
полное решение и ответы к пунктам лежали в разметке страницы задачи (`<template>`) у каждого гостя,
«Почему так» теста — тоже; корзина репетитора одним запросом со списком id отдавала любые задачи с
решениями, включая скрытые и бракованные; подборка (анонимная, по ссылке) пускала непроверенные
задачи и отдавала `.tex` с ответами без счёта; ни на скорость, ни на число разных задач лимитов не было.

## Решение

Слои, от ценного к открытому:

1. **Решения и ответы — только вошедшим** (решение владельца 24.09). В разметке их нет ни у кого;
   вошедший получает их `POST /catalog/api/solution/<id>/` после «Открыть»; верный вариант теста
   (`test-reveal`) и «Почему так» — тоже только ему. Гость видит карточку «Решение и ответы
   открываются после короткой бесплатной регистрации · Логин и пароль, без почты» с возвратом на
   задачу. Гостю остаются условие, подсказки и проверка своего ответа теста «верно / не то».
2. **Массовые пути закрыты.** Корзина, «Целиком» и предпросмотр репетитора — только видимое
   (`base_queryset('tutor')`) или из собственных работ, не больше 100 ключей. Подборка — только
   видимые задачи и не больше 50; файл с ответами/решениями — вошедшему, 20 в сутки.
3. **Квота РАЗНЫХ задач** (`catalog/scrape_guard.py`): гость 150/час и 600/сутки по адресу,
   вошедший 300 и 1000 по аккаунту; уже открытая задача квоту не тратит; сверх — 429. Проверенные
   поисковые роботы (User-Agent + обратный и прямой DNS) не ограничиваются.
4. **Лимиты скорости в nginx** по настоящему адресу: страницы задач 60/мин, эндпоинты скриптов
   120/мин, выгрузки 6/мин, вход 10/мин, остальное 10/с; статическая страница 429.

## Почему так, и что отвергли

* **Решение гостю по запросу с лимитом на адрес** — отвергнуто владельцем: адреса дешёвые.
* **Закрыть и условия** — ломает поиск по банку снаружи; SEO — канал привлечения.
* **Квота по запросам, а не по разным задачам** — наказывает человека, который возвращается к своим
  задачам, и почти не мешает терпеливому скрипту.
* **Проверять роботов только по User-Agent** — поддельный «Googlebot» получил бы безлимит.

## Последствия

* Индексация не меняется: содержимое `<template>` поисковики не индексировали и раньше.
* Задача из домашки у вошедшего ученика — как раньше: решение ему открывается.
* В прогоне тестов квота разных задач выключена по умолчанию (`SCRAPE_GUARD_ENABLED`), её тесты
  включают её явно.
* Честно открыто: условия задач (осознанно, ради SEO) — замедлены лимитами, не закрыты.
* Тесты: `catalog/tests/test_guest_solutions.py`, `test_guest_solutions_browser.py`,
  `test_scrape_guard.py`, `test_collections.py`, `teacher/tests/test_bank_leaks.py`. Техника —
  `docs/SECURITY.md`, «Защита от выгрузки банка».
