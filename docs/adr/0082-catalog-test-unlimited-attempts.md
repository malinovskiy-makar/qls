# ADR 0082. Тест в каталоге: попытки без ограничения, число верных с третьей

**Нумерация:** файл перенумерован из 0074 при синхронизации веток 05.09.2026 (номер был занят)

**Дата:** 2026-09-04 · **Статус:** принято · **Контекст:** редизайн каталога, этап 7

## Контекст

Тесты в каталоге (1 465 видимых, три формата) показывались статичным
списком вариантов с кнопкой «Показать решение»: сыграть было нельзя.
Мокап `test_page_mockup.html` делает варианты плитками с проверкой.
Надо было решить, сколько попыток давать и что говорить при неудаче.

## Решение

- **Попытки не ограничены.** Каталог — тренажёр, а не контрольная: остановить
  человека после трёх неудач значит отправить его смотреть ответ.
- **Всё или ничего.** Отмеченное множество сравнивается с верным целиком
  (`answer_check.check_option_answer`): частичный набор — «Не то», без
  указания, какой вариант лишний. Иначе тест из четырёх вариантов
  решается перебором за два хода.
- **Число верных сообщается с третьей попытки**, то есть после двух неудач:
  «верных вариантов: 2». Это сужает перебор, но не выдаёт ответа.
- **Счётчик попыток живёт в сессии** и у гостя тоже; верный ответ и «Показать
  ответ» его сбрасывают. Верный ответ вошедшего фиксируется `CatalogAttempt`
  с итогом «тест: решено с N-й попытки» — той же сущностью, что и
  свободные попытки, чтобы статистика ученика была в одном месте.
- **Показ ответа — четыре состояния плиток** (выбрал и верно, выбрал зря,
  надо было выбрать, нейтрально) с подписями из разбора домашки
  `student/_option_review.html`: один язык разбора на весь сайт.
- **Тест без игры показывается обычной задачей.** Игра есть только у
  теста с вариантами-подпунктами и верными метками среди них (1 443 из
  1 465 видимых); 16 тестов с верными метками вне вариантов и 3 без
  вариантов не получают кнопки «Проверить», а не получают сломанную игру.

## Отвергнуто

- **Три попытки и блокировка.** Наказывает за любопытство; в игре Wecon
  Rush ограничение уместно, в каталоге нет.
- **Подсветка лишнего варианта при неудаче.** Превращает проверку в
  подсказку: перебором тест решается без понимания.
- **Хранить попытки в базе у гостя.** Гость не имеет сущности; сессия
  достаточна, а после верного ответа счётчик не нужен.

## Следствия

- Один тест можно «решить» много раз: `CatalogAttempt` пишется на каждый
  верный ответ. Статистике это не мешает: попытки видны по датам.
- Форматы тестов: «все верные» — множественный выбор, «один ответ» и
  «верно/неверно» — одиночный; плитки «Верно»/«Неверно» хранятся
  подпунктами у всех 348 видимых тестов (проверено по данным 04.09.2026).
