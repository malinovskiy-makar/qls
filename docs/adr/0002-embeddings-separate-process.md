# ADR 0002. Эмбеддинги считаются вне боевого сервиса

**Дата:** зафиксировано задним числом 2026-08-18

## Контекст

Семантический поиск построен на локальной модели `BAAI/bge-m3` (~1,4 ГБ,
sentence-transformers). Боевой сервис живёт на free-тарифе Render: 512 МБ памяти
и один общий CPU на всё, включая `gunicorn` с двумя воркерами.

Модель физически не помещается в этот бюджет. Даже если бы помещалась, каждый
воркер загрузил бы **свою** копию — память умножается на число процессов.

## Решение

`sentence-transformers` на проде **не устанавливается и не грузится**
(`LOAD_EMBEDDINGS_MODEL = False` в `settings_production.py`). Зависимости
разведены: `requirements.txt` — без ML, `requirements-local.txt` — с ML.

Эмбеддинги считаются **локально**, готовые векторы заливаются в базу.
Блок «Похожие задачи» на проде работает по заранее посчитанному кэшу M2M
`similar_problems`, а не по живому поиску.

## Последствия

- Прод не умеет искать по смыслу. Страница «Подобрать похожие» работает только
  локально — это известное ограничение, а не баг.
- Любая правка текста задачи требует **ручного** пересчёта эмбеддингов локально и
  повторной заливки. Забыли — поиск деградирует именно на исправленных задачах.
- Развёртывание лёгкое: образ без torch поднимается за минуты.

## Отвергнутые варианты

- **Держать модель в боевом процессе.** Не помещается в 512 МБ; на платном
  тарифе означало бы копию модели в каждом воркере.
- **Внешний API эмбеддингов.** Корпус и запрос обязаны кодироваться одной
  моделью, значит переход требует полного пересчёта ~31 тысячи векторов. Плюс
  облачные модели дают меньше измерений (у Яндекса — 256 против наших 1024).
  Решение отложено, не отвергнуто навсегда.
