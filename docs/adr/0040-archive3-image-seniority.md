# ADR 0040. Картинка берётся только из СВОЕГО проекта Overleaf

**Дата:** 2026-08-30
**Статус:** Действует
**Ветка:** `feat/publish-readiness-legacy-new-sources`

## Контекст

После восстановления картинок из выгрузки 2026 года
([ADR 0037](0037-legacy-figures-from-raw-archives.md)) у 465 ссылок
`\includegraphics` файла не нашлось вовсе: ссылки ведут в папки вроде
`00все снимки/…`, которых в выгрузке нет.

Папка `weconomics-data/Archive 3 - ИЗНАЧАЛЬНАЯ БАЗА` оказалась не
распакованным каталогом, а четырьмя зипами, и внутри `Archive 2.zip` лежит
**61 вложенный зип проектов Overleaf**. По верхнему уровню было видно 214
картинок и ни одного `.tex`; внутри вложенных — **4 246 картинок и 3 754
`.tex`**. Это более ранние выгрузки тех же проектов: по `sha256` со слотами
`_raw2026` не совпал ни один из 62, по имени зипа совпали 56.

## Проблема

Имена картинок НЕ уникальны между проектами. Из 418 совпадений по имени
**390 неоднозначны**: `1.jpg`, `Fin1.png`, `фото кпв.png` встречаются в
разных проектах и означают разные картинки. Взять первую попавшуюся значило
бы приписать задаче чужой график — ровно то, что ADR 0037 назвал худшим
исходом, чем отсутствие картинки.

## Решение

Правило старшинства (`manage.py corpus_archive3_images`):

| вердикт | условие |
|---|---|
| **A** | файл в зипе ТОГО ЖЕ проекта Overleaf (имя вложенного зипа = имя зипа слота из `inventory.json`), совпал хвост пути |
| **B** | тот же проект, совпало имя файла |
| **C** | проект чужой, НО все копии с этим именем побитово равны (`CRC32` + размер) — выбор безразличен |
| **D** | не берём |

Команда не пишет в базу: она докладывает найденный файл в
`_raw2026/<слот>/<путь из ссылки>`, то есть достраивает выгрузку до вида,
которого ждёт `\includegraphics`. Дальше картинки заводит
`corpus_legacy_figures` своим обычным ходом — логика разрешения ссылок
остаётся в одном месте, а не копируется.

## Вторая находка: ссылка без расширения

`\includegraphics{Фото/СК2.4}` — на диске `СК2.4.png`: LaTeX подставляет
расширение сам, а `os.path.splitext` честно считает `.4` расширением.
Перебор написаний (тот же, что в `raw_units.resolve_image`) вернул ещё 23
ссылки у 12 задач. Голое имя без точки кладётся на диск С расширением:
`resolve_image` для такой ссылки перебирает `имя.png`, `имя.jpg`, … и
голое имя не проверяет вовсе.

## Результат

Нерешённых ссылок **465 → 24** (закрыто 441, то есть 94,8 %). Вердикты:
A 191, B 246, C 4, D 24. `ProblemFigure` 2 212 → 2 498.

## Чего это правило стоит

Из 24 оставшихся ссылок у 20 карточек реально показали бы картинку 7.
Скриншоты из PDF (вариант, который рассматривался) не делались: оставшиеся
ссылки не найдены НИГДЕ — ни файлом, ни внутри PDF, — и вырезать рисунок
пришлось бы угадывая, какая картинка какой задаче принадлежит. Это ровно
тот запрет, ради которого правило и вводилось.

## Проверка

15 тестов (`problems/tests/test_corpus_archive3_images.py`). Зубастость
главного свойства проверена возвратом дефекта: если убрать сверку байтов у
вердикта C, тест «одно имя, разные файлы, чужие проекты» краснеет.
