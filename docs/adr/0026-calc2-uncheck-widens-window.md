# ADR 0026. Снятая галочка «только первая четверть» сама раздвигает окно

- **Дата:** 2026-08-25
- **Статус:** принято
- **Автор:** Claude Code
- **Ветка:** `feat/calc2-priyomka-fixes`
- **Решение владельца в Notion:** «снятая галочка „только первая четверть“
  сама раздвигает окно до точек вне четверти» (25.08)

## Контекст

Дважды подряд сделанное за пределами первой четверти оказывалось невидимым:
продолжение MR и центр поворота при процентном налоге. Чтобы увидеть точку,
окно приходилось раздвигать вручную.

По [ADR 0019](0019-calc2-first-quadrant-is-scene-property.md) галочка управляет
границами плоскости и больше ничем. Значит раздвинуть границы — ровно её
работа, новой сущности не вводится.

## Решение

При СНЯТИИ галочки окно расширяется так, чтобы в кадр попали точки, которые
сцена показывает вне первой четверти. Границы:

- расширение происходит ОДИН РАЗ, в момент снятия. Дальше человек
  распоряжается окном сам: колесо и панорама сюда не заходят, потому что
  `fitWindowToOffQuad` зовёт только сама галочка;
- при включённой галочке не меняется ничего;
- показывать нечего — окно не трогается (остаётся обычный показ отрицательной
  части на четверть окна, который галочка делала и раньше);
- окно перестало быть масштабом сцены, поэтому ставится `STATE.viewDirty` —
  авто-подгонка молчит, а кнопка «Вернуть исходный вид» на месте.

Запас по краю — восьмая часть нынешнего окна: точка, легшая ровно на границу,
читается как обрыв кривой, а не как то, что нам хотели показать.

## Список точек берётся у НАРИСОВАННОГО, а не у второй копии правила

Продолжение предельной кривой рисуют четыре сцены, и докуда оно тянется, знает
только сам рисователь (`drawMarginalCurve`: до нуля породившей кривой).
Переписывать это условие в `86-workspace.js` значило бы завести вторую точку
правды, которая рано или поздно разойдётся с первой.

Поэтому хвосты читаются с холста по их собственной пометке
`data-marginal-tail`, а пиксели переводятся обратно теми же шкалами. Две
точки, которые сцена знает точно, берутся из модели: `STATE.offEq` и
`taxPivotPoint()`.

Отсюда же порядок: расширение считается ПОСЛЕ отрисовки. До неё продолжений на
холсте ещё нет. Второй перерисовки не боимся — это один щелчок человека, а не
кадр панорамирования.

## Числа

| случай | было | стало | запас от края |
|---|---|---|---|
| пересечение вне четверти (−100; 200) | окно −25…100 / −25…100, точка снаружи | −110…100 / −25…210 | 4,8 % и 4,3 % |
| центр поворота при акцизе 25 % (−60; 0) | точка снаружи | −70…100 / −25…100 | 5,9 % и 20 % |
| конец продолжения MR (100; −100) | точка ровно на границе | −25…110 / −110…100 | 7,4 % и 4,8 % |

## Отвергнутые варианты

**Раздвигать окно ВСЕГДА, когда галочка снята.** Тогда сцена без ничего вне
четверти получала бы окно шире нужного без всякой причины.

**Показывать такие точки в отдельной мини-панели, не трогая окно.** Заводит
второе место, где живёт график, и теряет главное — увидеть, КУДА именно уехала
точка относительно остальной картины.

**Держать окно раздвинутым, пока галочка снята (возвращать после панорамы).**
Отнимает окно у человека: снял галочку, отъехал посмотреть — и тебя вернули.
