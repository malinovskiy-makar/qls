# ADR 0080. Чат на странице задачи — одна реплика без памяти на сервере

**Нумерация:** файл перенумерован из 0072 при синхронизации веток 05.09.2026 (номер был занят)

**Дата:** 2026-09-04 · **Статус:** принято · **Ветка:** `feat/catalog-redesign`

## Контекст

Решение владельца 04.09.2026: ИИ-чат на странице задачи — постоянно видимая
карточка справа. Этап 5 редизайна делает её живой: ученик задаёт вопрос по
ОДНОЙ задаче, модель отвечает коротко и не выдаёт готовое решение.

## Решение

`POST /catalog/api/chat/` принимает `{problem_id, message, history}` и делает
**один вызов** `core.run('catalog_chat', …)`; ответ — `{reply}`. История
разговора — последние шесть реплик — **передаётся клиентом в каждом запросе
и на сервере не хранится**: новой модели под чат нет. Наружу уходят только
условие, подпункты, текст последней попытки и результат её проверки; поля
профиля — никогда (P0).

Если задача входит в активную домашку этого ученика (`AssignmentItem`
незакрытой работы), в системную часть добавляется режим «только наводящие
вопросы».

## Отвергнуто

- **Модель `ChatMessage` с историей** — хранить переписку школьника с
  моделью значит хранить ещё один массив персональных данных без нужды;
  для подсказок по одной задаче память в шесть реплик на клиенте достаточна.
- **Потоковый ответ (streaming)** — красивее, но требует другого транспорта;
  ответ до 900 знаков приходит за секунды и целиком.

## Последствия

- Обновил страницу — история пропала; это ожидаемо и написано в интерфейсе
  не будет: чат — подсказка, а не журнал.
- Лимит обращений общий с проверкой (`remaining_today`).
