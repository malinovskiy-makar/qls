# ADR 0074. Ученик попадает в занятие по коду приглашения

> **Дата:** 2026-09-04
> **Статус:** принято владельцем, реализовано
> **Где живёт:** `problems/models.py::StudentGroup.invite_code`,
> `teacher/views_groups.py`, `student/views.py::join_group`
> **Миграция:** `problems/0051_studentgroup_invite_code.py` (три шага)

## Решение

У каждого занятия есть **код приглашения** вида `XXXX-XXXX`. Репетитор
диктует его на занятии; ученик вводит на своём экране «Занятия» и попадает в
группу сам.

Выпадающий список всех учеников базы при создании индивидуального занятия
**удалён**.

```
Алфавит: ABCDEFGHJKLMNPQRSTUVWXYZ23456789   (32 знака)
Длина:   8 знаков, показываются как XXXX-XXXX
Всего:   32^8 ≈ 1,1·10^12 сочетаний
```

## Почему

**Прежний способ показывал чужих учеников.** `group_create` для
индивидуального занятия рисовал `<select>` со **всеми** учениками базы
поимённо. Это утечка, а не удобство: репетитор видел учеников других
репетиторов, их имена и фамилии. К бете таких имён будут тысячи, и список
перестанет быть пригодным и технически.

**Код диктуется голосом.** Это главное требование к формату, и из него
следует всё остальное: алфавит без пар, которые путают на слух и на доске
(нет `0` и `O`, нет `1` и `I`), дефис посередине для удобства чтения, и
приём кода в любом виде — строчными, без дефиса, с пробелами.

**Ученик приходит сам.** Репетитору не нужно ни знать логин ученика, ни
искать его в списке: он называет код, и дальше это забота ученика.

## Что отвергнуто

**Ссылка-приглашение с токеном.** Тоже годится и даже удобнее в переписке.
Отвергнута потому, что код **проще продиктовать голосом** — а занятие обычно
и происходит голосом. Ссылку ещё надо куда-то отправить; для этого нужен
канал связи, которого у платформы с учеником пока нет.

**Оставить список всех учеников.** Отвергнут как утечка (см. выше).

**Приглашение по логину ученика.** Отвергнуто: репетитор должен был бы
спросить логин, а логин — это половина пары для входа. Диктовать код
безопаснее, чем диктовать логин.

## Цена решения и чем она покрыта

| Риск | Чем удержан |
|---|---|
| перебор кодов | 32^8 ≈ 1,1·10^12; вслепую бессмысленно. Сверх того — лестница задержек с 10 промаха (`ratelimit`, scope `join`) |
| код утёк в чужие руки | «Новый код» одним нажатием; старый перестаёт работать сразу, уже вступившие остаются |
| ошибка выдаёт существование занятия | «Такого кода нет» — один и тот же ответ на выдуманный и на чужой существующий код |
| ученик раздаёт код дальше | Код ученику **не показывается** — он видит только название занятия и репетитора |

## Отчисление не стирает историю

`group.students.remove(...)` убирает из состава, но **не трогает**
`Assignment.students`. Уже выданные работы, ответы и оценки остаются за
учеником: это его история, а не собственность занятия. Отчисление означает
«новых работ не получает», а не «сделанного не было».

## Миграция — в три шага, и это не украшение

Поле уникальное и обязательное; добавить его сразу таким на таблицу со
строками — значит вписать во все занятия одно значение по умолчанию и тут же
нарушить уникальность. Отсюда: добавить с `null=True` → `RunPython` раздаёт
коды → `AlterField` закрывает поле.

⚠️ **Первая версия шага 1 добавляла поле с `db_index=True` — и развёртывание
с нуля падало на PostgreSQL:**

```
django.db.utils.ProgrammingError:
relation "problems_studentgroup_invite_code_b00ad554_like" already exists
```

Для текстовой колонки с индексом PostgreSQL заводит второй, вспомогательный
индекс `..._like` (`varchar_pattern_ops`); шаг 3 создавал уникальный индекс и
вместе с ним снова пытался завести `..._like`. **На SQLite этого не видно
вовсе** — там нет ни таких индексов, ни такой ошибки, и та же миграция
проходила зелёной. Индекс на шаге 1 не нужен: между шагами по коду никто не
ищет, а шаг 3 всё равно строит уникальный.

Проверено: развёртывание с нуля на чистом PostgreSQL, накат на копии рабочей
базы (5 занятий → 5 разных кодов по маске), откат `migrate problems 0050` и
повторный накат.

## Как сторожится

* `teacher/tests/test_invites.py` — 23 проверки: код по маске, 200 занятий →
  200 разных кодов, нормализация ввода, смена кода отменяет старый,
  отчисление сохраняет работы, **семь отрицательных** (чужой репетитор,
  ученик, гость, GET вместо POST), рост числа запросов;
* `student/tests/test_join.py` — 15 проверок: вступление в любом написании,
  молчание об существующих занятиях, повторное вступление, задержка после
  десяти промахов, код не показан ученику.
