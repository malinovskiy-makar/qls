# ADR 0128 – Умный поиск: платит только скрипт страницы; квоты, общий кэш в Redis, потолок $0,50 не меняем

* **Дата:** 2026-09-24
* **Статус:** действует. Развивает решение «SEO-фикс: боты не тратят бюджет умного поиска» (Notion, 19.09).

## Контекст

Платное переранжирование выдачи (GLM, ~$0,0024 за вызов) упирается в суточный потолок $0,50 — это
~205 вызовов. 17–19.09 краулеры (Amazonbot, Google) выбирали потолок к 20:42, 09:18 и 07:35, и живые
ученики до конца суток искали без сортировки. 19.09 закрыли `robots.txt`, `noindex` и проверкой
User-Agent. Этого мало: User-Agent подделывается, список ботов не бывает полным, карта тем
`/catalog/map/?q=` и эндпоинт `filter-state` оставались открытыми. Отдельно: кэш сортировки жил в
памяти каждого из воркеров (один запрос оплачивался до четырёх раз, неудачи кэшировались на час), а
расход упавшего запроса не попадал в потолок.

## Решение

1. **Полная загрузка страницы не платит никогда.** `/catalog/?q=` и `/catalog/map/?q=` приходят со
   статусом `deferred`: порядок «по словам» спрятан (только при включённых скриптах), горит
   индикатор, скрипт страницы сам просит `api_filter_state` — выдача показывается один раз, после
   ожидания (решение владельца 11.09).
2. **`api_filter_state` платит, только если одновременно**: заголовок `X-Weco-Search: 1` (ставят
   `catalog_filters.js` и `stol.js`), кука посетителя `weco_vid`, User-Agent не бот (пустой — бот,
   но только для сортировки). Иначе `deferred` или `bot` — бесплатный порядок.
3. **Квоты реально оплаченных вызовов** по московским суткам: посетитель 40, вошедший 80 (квота
   посетителя к нему не применяется), адрес 150 — `SMART_SEARCH_QUOTA_*`. Сверх — `quota`.
4. **Общий кэш удачных результатов** в кэше Django (на бою Redis) на сутки; ключ — хэш запроса и
   всего, что меняет пул. Неудачи не кэшируются.
5. **Потолок выбран** — `budget` и одна строка WARNING в лог за сутки. Расход пишется и при упавшей
   пачке. `AiUsageLog` в админке (только чтение), команда `rerank_spend`.
6. `robots.txt`: `/catalog/*?q=`, `/catalog/*&q=`, `/catalog/api/`; карта с `q` — `noindex`.
   Список краулеров шире (+24 маркера) — защита в глубину.

## Почему так, и что отвергли

* **Поднять потолок** — отвергнуто владельцем 24.09: после отсечения ботов и повторов $0,50 людям
  хватает с запасом; поднятый потолок боты выбрали бы так же.
* **Только расширить список ботов** — не барьер: заголовок подделывается одной строкой.
* **Показывать сначала порядок «по словам», потом пересортировку** — отвергнуто решением 11.09:
  выдача, которая перестраивается на глазах, читается как сбой.
* **Кэш в памяти воркера с TTL подольше** — не лечит четырёхкратную оплату и не переживает перезапуск.

## Последствия

* Страница с `?q=` без JS показывает порядок «по словам» (фолбэк работает).
* Безголовый браузер (`HeadlessChrome` в User-Agent) для сортировки — бот; браузерные тесты ставят
  обычный User-Agent.
* `rerank.clear_cache()` чистит кэш Django целиком — только для тестов и офлайн-замеров.
* Тесты: `catalog/tests/test_rerank_gate.py`, `test_deferred_search_browser.py`. Техника —
  `docs/EMBEDDINGS.md`, «Кто и когда платит за переранжирование».
