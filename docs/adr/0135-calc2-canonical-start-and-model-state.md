# ADR 0135 — «Графики»: канонический старт модели и слой состояния

* **Дата:** 2026-10-06
* **Статус:** принято (опорное решение задания редизайна), ветка `feat/calc2-redesign`

## Контекст

22 маршрута из 44 лишь переключали режим и наследовали входы предыдущей модели
(x₀, МРОТ, второй спрос монополии, цены потребителя, `boundsByHand`, поля графика
`CONFIG.margin`): модель открывалась по-разному в зависимости от порядка. Истории,
ссылке и автосохранению нужен один объект «состояние модели».

## Решение

1. **Канонический старт одним механизмом** (`89-model-state.js`): в конце загрузки
   снимается чистое состояние (простые поля `STATE`, форма: значения, границы,
   инлайновая видимость, нажатость сегментов и тумблеров; окно и поля графика);
   `pickScene` возвращает к нему ДО маршрута. На свежей странице это ничего не
   меняет — базовый снимок и контрольные числа совпадают по построению.
2. **Память сессии хранит все входы** (не только `SNAPSHOT_KEYS`).
3. **`collectModelState()` / `applyModelState()`** — состояние модели одним JSON
   (`{v:1, key, route, state, form, view, margin, counters}`); синонимы `tax` и
   `tax-adv` дают ключ `taxes`. Ленивые кэши (`…Sig`) применением гасятся.
4. **Кэш разбора — по модели**, а не по базовой сцене: старый код показывал в
   «Изоквантах», «Двух заводах», «Производстве», «Дискриминации 3-й степени» и
   «Адвалорном налоге» разбор их семьи.

## Отвергнуто

44 списка входов в маршрутах: их пришлось бы держать в согласии с литералом
`STATE`, и первая же новая переменная протекла бы снова.

## Проверка

`calc2/tests/redesign/order_probe.mjs` (44 ключа подряд вперёд и назад, старт
равен базовому; память «ушёл и вернулся» без потерь), `state_probe.mjs` (собрать →
сбросить → применить, 44 из 44).
