# ADR 0027. Суммарная КПВ — закрытая форма по участкам для любого числа линейных кривых

- **Дата:** 2026-08-25
- **Статус:** принято
- **Автор:** Claude Code
- **Ветка:** `feat/calc2-priyomka-fixes`
- **Решение владельца в Notion:** приёмка 25.08, дефект 7

## Контекст

`combinedPpfFormula` в `54-scenes-ppf.js` выводила закрытую форму только для
ДВУХ кривых, и то обычным текстом: «Форма кривой: Y = 120 − 1·X при
X ∈ [0; 40]». Для трёх и больше `recomputePpfSumRaw` писала «Построена
численно: складываем по очереди», хотя в сложении прямых ничего численного нет.

Заодно численный детектор изломов давал (99,999; 60,001) там, где ответ ровно
(100; 60).

## Решение

Задача та же, что у суммарного спроса в сцене сложения, и решается так же:
отсортировать по альтернативным издержкам и склеить участки.

- Кто дешевле производит X, тот наращивает его первым — значит участки идут по
  возрастанию наклона `b`.
- На k-м участке производит k-й по дешевизне, поэтому наклон там ровно его:
  `Y = c − b_k·X`, а постоянная `c` берётся из непрерывности в начале участка.
  Никакого перебора и никакой сетки.
- Границы участков — накопленные `Xmax`: первый кончается там, где первый
  участник отдал под X весь свой ресурс.
- Равные альтернативные издержки склеиваются в один кусок: излома между ними
  нет, и рисовать его было бы враньём.

Запись набирается МАТЕМАТИКОЙ (`\begin{cases}`), ширину подгоняет общий проход
`fitPanelMath` — врезка у него та же.

**Хоть одна кривая нелинейна — возвращаем `null`,** и панель честно пишет
«построена численно». Дуга и парабола складываются не так, и подсунуть им
ломаную значило бы нарисовать не ту кривую. Проверено отдельным случаем:
`sqrt(10000−x²)` плюс `60−2x` закрытой формы не получает.

### Границы участков и изломы — не одно и то же

Границ у записи столько же, сколько участков: у двух КПВ это 100 и 130.
А ИЗЛОМОВ на один меньше: последняя граница — выход кривой на ось X, там
кривая кончается, а не ломается.

Разница не косметическая. `kinks` идёт в отрисовку (от каждого излома пунктир
к обеим осям и кружок) и в «Схему», которая рисуется только до трёх участков.
Считать конец кривой изломом значило бы дважды нарисовать метку в одной точке
и отобрать схему у сложения трёх кривых. Обе границы человек видит: они стоят
в самой записи, участками.

## Контрольные числа

Две КПВ `y = 100 − x` и `y = 60 − 2x`:

```
Y = 160 − X   при 0 ≤ X ≤ 100
Y = 260 − 2X  при 100 < X ≤ 130
```

излом (100; 60), конец кривой X = 130, Y при нулевом X = 160.

Три КПВ (плюс `y = 40 − 4x`):

```
Y = 200 − X   при 0 ≤ X ≤ 100
Y = 300 − 2X  при 100 < X ≤ 130
Y = 560 − 4X  при 130 < X ≤ 140
```

изломы (100; 100) и (130; 40), конец кривой X = 140, Y при нулевом X = 200.

## Отвергнутые варианты

**Оставить численную кривую, а запись просто дописать для трёх и четырёх.**
Тогда рядом стояли бы две математики: запись по участкам и ломаная по сетке, —
и расходиться они начали бы на первой же нелинейной кривой. Закрытая форма
СВЕРЯЕТСЯ с численной (`verifyFormula`) и показывается только если сошлась.

**Показывать запись обычным текстом, как раньше.** Запись функции здесь и есть
предмет обучения; «X ∈ [0; 100]» обычным шрифтом читается как строка из
журнала, а не как математика.
