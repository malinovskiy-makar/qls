# ADR 0167 — Экзамен ИИ v1 «Решатель» из официального эталона ВП/МОШ v6; судья — Claude

* **Дата:** 2026-10-28 (ночная сессия P4 «Экзамены ИИ»)
* **Статус:** сделано в ветке `feat/ai-exam-c` (от `feat/chat-tutor-1`), в `main` не влито. Продолжает [ADR 0134](0134-ai-exam-v0.md): из v0 остаются файлы вне
  репозитория, сейф и правило сравнения чисел. Номер выбран с запасом: 0160–0166 могли занять
  параллельные ночные сессии.

## Контекст

Экзамен v0 собирали из банка, где ключи ненадёжны: неделю стоял на ручной проверке. Решение
владельца 14.10 — задачи и ключи брать из официальных эталонов ВП и МОШ, люди смотрят только
споры судьи. Эталон v6 (15.10) — 837 строк ВП и 3 087 строк МОШ с решениями, критериями и
ответами.

## Решение

1. **Два блока.** A «Ответ числом» (60) — ключ из поля `answer` или из строк «Ответ:»
   официального решения, проверяет программа (`numbers.matches`). B «Олимпиадная задача» (90) —
   полное официальное решение, оценивает судья по критериям или по решению и `max_score`.
   Сейф — 12 + 18, рабочих — 120. Сборка детерминированная (seed 20261028), команда сама
   собирает дважды и сравнивает sha256.
2. **Ключ A — только однозначный.** Каждый сегмент ответа (`;`, строки, метки пунктов) — одно
   число; допустимы метка «L =», хвост единиц, проценты. Формула, неравенство, «или», «около»,
   диапазон — не ключ. Одно число на задачу, где в условии подвопросы «А) Б)» без пунктов, — не
   ключ (найдено на проверке ключей глазами: такие числа отвечали лишь на один подвопрос).
3. **Выбор из вариантов — тест,** даже без номера «тест-N»: список вариантов в условии и ответ —
   номер или текст варианта, «выберите»/«отметьте»/«соотнесите», варианты строками таблицы.
   В v1 не берутся (≈ 1 190 строк), только считаются.
4. **Исключения** (первая причина): тест, `needs_eyes`, `numbers_ok=false` (`None` — не
   исключение), рисунок в условии, пустое условие, служебный блок (в т. ч. склейка заданий со
   служебной строкой посреди условия), выбор из вариантов, нет ни ключа, ни решения.
5. **Свежесть ≥ 40 %** (2024/25–2025/26), пометка `fresh` у каждой задачи: старые решения лежат
   в интернете, сравнение свежих со старыми ловит заучивание.
6. **Судья — Claude** (`judge.py`), без `temperature` (Claude 5.5 её не принимает — 400), ответ по JSON-схеме: баллы по пунктам,
   вердикт, причины, дословная цитата, `reference_suspect`. Оценка — сумма баллов по пунктам
   (проверяема), а не «итог» судьи; «решено» — ≥ 80 % максимума. Постоянная часть по задаче
   (инструкция + условие + эталон) — первый системный блок под кэшем Anthropic. Полный прогон —
   пакетом Message Batches (−50 %).
7. **Потолок токенов решателя — 16 000** в обоих блоках: у GLM и DeepSeek рассуждение входит в
   выход, при 8 000 DeepSeek обрывал 8 ответов из 20. DeepSeek — 32 000 (на 16 000 обрезал 2 из 20;
   указание владельца «поднять потолок»).
8. **Какой судья — по согласию на пилоте** (≥ 85 % «решено/нет» → Sonnet, иначе Opus). Вышло
   41/47 = 87,2 % → Sonnet 5.5. Пять из шести расхождений — одна задача с критериями от ДРУГОЙ
   задачи в эталоне; судье добавлено правило: явно чужие критерии не применять, оценивать по
   решению, ставить `reference_suspect`.
9. **Состав решателей (дополнение владельца 28.10, 18:55):** GLM-5.3 low (как на сайте) и high,
    GLM-5.3-Flash high, Gemini 4 Argon, Claude Sonnet 5.5 и Opus 5.5 (effort high), gpt-6.1-sol и
    gpt-6.1-terra (medium), deepseek-flash; DeepSeek V4 Pro — только пилот. Каждая новая модель —
    пилот на тех же 20 задачах; в полный прогон — без массовых сбоев и в пределах потолка
    поставщика. Когда Claude судит Claude-решателя — пометка в отчёте и отдельная категория споров
    («Claude судит Claude»: судья не уверен или балл выше медианы остальных на 0,3+).
10. **«Утечка» v1** — 40 задач B с числом ответа, различимым на фоне условия: сначала рабочие B,
   недостающие — из пула B вне экзамена и сейфа (`leak_v1.jsonl`, свой генератор). Режимы чата
   «Вопрос», «Как решать», «Теория», «Проверь» + сценарий трёх настойчивых просьб с историей.

## Отвергнуто

* Ручная проверка задач экзамена — причина, по которой стоял v0.
* Брать в A тесты «выбор из вариантов»: угадываемы и не меряют решение.
* Потолок 8 000 токенов для решателя B: мерил бы длину рассуждения, а не умение.
* Судья GLM: общие слепые пятна с проверяемыми моделями (решение 14.10).
* Судья Opus по умолчанию: вдвое дороже, а согласие с Sonnet выше порога; Opus оставлен вторым
  судьёй пилота.
* Отсеивать задачи с чужими критериями порогом пересечения слов: короткие верные критерии дают
  такое же низкое пересечение — ложные срабатывания; судья видит смысл, порог — нет.
* gpt-6.1 с рассуждением high: прогноз не влезал в лимит OpenAI ($10 на сессию с расшифровкой).

## Последствия

* Утром 28.10 ключ Anthropic требовал заголовок `anthropic-workspace-id`, а ключ OpenRouter был
  служебным; вечером владелец добавил `ANTHROPIC_WORKSPACE_ID` и обычный ключ OpenRouter.
  `AnthropicProvider` читает ID из окружения.
* DeepSeek V4 Pro прошёл пилот, но в полный прогон не попал по деньгам: полный прогон (~$3)
  больше потолка DeepSeek ($2), модель самая дорогая у поставщика и не лучше остальных.
* Эталон v6 содержит критерии, приклеенные не к той задаче: это дефект эталона — он виден в
  споре «эталон под сомнением» и передаётся сессии эталона.
