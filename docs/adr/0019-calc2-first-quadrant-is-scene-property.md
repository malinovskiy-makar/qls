# ADR 0019. Правило первой четверти — свойство сцены, а не положение галочки

- **Дата:** 2026-08-25
- **Статус:** принято
- **Автор:** Claude Code, по решению владельца от 24.08
- **Ветка:** `feat/calc2-pct-tax`
- **Решение владельца в Notion:** «правило первой четверти действует всегда в
  экономических сценах; галочка управляет только осями и сеткой»
- **Продолжает:** [ADR 0017](0017-calc2-math-independent-of-viewport.md)

## Контекст

Сессия «первая четверть» (ADR 0017) обрезала экономические кривые по цене, но
привязала обрезку к галочке «только первая четверть» — так же, как обрезку по
количеству рядом (`quadLo`).

Из этого вышел абсурд, и он остался в карточке-вопросе владельцу: **при
ВКЛЮЧЁННОЙ галочке правило работает, но его результата не видно** — холст
режет прямоугольный `clip-path` по осям; **при СНЯТОЙ галочке результат было
бы видно, но правило выключается.** Отличить работу правила по виду нельзя
было никогда.

Замер: спрос 100 − Q при окне до Q = 200 со снятой галочкой давал в пути
кривой 160 точек с P < 0 (до P = −100), у предложения — 80.

Корень: `STATE.firstQuad` делал **две разные работы одним флагом** —
«сцена экономическая» и «показывать только первую четверть».

## Решение

Две вещи разведены (`calc2/static/calc2/20-plane.js`):

1. **`isEconScene()` — свойство сцены**, человек его не переключает.
   В экономической сцене кривая существует только при P ≥ 0 и Q ≥ 0.
   Экономические сцены — рынок, монополия, издержки, труд, торговля,
   потребитель, макро, КПВ, неравенство. Не экономические — «Математика» и
   построение графиков: там кривая это функция, правило не действует, и
   отрицательные значения строятся как раньше.
   Рядом `econLo(v)` — нижняя граница экономики по оси.

2. **`STATE.firstQuad` — галочка**, выбор человека. Управляет ТОЛЬКО осями,
   сеткой, границами плоскости и `clip-path` холста. На то, где существует
   кривая, не влияет.

По правилу сцены пошли: обрезка пути кривой и нижний край сэмплирования
(`curvePoints`, `30-curves.js`), окно поиска пересечений (`viewWindow`),
прокатывание точки по кривой (`rollerClampX`, `60-overlays.js`) и якорь
подписи кривой (`curveAnchor`, `30-curves.js`).

Исключения остаются прежними и рисуются пунктиром каждое своим кодом, через
`econLo` не проходят: предельные кривые, центр поворота, пересечение вне
первой четверти.

## Отвергнутый вариант

**Оставить как есть: галочка управляет обеими осями одинаково.** Симметрично
и предсказуемо на словах, но даёт тот самый абсурд, описанный выше: правило
не работает никогда там, где его результат можно увидеть.

## Почему так

Отрицательная цена и отрицательное количество не перестают быть
бессмысленными оттого, что человек раздвинул оси. Галочка — про обзор, а не
про экономику. Наоборот: видеть раздвинутые оси и обрыв кривой ровно на нуле
само по себе обучающе.

## Следствия

- В экономической сцене со снятой галочкой оси уходят в минус и сетка
  рисуется, а кривые обрываются на осях.
- Якорь подписи кривой обязан лежать в первой четверти. Без этого подпись
  садилась туда, где кривая БЫ была: на снимке приёмки «D» висела в пустоте
  при Q ≈ 145 и P ≈ −30.
- `setMode` ставит начальное положение галочки через `isEconScene()`, и это
  единственное место, где одно связано с другим.

## Как проверено

- `calc2/tests/pct_tax_probe.mjs`, набор Г: 160 точек с P < 0 → 0; оси
  Qmin/Pmin −50, сетка на месте; Q\* 50, P\* 50, CS = PS = 1250 не изменились;
  «Математика», парабола x²−4 — 79 точек с y < 0, не изменилось.
- `calc2/tests/calc2_math.mjs`, случай (проц-д) — обе половины сразу.
- `calc2/tests/audit_matrix.mjs` совпал с прогоном до правки построчно.
- Зубастость проверена **двумя противоположными** дефектами: «привязать
  правило обратно к галочке» и «резать везде, включая Математику» — оба
  краснят (проц-д).
