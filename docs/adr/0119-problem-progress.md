# ADR 0119 — Прогресс ученика по задаче каталога: своя таблица, правила в одном модуле

* **Дата:** 2026-09-18
* **Статус:** действует

## Контекст

Каталог «Стол» (решения владельца 17.09) показывает в строке ленты статус задачи у ученика
(не открывал · открывал · решил сам · с подсказкой · не получилось), под условием — «Как прошло?»,
а панель помощи должна переживать перезагрузку (сколько подсказок открыто, открыто ли решение). В
проекте такого знания не было: `CatalogAttempt` пишет только проверенные попытки, `LearningEvent` —
журнал, а не состояние.

## Решение

* Модель `ProblemProgress` (`problems/models_platform.py`, рядом с `SavedProblem`): пользователь,
  задача, `status` (`opened` / `solved_self` / `solved_hint` / `failed`), `hints_opened`,
  `solution_viewed`, `updated_at`; одна строка на пару.
* Правила — только `catalog/progress.py`: открытие задачи вошедшим заводит `opened`
  (неблокирующе); выданная подсказка поднимает `hints_opened` (только растёт); «решил сам» после
  открытого решения — отказ 400; тест ставит статус сам: верно с первой попытки без подсказок —
  `solved_self`, иначе `solved_hint`, «Показать ответ» — `failed`.
* `POST /catalog/api/progress/<id>/` — только вход (гостю 401 JSON), задача за шлюзом — 404.
* Статусы строк ленты — одним запросом на страницу строк (`statuses_for`).

## Отвергнуто

* **Считать статус из `CatalogAttempt` и `LearningEvent`** — нет ни подсказок, ни «смотрел решение»,
  а «не получилось» ставит сам ученик.
* **Хранить в `localStorage`** — статус нужен на другом устройстве и учителю позже.
