# Правила каталога и поиска

Локальные правила для `catalog/`. Общие запреты — в корневом
[CLAUDE.md](../CLAUDE.md). Устройство поиска — в
[docs/EMBEDDINGS.md](../docs/EMBEDDINGS.md).

---

## Шлюз качества держит везде

Зафлагованная задача (`needs_quality_review=True`) не должна появляться **ни в
одной** публичной выдаче: список каталога, страница задачи, случайная задача,
блок «Похожие», конструктор подборок, экспорт `.tex` и PDF, публичный API модала.

Сейчас фильтр стоит в восьми местах `catalog/views.py`. Добавляете новую выдачу —
добавляете фильтр. Забыли в одном месте — скрытая задача просачивается наружу
именно там, и заметит это владелец, а не тест.

**Домашки ученика шлюзом не фильтруются намеренно** — уже выданное должно
оставаться решаемым. Это не забытый фильтр.

Отдельный флаг `solution_needs_review` прячет **только кнопку решения**; задача
остаётся видимой. Плохое решение не повод прятать хорошее условие.

---

## Публичный API

`/catalog/api/problem/<id>/` отдаёт **только** published-задачи без флага.
Это публичный эндпоинт без авторизации — проверять статус обязательно, иначе он
превращается в обход шлюза по прямой ссылке.

Учительский эндпоинт (`/teacher/api/...`) видит всё — это другой контур, у него
свой декоратор доступа.

---

## Подборки

`Collection.token` — доступ по ссылке без логина. **Токен не защита:** ссылка
уходит кому угодно. Персональных данных в подборках нет, поэтому это приемлемо;
класть туда что-то чувствительное нельзя.

## Поиск

- `semantic.py` — плотный поиск: ленивый синглтон (модель и индекс грузятся при
  первом запросе, живут в памяти процесса). Индекс строится **только** из
  published-задач без флага.
  ⚠️ `BinaryField` отдаёт `memoryview`, а не `bytes` — нужна обёртка `bytes(blob)`.
- `hybrid.py` — слияние плотной и лексической ног через RRF (`RRF_K = 60`).
  RRF выбран потому, что не требует знать шкалы обеих ног: у косинуса и у
  лексического счёта разные единицы, любые веса были бы подгонкой на глаз.
- Имя модели берётся **только** из `problems/embedding_config.py`
  (`EMBEDDING_MODEL_NAME`). Дублировать строку модели в файлах нельзя: корпус и
  запрос обязаны кодироваться одной моделью, иначе сравниваем несравнимое.

⚠️ **Индекс живёт в памяти процесса.** После правки корпуса он устаревает до
перезапуска — есть `invalidate_index()`. В тестах это даёт плавающий результат:
класс, зависящий от индекса, обязан в `setUp` звать `cache.clear()` и
`semantic.invalidate_index()`.

⚠️ На проде модель не грузится. `/catalog/smart-search/` работает только локально,
блок «Похожие» на проде живёт по кэшу M2M
([ADR 0002](../docs/adr/0002-embeddings-separate-process.md)).

## Шаблоны

- **KaTeX: `$$` раньше `$`** в списке разделителей. Обратный порядок режет
  `$$…$$` как два пустых `$…$` — этот баг уже был.
- Конвейер долларов — из общего партиала `templates/_katex_dollars.html`, а не
  копией в шаблоне. Копия неминуемо разъедется, и проверки перестанут отражать
  боевой рендер.
- **Проценты — через `{% widthratio pct 1 100 %}`** (даёт целое).
  `{{ pct|floatformat:0 }}` не использовать: возвращает строку с запятой.
- Цвета — только через `var(--…)` из `templates/_tokens.html`. Хардкод hex ломает
  тёмную тему. Карточка без явного `background` сольётся с серым фоном страницы —
  задавать `var(--surface)`.

## Фильтры каталога

Логика в `problem_list` наращивается **только additive**: новые параметры
(`sort`, `view`, чипы) не меняют поведение существующих фильтров. Каталог —
самый посещаемый экран, и регрессия в нём видна всем сразу.

Теги шаблонов — в `catalog/templatetags/catalog_filters.py`
(`filter_param`, `set_param`, `remove_param`).
