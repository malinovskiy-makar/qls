# Правила каталога и поиска

Локальные правила для `catalog/`. Общие запреты — в корневом
[CLAUDE.md](../CLAUDE.md). Устройство поиска — в
[docs/EMBEDDINGS.md](../docs/EMBEDDINGS.md).

---

## Шлюз качества держит везде

Зафлагованная задача (`needs_quality_review=True`) не должна появляться **ни в
одной** публичной выдаче: список каталога, страница задачи, случайная задача,
блок «Похожие», конструктор подборок, экспорт `.tex` и PDF, публичный API модала.

Сейчас фильтр стоит в восьми местах `catalog/views.py`. Добавляете новую выдачу —
добавляете фильтр. Забыли в одном месте — скрытая задача просачивается наружу
именно там, и заметит это владелец, а не тест.

**Домашки ученика шлюзом не фильтруются намеренно** — уже выданное должно
оставаться решаемым. Это не забытый фильтр.

Отдельный флаг `solution_needs_review` прячет **только кнопку решения**; задача
остаётся видимой. Плохое решение не повод прятать хорошее условие.

---

## Публичный API

`/catalog/api/problem/<id>/` отдаёт **только** published-задачи без флага.
Это публичный эндпоинт без авторизации — проверять статус обязательно, иначе он
превращается в обход шлюза по прямой ссылке.

Учительский эндпоинт (`/teacher/api/...`) видит всё — это другой контур, у него
свой декоратор доступа.

---

## Подборки

`Collection.token` — доступ по ссылке без логина. **Токен не защита:** ссылка
уходит кому угодно. Персональных данных в подборках нет, поэтому это приемлемо;
класть туда что-то чувствительное нельзя.

## Поиск

- `semantic.py` — плотный поиск: ленивый синглтон (модель и индекс грузятся при
  первом запросе, живут в памяти процесса). Индекс строится **только** из
  published-задач без флага.
  ⚠️ `BinaryField` отдаёт `memoryview`, а не `bytes` — нужна обёртка `bytes(blob)`.
- `hybrid.py` — слияние плотной и лексической ног через RRF (`RRF_K = 60`).
  RRF выбран потому, что не требует знать шкалы обеих ног: у косинуса и у
  лексического счёта разные единицы, любые веса были бы подгонкой на глаз.
- Имя модели берётся **только** из `problems/embedding_config.py`
  (`EMBEDDING_MODEL_NAME`). Дублировать строку модели в файлах нельзя: корпус и
  запрос обязаны кодироваться одной моделью, иначе сравниваем несравнимое.

⚠️ **Индекс живёт в памяти процесса.** После правки корпуса он устаревает до
перезапуска — есть `invalidate_index()`. В тестах это даёт плавающий результат:
класс, зависящий от индекса, обязан в `setUp` звать `cache.clear()` и
`semantic.invalidate_index()`.

⚠️ **Отдельного экрана умного поиска больше нет** (решение владельца
01.09.2026): он слился с каталогом. `/catalog/smart-search/` отвечает 301 на
`/catalog/`, пункт из шапки убран, шаблон удалён. Поиск на каталоге ОДИН и
всегда по смыслу; лексический — запасной путь при недоступности.

⚠️ **При пустом запросе смысловой поиск не трогается вовсе.** Модель грузится
лениво (~7 с первый раз). Пока поиск жил отдельной страницей, это была плата
за вход именно на неё; теперь каталог — главный вход. Сторожит
`catalog/tests/test_smart_catalog.py`.

⚠️ **Порог близости — настройка** `SEMANTIC_SEARCH_MIN_SCORE` (0,55). Близость
BGE-M3 НЕ калибрована по длине запроса: одно слово даёт максимум 0,63, абзац —
0,75. Порог 0,65 оставил бы абзацу 164 совпадения, а слову — ноль.

⚠️ На проде модель не грузится, блок «Похожие» живёт по кэшу M2M
([ADR 0002](../docs/adr/0002-embeddings-separate-process.md)).

## Шаблоны

- **KaTeX: `$$` раньше `$`** в списке разделителей. Обратный порядок режет
  `$$…$$` как два пустых `$…$` — этот баг уже был.
- Конвейер долларов — из общего партиала `templates/_katex_dollars.html`, а не
  копией в шаблоне. Копия неминуемо разъедется, и проверки перестанут отражать
  боевой рендер.
- **Проценты — через `{% widthratio pct 1 100 %}`** (даёт целое).
  `{{ pct|floatformat:0 }}` не использовать: возвращает строку с запятой.
- Цвета — только через `var(--…)` из `templates/_tokens.html`. Хардкод hex ломает
  тёмную тему. Карточка без явного `background` сольётся с серым фоном страницы —
  задавать `var(--surface)`.

## Фильтры — ОДИН компонент на каталог и домашку

`catalog/filters.py` — единственное место, где разбираются параметры отбора,
строится запрос и считаются числа по вариантам. Его же разметку рисуют
`_filters.html` (режимы «полоса» и «панель») и `_filters_body.html`; стили —
`_filters_css.html`, рядом с разметкой, а не внутри одного из экранов.

Компонент читают ДВА экрана: `catalog.views.problem_list` и
`teacher.picker.picker_context`. Раньше у каждого была своя копия разбора, и
они уже разошлись — в каталоге был фильтр «Источник», на домашке нет
(решение владельца 01.09.2026).

Различия экранов названы ПАРАМЕТРАМИ, а не спрятаны в двух реализациях:

- `base_queryset(gate=…)` — `'catalog'` показывает только проверенное
  человеком (14 458), `'tutor'` — всё опубликованное без брака (28 593);
- `solution_strict` — каталог прячет непроверенные решения, конструктор нет.

⚠️ **Группа фильтра показывается, только если у неё есть варианты**, и
считается это по КОРПУСУ, а не по текущей выдаче (`_has_data`). Первая
версия решала по отфильтрованному набору, и фильтры исчезали по мере
сужения вместе со способом их снять.

⚠️ **Параметр вида задачи называется `type`, а не `kind`.** У мастера
домашки `kind` занят видом РАБОТЫ (домашка/контрольная).

⚠️ **Числа считаются группировкой, а не списком `id__in`.** Первый вариант
вытаскивал 14 458 ключей в питон и вкладывал их в SQL списком — секунда на
каждой отрисовке.

Старые теги шаблонов (`filter_param`, `set_param`, `remove_param` в
`catalog/templatetags/catalog_filters.py`) новым экраном НЕ используются:
адреса вариантов собирает `filters.query()`, потому что «чужие» параметры
экрана (режим отображения, занятие, вид работы) должен помнить питон, а не
разметка. Живым остался `spaceint`.

## Карта тем и тегов: два режима одного движка

`/catalog/map/` — полная карта: `topic_map.js` (около 170 КБ), подписи,
поиск, панель-дерево, хождение по линиям, обучение.

`topic_map_preview.js` (около 29 КБ) — **встраиваемый режим** для чужого
экрана: только узлы и связи, медленное автовращение, курсор не слушается,
клик в любом месте ведёт на полную карту. Данные и раскладка считаются
после отрисовки экрана-хозяина и только когда блок показался; вне экрана и
при `prefers-reduced-motion` цикл кадров снимается.

⚠️ **Это два файла, а не флаг в одном, и общее у них — ДАННЫЕ, а не код.**
Оба берут `/catalog/map/data.json` и одно зерно раскладки, поэтому облако
узнаётся глазом как та же карта. Тянуть полный движок на каждое открытие
каталога ради вращающегося окошка — платить за то, что в маленьком окне не
показывается (решение владельца 01.09.2026).

Как подключить предпросмотр к своему экрану — комментарий в шапке
`catalog/static/catalog/js/topic_map_preview.js`; стенд приёмки —
`/catalog/map/preview-demo/` (в навигации его нет).

Цвета разделов — роли `--map-g-*` в `templates/_tokens.html`, читают оба
режима ([ADR 0053](../docs/adr/0053-topic-map-seven-section-colours.md)).
Справочник тем и тегов — `catalog/taxonomy_map.py`, единственная точка
сборки данных `build_map()`.

⚠️ **Разделов карты ПЯТЬ, а не семь** (04.09.2026,
[ADR 0071](../docs/adr/0071-five-sections-one-module.md)): Микро, Макро,
Финансы, Математика, Прочее — те же блоки, что в фильтрах каталога, в
тренажёре и на радаре статистики. Границы блоков живут в
`problems/sections.py`, а не здесь: `GROUPS` строится из него. Имя файла
ADR 0053 («seven-section») осталось прежним — переименовывать принятый ADR
нельзя, уточнение записано в 0071.
