# Правила каталога и поиска

Локальные правила для `catalog/`. Общие запреты — в корневом
[CLAUDE.md](../CLAUDE.md). Устройство поиска — в
[docs/EMBEDDINGS.md](../docs/EMBEDDINGS.md).

---

## Шлюз качества держит везде

Зафлагованная задача (`needs_quality_review=True`) не должна появляться **ни в
одной** публичной выдаче: список каталога, страница задачи, случайная задача,
блок «Похожие», конструктор подборок, экспорт `.tex` и PDF, публичный API модала.

Сейчас фильтр стоит в восьми местах `catalog/views.py`. Добавляете новую выдачу —
добавляете фильтр. Забыли в одном месте — скрытая задача просачивается наружу
именно там, и заметит это владелец, а не тест.

**Домашки ученика шлюзом не фильтруются намеренно** — уже выданное должно
оставаться решаемым. Это не забытый фильтр.

Отдельный флаг `solution_needs_review` прячет **только кнопку решения**; задача
остаётся видимой. Плохое решение не повод прятать хорошее условие.

---

## Публичный API

`/catalog/api/problem/<id>/` отдаёт **только** published-задачи без флага.
Это публичный эндпоинт без авторизации — проверять статус обязательно, иначе он
превращается в обход шлюза по прямой ссылке.

Учительский эндпоинт (`/teacher/api/...`) видит всё — это другой контур, у него
свой декоратор доступа.

---

## Подборки

`Collection.token` — доступ по ссылке без логина. **Токен не защита:** ссылка
уходит кому угодно. Персональных данных в подборках нет, поэтому это приемлемо;
класть туда что-то чувствительное нельзя.

## Поиск

- `semantic.py` — плотный поиск: ленивый синглтон (модель и индекс грузятся при
  первом запросе, живут в памяти процесса). Индекс строится **только** из
  published-задач без флага.
  ⚠️ `BinaryField` отдаёт `memoryview`, а не `bytes` — нужна обёртка `bytes(blob)`.
- `hybrid.py` — слияние плотной и лексической ног через RRF (`RRF_K = 60`).
  RRF выбран потому, что не требует знать шкалы обеих ног: у косинуса и у
  лексического счёта разные единицы, любые веса были бы подгонкой на глаз.
- Имя модели берётся **только** из `problems/embedding_config.py`
  (`EMBEDDING_MODEL_NAME`). Дублировать строку модели в файлах нельзя: корпус и
  запрос обязаны кодироваться одной моделью, иначе сравниваем несравнимое.

⚠️ **Индекс живёт в памяти процесса.** После правки корпуса он устаревает до
перезапуска — есть `invalidate_index()`. В тестах это даёт плавающий результат:
класс, зависящий от индекса, обязан в `setUp` звать `cache.clear()` и
`semantic.invalidate_index()`.

⚠️ **Отдельного экрана умного поиска больше нет** (решение владельца
01.09.2026): он слился с каталогом. `/catalog/smart-search/` отвечает 301 на
`/catalog/`, пункт из шапки убран, шаблон удалён. Поиск на каталоге ОДИН и
всегда по смыслу; лексический — запасной путь при недоступности.

⚠️ **При пустом запросе смысловой поиск не трогается вовсе.** Модель грузится
лениво (~7 с первый раз). Пока поиск жил отдельной страницей, это была плата
за вход именно на неё; теперь каталог — главный вход. Сторожит
`catalog/tests/test_smart_catalog.py`.

⚠️ **Порог близости — настройка** `SEMANTIC_SEARCH_MIN_SCORE` (0,55). Близость
BGE-M3 НЕ калибрована по длине запроса: одно слово даёт максимум 0,63, абзац —
0,75. Порог 0,65 оставил бы абзацу 164 совпадения, а слову — ноль.

⚠️ На проде модель не грузится, блок «Похожие» живёт по кэшу M2M
([ADR 0002](../docs/adr/0002-embeddings-separate-process.md)).

## Шаблоны

- **KaTeX: `$$` раньше `$`** в списке разделителей. Обратный порядок режет
  `$$…$$` как два пустых `$…$` — этот баг уже был.
- Конвейер долларов — из общего партиала `templates/_katex_dollars.html`, а не
  копией в шаблоне. Копия неминуемо разъедется, и проверки перестанут отражать
  боевой рендер.
- **Проценты — через `{% widthratio pct 1 100 %}`** (даёт целое).
  `{{ pct|floatformat:0 }}` не использовать: возвращает строку с запятой.
- Цвета — только через `var(--…)` из `templates/_tokens.html`. Хардкод hex ломает
  тёмную тему. Карточка без явного `background` сольётся с серым фоном страницы —
  задавать `var(--surface)`.
- **Каталог собран из партиалов** (редизайн 04.09.2026): `_catalog_results.html`
  — секция найденных задач, её же отдаёт `api_filter_state`; `_catalog_chips.html`
  — чипы полосы; `_catalog_modal.html` + `_catalog_modal_block.html` — окно «Все
  фильтры»; стили полосы и окна — `_catalog_filters_css.html`. Бегущая подсказка
  поля — один партиал `templates/_typing_placeholder.html` на главную и каталог,
  фразы — `catalog/placeholder_phrases.py`.
- **Правило нуля:** число, имя, список на экране — из контекста, а контекст — из
  базы или данных (подпись карты считается из `topic_map.json`, звёзды только при
  сложности, чип темы только при теме, заголовок — только если не обрезок
  условия: `catalog/preview.py`). Слова-обещания («появится», «скоро», «пример»)
  в шаблонах каталога запрещены — `test_no_slop.py` читает файлы.
- **Превью карточек и «Похожих» — сырой TeX** (`preview.tex_preview`, 17.09.2026):
  токены `[[FIGURE:…]]` вырезаны, разрез не внутри формулы. KaTeX — один конвейер
  `renderMathIn(root)` в `base.html`: при загрузке, после подмены выдачи фильтром
  (`catalog_filters.js`) и после подмены задачи «Стола» (`stol.js`). Модалки «Условие»
  нет с 18.09.2026 — задача открывается на месте. Текст задачи — всегда серверный
  `_math_text.html` (санитайзер, картинки); сырые данные в `innerHTML` не кладутся никогда.
- **Чип источника — ссылка на первоисточник** (`views.source_url`, 17.09.2026):
  `SourceReference.url` только http(s); ILE без адреса — главная ILE; МатЭк и
  «Сборник тестов АА» — текст без ссылки.
- **У `<dialog>` цвет текста задавать явно** (`.ct-all { color: var(--text) }`):
  браузерный цвет диалога чёрный и не наследует `body` — в тёмной теме контраст
  был 1,45. Сторож — `catalog/tests/test_contrast.py` (serial, браузер).
- **Длинного тире «—» в тексте нет** (правило сайта, `scripts/check_em_dash.py`):
  мокапы владельца тире содержат — при переносе менять на «–» или двоеточие.
- **Страница задачи** (с 19.09.2026 — вид `stol` шаблона `stol.html`, раздел «Стол»
  ниже; прежние полоса 1120 и карточка ИИ из ADR 0078 заменены ADR 0121). Заголовок — только для названия; обрезок условия
  (`preview.looks_like_statement_cut`) уходит в скрытый `h1` «Задача: <тема>».
  Номер задачи нигде, кроме адреса. Облачка свойств — ссылки в каталог через
  `filters.query()`. Ответ и решение раздельно: решение короче 30 знаков или равное
  ответу — это ответ; `solution_needs_review` прячет решение, ответ остаётся.
  Текст с формулами — один партиал `_math_text.html`; «+ В домашку» — корзина
  репетитора «Стола» (раздел ниже).
- **Подсказки уровнями и файлы к попытке** (этап 6, 04.09.2026). Подсказка —
  `GET /catalog/api/hint/<problem_id>/<n>/`, `n` с единицы, за пределом 404;
  общие идут по `order`, к подпунктам — после общих с пометкой пункта. Кнопка
  «💡 Подсказка 1 из N» рендерится только при подсказках (`hint_total`), у
  непроверенных подсказок ИИ подпись «сгенерировано ИИ, не проверено
  человеком» (`Hint.generated_by_ai`, `Hint.reviewed`). Заливка —
  `import_hints` (JSONL, сухой прогон по умолчанию, `--apply`, `--replace` со
  снимком). Файл к попытке — `POST /catalog/api/attempt-file/` (вход, один
  файл, jpg/png/webp/pdf до 10 МБ, три на попытку; `catalog/attachments.py`
  проверяет расширение, сигнатуру PDF и открывает картинку Pillow); попытка
  принимает `file_ids` СВОИХ файлов, текст с фото распознаётся до проверки
  ([ADR 0081](../docs/adr/0081-photo-is-recognised-before-the-check.md)).
- **Тест как игра** (этап 7, 04.09.2026, [ADR 0082](../docs/adr/0082-catalog-test-unlimited-attempts.md)).
  Модель игры — `catalog/testplay.py`: варианты из подпунктов, верные метки
  — `answer_check.catalog_test_correct_labels`, правило «всё или ничего» —
  `check_option_answer`. `POST /catalog/api/test-check/<id>/` принимает
  `{labels: [...]}` и от гостя тоже: попытки считаются В СЕССИИ по ключу
  задачи, число верных (`correct_count`) приходит после двух неудач, верный
  ответ сбрасывает счётчик и у вошедшего пишется `CatalogAttempt`
  «тест: решено с N-й попытки». `POST /catalog/api/test-reveal/<id>/` отдаёт
  верные метки и сбрасывает счётчик. Экран — партиал `_problem_test.html`:
  плитки `aria-pressed`, разбор четырьмя состояниями с подписями из
  `student/_option_review.html`. Правило нуля: тест без вариантов или с
  верными метками вне вариантов — обычная задача без «Проверить»; «Почему
  так» только при решении; строка игры только при `game_stat`; «Ещё тест по
  этой теме» только если другой тест по первой известной теме есть
  (`random_problem` понимает фильтры каталога и `exclude=`).
  ⚠️ Слитные ответы («аб») режет `answer_check.label_set`, ей же пользуется
  `build_game_pool`: две копии разошлись бы на первом же исправлении.
- **Карточка «Решение» на странице задачи** живёт по правилу нуля: поле
  ввода только при доступной модели, подсказки только при подсказках, кнопка
  решения только при решении или ответе; нет ничего — нет карточки.

## «Стол» — один экран на вход, задачу и карту (ADR 0121–0123, 19.09.2026)

Спецификация — `claude/mockups/catalog_stol_20260917/README.md` §1–§9 и `shots/`.

**Адреса и шаблон.** Один шаблон `catalog/stol.html`, вид — `view`: `/catalog/` — `entry`,
`/catalog/problem/<id>/` — `stol`, `/catalog/map/` — `map` (вход под картой). Каждый адрес сервер
отдаёт целиком (прямая ссылка работает без скрипта). Партиалы — `catalog/stol/`: `_stol_entry`,
`_stol_desk`, `_stol_rail`, `_stol_center`, `_stol_help`, `_stol_map`, `_stol_basket`, строка ленты
`_rail_row` (одна на широкую и узкую ленту). Стили — один файл `catalog/css/stol.css`.

**Без перезагрузки.** `?pane=1` на адресе задачи — JSON `{center_html, help_html, similar_html,
meta}` теми же партиалами; на `/catalog/map/` — `{html}` разметки карты. `stol.js` — вид
(`weco.stol.setView`, событие `weco:view`), адреса (`pushState`/`popstate`), панели (лента 316 ·
условие 680 · помощь 392, полоски 52; `localStorage` `weco_stol`; на телефоне свои, закрыты при
каждой задаче), лента «Лента / Похожие / Мои ★» (вкладка «Выдача» переименована 24.09), соседи и «Дальше», вход (поиск, чипы,
фон-облако). `stol_task.js` — всё внутри задачи, идемпотентный `init(root)` после каждой подмены.
`stol_map.js` — карта (грузится при наведении на «Карта тем»), `stol_basket.js` — только репетитору.

**Фильтры — одно состояние** `weco.filters` (`catalog_filters.js`): окно «Все фильтры», чипы
входа, поиск и карта пишут его. Выбор на карте = фильтр (`TMAP_EMBED.onPick`, ADR 0122).

**Помощь** — лестница, потом одна лента по времени; переживает перезагрузку (ADR 0123).
Прогресс ученика — `ProblemProgress`, правила только в `catalog/progress.py` (ADR 0119).

**Полировка 24.09.2026 (ADR 0132).** Фокус: «Лента» и «Помощь» открываются поверх задачи —
`state.focusPanels` в `stol.js`, атрибуты `data-focus-rail/help`, в `weco_stol` не пишется; Esc
сначала закрывает панель, потом фокус. Строка свойств задачи: особенности из `ProblemFeature`
(одна выборка в `_problem_context`), скрытые — `problems/enrich/features.py::CARD_HIDDEN`; теги
раскрываются кнопкой (`stol_task.js::bindTags`). Строка лимита ИИ видна при остатке ≤
`problems/ai/core.py::LIMIT_WARN_AT`; совет помощи один раз — ключ `weco_help_tip_seen`.
Строка выдачи: метки в `rail-marks` у названия, в `rail-meta` только тема и звёзды (колонки 240/72).
Замеры — `test_stol_polish_browser.py` + `stol_polish_runner.mjs`.

**Корзина репетитора** (README §7): галочки в строках (`card.teach`), «в N домашках» (`card.in_hw`,
один запрос на страницу строк), `localStorage` `weco_basket_<uid>`, «В домашку ▾» →
`teacher.views.add_catalog_problems` (позиции `AssignmentItem` + M2M, шлюз), «PDF или TeX» →
`POST /catalog/collection/from-basket/` (только репетитору, иначе 404) → конструктор подборок.

⚠️ Шлюз качества в новых ответах — `views._visible(qs)`. Узлы карты несут `db` и живое `c`
(`catalog/map_numbers.py`). Решение, повторяющее условие: `preview.solution_is_statement_copy`,
`preview.strip_statement_retell`; «Почему так» теста — `preview.strip_correct_repeat`.
⚠️ Замеры числами в браузере — `catalog/tests/test_stol_browser.py` (+ `stol_runner.mjs`):
ширины, шрифты, облако, переход карты, телефон 360/390/430. Снимки — `scripts/beta_shots.mjs
<префикс> <порт> stol[:фаза]`.

## Фильтры — ОДИН модуль на каталог и домашку, ДВЕ разметки

`catalog/filters.py` — единственное место, где разбираются параметры отбора,
строится запрос и считаются числа по вариантам. Читают его два экрана:
`catalog.views._catalog_context` (каталог и эндпоинт живого состояния) и
`teacher.picker.picker_context` (конструктор домашки). Различия экранов
названы параметрами: `base_queryset(gate=…)` (каталог — только проверенное
человеком, конструктор — всё опубликованное без брака), `solution_strict`.

⚠️ **Множественный выбор** (решение владельца 04.09.2026): `topics`, `tags`,
`difficulties`, `sources`, `features` — списки; внутри группы — ИЛИ, между
группами — И; теги — И (человек уточняет). Старые одиночные адреса
(`?topic=843`) читаются как список из одного. Имена параметров — `PARAM`,
одна таблица на разбор, адрес, скрытые поля формы и скрипт окна (тест
`test_catalog_modal.ScriptContractTests` сверяет скрипт с ней).

⚠️ **Правило нуля** (решение 04.09.2026): вариант с нулём В КОРПУСЕ не
рендерится вовсе (`_corpus` считает корпус один раз на сборку), ноль под
ТЕКУЩИМИ фильтрами остаётся с флагом `zero` / классом `is-zero`; группа без
вариантов не показывается. Так «Характер задачи» и «Особенности» молчат,
пока владелец не зальёт разметку командой `import_problem_attributes`, и
включаются сами. Сторож — `catalog/tests/test_no_slop.py`.

**Каталог** — окно «Все фильтры»: варианты — кнопки `aria-pressed`,
состояние живёт в `catalog/static/catalog/js/catalog_filters.js` и в адресе
страницы; каждый клик идёт в `GET /catalog/api/filter-state/`, который
отдаёт числа по вариантам, чипы и список, собранные `_catalog_context`
теми же партиалами, что и страница; окно не закрывается. Теги темы —
`api_tags?topic=<id>`. Без скрипта страница остаётся рабочей: форма поиска
и крестики чипов — серверные ссылки.

**Конструктор домашки** остаётся на прежней разметке фильтров
(`_filters.html` в режиме панели, `_filters_body.html`, `_filters_css.html`:
ссылки, без JS) до отдельного решения владельца — его не трогать.

Темы лежат в пяти блоках владельца по НАЗВАНИЮ. Границы блоков, оба набора
названий (23 живых и 29 таксономии v2) и цвет — в `problems/sections.py`,
одном на весь сайт (решение 05.09.2026); `catalog/topic_blocks.py` — тонкий
слой над ним: нестрогое сравнение названий, `is_known`, порядок в блоке.
Цвет темы — её блок, `section_of()` → `--map-g-micro/macro/fin/math/other`.
Мусорные названия `Topic` в фильтр не попадают (`is_known`).

⚠️ **В фильтре только канонические темы и теги** (решение 17.09.2026): темы —
`is_canonical=True` в `_topic_options`, теги списком и в подсказках `api_tags` —
`kind='canonical'`. Одного `is_known` мало: он узнаёт и 23 старых названия, и
на бою, пока старые связи не сняла синхронизация банка, фильтр показывал 36 тем
вместо 29. Сторож — `catalog/tests/test_filter_canonical.py`. Фикстурам тестов
фильтра тема и тег нужны каноническими явно (`make_topic(..., is_canonical=True)`).

⚠️ **Параметр вида задачи называется `type`, а не `kind`.** У мастера
домашки `kind` занят видом РАБОТЫ (домашка/контрольная).

⚠️ **Числа считаются группировкой, а не списком `id__in`.** Первый вариант
вытаскивал 14 458 ключей в питон и вкладывал их в SQL списком — секунда на
каждой отрисовке.

Старые теги шаблонов `filter_param`, `set_param`, `remove_param` удалены
24.09.2026 (ни одной ссылки): адреса собирает `filters.query()`. Живые в
`catalog/templatetags/catalog_filters.py` — `spaceint` и `script_json`
(JSON для `<script type="application/json">` с кириллицей как есть).

## Карта тем и тегов: два режима одного движка

`/catalog/map/` — полная карта: `topic_map.js` (около 170 КБ), подписи,
поиск, панель-дерево, хождение по линиям, обучение. С 19.09.2026 это вид `map` «Стола»:
движок работает в режиме встраивания `window.TMAP_EMBED` (переход из фонового облака,
выбор = фильтры; без него — прежнее поведение), разметка — `catalog/stol/_stol_map.html`.

`topic_map_preview.js` (около 29 КБ) — **встраиваемый режим** для чужого
экрана: только узлы и связи, медленное автовращение, курсор не слушается,
клик в любом месте ведёт на полную карту. Данные и раскладка считаются
после отрисовки экрана-хозяина и только когда блок показался; вне экрана и
при `prefers-reduced-motion` цикл кадров снимается.

⚠️ **Это два файла, а не флаг в одном, и общее у них — ДАННЫЕ, а не код.**
Оба берут `/catalog/map/data.json` и одно зерно раскладки, поэтому облако
узнаётся глазом как та же карта. Тянуть полный движок на каждое открытие
каталога ради вращающегося окошка — платить за то, что в маленьком окне не
показывается (решение владельца 01.09.2026).

Как подключить предпросмотр к своему экрану — комментарий в шапке
`catalog/static/catalog/js/topic_map_preview.js`; стенд приёмки —
`/catalog/map/preview-demo/` (в навигации его нет).

Цвета разделов — роли `--map-g-*` в `templates/_tokens.html`, читают оба
режима ([ADR 0053](../docs/adr/0053-topic-map-seven-section-colours.md)).
Справочник тем и тегов — `catalog/taxonomy_map.py`, единственная точка
сборки данных `build_map()`.

⚠️ **Разделов карты ПЯТЬ, а не семь** (04.09.2026,
[ADR 0071](../docs/adr/0071-five-sections-one-module.md)): Микро, Макро,
Финансы, Математика, Прочее — те же блоки, что в фильтрах каталога, в
тренажёре и на радаре статистики. Границы блоков живут в
`problems/sections.py`, а не здесь: `GROUPS` строится из него. Имя файла
ADR 0053 («seven-section») осталось прежним — переименовывать принятый ADR
нельзя, уточнение записано в 0071.

## Решения и ответы — только вошедшим; кто платит за поиск (24.09.2026)

- **Решение, ответы к пунктам, «Почему так», верный вариант теста** — в разметке
  нет ни у кого (ни в странице, ни в `?pane=1`). Вошедшему — `POST
  /catalog/api/solution/<id>/` (`{}` — решение, `{"part": n}` — ответ к пункту),
  гостю — карточка `help-invite-tpl` с входом/регистрацией и возвратом на задачу
  (ADR 0129). `test-reveal` гостю — 403.
- **Платит за сортировку поиска только скрипт страницы** — `catalog/rerank_gate.py`,
  ADR 0128: полная загрузка `?q=` — `deferred`, `api_filter_state` — с
  `X-Weco-Search: 1`, кукой посетителя, UA не бота, в квотах и потолке.
- **Квота разных задач** — `catalog/scrape_guard.py` (в тестах выключена по
  умолчанию, `SCRAPE_GUARD_ENABLED`).
- **«Решить заново»** — `catalog/progress.reset`, `POST
  /catalog/api/progress/<id>/reset/`; экран после `reset_at` (ADR 0130).
- «Beta 1.0» на странице задачи скрыта правилом `body:has(.stol-app[data-view="stol"])`.

## SEO: роботы, карта сайта, заголовки (19.09.2026)

Всё в `catalog/seo.py`; решение — Notion «Решения», «SEO-фикс: боты не тратят
бюджет умного поиска…».

⚠️ **Краулеры не тратят бюджет.** Amazonbot и Googlebot по адресам `/catalog/?q=…`
выбирали суточный потолок переранжирования ($0,50 ≈ 205 вызовов) к 9:18 МСК —
остаток суток живые ученики искали без переранжирования. Три слоя: `robots.txt`
(`Disallow: /catalog/?q=*`), `<meta name="robots" content="noindex, nofollow">` на
выдаче с `q` и страховка `seo.is_crawler(request)` (по User-Agent): бот получает
обычную выдачу со статусом `off`, `apply()` не вызывается, `SearchLog` не пишется.
Новый краулер — строка в `CRAWLER_MARKERS`. Пустой User-Agent краулером не считается.

- `/sitemap.xml` — постоянные входы + задачи по `base_queryset('catalog')`, то есть
  ровно то, что не отдаёт 404 на `problem_detail`. Страниц тем с постоянным адресом
  нет (тема — это фильтр `?topic=`), в карте их нет.
- Мета-теги — общий партиал `templates/_seo_meta.html` (имя сайта, подтверждение
  Google и Яндекса, description/og:* из `seo_title` и `seo_description` контекста).
  Подключён в `<head>` каждого публичного базового шаблона; у нового базового
  шаблона он обязан быть.
- Заголовок задачи — `heading` из `_problem_context` (настоящее название либо «Задача:
  тема»), без формул. Название олимпиады — только для `OLYMPIAD_SHORT` (ВсОШ, МОШ,
  «Высшая проба», IEO): полные названия из `OlympiadRef` дали бы кривую фразу.
- Каталог с ровно одним фильтром «тема» получает заголовок темы; любое другое
  сочетание фильтров — прежний заголовок.
- **«Высшая проба» (21.09.2026, ADR 0127):** `/vp/` в `StaticSitemap`, `/vp/<слаг>/` опубликованных
  вариантов – `VPSitemap`; `vp_landing_meta` / `vp_variant_meta`. Страницы попыток и результатов – `noindex`,
  в `robots.txt` закрыт `/vp/a/`, а `/vp/r/` открыт намеренно (закрытый адрес не даёт роботу прочитать `noindex`).
